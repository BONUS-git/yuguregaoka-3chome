# 0092 — 配達回は見回りで進め、持ち越せない回は failed にする

- 状態: 置き換え（→ 0094）
- 日付: 2026-11-25

ADR-0016 を丸ごと置き換える。ADR-0016 の決定（見回りのジョブ J0、工程の順序と関門時刻、間に合わなかったときの休刊と持ち越し）は、今の状態に書き直して D1〜D4 に移した。
新しく決めたのは、`failed` を書くのは J0 だけで、J6 の再試行が尽きたときに書くこと（D5）、後の回の公開の条件となる「前の回が済んだ」を `done`・`skipped`・`failed` のどれかとすること（D6）、`failed` の回の中身と見え方（D7）。
`reviews/0001-design-review.md` の R-011、`triage.md` 仕分け 3 の K-005（YGO-031）。

## 背景

配達回（`delivery_runs`）は締め切り・審査・組版・準備・公開という複数の工程を経る。
これらをどう制御するかで 3 つの案があった。

1. **決まった時刻の cron だけ**: 各工程を固定時刻の cron ジョブとして並べる。
2. **工程が次の工程を積む鎖**: 各工程が完了したとき、次の工程のジョブを自分で積む。
3. **見回りジョブ（tick）と時刻の関門**: 定期的な見回りジョブが配達回の状態と現在時刻を見て、次の工程を 1 つずつ積む。

配達時刻に間に合わなかった場合の対処（休刊 / 持ち越し）も決める必要があった。

さらに、状態の `failed`（持ち越し先も作れない）を誰がいつ書くかが決まっておらず、後の回の公開の条件が `async.md` の中で「前の回が `done` か `skipped`」と「前の回がすべて `done`」に分かれていた。
どちらの条件でも、`failed` の回が 1 つあると後の回の J5 がずっと積まれず、定時配達（構想の根幹）が止まる（R-011）。

## 決定

### D1 見回りのジョブ

**J0 `delivery.tick`** を 5 分ごとに動かし、配達回ごとに次の工程を 1 つだけ `singletonKey` で積む。

### D2 工程の順序と関門時刻（JST）

| 工程 | ジョブ | 開始の条件（関門）| 打ち切り / 締め切り |
|------|--------|----------------|-------------------|
| 締め切り | J1 | 01:00 / 14:00 以降 | — |
| 審査 | J2 | 02:00 / 15:00 以降 | 04:00 / 16:00 [assumed] |
| 組版 | J3 | J2 完了または審査打ち切り後 | 05:00 / 16:30 |
| 準備 | J4 | `newspapers` の行ができた後 | — |
| 公開 | J5 | 07:00 / 17:00 以降、準備が済み（`prepared_at` が NULL でない）、前の配達回がすべて済んだ（D6） | 07:15 / 17:15 [assumed] |
| 持ち越し | J6 | 公開の打ち切りを過ぎた場合 | — |
| 手紙の通知 | J15（`kind = letter`） | 公開済み（`done`）で、手紙の枠の時刻（08:00〜11:50 / 18:00〜20:50 の 10 分ごと）以降 | 枠の時刻から 30 分 [assumed] |

公開（J5）は 07:00 / 17:00 に配達回を `done` にし、その時刻に見えるのは新聞と掲示板だけ（ADR-0035）。
手紙は住民ごとの枠の時刻（`mailbox_items.visible_at`）から見える。J0 は公開済みの配達回について、時刻を過ぎた枠ごとに手紙の通知（J15）を積む。
新聞の通知は J5 が公開と同じトランザクションで積む（休刊の回にも積む。郵便受けには休刊の印が届く。ADR-0035 の D11）。

審査の打ち切りと公開の打ち切りの時刻は仮置き [assumed]。

### D3 組版が間に合わないとき（休刊）

組版の締め切りまでに J3 が完了しなければ、J0 が `is_holiday = true` の行を挿入して休刊にする。
その配達回は紙面を届けない（ADR-0007）。郵便受けには休刊の印と手紙が届き、新聞の通知も送る（ADR-0035）。

### D4 公開が間に合わないとき（持ち越し）

公開の打ち切りまでに J5 が完了しなければ、J0 が J6（持ち越し）を積む。どの工程で止まっていても同じで、J0 は `running` の枝の先頭でこれを判断する。
J6 はその配達回の中身を次の受付中の配達回に移し、`delivery_runs.status` を `skipped` にする。

### D5 `failed` を書くのは J0 だけ

- J6 の再試行が尽きた（pg-boss の `delivery.carry_over:<run_id>` のジョブが `failed` の状態になった）とき、J0 がその配達回を `failed` にする [assumed]。
- J0 はこの判断を `running` の枝の先頭（持ち越しの打ち切りの判断より前）に置く。`failed` にした回には J6 を積み直さない。
- 書き込みは見回りのほかの処理と別のトランザクションで、`UPDATE delivery_runs SET status='failed' WHERE run_id=$1 AND status='running'` とする（2 回目は 0 行で何もしない）。
- 書いた J0 は `alert=delivery_run_failed` と `run_id` を含む 1 行をログに書く（`async.md` §7 の監視）。
- J5・J6 は `failed` を書かない。J6 は失敗すれば例外で終わり、pg-boss の再試行に任せる。

### D6 後の回の公開の条件

J0 は、その回より古い（`run_id` の小さい）配達回がすべて `done`・`skipped`・`failed` のどれかになるまで、J5 を積まない [assumed]。
`failed` の回があっても後の回は公開できる。前の回が `pending`・`running` の間だけ待つ（古い回から順に公開する）。

### D7 `failed` の回の中身と見え方

- `failed` の回の手紙・投稿・`mailbox_items` は動かさない（J6 のトランザクションが戻ったまま）。`finished_at` は NULL のまま。
- 住民の郵便受けには何も出ない。J4 が準備し終えて `visible_at` のある行が残っていても、住民に見せる・数える経路はどれも行の配達回が `done` であることを条件にするので、`failed` の回の行は使わない（郵便受けの一覧と項目は `api.md` §7 F-03・ADR-0035、プロフィールの年齢の見せる条件は ADR-0093 の D4 (a)・`api.md` §7 F-01）[assumed]。送った人には「投函済み」と見えたまま。
- 運用者が直す手順（原因を直したあとに、運用者の CLI で持ち越しをやり直す）は暫定で、M3 で決める（`gaps.md` G-053）。

## 理由

- **再起動しても工程を再開できる**: 各工程の完了はテーブルの状態で分かるため、worker を再起動したあと J0 が見回れば止まっていた工程を正しく拾い直せる。
- **鎖が一度切れても自動回復する**: 工程が次の工程を積む設計では、ジョブが失敗して次のジョブが積まれなかった場合に止まったまま自動回復しない。J0 の見回りがその保険になる。
- **時刻の制約と状態の確認を 1 か所に集められる**: J0 が「今何時か」と「どこまで進んだか」を組み合わせて判断するため、時刻ロジックが分散しない。
- **D5**: J6 は失敗したトランザクションの中では `failed` を書けない（戻ると書いた値も消える）。再試行が尽きたことは pg-boss のジョブの状態で外から分かるので、状態を進める役の J0 が書くのが、ほかの状態の判断と 1 か所にそろう。別のトランザクションにするのは、見回りのほかの回の処理の失敗で `failed` が戻らないため。
- **D6**: `failed` の回は運用者が手で直すまで終わらない。それを待つと、1 回の失敗で後の定時配達がすべて止まる。`failed` の回の中身は動かないので、後の回を公開しても中身が混ざらない。
- **D7**: 持ち越せなかった中身を J0 が別の方法で動かすと、失敗の原因（DB の制約違反など）を同じ手順で踏み直すことになる。動かさずに残し、アラートで運用者に知らせる。

## 代わりの案（選ばなかった理由）

**決まった時刻の cron だけで動かす**: worker の再起動やジョブの失敗のあと、途中の工程を再開する仕組みが別途必要になる。不採用。

**工程が次の工程を積む鎖だけにする**: 鎖が一度切れると止まる。監視と手動介入が必要になり、運用コストが上がる。不採用。

**J6 が最後の再試行で `failed` を書く**: J6 のトランザクションの外でもう 1 つの書き込みが要り、`failed` を書く場所が J0 と J6 に分かれる。最後の試行が処理の外で終わった（worker が止まった）ときに書かれない。不採用。

**前の回の条件を `done`・`skipped` のままにする**: `failed` の回が 1 つあると後の回の公開がずっと止まる（R-011）。不採用。
