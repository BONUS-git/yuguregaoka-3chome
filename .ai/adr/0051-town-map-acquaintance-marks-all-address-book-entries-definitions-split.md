# 0051 — 地図の知り合いの家の印は、自分の住所録のすべてのエントリに付ける。地図と新聞・手紙で「知り合い」の定義を分け、地図の印は `acquainted` で変えない

- 状態: 採用
- 日付: 2026-11-20

## 背景

OQ-054 の答え「2:1」で、地図の知り合いの家の印は (a) 自分の住所録に入れた住民に付けると決めた（ADR-0042 の D1 (c)）。
その後、OQ-058 の答え「知り合いの定義は b。新聞でも同じ定義」で新聞の知り合いは (b) 互いに住所録に入れた住民になり（ADR-0074 の D2）、
OQ-066 の答えで手紙を出せる知り合いも互いの追加（または掲示板でのオープン）になった（ADR-0065 の D2）。住所録の応答には各エントリが知り合いかを示す `acquainted` が入った（ADR-0065 の D4）。
地図は答え「2:1」のまま、と新聞の「同じ定義」が食い違うので、`open-questions.md` の OQ-071 でマスターに次を聞いていた。
(i) 地図の印を住所録のすべてのエントリに付ける（答え「2:1」のまま）か、(ii) 知り合い（`acquainted: true`）のエントリだけに付ける（新聞と手紙と同じ定義）か。
暫定は (i) だった（ADR-0065 の D8）。

2026-11-20、マスターが OQ-071 に次のとおり答えた（原文）。

> (i) 地図は (a) のまま。新聞と地図で定義は分ける。
>
> 公開範囲の判断において、個人の特定につながる情報は隠す（criteria）。地図の印を見て「相手が自分を住所録に入れたか」が推測できてしまうのは、意図しない情報の露出だ。
>
> 新聞の「知り合い」は、コミュニティ内の繋がり（双方向性）を可視化して楽しむための機能。一方で、地図はあくまで場所のインフラ。インフラの段階で、相手の意思（自分を登録したかどうか）が勝手に露呈するような設計はしたくない。仕組みの側が自然な振る舞いを受け止めるべき（criteria）なので、地図は「自分が知っている人を表示する」というシンプルな振る舞いに留める。

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと |
|---|---|---|
| 「(i) 地図は (a) のまま」 | 地図の印は本人の住所録のすべてのエントリに付ける。暫定 (i) がそのまま決定になる | — |
| 「新聞と地図で定義は分ける」 | 地図の「知り合い」は (a) 自分の住所録に入れた住民。新聞の「知り合い」は互いに住所録に入れた住民（ADR-0074 の D2）、手紙を出せる「知り合い」は互いに住所録に入れた住民か、掲示板で相手がオープンにした住民（ADR-0065 の D2）のまま | — |
| 「地図の印を見て「相手が自分を住所録に入れたか」が推測できてしまうのは、意図しない情報の露出だ」「地図は「自分が知っている人を表示する」というシンプルな振る舞いに留める」 | 地図の印から、相手が自分を足したかを推し量れないようにする（基準） | 住所録の `acquainted` そのものから相手の追加を探れることを許すか。答えは地図についてのもので、その答えとは読まない（OQ-081 → 決定（ADR-0065 の D13）） |

## 決定

1. **D1 印を付けるエントリ（答え「(i) 地図は (a) のまま」）**: 地図の知り合いの家の印は、本人の住所録（`GET /api/v1/address-book`）のすべてのエントリの住所（登録した時点の住所、ADR-0003）に付ける。
   OQ-071 の暫定 (i)（ADR-0065 の D8）がそのまま決定になる。ADR-0042 の D1 (c)・D5 は変わらない。
2. **D2 定義を分ける（答え「新聞と地図で定義は分ける」）**: 地図の「知り合い」は、自分の住所録に入れた住民とする（ADR-0042 の D1 (c)）。
   新聞の知り合いの組の「知り合い」（互いに住所録に入れた住民、ADR-0074 の D2）と、手紙を出せる「知り合い」（互いに住所録に入れた住民か、掲示板で相手がオープンにした住民、ADR-0065 の D2）は変えない。
   文書で「知り合い」と書くときは、どの定義かを文脈か参照で示す（`requirements.md` §2 の用語）。
3. **D3 `acquainted` で印を変えない（秘書の判断。答えの基準から）**: 印の有無・形・見出し・代替テキストは、エントリの `acquainted` によらず同じにする。
   地図の画面（C1 の印の層）は住所録の応答の `acquainted` を読まず、住所だけを使う。片方だけ足したエントリと互いに足したエントリは、地図の上で見分けられない。
   印があっても手紙を出せるとは限らない（出せるかは住所録の画面と手紙の画面の `acquainted` で分かる。ADR-0065 の D4）。
4. **D4 要求の区分**: FR-114 の地図の印のエントリを、暫定から決定（`[inferred]`、マスターの答え OQ-071（2026-11-20）より）に直す。新しい FR は足さない。
   `requirements.md` §2 に「知り合い」の用語を足し、文脈ごとの定義を書く。

## 理由

- D1・D2 は答えによる。地図は「場所のインフラ」で、「自分が知っている人を表示する」ので、本人が住所録に入れたことだけで印を付ける。
- D3 は答えの基準「地図の印を見て「相手が自分を住所録に入れたか」が推測できてしまうのは、意図しない情報の露出だ」から直接出る。
  印の形や代替テキストを `acquainted` で変えると、(ii) と同じく地図の印から相手の追加が分かってしまう。地図の画面で `acquainted` を読まなければ、印の層の作りからこの分かり方が出ない。
- 新聞と手紙の定義（D2）を変えないのは、答えが「新聞の「知り合い」は、コミュニティ内の繋がり（双方向性）を可視化して楽しむための機能」と分けているため。手紙の同意（ADR-0065）は答えの範囲の外。

## 代わりの案（選ばなかった理由）

- **(ii) 地図の印を `acquainted: true` のエントリだけに付ける**: 答えが (i) を選んだ。地図の印から相手が自分を足したかが分かる。
- **印はすべてのエントリに付け、`acquainted` で形を変える（例: 互いに足した家だけ二重丸）**: 答えの基準に反する（地図の印から相手の追加が分かる）。
- **住所録の応答から `acquainted` を外す**: 手紙の宛先を選ぶとき（FR-053）に要り、ADR-0065 の D4 を変える。住所録の `acquainted` による探りを許すかは、この答えでは決めない（OQ-081 → 決定（ADR-0065 の D13））。

## 決めていないこと

- 住所録の `acquainted` で、足した側が相手の追加を探れることを許すか: OQ-081 → 決定（ADR-0065 の D13）。足した側が相手もすでに自分を足していたと知れる程度は許し、1 日の上限（ADR-0065 の D4）と相互にならない追加の停止（ADR-0066）で抑える。地図の印は `acquainted` で変えない（D3）ので、地図からは探れない。
- 印の形・大きさ・見出しの置き方と、代替テキストの文面: 実装で決める（ADR-0042 の D8・D9 と、この ADR の D3 の範囲の中で）。
