# 0085 — 退去で住民を指す行をすべて消すか外す

- 状態: 採用
- 日付: 2026-11-22

ADR-0079 を丸ごと置き換える。ADR-0079 の決定（退去のときの処理・長期不在のときの処理・保持期間・手紙の保持の D1〜D6・退去の受付の D7・J7 の手順 0 の D8・配達回を消さないこと・新聞の組み直し）は、今の状態に書き直してこの ADR に同じ番号で移した。
新しく決めたのは、住民を指す外部キーの ON DELETE（D9）、居住記録を住所を空き家にするのと同じトランザクションで終わらせること（D10）、`residents` を消す前に住民を指す列を NULL にすること（D11）、J14 が居住記録を消すときにそれを指す列を NULL にすること（D12）。`reviews/0001-design-review.md` の R-008 による。

## 背景

OQ-030「アカウント情報の保持期間・削除ポリシー」は `db.md` と `security.md` で定めるとされている（持ち越し）。

住民が退去する（アカウントを削除する）とき、次の問いに答える必要がある。

1. 住民が作ったデータ（手紙・掲示板の投稿）はどうするか。
2. 受取人の郵便受けに届いた手紙はどうするか。
3. その住民が載った新聞はどうするか。
4. それぞれのデータを何日持つか（NFR-009、FR-097）。
5. 認証情報（`credentials`）とセッション（`sessions`）をいつ、どの順に消すか。
6. `residents` を外部キーで指すほかの行（居住記録・手紙の差出人・投稿者・通報者・モデレーター・画像）をどうするか。

`credentials`（メールの暗号化した値・検索用の HMAC・パスワードのハッシュ）と `sessions` は、どちらも `residents` を外部キーで指す（`db.md` §2）。
`push_subscriptions` は `sessions` を、`delivery_notifications` は `push_subscriptions` を外部キーで指す。
J7 が `residents` の行を消す前にこれらの行を消さないと、認証情報とセッションが退去のあとも残り、`residents` の行の削除も外部キーで止まる。
退去の受付（`DELETE /me`）ではセッションを無効にする（`invalidated_at` を付ける）だけで、行は残る。

ほかにも、次の列が `residents` を外部キーで指し、退去のあとも行が残る（`db.md` §2）。

- `tenancies.resident_id`（居住記録。退去から 1 年持つ）
- `letters.sender_id`（届いた手紙の差出人。手紙は受取人の側に残す）
- `board_posts.author_id`（投稿者。投稿は `deleted` にして本文を消すが、行は残る）
- `reports.reporter_id`（通報者。通報はクローズから 1 年持つ）
- `moderation_actions.moderator_id`（モデレーター。操作の記録は 1 年持つ）
- `images.uploader_id`（画像を上げた住民。加工した画像は、参照するコンテンツがある間持つ）

これらを NULL にする手順がなければ、J7 の最後の `DELETE FROM residents` が外部キーで失敗し、再試行しても通らない。
また、居住記録を終わらせる手順がなければ、退去した住民の居住記録が `is_current = true` のまま残り、J4 は退去した住民にも新聞の郵便受けの行を作り続ける（`async.md` J4 は `tenancies.is_current = true` の全住民に新聞を届ける）。

配達回（`delivery_runs`）は、次の 8 つの表から外部キーで指されている（`db.md` §2）: `letters`・`mailbox_items`・`delivery_notifications`・`newspapers`・`newspaper_articles`・`external_news_items`・`board_posts`・`moderation_queue`。
郵便受けの行は受取人が消すまで残り（FR-099）、紙面はバックナンバーとして残る（FR-039。保持期間は OQ-030 次第、仮に無期限）。
郵便受けとバックナンバーは、`delivery_runs.status = 'done'` の配達回の行だけを返す（`api.md`）。
このため、配達回を一定の期間で消すと、外部キーで DELETE が失敗する。CASCADE か SET NULL にすれば、今度は「`done` の回だけ返す」の条件が成り立たず、古い手紙とバックナンバーが郵便受けから消える。

手紙の行は、次のどれかで終わる（`db.md` §4 の状態遷移図）。

- `blocked`（モデレーターが却下）: 届かない。
- `returned`（差し戻し）: J4 が宛先を解決できないとき。郵便受けの行（`mailbox_items`）を作らない。
- `suppressed`（受取人が送った人をブロック中）: J4 がこうする。郵便受けの行を作らない。送った人には「配達済み」と見せる（ADR-0015）。
- `delivered`（配達済み）: 受取人の郵便受けに行があり、受取人が消すと `mailbox_items.deleted_at` を付ける（FR-099）。

`returned`・`suppressed` の手紙は郵便受けに入らないので、「受取人全員が郵便受けから削除したとき」に消すという条件が起きず、暗号化した本文と宛先が無期限に残る。
届いた手紙も、受取人全員が消したことを確かめて消すジョブがない。個人情報を最小限にすること（NFR-002）と、データの保持期間を明らかにすること（FR-097）に反する。
また、手紙の状態ごとに消える時期が違うと、送った人が送信済みから手紙が消える時期を見て、ブロック（`suppressed`）を推し量れる（`security.md` T-06）。

## 決定

保持期間などの数値は、断りのない限りすべて `[assumed]`（仮に置いた値）とする。

### 住民のアカウント削除のとき（J7 `account.erase`）

手順の番号は `async.md` J7 の番号（0〜10）。

| 対象 | 処理 |
|------|------|
| `residents` の行 | J7 の最後の手順（手順 10）で物理削除。`erasure_log` に記録 |
| 認証情報（`credentials` の行） | J7 の最初の手順（手順 0）で行ごと消す。`erasure_log` に記録（D8） |
| セッション（`sessions` の行） | 退去の受付（API）で有効なセッションをすべて無効にする（`invalidated_at`、D7）。行は J7 の手順 0 ですべて（無効にした行も含む）消す。`erasure_log` に記録（D8） |
| その住民が送った届いていない手紙（`state = pending / scheduled / held / blocked / returned / suppressed`） | 即時に本文と宛先ごと消す。`scheduled` の手紙の、まだ `visible_at` を過ぎていない郵便受けの行も同じトランザクションで消す（届いていないので受取人のために残す理由がなく、送った人ももう送信済みを見られない。`held`・`blocked` は ADR-0069 の D6） |
| その住民が受け取った郵便受けの行（`mailbox_items`、`resident_id` が本人。手紙・新聞・掲示板のすべての行） | 手順 8 で消す（`residents` を消す前。外部キーは CASCADE にしない）。行が消えた手紙は、残りの受取人の行で D3 を当てる |
| 届いた手紙（`state = delivered`） | そのまま残す。手順 9 で `letters.sender_id` を NULL にし（D11）、API では「退去済み」と示す。消し方は下の「手紙の保持」の D3 |
| 掲示板の投稿（掲載前） | 即時に `deleted` にし、`body` を消す |
| 掲示板の投稿（掲載済み） | 即時に `deleted` にし、`body` を消す。その投稿が載った版を組み直す（下の「新聞の組み直し」） |
| 掲示板の投稿の投稿者（`board_posts.author_id`、どの状態の行も） | 手順 9 で NULL にする（D11）。行の消し方は変えない |
| 住所録（持っているもの） | 即時に消す |
| 住所録の追加の数え（`address_book_daily_counts`） | 手順 10 の `residents` の削除で消える（外部キーの CASCADE、ADR-0065 の D4。D9） |
| ブロック（する側・される側） | 即時に消す |
| 通知の購読（`push_subscriptions`） | 退去の受付でセッションの無効化と同じトランザクションで消す（D7・ADR-0076）。残りは J7 の手順 0 で消す（D8） |
| 通知を送った記録（`delivery_notifications`） | 購読を消すとき同じトランザクションで消す。残りは J7 が消す（ADR-0076） |
| 興味（`resident_interests`） | 即時に消す（ADR-0055 の D5） |
| 推し量った興味（`inferred_interests`、段階 2） | 即時に消す（ADR-0045 の D5） |
| その住民の投稿から作った記事（`newspaper_articles`） | 即時に消す。その記事が載った版をすべて組み直す（ADR-0055） |
| `tenancies`（居住記録） | 手順 7 で、住所を `vacant_deleted` にするのと同じトランザクションで今の行を終わらせる（D10）。手順 9 で、引っ越しで終わった前の行も含めてその住民の行の `resident_id` を NULL にし、同じ UPDATE で `resident_erased_at` に退去の時刻を書く（D10・D11）。退去から **1 年後**に J14 が消す（D12） |
| `addresses` | 手順 7 で `status = vacant_deleted` にする。住所の行は消さない（ADR-0060 の D1） |
| 通報（`reports`、その住民が通報した行） | 行は残す。手順 9 で `reporter_id` を NULL にする（D11）。消し方は下の保持期間の表のまま |
| モデレーター操作（`moderation_actions`、その住民が操作した行） | 行は残す。手順 9 で `moderator_id` を NULL にする（D11）。消し方は下の保持期間の表のまま |
| 画像（`images`、その住民が上げた行） | 行は残す。手順 9 で `uploader_id` を NULL にする（D11）。消し方は `db.md` §4 のまま |
| 配達回（`delivery_runs`） | 消さない（住民の ID を持たない） |

### 退去の受付と、認証情報・セッションの消し方

- **D7 退去の受付**: API は `DELETE /me` を受けたら、1 つのトランザクションで次を行う `[assumed]`。
  1. `residents.deleted_at` を今の時刻にする。
  2. その住民の有効なセッションをすべて無効にする（`sessions.invalidated_at` を今の時刻にする）。どの端末のセッションでも、このあとの要求は 401 になる。
  3. 無効にしたセッションの通知の購読（`push_subscriptions`）と、その購読を指す送った記録（`delivery_notifications`）を消す（ADR-0019・ADR-0076）。
  4. J7 `account.erase` を積む（ID だけ）。

  受付では `sessions` と `credentials` の行を消さない。消すのは J7 の手順 0（D8）で、`erasure_log` への記録を J7 の削除にまとめるため。
- **D8 J7 の手順 0**: J7 は最初の手順として、1 つのトランザクションで次の順に消す `[assumed]`。外部キーの向き（`delivery_notifications` → `push_subscriptions` → `sessions` → `residents`、`credentials` → `residents`）に合わせた順で、どれも CASCADE にしない。
  1. その住民の `push_subscriptions` の残りの行と、それを指す `delivery_notifications` の行（受付のあとにできた行や、受付で消せなかった行。なければ何もしない）。
  2. その住民の `sessions` の行すべて（D7 で無効にした行も、期限が切れて次の J14 を待っている行も含む）。
  3. その住民の `credentials` の行（メールの暗号化した値・検索用の HMAC・パスワードのハッシュ）。

  消した `sessions` と `credentials` の行は、同じトランザクションで `erasure_log` に `table_name` を `sessions`・`credentials`、`record_id` をその行の ID（`credentials` は `resident_id`）として記録する。
  リストアのあとは `erasure.replay` が同じ行を消し直す。J7 を再実行したときは、行がないので何もしない。

### 住民を指す外部キーと、居住記録の終わらせ方

- **D9 住民を指す外部キー**: `residents` を指す外部キーは、`address_book_daily_counts.owner_id`（ON DELETE CASCADE のまま、ADR-0065 の D4）を除き、すべて ON DELETE を書かない既定（NO ACTION）にする `[assumed]`。
  J7 が手順 10 で `residents` を消す前に、指す行を消すか（手順 0〜8）、指す列を NULL にする（手順 9、D11）。
  NULL にする列のうち、`tenancies.resident_id`・`moderation_actions.moderator_id`・`images.uploader_id` を NULL 可にする（`letters.sender_id`・`board_posts.author_id`・`reports.reporter_id` はもとから NULL 可）。
  列ごとの扱いは `db.md` §2 の「住民を指す外部キー」に一覧で書く。
- **D10 居住記録を終わらせる**: J7 の手順 7 は、1 つのトランザクションで、住所を `vacant_deleted` にし、その住民の今の居住記録（`is_current = true` の行）の `ended_at` を今の時刻、`is_current` を false にする `[assumed]`。
  `tenancies` に `resident_erased_at timestamptz NULL`（住民が退去した時刻）を持つ。J7 の手順 9 が、`resident_id` を NULL にするのと同じ UPDATE（`UPDATE tenancies SET resident_id = NULL, resident_erased_at = now() WHERE resident_id = $1`）で書く。今の行だけでなく、その住民が引っ越して終わった前の行にも同じ時刻を書く。
  J14 は、`resident_erased_at < now() - interval '1 year'` の居住記録を消す（退去から 1 年。`ended_at` は起点にしない。前の行の `ended_at` は退去より前の引っ越しの時刻なので、起点にすると退去の直後に消える）。引っ越しで終わった行で住民が残るものは `resident_erased_at` が NULL なので消さない。
  手順 7 が終われば、そのあとに始まる J4 はその住民を `is_current = true` の全住民に数えず、新聞の郵便受けの行を作らない。
- **D11 住民を指す列を NULL にする**: J7 の手順 9 は、1 つのトランザクションで、その住民を指す次の 6 つの列を NULL にする `[assumed]`。
  - `letters.sender_id`（残っているのは届いた手紙だけ。手順 1 で届いていない手紙を消したあと）
  - `board_posts.author_id`（手順 2・3 で投稿を引いたあと）
  - `reports.reporter_id`
  - `moderation_actions.moderator_id`
  - `images.uploader_id`
  - `tenancies.resident_id`（手順 7 で終わらせたあと。同じ UPDATE で `resident_erased_at` を書く、D10）

  どれも `UPDATE … SET <列> = NULL WHERE <列> = $1` で、2 回目は対象が 0 行になる。
  手順 9 の UPDATE は `erasure_log` に記録しない（記録の範囲は `reviews/0001-design-review.md` の R-014 で決める）。
- **D12 J14 が居住記録を消すとき**: `tenancies` を指す外部キー（`address_book.registered_tenancy_id`・`letter_recipients.registered_tenancy_id`）は既定（NO ACTION）のままにする `[assumed]`。
  J14 は、D10 の条件に当たる居住記録を消すトランザクションの中で、先にその行を指す `address_book.registered_tenancy_id` と `letter_recipients.registered_tenancy_id` を NULL にし、そのあと `tenancies` の行を消す（1,000 件ずつ区切るときも、区切りごとに同じトランザクションで NULL にしてから消す）。
  住所録の行は消さない（住民が消すまで残す、ADR-0003）。`registered_tenancy_id` が NULL の住所録の行は知り合いにならず（`db.md` §2 `address_book`）、宛先の `registered_tenancy_id` が NULL の手紙は配達の振り分けで差し戻しになる（`db.md` §3）。NULL にする UPDATE は `erasure_log` に記録しない（D6 と同じく保持期間による処理）。

### 長期不在で空き家になったあとの処理

`addresses.status = vacant_expired` になった住所の元住民について:

- 移ってから **12 か月後**に、アカウント削除と同じ処理（上の表）を当てる。
- 今は `dormant` から `vacant_expired` への移行を作らないので、この処理は起きない。OQ-088 の答えでこの移行を作るときだけ当てる（ADR-0060 の D3・ADR-0062）。

### データの保持期間

| データの種類 | 保持期間 |
|-------------|---------|
| アクセスログ・操作ログ（DB の外） | 30 日 |
| `credentials`（認証情報） | 退去まで。退去で J7 の手順 0 が消す（D8） |
| `sessions`（セッション） | 有効期限切れ・ログアウトまで。ログアウトでは API が行を消す。有効期限切れでは J14 が `expires_at < now()` の行を、それを指す `push_subscriptions` と `delivery_notifications` を同じトランザクションで先に消してから削除する `[assumed]`（`security.md` §2.1、`async.md` J14）。退去では受付で無効にし（D7）、J7 の手順 0 が残りの行をすべて消す（D8） |
| `delivery_runs`（配達回） | 消さない（期間を置かない。1 日 2 行で、住民の ID も本文も持たない） |
| `delivery_notifications`（配達完了の通知の記録、ADR-0076） | 指している配達回の `finished_at` から 30 日 |
| `newspaper_articles`（新聞の記事の文字、ADR-0055） | 紙面（`newspapers`・`newspaper_editions`）と同じ |
| `external_news_items`（取り込んだ外のニュース、ADR-0055） | 取り込みから 30 日（OQ-060 の利用の条件で変わる） |
| `inferred_interests`（過去の新聞の検索から推し量った興味、段階 2、ADR-0045） | 最後に当たってから 30 日（J14 が消す） |
| `moderation_queue` / `moderation_actions` | 1 年（退去したモデレーターの行も、`moderator_id` を NULL にして同じ期間持つ。D11） |
| 確認待ちの手紙（`letters.state = held`、ADR-0069） | モデレーターが操作するまで（長く確かめられないときの扱いは OQ-065） |
| 却下の手紙（`letters.state = blocked`、本文と宛先、ADR-0069 の D6） | `decided_at` から 30 日（D2） |
| 差し戻しと抑止の手紙（`letters.state = returned / suppressed`、本文と宛先） | `settled_at` から 30 日（D2） |
| 届いた手紙（`letters.state = delivered`、本文と宛先と郵便受けの行） | `settled_at` から 30 日を過ぎ、受取人全員が郵便受けから削除するまで（D3） |
| 通報された手紙（`reports` の行があるもの） | 通報の行が消えるまで。そのあとは状態ごとの上の行（D4） |
| `reports`（通報） | クローズの日から 1 年（退去した通報者の行も、`reporter_id` を NULL にして同じ期間持つ。D11） |
| バックアップ | 30 日 |
| `erasure_log` | 60 日 |
| `tenancies`（退去した住民の分） | 退去から 1 年（J14 が `resident_erased_at < now() - interval '1 year'` の行を、それを指す列を NULL にしてから消す。引っ越しで終わった前の行も退去の時刻から数える。D10・D12） |

### 手紙の保持

- **D1 確定の時刻**: `letters` に `settled_at timestamptz NULL` を持つ。手紙を `delivered`・`suppressed`・`returned` に確定させた時刻で、書くのは J5 の手順 3 だけ。同じ配達回で確定させた手紙のすべてに同じトランザクションで同じ値を書くので、同じ回の手紙は状態にかかわらず同じ時刻になる。
  - J4 は宛先の振り分けで `state` を `returned`・`suppressed` にするが、`settled_at` は書かない（NULL のまま）。
  - その配達回を J6 が持ち越すとき（J5 が動かず `skipped` で終わる）は、J4 が `returned`・`suppressed` にしたその回の手紙も `scheduled` に戻して次の便に移す（`settled_at` は NULL のまま）。次の便の J4 が振り分け直し、次の便の J5 が、一緒に移った `scheduled` の手紙と同じ値で `settled_at` を書く。

  `blocked` の手紙は `decided_at`（モデレーターが却下した時刻）を同じ役に使う。`delivery_runs.finished_at` は起点に使わない。`skipped` で終わる配達回もあり、手紙の行に時刻を持てば条件が 1 つの列で済むため。
- **D2 届かずに確定した手紙**: `state` が `returned`・`suppressed` の手紙は `settled_at` から、`blocked` の手紙は `decided_at` から 30 日を過ぎたあとの次の J14 が、`letter_recipients` ごと消す。
- **D3 届いた手紙**: `state = 'delivered'` の手紙のうち、`settled_at` から 30 日を過ぎ、`kind = 'letter'`・`item_id` がその手紙の `mailbox_items` で `deleted_at IS NULL` の行が 1 つもないものは、次の J14 が消す。同じトランザクションで、その `letter_recipients` と、その手紙の `mailbox_items` の行（`deleted_at` を付けたもの）も消す。
  受取人が退去すると、J7 がその受取人の郵便受けの行を消す（上の退去の表）。そのため退去した受取人の行は D3 の条件に残らず、残りの受取人が消せば同じく消える（受取人が全員退去すれば行がなくなり、消える）。`visible_at` の前の行も `deleted_at IS NULL` なので、受取人が見る前に消えることはない。
- **D4 通報された手紙**: `reports` に `content_kind = 'letter'`・`content_id` がその手紙の行がある手紙は、D2・D3 で消さない。通報の行はクローズから 1 年で J14 が消し、そのあとの J14 で D2・D3 を当てる。
- **D5 送った人の送信済み**: `GET /api/v1/letters/sent` と `/sent/{id}` は、確定した手紙（`delivered`・`suppressed`・`returned`・`blocked`）を、状態にかかわらず確定の時刻（`settled_at`、`blocked` は `decided_at`）から 30 日まで返し、そのあとは一覧に出さず詳細は 404 にする。確定していない手紙（`pending`・`scheduled`・`held`）は返し続ける。
  D2・D3 で手紙を消すのは、どれも送信済みから見えなくなったあとなので、送った人には手紙を消したかどうかと、いつ消したかが分からない。`suppressed` の手紙も、`delivered` の手紙と同じ時期に送信済みから消える（`security.md` T-06）。配達回が持ち越されたときも、D1 のとおり `suppressed` の手紙は同じ回に出した `delivered` の手紙と同じ J5 で確定し、同じ時刻から 30 日を数える。
- **D6 消去の記録**: D2・D3 の削除は `erasure_log` に記録しない（住民の削除の求めではなく保持期間による削除のため）。バックアップから戻したときは、次の J14 が同じ条件でまた消す。

30 日は OQ-030（保持期間、持ち越し）の答えまでの仮の値で、答えで変わるのは D2・D3・D5 の日数だけ。D5 の日数は D2・D3 の日数と同じにする（短くはしない）。

### 配達回を消さないこと

1. J14 `retention.purge` も J7 `account.erase` も、`delivery_runs` の行を消さない。
2. `delivery_runs` を指す 8 つの外部キー（背景を参照）は、CASCADE にも SET NULL にもしない。今のまま（既定の制約）にする。
3. 郵便受けとバックナンバーが返す条件「`delivery_runs.status = 'done'` の配達回」は変えない。古い回の手紙と紙面も、配達回の行が残るので返り続ける。
4. 通知の記録（`delivery_notifications`）は、指している配達回の `finished_at` から 30 日で J14 が消す（ADR-0076 の D7）。配達回は残るので、消す順番の決まりは置かない。

### 新聞の組み直し

住民の掲示板の投稿が消えたとき、その投稿を素材に使った紙面を `newspaper_items` から探し、その投稿が載った版（`newspaper_editions`）をすべて描き直して、版の `storage_url` を上書きする。その投稿から作った `newspaper_articles` の行も消す。
ほかの素材は残すので、素材が減っても紙面を休刊として扱わない。

## 理由

- **認証情報とセッションを J7 の最初に消す**: メールの暗号化した値・HMAC・パスワードのハッシュは、退去した住民には要らない個人情報で、残せば NFR-002・NFR-010 に反する。`residents` を外部キーで指すので、`residents` を消す（最後の手順）より前に消さなければならない。最初に消せば、J7 が途中で止まっても、そのあとに残るのは住民に結びつく認証の手がかりのない行だけになる。
- **受付では無効にし、行は J7 で消す**: 受付で `invalidated_at` を付ければ、どの端末の要求もすぐに 401 になる（行が残っていても使えない）。行の削除と `erasure_log` への記録は J7 にまとめ、退去で消す行の記録を 1 か所にする。受付の API を重くしない。
- **購読・セッション・認証情報の順**: 外部キーを CASCADE にしない（`db.md` の方針）ので、指す側から消す。1 つのトランザクションにすれば、途中の状態が残らない。
- **`erasure_log` に記録する**: 住民の削除の求めによる削除なので、リストアのあとに `erasure.replay` で消し直せるようにする（D6 の保持期間による削除とは違う）。
- **外部キーを既定（NO ACTION）にし、J7 が先に消すか外す（D9）**: CASCADE にすると、住民の行の削除で居住記録・届いた手紙・通報・操作の記録まで一緒に消え、受取人の郵便受け（FR-099）と、保持期間の表で決めた期間が成り立たない。SET NULL にすると、どの列が退去で NULL になるかが DB の定義に散り、J7 の手順から読めない。既定にすれば、J7 が消し忘れた行は `residents` の削除の失敗として表に出る（黙って消えたり残ったりしない）。`address_book_daily_counts` は件数だけの行で、住民がいなければ要らないので CASCADE のままにする。
- **列を NULL にして行を残す（D11）**: 届いた手紙は受取人のもの、通報と操作の記録はモデレーションの根拠、画像は参照するコンテンツのもので、住民の退去で消す理由がない。住民の ID を残す理由もない（`residents` の行がなくなり、誰を指すか分からない ID になる）。1 つのトランザクションにすれば、途中で止まっても一部の列だけが NULL の状態が残らない。
- **居住記録を住所を空き家にするのと同じトランザクションで終わらせる（D10）**: 住所が `vacant_deleted` なのに居住記録が `is_current = true` の状態が見えると、J4 が退去した住民に新聞の行を作り、手紙の宛先の振り分け（`db.md` §3）も住所の状態と食い違う。同じトランザクションにすれば、その状態が起きない。
- **J14 の居住記録の起点を `resident_erased_at` にする（D10）**: 保持期間は「退去から 1 年」なので、起点は退去の時刻でなければならない。`ended_at` は前の引っ越しで終わった行では退去より前の時刻で、起点にすると 1 年より前に引っ越した住民の前の行が退去の直後の J14 で消える。`resident_id` を NULL にするのと同じ UPDATE で書けば、NULL になった行には必ず退去の時刻があり、`residents` と突き合わせなくても退去した住民の行を見分けられる。引っ越しで終わった居住記録（住民が残る）は `resident_erased_at` が NULL なので消さない。
- **J14 が居住記録を指す列を先に NULL にする（D12）**: 知り合いのいた住民が退去すると、相手の住所録の行が退去した住民の居住記録を指し続ける。そのままでは 1 年後の J14 の削除が外部キーで止まり、保持期間が成り立たない。消す行は 1 年より前に終わっているので転送の期間（6 か月、ADR-0060 の D4）を過ぎており、指していても配達の振り分けは差し戻しになる。NULL にしても配達の結果と知り合いの判定（今の居住記録を指すときだけ知り合い）は変わらない。
- **届いた手紙を受取人の側に残す**: 受け取った手紙が突然消えると、受取人の体験を損なう。送った人が退去しても、受取人の郵便受けはその人のものである。届いた手紙は期間だけでは消さず、受け取った全員が消したときに消す。それで、受取人の誰も持たない本文をサーバーが持ち続けることがなくなる。
- **退去した住民の届いていない手紙をすぐに消す**: 届いていないので受取人のために残す理由がなく、30 日残す理由（送った人が送信済みで状態を見て、必要なら送り直せること）も、送った人がいなくなれば成り立たない（`held`・`blocked` と同じ）。
- **送信済みに出す期間を状態でそろえる**: 消える時期が状態で違うと、`suppressed` の手紙が決まった日に消えることから、送った人がブロックを推し量れる（T-06）。送信済みに出す期間をどの状態でも確定から 30 日にし、消すのをそのあとにすれば、送った人から見た手紙の消え方は状態に依らない。届いた手紙が受取人全員の削除で早く消えることも、送った人に見えない。
- **確定の時刻を手紙の列に持つ**: 配達回が `skipped` で終わることもあるので、配達回の時刻では確定の時刻を決められない。手紙の行に持てば、J14 と送信済みの条件が 1 つの列で済む。
- **30 日**: 送った人は、送信済みの一覧で「差し戻し」「配達済み」「届けられませんでした」を見て、必要なら送り直せる。
- **通報された手紙を残す**: モデレーターが通報を確かめ、処置の根拠を残すのに本文が要る（`security.md` §5.4）。
- **新聞を組み直す**: 退去した住民の投稿が配達のあとも載り続けると、その住民がいなくなったのに過去の新聞に残り続ける。
- **居住記録（tenancies）を 1 年持つ**: 住所録の配達先の解決（`registered_tenancy_id`、`db.md` §3）に、退去のあとも一定の期間 tenancy を指す必要がある。1 年は、その転送と解決が起こりうる期間として仮に置いた。
- **erasure_log を 60 日持つ**: バックアップ（30 日）より長く持てば、リストアのあとの再生に使える期間を確保できる（`db.md` §6）。
- **配達回を消さない**: 配達回は 1 日 2 行（年に約 730 行）で、`run_id`・`status`・開始と終了の時刻だけを持ち、住民の ID も本文も持たない。持ち続けても、個人情報を最小限にすること（NFR-002）に反せず、容量もほとんど増えない。消さなければ、8 つの外部キーも、郵便受けとバックナンバーの「`done` の回だけ返す」の条件も、今のまま成り立つ。

## 代わりの案

- **退去の受付（API）でセッションと認証情報の行を消す**: 受付のトランザクションが重くなり、`erasure_log` の記録が API と J7 の 2 か所に分かれる。無効にすれば要求はすぐに止まるので採らない。
- **`credentials`・`sessions` の外部キーを CASCADE にして、`residents` の削除で一緒に消す**: 外部キーを CASCADE にしない方針（`db.md`）に反し、消した行が `erasure_log` に残らない。採らない。
- **住民を指す 6 つの列の外部キーを ON DELETE SET NULL にする**: J7 の手順 9 は要らなくなるが、退去で何が変わるかが J7 の手順と DB の定義の 2 か所に分かれる。J7 の手順の抜けも `residents` の削除の失敗として表に出なくなる。採らない。
- **住民を指す列を外部キーにしない**: 住民の ID が `residents` にない値を指しても DB が止めず、退去のあとも住民の ID が残る。採らない。
- **居住記録を J7 の最後（`residents` を消すとき）に終わらせる**: 手順 7 から最後までのあいだ、住所は空き家なのに居住記録は今の行のままになり、その間に動いた J4 が退去した住民に新聞の行を作る。採らない。
- **J14 の居住記録の起点を `ended_at` にする**: 前の引っ越しで終わった行の `ended_at` は退去より前なので、退去から 1 年持つことにならない。手順 7 で前の行の `ended_at` を書き換える案も、引っ越しの時刻（転送の期間の起点、ADR-0060 の D4）を失うので採らない。
- **`tenancies` を指す外部キーを ON DELETE SET NULL にする（D12 の代わり）**: J14 の削除で何が変わるかが J14 の手順と DB の定義の 2 か所に分かれる（D9 で SET NULL を採らない理由と同じ）。採らない。
- **住所録から指されている居住記録を残す**: 知り合いのいた住民の居住記録が、相手が住所録の行を消すまで無期限に残り、退去から 1 年の保持期間が成り立たない。採らない。
- **居住記録の `resident_id` を残し、J14 で `residents` に行がないことを見て消す**: `residents` の行を消すには、それを指す `tenancies` の行を先に消すか外さなければならず、退去から 1 年持つことと両立しない。採らない。
- **セッションの行は有効期限が過ぎるまで残す**: 退去した住民の行が最長 90 日残り、`residents` の削除が外部キーで止まる。採らない。
- **配達済みの手紙も期間で消す**: 受取人の郵便受けから手紙が消え、FR-099（受取人が消すまで残す）に反するので採らない。
- **差し戻しと抑止はすぐに消す**: 送った人が送信済みで状態を見る前に消え、「差し戻し」を見せられない。`suppressed` の手紙が送信済みからすぐに消えると、ブロックを明かす（T-06）。採らない。
- **差し戻しと抑止は送った人が消すまで残す**: 送った人が消さなければ無期限に残る。採らない。
- **送信済みには行がある間ずっと出す**: `suppressed` の手紙だけが決まった日に消え、ブロックを推し量れる（T-06）。採らない。
- **`suppressed` の手紙は本文と宛先だけを消し、送信済みの表示の行を残す**: 表示のための行が送った人が消すまで残り、行の状態ごとの扱いが増える。送信済みの期間をそろえれば足りるので採らない。
- **退去で差し戻した手紙も 30 日残す**: 送った人がもう見られないので、残す理由がない。採らない。
- **受取人が削除した時点（API）で手紙を消す**: 郵便受けの削除の API に、ほかの受取人の行と通報を確かめる処理と本文の削除が入り、API の削除が重くなる。送った人の送信済みからも早く消え、受取人が消したことを送った人に知らせる。採らない。
- **ソフトデリートだけにする（物理削除しない）**: NFR-010（データの削除の求め）・NFR-002（個人情報を最小限にする）に反するおそれがある。物理削除を基本にし、`erasure_log` で監査する。
- **手紙を住民ごとに暗号化し、退去のときに鍵を捨てる（per-letter key）**: ADR-0006 はサーバー鍵（鍵管理のサービスで管理）を採り、個別の鍵の仕組みを持たない。鍵を捨てるだけでは DB の行が残り、管理が複雑になる。採らない。
- **新聞を組み直さない**: 退去した住民の投稿が残り続けるので採らない。
- **配達回を 30 日で消し、外部キーを外す**: 休刊（`skipped`）や失敗（`failed`）の回の紙面を出さないための条件を、配達回の状態の代わりに別の列で持つ必要が出て、8 つの表の整合を DB の制約で守れなくなる。消して得るもの（1 日 2 行）が小さいので採らない。
- **配達回を 30 日で消し、外部キーを CASCADE にする**: 郵便受けの手紙・紙面・記事まで 30 日で消え、FR-099 と FR-039（バックナンバー）に反するので採らない。
