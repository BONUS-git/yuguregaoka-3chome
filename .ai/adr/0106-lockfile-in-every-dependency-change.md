# 0106 — 依存を足す変更ごとにロックファイルを直す

- 状態: 採用
- 日付: 2026-11-27

チケット YGO-075（YGO-073 で YGO-065 から分けた 1 枚目）による。ADR-0103 を丸ごと置き換える。D1〜D3 は ADR-0103 と同じ番号で、D1 の範囲を「最初のロックファイル」から「依存を足す・変える変更ごと」に広げ、D2・D3 は ADR-0103 と同じ中身を書き直す。
ADR-0052（手元で再現できる環境、`check.sh` はネットワークなし）と ADR-0105（CI は `prepare.sh` のあとに `check.sh`、CI の定義の確かめは YGO-070）の決定は変えない。

## 背景

`environment.md` §3.1 は依存をロックファイルで固定し、依存を変えるときは `scripts/prepare.sh` とマニフェスト・ロックファイルを同じ変更で直すと決めている。ネットワークを使うのは `prepare.sh` の依存の取り込み（`npm ci` と、IaC のコードを書いたあとの `tofu init -backend=false`。ADR-0052 の D3・D6）だけである。
ADR-0103 の D1 は、ネットワークの例外の `npm install --package-lock-only --ignore-scripts` を「最初のロックファイル」を作るときだけに認めていた。ロックファイルがすでにある状態で依存を足す変更（YGO-076 の `pg`・`@types/pg`）では、ロックファイルを直す手段がどの決定にもなく、`npm ci` はマニフェストとロックファイルが合わないと失敗する。

## 決定

依存を足す・変える変更でのロックファイルの扱いを次のとおりにする。

- **D1 依存を足す・変える変更ごとに、その変更の中でロックファイルを直す**: `package.json` を書いたあと（最初に書くときも、依存を足す・変える・消すときも）、その変更の中で `npm install --package-lock-only --ignore-scripts` を 1 回試す。`package.json` の依存の版は `^`・`~` なしで固定して書き、ロックファイルと同じ版にする（`check.sh` が、依存の名前がロックファイルにあり版に `^`・`~` がないことを確かめる。`environment.md` §4.1 の 1）。ADR-0052 が `prepare.sh` に認めるネットワークの利用（`npm ci` と、IaC のコードを書いたあとの `tofu init -backend=false`。ADR-0052 の D3・D6）のほかに、ネットワークを使ってよい例外はこの 1 つのコマンドだけで、`sh scripts/check.sh` はネットワークなしのまま（NFR-063）。できた（または直った）`package-lock.json` を `package.json` と同じ変更に入れる。ロックファイルがまだない状態（最初のロックファイル）もこの D1 に入る。終える前に `sh scripts/prepare.sh` と `sh scripts/check.sh` を動かし、どちらも終了コード 0 で終わることを確かめる。
- **D2 作れなかったら止まった段を残す**: ロックファイルを手で書かない・手で直さない。止まった段（ロックファイルの作成・直し）と出たエラーの行をそのままチケットの「確かめた事実」に書き、それまでの段のファイルを変更として出す（変更 0 件で終えない）。秘書の準備の段階がロックファイルを作ることは当てにしない。
- **D3 `prepare.sh` はロックファイルを作らない**: `package.json` があり `package-lock.json` がないとき、`scripts/prepare.sh` はロックファイルを作らず、「依存を変える変更の中でロックファイルを作ってコミットする」と出して終了コード 1 で止まる。ロックファイルがあるときは `npm ci` だけを動かす。

## 理由

- ロックファイルを依存の変更と同じ変更に入れれば、秘書の準備の段階・CI・手元のどれでも `npm ci` で同じ依存が入る（ADR-0052 の手元で再現できる環境）。これは最初のロックファイルでも、あとから依存を足すときでも同じで、例外を最初の 1 回に限る理由がない。
- `--package-lock-only --ignore-scripts` は `node_modules` を作らず、依存の install のスクリプトも動かさないので、ジョブの中で動かしても作業のディレクトリを汚さず、外のコードを実行しない。ロックファイルがあるときは、その中身を保ったまま足した・変えた依存の分だけを直す。
- 手で書いた・直したロックファイルは整合性のハッシュが本物と合わず、`npm ci` が失敗するか、確かめていない中身を固定してしまう。止まった段を残せば、次の変更が同じところから進められる。
- `prepare.sh` がロックファイルを作ると、変更に入っていないロックファイルで検証が通り、コミットされたものと検証したものが食い違う。

## 代わりの案（選ばなかった理由）

- **ADR-0103 を残し、依存を足す変更の分だけ別の ADR で補う**: 同じコマンドの例外が 2 つの ADR に分かれ、D2・D3 がどちらに属するかが読み取りにくい。1 つの ADR に 1 つの決定とし、丸ごと置き換える（CLAUDE.md の ADR の決まり）。
- **依存を足す変更ごとに秘書の準備の段階がロックファイルを直す**: 直したロックファイルが変更に入らず、コミットしたものと検証したものが食い違う。
- **ロックファイルを使わず `npm install` で入れる**: 依存の版が日ごとに変わり、手元と CI で同じにならない（ADR-0052）。

## 影響

- `environment.md` §3.1・§3.2 の 1・§4.1・§5 の参照を、この ADR の D1〜D3 にする。
- 開いているチケット（YGO-078）の「ADR-0103 の D1〜D3」の参照を、この ADR の同じ番号の D に直す。
- `scripts/check.sh` と `scripts/prepare.sh` のコメントと出力の文に残る `ADR-0103` は、`check.sh` を次に触る YGO-076 の変更で `ADR-0106` に直す（YGO-075 は `.ai/` の文書だけを範囲にした）。
