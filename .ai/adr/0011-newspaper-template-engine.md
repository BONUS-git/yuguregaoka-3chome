# 0011 — 組版エンジンは TSX を静的 HTML に描く

- 状態: 採用
- 日付: 2026-11-19

## 背景

ADR-0007 で「新聞の組版はテンプレートエンジンで決定的に生成する」と決まったが、
テンプレートエンジンの実装方式（どの技術を使うか）が「別途 ADR に記録する」とされていた。
また NFR-022 では「組版バッチは冪等に設計し、同じ入力から同じ紙面が生成される」が要求され、
NFR-063 では「`check.sh` がネットワークなしで通ること」が要求されている。

## 決定

組版エンジン（C6）は TSX コンポーネントを Node.js で静的 HTML に描く実装とする。
React の `renderToStaticMarkup`（または同等の関数）を使ってサーバー側でレンダリングする。
冪等性はスナップショットテスト（Vitest）で確かめる。

## 理由

- **TypeScript との統一**: ADR-0009 でフルスタック TypeScript を選択しており、TSX で組版を書くことで型安全・IDE サポート・リファクタリング容易性が得られる。専用のテンプレートエンジンを別途学ぶコストが不要。
- **型安全な紙面レイアウト**: React コンポーネントとして記事・住民・掲示板投稿を受け取ることで、紙面に表示できないデータが型エラーになる。入力の形が変わったときにコンパイル時に検出できる。
- **冪等性のテストが容易**: `renderToStaticMarkup` は副作用なしに同じ HTML を返す純粋な関数として扱えるため、Vitest のスナップショットテストで同じ入力が同じ出力になることを確かめられる（NFR-022）。
- **ネットワークなしで動く**: LLM を使わないため、`check.sh` がオフラインで通る（NFR-063）。
  （ADR-0039 で追記）記事の文字は J16 が LLM で作るようになったが、組版エンジン自体は LLM を呼ばず、`newspaper_articles` に保存した文字から版ごとに組む。
  文章アダプタはテストではモックなので、`check.sh` はオフラインのまま通る。

## 代わりの案

**Handlebars・EJS 等の専用テンプレートエンジン**: 型安全がなく、コンポーネントの再利用が難しい。ADR-0009 の TypeScript 統一方針と相性が悪い。不採用。

**PDF（Puppeteer で HTML → PDF 変換等）**: PDF ビューアが必要になり、SPA での閲覧体験が複雑になる。バックナンバー（F-12）の実装コストが増す。不採用。

**LLM で記事・紙面を生成する**: ADR-0007 で既に排除済み（冪等性の保証が難しく、幻覚リスクがある）。
（ADR-0039 で置き換え）記事の文字だけは LLM が作り、保存してから組む。紙面（HTML）を LLM に生成させることは今も不採用。

## 影響

- C6 組版エンジンは `src/modules/newspaper/templates/` 以下の TSX コンポーネントとして実装する
- 組版結果の HTML は C8 オブジェクトストレージに保存し、配達時に参照する
- スナップショットテストは Vitest で実装し、`check.sh` からつなぐ（コードができてから）
- 非同期処理の詳細（入力仕様・「休刊」ロジック）は `async.md` で定義する
