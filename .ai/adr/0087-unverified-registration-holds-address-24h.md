# 0087 — 確認が済まない登録が住所を押さえるのは 24 時間

- 状態: 採用
- 日付: 2026-11-25

OQ-046（持ち越し）を決定にする（K-004、`triage.md` 仕分け 3）。ADR-0030・ADR-0080 の D2・ADR-0082 の D3・ADR-0084 の D18 は、この期限を OQ-046 に送っていた。この ADR はその送り先を埋めるもので、それらの決定の中身は変えない。

## 背景

新規登録は開放式で（ADR-0030）、登録の要求がそのまま住所を割り当てる（ADR-0082 の D3）。候補でない空き家も地図の空き家の印から選べる（ADR-0084 の D7）。
メールの確認（ADR-0080 の D2・D6）が済まないままの登録が住所を押さえ続けると、街のどの空き家でも、届かないメールアドレスで先に押さえられる。
OQ-046 は次の 3 つを決める持ち越しだった。(1) 確認が済まない登録が住所を押さえる期限、(2) 期限が来た住所を候補に戻すか（ADR-0062 の D3「使われたことのない住所だけ」との関係を含む）、(3) 確認のメールのリンクの期限（(1) との関係を含む）。

## 決定

1. **D1 期限**: メールの確認が済まない登録（`credentials.email_verified_at IS NULL`）が住所を押さえるのは、`credentials.created_at` から 24 時間 `[assumed]`。
2. **D2 確認のリンク**: 登録の確認のメールのリンク（トークン）も、同じ `credentials.created_at` から 24 時間で切れる。確認のメールを送り直しても（`POST /api/v1/email-verification-requests`）期限は延びない。期限を過ぎた登録には送り直しても確認のメールを送らず、いつもと同じ 202 と同じ本文を返す（ADR-0080 の D6）。期限を過ぎたトークンは、違う・使ったトークンと同じ 400 `token_invalid`。メールアドレスの変更の確認のリンク（ADR-0090 の D7）は、この期限に入らない。
3. **D3 ログイン**: 期限を過ぎた確認が済まない登録のログインは、確認が済んでいない登録と同じ 401 `unauthenticated`（ADR-0080 の D5）。応答で期限の前後を分けない。
4. **D4 消すとき**: 期限を過ぎた確認が済まない登録は、J14（`retention.purge`）が消す。1 つの登録ごとに 1 つのトランザクションで、`auth_tokens`（確認のトークン、ADR-0101 の D6） → `resident_interests` → `tenancies` → `addresses` → `credentials` → `residents` の順に行を消す（外部キーは CASCADE にしないので指す側から。`address_book_daily_counts` は `residents` の削除で一緒に消える）。確認が済まない登録はログインできないので、セッション・購読・手紙・投稿・住所録・通報の行はない。`erasure_log` には記録しない（退去ではなく、住民になる前の登録を戻すもの。バックアップから戻ったら次の J14 がまた消す）。
5. **D5 登録し直し**: 登録のトランザクション（`POST /api/v1/registrations`）は、住所を割り当てる前に、要求の住所か要求のメールアドレスの `email_hmac` に当たる、期限を過ぎた確認が済まない登録を D4 と同じ順に消す。消したあとの住所は行がないので、ADR-0082 の D3 のとおり割り当てられる。期限の前の登録に当たる住所は、今のとおり 409 `conflict`。
6. **D6 候補に戻る**: D4・D5 で行を消した住所は `addresses` に行がなくなり、使われたことのない住所として候補（`GET /api/v1/addresses/candidates`）と空き家に戻る。ADR-0062 の D3 の「使われたことのない住所」は「`addresses` に行がない住所」（ADR-0082 の D3）なので、食い違わない。
7. **D7 受け入れること**: J14 は毎日 1 回なので、期限を過ぎた登録の住所は、J14 か D5 の登録し直しで消えるまで、入居の一覧（`GET /api/v1/addresses/occupancy`）に入居と出て、候補に出ない。最長で登録から約 48 時間。これより短い間隔の掃除のジョブは足さない。

## 理由

- **24 時間**: 確認のメールはふつう数分で届き、迷惑メールのフォルダを見るのにも 1 日あれば足りる。長くすると、押さえたままの住所が増え、空き家を先に押さえることの効き目が大きくなる（ADR-0084 の D18）。短くすると、届くのが遅れたメールで登録をやり直させる。
- **リンクを同じ期限にする**: リンクだけ長いと、住所を手放したあとに確認が済む登録が出る。リンクだけ短いと、送り直しで期限を延ばさせる理由ができる。1 つの時刻にすれば、確かめるのも `credentials.created_at` の 1 列で足りる。
- **送り直しで延ばさない**: 送り直しで延びると、送り直しを続けて住所を押さえ続けられる。
- **行ごと消す**: ADR-0062 の D3 で、MVP の候補は使われたことのない住所だけ。住民にならなかった登録の住所を「使われた」と扱うと、届かないメールアドレスの登録だけで候補が減り続ける。行を残して状態を足すより、行を消すほうが列も遷移も足さずに済む。
- **`erasure_log` に書かない**: 退去の記録（ADR-0091 の D8）は、戻したバックアップから住民のデータを消し直すためのもの。確認が済まない登録は D4 の条件で J14 が何度でも消せるので、記録は要らない。
- **登録し直しで先に消す**: J14 を待たずに、同じ住所や同じメールアドレスで登録をやり直せるようにする。`email_hmac` の UNIQUE に当たって登録し直せないことを防ぐ。

## 代わりの案（選ばなかった理由）

- **期限を置かない**: 届かないメールアドレスで街の空き家を押さえ続けられる。不採用。
- **期限を 7 日**: 押さえたままの住所が 7 倍に増える。確認のメールは 1 日で足りる。不採用。
- **行を残して状態（例: `expired`）を足す**: `addresses.status` の値と遷移が増え、ADR-0062 の D3 の候補の定義を変えることになる。不採用。
- **確認が済むまで住所を割り当てない**: 確認のあとに住所を選ばせると、選んだ住所が確認の間に取られ、登録の画面の流れ（ADR-0084 の D7）を変えることになる。不採用。
- **期限を過ぎた登録を数分ごとのジョブで消す**: ジョブが増える。入居と出る時間が 1 日ほど延びるだけで、守りは流量の制限（ADR-0088）が受け持つ。不採用。
