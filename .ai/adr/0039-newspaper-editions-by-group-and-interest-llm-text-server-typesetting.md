# 0039 — 新聞は一人 1 枚にせず、知り合いの数で分けた組ごとの版にする。知り合いのない組は興味で分ける。興味は登録とあとからの設定で集め、ニュースは街の中と外から取り、記事の文字は LLM が作り、組版はサーバーで決定的に行う

- 状態: 採用（D1 の版の数のうち知り合いの組の版と、D2 の暫定は ADR-0044 で置き換え。OQ-058 → 決定、2026-11-20。D4 の検索の暫定と、D3・D5 の推し量った興味の扱いは ADR-0045 で置き換え。OQ-059 → 決定、2026-11-20。D9 の暫定は ADR-0046 で置き換え。OQ-061 → 決定、2026-11-20）
- 日付: 2026-11-20

## 背景

OQ-042 の答え（ADR-0035）で、新聞は手紙の有無にかかわらず全住民に定時に届けると決まった。
答えの「興味があることを回収して、ニュースを加工して新聞にする」「新聞も知り合いの数がいないと成り立たない可能性がある」は例だったので、
知り合いが少なくても成り立つ紙面の中身を `open-questions.md` の OQ-051 でマスターに聞いていた。聞いたのは次の 4 点。
(1) 紙面を住民ごとに変えるか。(2) 住民の興味を集めるか、どう集めるか。
(3) ニュースの出どころ（(a) 街の中だけ・(b) 実在の外のニュース・(c) 運営が書く架空の記事）。(4) 加工に LLM を使うか、使うなら「組版は LLM を使わず決定的に組む」（ADR-0007・FR-037）との扱い。
暫定は ADR-0007 のまま（全住民に同じ紙面を、掲示板の投稿からテンプレートで組み、LLM を使わない）だった。

2026-11-20、マスターが OQ-051 に次のとおり答えた（原文）。

> １：変えたいが、サーバー負荷考えると一人１枚はきつい。知り合いで埋まるグループ一部埋まらないグループ、知り合い0のグループで分けて、0のグループは趣味、興味でさらにグループして出し分ける
> ２：登録の時と後から設定、検索などから収集しようかな
> ３：a,b
> ４：使う。モデルやプロンプトは要検討。文字だけLLMで作成し、新聞の生成部分はサーバーで行う想定

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと（新しい OQ） |
|---|---|---|
| 1 | 紙面は住民ごとにしない。組ごとに組み、版の数は住民の数によらない。組は「知り合いで埋まる」「一部埋まらない」「知り合い 0」の 3 つ。知り合い 0 の組は趣味・興味で分ける | 「知り合い」は誰か（地図の印では OQ-054 → 決定、2026-11-20、自分の住所録に入れた住民、ADR-0042 の D1 (c)。新聞でも同じにするかは答えていない）・知り合いの何を載せるか・組 1・2 の紙面を組で共有するのか（知り合いは住民ごとに違う）・組 2 の足りない分を何で埋めるか・組の境 → OQ-058（のちに決定、2026-11-20、ADR-0044） |
| 2 | 興味は登録のとき（任意）と、あとからの設定で集める | どの検索か（今ある検索は住所録の `?q=` だけで、自分のメモも含む私的なもの）・「など」は何か・住民への知らせ・同意・止められるか・推し量った興味を本人が見て消せるか → OQ-059（のちに決定、2026-11-20、ADR-0045） |
| 3 | 出どころは (a) 街の中と (b) 実在の外のニュース。(c) 運営が書く架空の記事は使わない | 配信元・利用の条件（著作権・出典の表示・LLM で要約や書き直しをしてよいか）・契約と費用の上限 → OQ-060（持ち越し） |
| 4 | 記事の文字は LLM が作る。組版（新聞の生成部分）はサーバー（C6）でテンプレートから決定的に行う | モデル・プロンプト・記事と興味の結び付け方・興味の一覧の中身 → OQ-062（持ち越し）。LLM の文であることを示すか・投稿を LLM が書き換えてよいか（倫理） → OQ-061（のちに決定、2026-11-20、ADR-0046） |

答えは、ADR-0007 の「LLM による文章生成は行わない」「紙面は全住民に同じ」を置き換える。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 組ごとの版**（答え 1、`[inferred]`）: 紙面は住民ごとに組まない。配達回ごとに、組ごとの版（edition）を組む。
   版の数は「共通の版 1 + 興味の版（興味の一覧の数まで）」で、住民の数では増えない。
   （ADR-0044 で置き換え）もとは「+ 知り合いの組の版（OQ-058 の答えのあと）」だった。組 1・2 の版は住民ごとに組む（`acquaintance:<resident_id>`、ADR-0044 の D4）ので、「住民の数によらない」は組 0 の版だけに当たる。MVP では組 1・2 を作らない（ADR-0044 の D1）。
   興味の一覧は 30 種まで `[assumed]`。理由はサーバーの負荷（答えの「サーバー負荷考えると一人１枚はきつい」、想定規模は ADR-0012 の住民 1 万人）。
2. **D2 3 つの組**（答え 1、`[inferred]`）: 住民を「知り合いで埋まる組」「一部埋まらない組」「知り合い 0 の組」に分ける。
   （ADR-0044 で置き換え）もとは「組の決め方と、組 1・2 の紙面の中身は OQ-058（要回答）。暫定は全住民を知り合い 0 の組として扱う」だった。
   OQ-058 → 決定（2026-11-20、ADR-0044）: MVP では全住民を知り合い 0 の組として扱う（D1）。知り合いは互いに住所録に入れた住民（D2）、載せるのは知り合いの掲示板の投稿（D3）、
   組 1・2 は住民ごとに組み（D4）、組 2 の足りない分は組 0 なら受け取る版の記事で埋め（D6）、組の境は J3 が記事の枠の数で計算する（D7）。組 1・2 を作る時期は OQ-070（持ち越し）。
3. **D3 知り合い 0 の組は興味で分ける**（答え 1、`[inferred]`）: 知り合い 0 の組の住民には、興味の版を届ける。次の 2 つは秘書の判断。
   - (a) 興味を選んでいない住民には、共通の版を届ける。
   - (b) 興味が複数ある住民には、`SHA-256(run_id + ":" + resident_id)` を整数として興味の数で割った余りで、興味を 1 つ選ぶ（興味は `interest_categories.sort_order, id` の順に並べる）。
     ADR-0035 の D9 と同じ考えで、決定的で、配達回ごとに変わる。J4 をやり直しても同じ版になる。乱数の状態を DB に持たない。
   - （ADR-0045 で置き換え）「興味」は、選んだ興味（`resident_interests`）と、段階 2 で過去の新聞の検索から推し量った興味（`inferred_interests`）を合わせた集合とする（ADR-0045 の D6）。選び方は (a)・(b) のまま。
4. **D4 興味の集め方**（答え 2、`[inferred]`）: 興味は、登録のとき（任意）と、あとからの設定で集める。
   - 興味は、運用者が CLI で保つ一覧（`interest_categories`）から選ぶ。自由記述にしない（秘書の判断）。
   - シードには架空の一般的な名前だけを入れる（ADR-0038 の D5 と同じ考え）。一覧の中身は OQ-062 で決める。
   - 1 人 5 つまで `[assumed]`。
   - 登録の画面で選べるよう、興味の一覧（`GET /api/v1/interest-categories`）は認証なしで呼べる経路に足す（4 つ目。一覧だけを返し、住民の情報と件数は返さない）。
   - （ADR-0045 で置き換え）もとは「検索などから集めることは OQ-059（要回答）。暫定: 検索からは集めない。住所録の検索語を DB・ログに残さない」だった。
     OQ-059 → 決定（2026-11-20、ADR-0045）: 自分に届いた過去の新聞の検索（段階 2、S2-3）から興味を推し量り、当たった興味の ID だけを `inferred_interests` に持つ（D1・D3・D4）。
     住所録の検索からは今までどおり集めず、検索語を DB・ログに残さない。「など」はこの変更では足さない（D2）。
5. **D5 興味の守り**（秘書の判断）: 興味は個人情報として扱う。
   （ADR-0045 で置き換え）次の「見て変えられるのは本人だけ」は選んだ興味のこと。推し量った興味（`inferred_interests`）は本人にも返さず、本人が消す経路も作らない（ADR-0045 の D8、OQ-059 の答え 4）。ほかの守り（ほかの住民・モデレーター・LLM に渡さない、件数を載せない、退去で即時に消す）は推し量った興味にも当てる。
   - 見て変えられるのは本人だけ。ほかの住民・モデレーターには見せず、LLM にも渡さない（LLM が受け取るのは版の興味の名前だけで、住民と結び付けない）。
   - 興味ごとの住民の数などの件数を、どの応答にも載せない（P-2）。
   - 退去すると即時に消す（ADR-0013）。
6. **D6 ニュースの出どころ**（答え 3、`[inferred]`）: 素材は、街の中（承認済みの掲示板の投稿。商店街は段階 3。商店の記事の頻度と大きさはランクで決め（ADR-0043）、新聞への載せ方は OQ-069。架空の店は発信せず新聞に載らない（ADR-0050 の D3・D4）。素材に運営の入居者募集の広告を足す（ADR-0050 の D5。本物の募集で架空の記事ではない。いつからは OQ-083、細部は OQ-084））と、実在の外のニュース。運営が書く架空の記事は使わない。
   - 外のニュースを取り込むのは worker の J17 `news.fetch` だけで、送り先は許可した一覧の中に限る。取り込んだ記事は、組版の前にルール表（`security.md` §5.1）に当てる。
   - 外のニュースは、取り込んだ配達回（`external_news_items.delivery_run_id`）に結び付ける（秘書の判断）。J16・J3 の素材はその回に取り込んだ行だけで、前の回に取り込んだ記事は入れ直さず、ほかの回の素材にもしない（UNIQUE(source_key, external_id)）。J17 が行を入れられるのは取り込みの打ち切り（審査の打ち切りと同じ 04:00 / 16:00 `[assumed]`）より前だけで、J0 は J17 が完了・失敗するか打ち切りを過ぎるまで J16 を積まない。これで素材の範囲が回ごとに決まり、同じ記事が何度も載らない。
   - 配信元・利用の条件・費用は OQ-060（持ち越し）。**それまで本番のアダプタは作らない**。テストと M5 では、偽の記事（`EXAMPLE_NEWS_DO_NOT_USE`）を返すアダプタを使う。
7. **D7 記事の文字は LLM、組版はサーバー**（答え 4、`[inferred]`）:
   - J16 `newspaper.write` が、素材ごとに見出しと記事の文字を作り、`newspaper_articles` に保存する。
   - J3 `newspaper.typeset` は、保存した文字から、版ごとにテンプレートで決定的に組む（ADR-0011 の組版エンジン）。J3 と J8 をやり直しても LLM は呼ばない。
   - 1 つの素材の記事は、1 回の配達につき 1 つにし、版どうしで使い回す（UNIQUE(delivery_run_id, source_kind, source_id)）。
   - 冪等性（FR-037・NFR-022）は、LLM の出力を保存し、組版をそこから決定的に行うことで保つ。
8. **D8 LLM に渡すもの・確かめること**（秘書の判断）:
   - 渡すのは、承認済みの掲示板の投稿の本文（J2 ですでに外部の LLM に渡している範囲、ADR-0031）・取り込んだ外のニュース・版の興味の名前だけ。
     手紙・住所・ID・ニックネーム・住民ごとの興味は渡さない。
   - 出力は、長さの上限・文字だけであること（HTML は使わず、組版のときにエスケープする）・ルール表の掲示板向けの項目、を確かめる。
   - 確かめて外れたとき、または LLM の失敗・打ち切り（記事の打ち切り 04:30 / 16:15 `[assumed]`）のときは、記事を決まった形（素材の題と本文そのまま、`written_by = 'template'`）で組む。
     LLM のせいでは休刊にしない。
   - J16 が `newspaper_articles` に行を入れられるのは記事の打ち切りより前だけ（入れるトランザクションの中で確かめる。D6 の J17 の取り込みの打ち切りと同じ形）。
     打ち切りまでに作れなかった素材には、J3 が組む前に `written_by = 'template'` の行を `ON CONFLICT DO NOTHING` で入れ、それから組む。
     これで J3 が組んだあとに記事が変わらず、J3 の再試行・J8 の組み直しでも同じ版の HTML になる（FR-037・NFR-022）。
   - LLM は公開してよいかを決めない（NFR-011・ADR-0005）。公開してよいかは、今までどおり J2 の審査とルール表で決まる。
9. **D9 投稿の本文と LLM の文の印**:
   （ADR-0046 で置き換え）もとは「（OQ-061 の暫定）住民の投稿の本文は、LLM で書き換えずにそのまま載せる。LLM が書くのは、見出し・まとめ・外のニュースの記事の文だけで、その文には「AI が書いた文」の印を付ける」だった。
   OQ-061 → 決定（2026-11-20、ADR-0046）: 住民の投稿の本文は書き換えずに `board_posts.body` をそのまま載せる（D4）。LLM が書くのは見出し・まとめ・外のニュースの記事の文だけ（D5）。
   LLM の文には印を付けない（D1）。投稿の本文は投稿の枠に入れ、LLM の文は枠の外に新聞の文として置き、本人の文に見せない（D6）。
   規約が示すことを求めるかは OQ-073（持ち越し、本番の文章アダプタを作る前に秘書が確かめる）。
   住民の投稿を素材にした記事の見出しとまとめを LLM が書いてよいかは OQ-074（要回答。暫定は書く、ADR-0046 の D5）。
10. **D10 モデルとプロンプト**は OQ-062（持ち越し、M5 の前に秘書が ADR で決める）。それまではモックの文章アダプタで作る。
    本番のアダプタは、デプロイと契約の承認（NFR-080）のあとに作る（ADR-0031 の D3 と同じ）。
    参考の見積もりは `roadmap.md` §9.1 に書き、費用の上限は OQ-047 と一緒にマスターに聞く。
11. **D11 版を見られる人**（秘書の判断）: 住民が見られるのは、自分の郵便受けに届いた版だけで、ほかの版は 404。バックナンバー（F-12）も同じ。
    API はどの版か（`edition_key`）を返さない。版からほかの住民の興味が分からないようにするため。
12. **D12 段階**: MVP の M5 に入れる（モックの LLM・偽の外のニュース）。登録の興味の項目と、興味の設定の API も M5 で足す。M3・M4 の J0・J3 は今のまま。
13. **D13 要求の区分**: FR-106 を直し、FR-108〜FR-111 を足す。どれも `[inferred]`（マスターの答え OQ-051（2026-11-20）より）。

## 理由

- D1 は、答えの「変えたいが、サーバー負荷考えると一人１枚はきつい」による。組ごとの版にすれば、組版の回数は興味の一覧の数で決まり、住民 1 万人（ADR-0012）でも増えない。
- D2 は、答えの 3 つの組による。「知り合い」の定義・載せる中身・紙面を組で共有するかは、住民どうしの関係を紙面に出すことになり、構想の意図と倫理にかかわる。
  マスターにしか決められないので、CLAUDE.md の「要回答の答えを前提にした決定をしない」に従い、暫定は今ある情報だけで成り立つ形（全員を知り合い 0 の組）にする。
- D3 (a) は、興味を選ばない住民にも新聞を届ける（ADR-0035 の D1）ため。(b) は、1 人に 1 つの新聞を届けつつ、複数の興味を回ごとに巡らせるため。ハッシュにすると冪等性（FR-025）を状態を持たずに保てる。
- D4 で一覧から選ぶのは、自由記述は審査が要り、版の数が住民の数に近づき（D1 と食い違う）、個人を特定しうる文が入るため。
  検索から集めるのは、住民の知らないうちに私的な行い（住所録の検索・メモ）から興味を推し量ることになり、知らせと同意（APPI、`security.md` §2.6・OQ-032）がまだ決まっていないので、暫定では集めない。
  （ADR-0045 で置き換え）OQ-059 の答えで、集める検索は過去の新聞の検索、知らせるが個別の同意は取らないと決まった。住所録の検索から集めない理由は上のまま。
- D5 は、興味が趣味・関心という個人の情報で、ほかの住民に見えると P-2 の数値の評価や詮索につながるため（NFR-002）。
- D6 は、答えの「a,b」による。外のニュースは利用の条件と費用（NFR-080）が決まるまで本番で取り込めない。取り込み先を許可した一覧に限るのは SSRF を防ぐため（`security.md` §7 の T-19）。
- D7 は、答えの「文字だけLLMで作成し、新聞の生成部分はサーバーで行う」による。LLM の出力は呼ぶたびに変わりうるので、保存してから組むことで、組版のやり直し（J3・J8）が同じ紙面になる（FR-037・NFR-022）。
  素材ごとに 1 回だけ呼ぶのは、費用を版の数で掛け算しないため。
- D8 は、LLM に渡す個人情報を J2 より広げないため（NFR-002・ADR-0026）、出力の作り話・プロンプトインジェクション・XSS を紙面に出さないため（T-20）。
  決まった形に倒すのは、新聞を全住民に届けること（ADR-0035）を LLM の失敗で止めないため。
- D9 は、住民の文を住民の知らないうちに LLM が書き換えることと、AI の文を人の文に見せることが倫理にかかわるため。答えまでいちばん控えめな形にする。
  （ADR-0046 で置き換え）OQ-061 の答えで、投稿は書き換えず、LLM の文に印は付けず、LLM の文を本人の文に見せないと決まった（ADR-0046 の理由）。
- D10 は、答えの「モデルやプロンプトは要検討」による。技術と設計で決められるので持ち越しにし、費用は承認を得る（NFR-080）。
- D11 は、版の中身（どの興味の版か）からほかの住民の興味を推し量れないようにするため（D5）。

## 代わりの案（選ばなかった理由）

- **一人 1 枚の紙面**: 答えの「一人１枚はきつい」と食い違う。
- **全住民に同じ紙面のまま（ADR-0007 のまま）**: 答えの「変えたい」「出し分ける」と食い違う。
- **LLM に紙面全体（HTML）を組ませる**: 答えの「新聞の生成部分はサーバー」と食い違い、冪等性も保てない。
- **組版のたびに LLM を呼ぶ**: J3・J8 のやり直しで紙面が変わり、FR-037・NFR-022 と食い違う。費用も版の数だけ増える。
- **興味を自由記述にする**: 審査が要り、版の数が増え、個人を特定しうる文が入る。
- **検索から興味を今すぐ集める**: 住民への知らせと同意が未定（OQ-059）。（ADR-0045 で置き換え）OQ-059 → 決定（2026-11-20）で、段階 2 の過去の新聞の検索から集める（ADR-0045）。MVP に検索はないので、MVP では今も集めない。
- **外のニュースの本番のアダプタを今作る**: 配信元と利用の条件・契約の前で、費用にかかわる（NFR-080・OQ-060）。
- **LLM が失敗したら休刊にする**: 新聞を全住民に届ける（ADR-0035）ことが外部のサービスの都合で止まる。

## 決めていないこと

- 知り合いで埋まる組・一部埋まらない組の紙面（ADR-0044 で置き換え。もとは OQ-058、要回答）: OQ-058 → 決定（2026-11-20、ADR-0044）。MVP では全住民を知り合い 0 の組として扱う。
  残りは、組 1・2 をいつ作るか・負荷の見積もり・知り合いの側の同意（OQ-070、持ち越し）と、地図の知り合いの印も (b) にするか（OQ-071 → 決定、2026-11-20、ADR-0051。地図は (a) 自分の住所録に入れた住民のままで、新聞と定義を分ける）。
- 検索などから興味を集めること（ADR-0045 で置き換え。もとは OQ-059、要回答）: OQ-059 → 決定（2026-11-20、ADR-0045）。
  残りは、住民が推し量ることを止められるか（OQ-072、要回答。暫定は止める設定を置かない）。
- 外のニュースの配信元・利用の条件・費用（OQ-060、持ち越し）。暫定は置かず、本番のアダプタは作らない。
- LLM が書いた文の示し方と、住民の投稿を LLM が書き換えてよいか（ADR-0046 で置き換え。もとは OQ-061、要回答）: OQ-061 → 決定（2026-11-20、ADR-0046）。
  残りは、規約が AI の文であることを示すよう求めるか（OQ-073、持ち越し）。
- 新聞の LLM のモデル・プロンプトと、記事と興味の結び付け方・興味の一覧の中身（OQ-062、持ち越し）。M5 の前に秘書が ADR で決める。
- 興味の一覧の上限（30 種）・1 人の上限（5 つ）・記事の打ち切り（04:30 / 16:15）・外のニュースの取り込みの打ち切り（04:00 / 16:00）・`external_news_items` の保持（30 日）は仮置き `[assumed]`。
