# 0088 — 流量の制限の既定の値と対象の経路

- 状態: 採用
- 日付: 2026-11-25

`security.md` §3.5 の流量の制限の値と対象の経路を決める（K-010、`triage.md` 仕分け 3。`reviews/0001-design-review.md` の R-018）。
ADR-0030 の D2・ADR-0080 の D4・ADR-0090 の D5・D7・ADR-0084 の D18 は、流量の制限を置く経路を決めている。この ADR はその値と数え方を決める。再認証の数える主体と、確かめる順番の中の流量の制限の位置は、ADR-0090 の D5 と同じ。
手紙の 422 と手紙のほかの書き込みの 422 を合わせた流量の制限（ADR-0069 の D7・ADR-0070 の D4）の値は、この ADR では決めない（OQ-065、M4 の前に決める）。

## 背景

流量の制限を置く経路は決まっていたが、回数と時間の幅と、何ごとに数えるかが「実装の段階で決める」のままだった。
M1 の受け入れ（`roadmap.md` A-11・A-12）は、ログイン・再設定・登録の要求が流量の制限を超えると 429 `rate_limited` になることを確かめるので、値がないとテストが書けない。
守りたいものは次の 4 つ。パスワードの総当たり、メールアドレスから住民がいるかの探り（`security.md` §3.1）、ほかの人のアドレスへの大量のメール（ADR-0090 の D7）、空き家を順に試して前に使われた住所を探ることと決まった住所を先に押さえること（ADR-0084 の D18）。あわせて、認証なしで街のすべての家を返す経路の負荷を抑える。

## 決定

1. **D1 出し方**: 窓は固定（`window_start` を窓の幅で切り下げた時刻）。1 つの要求に当たる規則をすべて数え、どれか 1 つでも上限を超えたら 429 `rate_limited` を返し、本来の処理をしない。残りの回数・窓の終わりの時刻・`Retry-After` ヘッダは返さない（`api.md` §5）。
2. **D2 値と対象**（`security.md` §3.5 の表が正本。どれも `[assumed]`）:

   | 経路（`api.md` §7） | 数える主体 | 上限 |
   |---|---|---|
   | `POST /api/v1/registrations` | IP | 3 回／1 時間、10 回／1 日 |
   | `POST /api/v1/sessions` | 要求のメールアドレス | 10 回／15 分 |
   | `POST /api/v1/sessions` | IP | 50 回／15 分 |
   | `POST /api/v1/sessions/current/reauthentication` | 住民 | 10 回／15 分 |
   | `POST /api/v1/email-verifications` | IP | 20 回／1 時間 |
   | `POST /api/v1/email-verification-requests` | 要求のメールアドレス | 3 回／1 時間 |
   | `POST /api/v1/email-verification-requests` | IP | 10 回／1 時間 |
   | `POST /api/v1/password-reset-requests` | 要求のメールアドレス | 3 回／1 時間 |
   | `POST /api/v1/password-reset-requests` | IP | 10 回／1 時間 |
   | `POST /api/v1/password-resets` | IP | 20 回／1 時間 |
   | `PUT /api/v1/me/email` | 住民 | 3 回／1 時間 |
   | `GET /api/v1/addresses/occupancy`・`GET /api/v1/addresses/candidates`（2 つを合わせて数える） | IP | 60 回／10 分 |
   | `POST /api/v1/reports` | 住民 | 10 回／1 時間 |
   | `POST /api/v1/blocks` | 住民 | 20 回／1 時間 |
   | `GET /api/v1/profiles/{address}` | 住民 | 60 回／1 時間 |
   | `GET /api/v1/address-book`（検索語 `?q=` があるときだけ） | 住民 | 60 回／1 時間 |
   | 上の表にない `/api/v1/*` の経路の既定（表にない経路をすべて合わせて数える） | 認証の要る経路は住民、認証なしの経路は IP | 300 回／5 分 |

   段階 2 の過去の新聞の検索（FR-119）は、作るときに住所録の検索と同じ 60 回／1 時間を当てる。手紙・投稿・住所録の追加の 1 日の上限（429 `daily_limit_reached`）と相互にならない追加の停止（429 `add_suspended`）は別の仕組みで、この表と重ねて当てる。
3. **D3 数え方**:
   - 主体（IP・メールアドレス・住民 ID）は平文で持たない。`HMAC-SHA-256(RATE_LIMIT_HMAC_KEY, <規則の名前> ":" <主体>)` を `rate_limit_buckets.key` にする（表は ADR-0102）。メールアドレスは小文字にそろえてから計算する。IPv6 は /64 にまとめ、IPv4 は 1 つのアドレスごと。
   - 成功も失敗も同じに数える（ログインの成功で数えを戻さない）。上限を超えた要求も数える。
   - 数えは本来の処理とは別の短いトランザクションで、本来の処理より先に書く（`INSERT … ON CONFLICT (key, window_start) DO UPDATE SET count = count + 1 RETURNING count`）。本来の処理が 409 や 400 で戻っても、数えは残る。
   - 確かめる順番: 認証の要る経路は、認証のすぐあとに流量の制限を確かめる（認証 → 流量の制限 → ロールと二要素認証 → 再認証 → 入力の検証と対象の確かめ。順番の正本は ADR-0090 の D5）。認証なしの経路は、流量の制限を最初に確かめる。
4. **D4 知らせない**: 上限に当たったことを住民・モデレーターに知らせない。運用の監視は数えの表を主体ごとに見ず、429 を返した回数だけを規則ごとに数える（`security.md` §7.1）。

## 理由

- **固定の窓**: 数えの行が (主体, 窓) ごとに 1 行で済み、PostgreSQL だけで数えられる（ADR-0010）。窓の境目で 2 倍まで通ることは、値に余裕を持たせて受け入れる。
- **登録を IP ごとに 1 時間 3 回**: 1 人が登録をやり直すのは数回で足りる。1 日 10 回で、1 つの IP から 1 日に押さえられる住所は 10 まで（確認が済まない登録は 24 時間で手放す、ADR-0087）。
- **ログインをメールアドレスと IP の両方で数える**: メールアドレスごとの数えで 1 人への総当たりを、IP ごとの数えで多くのアドレスへの試しを抑える。メールアドレスごとの数えは、アカウントがなくても同じに数える（応答でアカウントの有無を明かさない、ADR-0080 の D4）。
- **メールを送る経路をメールアドレスごとに 1 時間 3 回**: 送り直し・再設定の依頼・メールアドレスの変更は、住民が入れた任意のアドレスにメールを送るので、踏み台にさせない。
- **入居の一覧と候補を 10 分 60 回**: 登録の画面で地図を開き直す・409 のあとに取り直す（ADR-0084 の D7）には足り、街のすべての家を返す認証なしの経路の負荷を抑える。
- **通報・ブロック・プロフィール・住所録の検索**: どれも 1 日の上限がない経路で、住所を順に試して住民がいるかを探れる（`security.md` §7 の T-05）。ふつうの使い方の何倍かにする。
- **既定 300 回／5 分**: 表にない経路でも、1 秒に 1 回を続ける使い方は人の操作でない。画面の読み込みで数本の要求が重なっても届かない。
- **主体を HMAC にする**: IP とメールアドレスを平文で DB に残さない（NFR-002・`security.md` §2.5）。数えには等値で引ければ足りる。
- **数えを先に別のトランザクションで書く**: 本来の処理が失敗して戻っても数えが残らないと、409 や 401 を返す試しだけは数えずに済んでしまう。

## 代わりの案（選ばなかった理由）

- **すべり窓・トークンバケット**: 境目の 2 倍を防げるが、数えの行か計算が増える。MVP の規模（ADR-0012）では固定の窓で足りる。不採用。
- **Redis で数える**: 別のブローカを置かない決定（ADR-0010）に反する。不採用。
- **`Retry-After` を返す**: 窓の終わりが分かり、上限ちょうどまで試す道具になる。残りの数を返さない今の決まり（`api.md` §5）にもそろえる。不採用。
- **失敗だけを数える**: 成功と失敗で数えが変わると、数えの差から正しいパスワードを推し量れる。不採用。
- **IP を平文で持つ**: 個人に結び付く値を DB に増やす。不採用。
