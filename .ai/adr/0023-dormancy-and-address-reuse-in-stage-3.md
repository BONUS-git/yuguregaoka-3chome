# 0023 — 休眠と空き家の再割り当ては段階 3。MVP の住所の候補は使われたことのない住所だけ

- 状態: 採用
- 日付: 2026-11-19

## 背景

ADR-0002 は、休眠（12 か月ログインなし → 通知 → 30 日で休眠空き家）と、空き家（全種）を
新しい住民の割り当て候補にすることを決めた。時期は書いていない。
`architecture.md` §5 は F-01（MVP）の worker の仕事に「休眠判定・住所再割り当て（F-16 と共通）」を置き、
`async.md` は J9（長期不在の退去）・J10（休眠の判定）・J12（休眠の通知）の段階を書いていない。
一方 `features.md` は空き家と再割り当て（FR-071・FR-072・FR-074）を F-16（段階 3）に置いている。
`roadmap.md`（YGO-008）で段階を決めるため、この食い違いを解く。

## 決定

1. 休眠（J10・J12）・長期不在の退去（J9）・空き家の再割り当て（`vacant_*` → `active`）は段階 3（F-16）に置く。
2. MVP の住所の候補（`GET /api/v1/addresses/candidates`）は、使われたことのない住所だけを返す。
3. MVP で起きる住所の遷移は「割り当て（→ `active`）」と「アカウント削除（`active` → `vacant_deleted`、J7）」の 2 つだけ。
   `vacant_deleted` の住所は段階 3 まで候補に戻さない。
4. 段階 3 で再割り当てを入れるときは、引っ越しと転送（J11）と同じ変更で、db.md §3 の居住記録による振り分けの
   テスト（前の住民あての手紙が新しい住民に届かないこと）を受け入れ条件にする（roadmap.md C-04）。

## 理由

- 休眠・再割り当て・転送は同じ住所の状態遷移（db.md §4）と同じ毎日のジョブの群（J9〜J12）で、
  まとめて作るとテストもまとめられる。
- 休眠は 12 か月たたないと起きない。MVP の体験（朝、ポストを開ける）には関係しない。
- 再割り当ては、住所録の古い住所あての手紙が新しい住民に届く事故の元になる。居住記録による振り分けを、
  転送と一緒に確かめてから入れるほうが安全である。
- 休眠の通知は、バッチが住民へ定期的に送るメール（OQ-039）である。
  段階 3 に置くと、MVP がメール送信に頼る範囲が認証の流れ（登録の確認・パスワードの再設定）と
  漏えい時の連絡（security.md §6.4）だけになる。
- 想定規模（ADR-0012、住民 1 万人）に対し、使われたことのない住所のプールを十分に用意できる [assumed]。

## 代わりの案（選ばなかった理由）

- **MVP から休眠と再割り当てを入れる**: MVP の範囲が広がるうえ、転送のない状態で再割り当てを入れることになり、
  振り分けの組み合わせを 2 回に分けて確かめることになる。
- **空き家を作らない（`vacant_deleted` も作らない）**: ADR-0002・ADR-0013 のアカウント削除の扱いと食い違う。

## 影響

- `async.md` §2: J9・J10・J12 に段階 3 と書く。
- `architecture.md` §5: F-01 の行から休眠判定と再割り当てを外し、F-16 の行に置く。
- `api.md` §7 F-01: 候補は使われたことのない住所だけと書く。§2.2 のログイン時の `dormant → active` は段階 3。
- `db.md` §4: 住所の再割り当てと休眠の遷移は段階 3 と書く。
- ADR-0002 の決定（期間と状態の値）は変えない。時期だけをこの ADR で決める。
