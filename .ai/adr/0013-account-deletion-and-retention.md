# 0013 — 退去処理とデータ保持期間

- 状態: 置き換え（→ 0075）
- 日付: 2026-11-19

## 背景

OQ-030「アカウント情報の保持期間・削除ポリシー」は `db.md` と `security.md` で定義する
とされていた（持ち越し）。

住民が退去する（アカウントを削除する）とき、次の問いに答える必要がある。

1. 住民が作成したデータ（手紙・掲示板投稿）はどうするか。
2. 受取人の郵便受けに届いた配達済み手紙はどうするか。
3. その住民が掲載された新聞はどうするか。
4. 各種データを何日間保持するか（NFR-009、FR-097）。

また、空き家化（12 か月ログインなし→休眠→30 日応答なし→vacant_expired）した住所の
元住民のデータをいつ削除するかも未定であった（ADR-0002 はこの点を詳細化していない）。

## 決定

すべての数値は `[assumed]`（確認が取れていない仮置き値）とする。

### 住民のアカウント削除時

| 対象 | 処理 |
|------|------|
| `residents` レコード | 即時物理削除。`erasure_log` に記録 |
| 認証情報 | 即時消去（`security.md` と連携） |
| 未配達の手紙 (`state = pending / scheduled`) | 即時キャンセル（`state = returned`） |
| 配達済み手紙（受取人の郵便受けにあるもの） | そのまま保持。`letters.sender_id` を NULL に変更し API では「退去済み」と表示 |
| 確認待ちの手紙・届けられなかった手紙（`state = held / blocked`、ADR-0040 で追記） | 即時に本文と宛先ごと削除（届いていないので、受取人のために残す理由がない） |
| 掲示板投稿（掲載前） | 即時削除（`state = deleted`, `body` を消去） |
| 掲示板投稿（掲載済み） | 即時 `deleted` に変更・`body` を消去。その投稿が含まれる新聞を組み直す |
| 住所録（所有するもの） | 即時削除 |
| ブロック（blocker / blocked） | 即時削除 |
| 通知の購読（`push_subscriptions`）・送った記録（`delivery_notifications`） | 即時削除（ADR-0025） |
| 興味（`resident_interests`） | 即時削除（ADR-0039 の D5） |
| 推し量った興味（`inferred_interests`、段階 2、ADR-0045 で追記） | 即時削除（ADR-0045 の D5） |
| その住民の投稿から作った記事（`newspaper_articles`） | 即時削除。その記事が載った版をすべて組み直す（ADR-0039） |
| `tenancies`（居住記録） | アカウント削除から **1 年後**に削除 |
| `addresses` | `status = vacant_deleted` に変更。住所レコード自体は削除しない |

### 長期不在による空き家化後の処理

`addresses.status = vacant_expired` になった時点の元住民について:

- 移行から **12 か月後**に、アカウント削除と同じ処理を適用する（上表を参照）。

### データ保持期間

| データ種別 | 保持期間 |
|-----------|---------|
| アクセスログ・操作ログ（DB 外） | 30 日 |
| `delivery_runs` | 30 日 |
| `delivery_notifications`（配達完了の通知の記録、ADR-0025） | 30 日 |
| `newspaper_articles`（新聞の記事の文字、ADR-0039） | 紙面（`newspapers`・`newspaper_editions`）と同じ |
| `external_news_items`（取り込んだ外のニュース、ADR-0039） | 取り込みから 30 日（OQ-060 の利用の条件で変わる） |
| `inferred_interests`（過去の新聞の検索から推し量った興味、段階 2、ADR-0045 で追記） | 最後に当たってから 30 日 [assumed]（J14 が消す） |
| `moderation_queue` / `moderation_actions` | 1 年 |
| 届けられなかった手紙（`letters.state = blocked`、本文と宛先、ADR-0040 で追記） | `blocked` にしてから 30 日 [assumed] |
| 確認待ちの手紙（`letters.state = held`、ADR-0040 で追記） | モデレーターが操作するまで（長く確かめられないときの扱いは OQ-065） |
| `reports`（通報） | クローズ日から 1 年 |
| バックアップ | 30 日 |
| `erasure_log` | 60 日 |
| `tenancies`（退去済み住民分） | 退去から 1 年 |

### 新聞の組み直し

住民の掲示板投稿が削除されたとき、その投稿を素材として使った `newspapers` レコードを
特定し、`newspaper_items` から削除したうえで紙面を再生成する（`newspapers.storage_url` を上書き）。
（ADR-0039 で置き換え）紙面は版ごとになったので、その投稿が載った版（`newspaper_editions`）をすべて描き直し、版の `storage_url` を上書きする。その投稿から作った `newspaper_articles` の行も消す。
休刊でない限り、空になった紙面は休刊として扱わない（他の素材は残す）。

## 理由

- **配達済み手紙を受取人側に残す**: 自分が受け取った手紙が突然消えると、受取人の体験を損なう。
  送信者が退去しても受取人の郵便受けはその人のものである。
- **新聞を組み直す**: 退去済みの住民の投稿が配達後も掲載され続けると、その住民の存在が
  消えたにもかかわらず過去ニュースに残り続ける。整合性を保つために再生成する。
- **居住記録（tenancies）を 1 年保持**: 住所録の配達先解決（`registered_tenancy_id`、db.md §3）
  に使うため、退去後も一定期間 tenancy の参照が必要。1 年はその転送・解決が発生しうる期間として仮置き。
- **erasure_log を 60 日保持**: バックアップ（30 日）よりも長く持つことで、
  リストア後の再生に使える期間を確保する（db.md §6）。

## 代わりの案

**配達済み手紙も削除する**: 受取人の体験を損なうため不採用。
**ソフトデリートのみ（物理削除しない）**: NFR-010（データ削除要求）・NFR-002（個人情報最小限）に
反するリスクがある。物理削除を基本とし、`erasure_log` で監査する。
**手紙を住民ごとに暗号化して退去時に鍵を破棄する（per-letter key）**: ADR-0006 ではサーバー鍵（KMS 管理）を採用しており、個別鍵の仕組みは設けていない。鍵破棄だけでは DB のレコードが残り、管理が複雑になる。不採用。
**新聞を組み直さない**: 退去住民の投稿が残り続けるため不採用。

## 影響

- DB 設計: `db.md` §4・§5 で本 ADR の内容を参照する
- 非同期処理: `async.md` で退去後の再組版ジョブを設計する
- セキュリティ: 認証情報の削除手順は `security.md` で定義する（OQ-028 と連携）
- OQ-030: `open-questions.md` の OQ-030 を決定（ADR-0013）にするかと、紙面の保持期間を分けることは `reviews/0001-design-review.md` の R-032 で決める
