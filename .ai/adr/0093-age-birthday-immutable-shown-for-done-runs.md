# 0093 — 年齢と誕生日は必須で変えられず、配達済みの手紙で見せる

- 状態: 採用
- 日付: 2026-11-25

ADR-0073 を丸ごと置き換える。ADR-0073 の決定（D1〜D8）は同じ番号でこの ADR に移した。
変わったのは D4 (a) だけで、数える `mailbox_items` の行に「行の配達回（`delivery_run_id`）が `done`」を足した（郵便受けに出る行と同じ条件。`failed` の回の行は数えない、ADR-0092 の D7、`triage.md` 仕分け 3 の K-005、YGO-031）。

## 背景

OQ-052 の答え（2026-11-20）で、年齢は住民が設定した値をそのまま使い、確かめないと決めた（ADR-0041 の D2）。
OQ-063 の答え（2026-11-20）で、年齢による違いは作らないと決めた（ADR-0057）。答えは「データ構造として年齢を持っておくこと」「年齢によって（属性として）表示が変わる可能性」を意図に含むとしていた。

2026-11-20、マスターが OQ-064（年齢の項目の扱い）に次のとおり答えた（原文）。

> (1) 必須
> (2) 変更は不可
> (3) 一定条件で見せる。一定条件は安全性に基づき秘書が決定する
> (4) 進む。誕生日の情報も新聞に載せたら面白そう

誕生日の扱いは OQ-064 の答えから読み切れなかったので、OQ-077 で (1) 誕生日（月日）を集めるか（必須か・架空でよいか・変えられるか）、(2) 新聞に何を載せるか、(3) 誰の新聞に載せるか・本人が載せないことを選べるか、を聞いた。
2026-11-21、マスターが OQ-077 に次のとおり答えた（原文）。

> 1:後からの変更は不可で必須。架空でOK。あくまでこの町（夕暮ヶ丘三丁目）内での設定
> 2:互いに登録済みならニックネームと年齢、住所載せる
> 3:知り合い同士以外は載せない

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定、`[inferred]`） | 読み取れないこと → 扱い |
|---|---|---|
| OQ-064 (1) | 登録で年齢の入力を必須にする | 値の範囲 → 秘書の判断（D1） |
| OQ-064 (2) | 年齢はあとから変えられない | 間違えたときの直し方 → 秘書の判断（D2、退去して登録し直す） |
| OQ-064 (3) | ほかの住民に、一定の条件のときだけ見せる。条件は安全性に基づいて秘書が決める | 条件の中身 → 秘書の判断（D4）。年齢の属性で何の表示が変わるか → OQ-078（持ち越し、D6） |
| OQ-064 (4) | 年齢は年とともに進む | 進め方 → OQ-077 の答え 1 で誕生日を集めるので、誕生日に進める（D3） |
| OQ-077 1 | 誕生日（月日）は登録で必須。あとから変えられない。架空の日でよく、確かめない。町の中の設定として持つ | 形式・2/29・年齢の進め方の細部 → 秘書の判断 `[assumed]`（D3・D5） |
| OQ-077 2・3 | 誕生日の住民のニックネーム・年齢・住所を、互いに住所録に入れた住民（知り合い）の紙面にだけ載せる | 紙面の組み方 → ADR-0074 の D9。本人が載らないことを選べるか → OQ-070 (3)（持ち越し） |

配達回の状態に `failed`（持ち越せなかった回）があり、その回の `mailbox_items` は動かさずに残る（ADR-0092 の D7）。J4 が準備した行には `visible_at` があるので、年齢の条件が行の配達回を見ないと、住民の郵便受けに出ていない手紙で年齢が見えてしまう。

ADR-0041 の D5（年齢の項目と列は置かない）、ADR-0047 の D5 のうち ADR-0041 の D5 の待つ条件を OQ-064 にした部分、ADR-0027 の D3 のうち「年齢を集めない」は、置き換えたまま、この ADR が引き継ぐ。
ADR-0041 の D2〜D4・D6（年齢は住民の設定をそのまま使い確かめない・危険な機能は設けない・年を含む生年月日は集めない・登録に年齢制限を置かない）と ADR-0057（年齢による違いは作らない）は変わらない。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 年齢は登録で必須**（OQ-064 の答え 1、`[inferred]`）: `POST /api/v1/registrations` は `age`（整数）を必須で受け取る。
   - `age` がない・整数でない・範囲の外なら 400（`validation_failed`）。範囲は 0〜999（`[assumed]`。架空の年齢（ADR-0041 の D2）を許すために広く取る）。
   - 既定値と「未設定」の状態は置かない。
   - 年齢は確かめない（ADR-0041 の D2 のまま。本人確認の書類・外部の年齢確認・保護者の同意は設けない）。
2. **D2 あとから変えられない**（OQ-064 の答え 2・OQ-077 の答え 1、`[inferred]`）: 年齢と誕生日のどちらにも当てる。
   - `PATCH /api/v1/me` は `age` と `birthday` を受け取らない。要求にどちらかがあれば 400（`validation_failed`）で、何も変えない（ほかの項目も変えない）。
   - モデレーター・admin と運用者の CLI を含め、年齢と誕生日を書き換える経路をどこにも作らない。
   - 直したい住民は、退去して登録し直すしかない `[assumed]`。
   - 年齢で守りは変わらない（ADR-0057）ので、変えられないことは ADR-0078 の D3（住民を守る制限は住民が自分で外せる設定にしない）とはぶつからない。
3. **D3 年は誕生日に進む**（OQ-064 の答え 4・OQ-077 の答え 1 から `[inferred]`。細部は `[assumed]`）: `residents` に次の列を持つ。
   - `age_at_registration smallint NOT NULL`（CHECK 0〜999）: 登録のときに入れた年齢。
   - `age_base_date date NOT NULL`: 登録した日の JST の日付。
   - `birthday_month smallint NOT NULL`（CHECK 1〜12）と `birthday_day smallint NOT NULL`（CHECK 1〜31）。月日の組み合わせを CHECK で確かめる（2/29 は許し、2/30・2/31・4/31・6/31・9/31・11/31 は許さない）。
   - 今の年齢 = `age_at_registration` + 「`age_base_date` より後で、今日（JST）以前に来た誕生日の回数」。
   - 登録の日が誕生日でも、その日には上がらない（入れた年齢をその日の年齢とみなす）。
   - 誕生日が 2/29 の住民は、うるう年でない年は 3/1 に上がる（うるう年は 2/29）。
   - 年齢は C2 が読むときに時計のアダプタで計算する。worker のジョブも、列の書き換えも持たない。上限の 999 を超えても今の年齢はそのまま返す（CHECK は登録のときの値だけに掛かる）。
4. **D4 見せる条件**（OQ-064 の答え 3、秘書に任された判断。`[inferred]`。(a) の配達回の条件は `[assumed]`）:
   - 本人には、`GET /api/v1/me` が今の年齢と誕生日（`birthday`、`MM-DD`）を返す。
   - ほかの住民には、`GET /api/v1/profiles/{address}` が、次をすべて満たすときだけ `age` を返す。満たさないときは `age` の項目そのものを返さない（`null` も返さない）。
     - (a) 見る住民の `mailbox_items`（`kind = 'letter'`、行の配達回（`delivery_run_id`）が `done`、`visible_at` を過ぎたもの、`deleted_at IS NULL` の行だけ）に、プロフィールの住民が送った手紙（`letters.sender_id`）が 1 通以上ある。郵便受けに出る行（`api.md` §7 F-03）と同じ条件で、`failed` の回など `done` でない回の行は数えない（ADR-0092 の D7）。見る住民が郵便受けから削除した手紙は数えない（削除で `mailbox_items`・`letters` は消える、ADR-0091・FR-099）。
     - (b) その手紙の `created_at` が、プロフィールの住民の今の居住記録（`tenancies.is_current`）の `started_at` 以後である。
     - (c) 見る住民が、プロフィールの住民をブロック（`blocks`）していない。
   - プロフィールの住民が見る住民をブロックしても、年齢の見え方は変えない（(a)〜(c) だけで決める）。ブロックした側の年齢がブロックされた側から消えると、ブロックされたと分かる（`security.md` T-06・ADR-0015）。
     ブロックの後も、ブロックされた側の郵便受けに残っている手紙で (a) を満たすあいだは見え続け、その手紙をすべて削除すると見えなくなる。
     ブロックした側から手紙が新しく届くのは、ブロックした側が自分で出したときだけ。
   - 年齢を見せる事実だけを持つ表（見る住民・見られる住民・居住記録）は足さない。
   - 次には出さない: 住所録・地図・掲示板・マッチング・通知・検索、モデレーターと運用者の画面、LLM・ログ・ジョブのペイロード。
   - 新聞にも出さない。例外は ADR-0074 の D9 の誕生日の欄だけで、そこには誕生日の住民のその日の年齢が、その住民の知り合いの住民ごとの版に載る。
   - 誕生日（月日）は `GET /api/v1/me` で本人にだけ返す。`GET /api/v1/profiles/{address}` を含むほかの応答には出さない `[assumed]`（答えは新聞のことだけを言っているので、見せる先を広げない）。誕生日の欄は月日の数字を載せない（ADR-0074 の D9）。
   - 見せるかどうかの住民の設定は置かない。条件は全員に同じ。
   - 年齢と誕生日で並べる・探す経路は作らない（`api.md` §8）。
5. **D5 誕生日を集める**（OQ-077 の答え 1、`[inferred]`。形式と画面の文は `[assumed]`）:
   - `POST /api/v1/registrations` は `birthday` を必須で受け取る。文字列 `MM-DD`（月・日とも 2 桁。例: `04-01`）。
   - `birthday` がない・文字列でない・形が違う（`4-1`・`""` など）・暦にない月日（`13-01`・`02-30` など）なら 400（`validation_failed`）。`02-29` は受け付ける。
   - 誕生日は確かめない。架空の日でよい（ADR-0041 の D2 と同じ考え）。この町の中の設定として持つ。
   - 登録の画面（C1）は、誕生日の入力に「この町での誕生日です（本当の日でなくてかまいません）」と示し、送る前に「年齢と誕生日はあとから変えられません」と示して確かめる。
   - 年を含む生年月日の項目は置かない（ADR-0041 の D4 のまま）。
6. **D6 年齢の属性で変わる表示は決めない**: OQ-064 の (3) の後半（年齢の属性で何の表示が変わるか）は答えにない。OQ-078（持ち越し）にし、暫定は作らない（D4 の `age` の数値と、ADR-0074 の D9 の誕生日の欄の年齢を出すほかに、年齢で変わる表示は置かない）。
   表示が変わっても、権限と照合には年齢の条件を持たせない（ADR-0057）。
7. **D7 置き換える決定**: この ADR は ADR-0073 を丸ごと置き換える。ADR-0073 が引き継いでいた次の部分は、そのままこの ADR が引き継ぐ。
   - ADR-0041 の D5（年齢の項目と列は置かない）。
   - ADR-0047 の D5 のうち、ADR-0041 の D5 の待つ条件を OQ-064 にした部分（ADR-0047 は ADR-0057 で置き換え済み）。
   - ADR-0027 の D3 のうち「年齢を集めない」。年を含む生年月日を集めないことは変わらない。
   - ADR-0041 の D2〜D4・D6 と ADR-0057 は変えない。
8. **D8 保存と消去**: 年齢と誕生日は平文で持つ（暗号化するのは手紙の本文、ADR-0006）。退去で `residents` の行ごと消す（ADR-0091）。
   - ログ・メトリクス・エラー報告・LLM・モデレーターと運用者の画面・ジョブのペイロードには出さない（`security.md` §2.5）。
   - 誕生日と年齢がそろうと生年月日に近い情報になるので、誕生日は年齢と同じに扱う。
   要求の区分: FR-008・FR-113・FR-127（`[inferred]`、マスターの答え OQ-064（2026-11-20）・OQ-077（2026-11-21）より。範囲の 0〜999・`MM-DD` の形・2/29 の扱い・(a) の配達回の条件は `[assumed]`）。

## 理由

- D1・D2・D4 の「一定条件で見せる」は OQ-064 の答えのとおり。誕生日を必須にし、変えられないのは OQ-077 の答え 1 のとおり。
- D1 の範囲を広く取るのは、架空の年齢を許す（ADR-0041 の D2）ため。上限は、型と入力の誤りを弾くためだけに置く。
- D2 の直し方を退去と登録のし直しにするのは、答えが「変更は不可」で、例外の経路（モデレーターの書き換えなど）を作ると、その経路が書き換えの手段になるため。`PATCH /me` で何も変えないのは、一部だけ変わった状態を作らないため。
- D3 の基準を誕生日にするのは、誕生日を集める（OQ-077 の答え 1）ので、「進む」（OQ-064 の答え 4）を誕生日で満たすのが自然で、誕生日の欄（ADR-0074 の D9）に載る年齢とも合うため。
  登録の列（`age_at_registration`・`age_base_date`）を残すのは、入れた年齢を「登録の日の年齢」として、そこから誕生日の回数で進めれば、年を含む生年月日を持たずに済むため（ADR-0041 の D4）。
  登録の日に上がらないのは、住民が入れた年齢をその日の年齢として扱うため。読むときに計算するので、ジョブの失敗で年齢がずれることがなく、テストは偽の時計で済む。
- D4 の年齢の条件は、次の安全性による。
  - 住所を順に引いて年齢で住民を探すこと（`security.md` T-05）ができない。見るには、相手から手紙を受け取っている必要がある。
  - 見せる相手は、年齢の持ち主が自分で手紙を出したかどうかで決まる。手紙を出していない住民には知られない。
  - (a) の行を郵便受けに出る行と同じ条件（配達回が `done`）にするのは、見る住民がまだ受け取っていない手紙（`failed` の回に残った行、ADR-0092 の D7）で年齢が見えないようにするため。見える手紙と年齢の見え方がずれない。
  - (b) によって、引っ越した住民の新しい住所が、前の住所から届いた手紙と結び付かない（ADR-0003）。
  - (c) によって、見る住民が自分でブロックした相手の年齢は出さない。見る住民が自分で決めたことなので、相手には何も漏れない。
  - プロフィールの住民がしたブロックを条件に入れないのは、ブロックを相手に気づかせない（T-06・ADR-0015）ことを、ブロックされた側から年齢を隠すことより優先するため。
    ブロックされた側は、ブロックの前に手紙を受け取って年齢をすでに知っている。年齢は決まった進み方をする（D3）ので、後から隠しても守りにはほとんどならない。一方、消えればブロックが露見する。
  - 削除した手紙を数えないのは、削除で `mailbox_items` の行と（受取人全員が削除すれば）`letters` の行が消え（ADR-0091・FR-099）、判断に使える行が残らないため（NFR-002）。
- D4 で新聞の誕生日の欄だけを例外にするのは、OQ-077 の答え 2・3 が、知り合いの紙面に年齢を載せることを決めたため。載る相手は知り合い（互いに住所録に入れた住民）だけで、住所を順に引いて探す経路にはならない。
  誕生日の月日をプロフィールに出さないのは、答えが新聞のことだけを言っていて、見せる先を広げる根拠がないため。
- D5 で年を含まない月日だけにするのは、答えの「この町内での設定」と、年を含む生年月日を集めない決定（ADR-0041 の D4）を両方満たすため。
- D6 は、答えに書かれていないことを決めないため（CLAUDE.md）。
- D8 は、年齢と誕生日が個人情報で、使い道がプロフィールの表示と誕生日の欄だけだから（データ最小化、NFR-002・NFR-010）。誕生日が架空でよくても、本当の日を入れる住民がいるので、年齢と同じに守る。

## 代わりの案（選ばなかった理由）

- **年齢の基準を登録の日のままにする**: 誕生日を集めるのに、誕生日の欄の年齢と年齢の上がる日がずれる。
- **誕生日を任意にする**: OQ-077 の答え 1「必須」と食い違う。
- **誕生日をプロフィールに出す（知り合いにだけ・全員に）**: 答えは新聞のことだけで、見せる先を広げる根拠がない。月日と年齢がそろって見える相手が増える。
- **年も集める（生年月日）**: 答えは「町内での設定」で、年を含む生年月日を集めない決定（ADR-0041 の D4）とぶつかる。年齢と誕生日の回数で足りる。
- **全住民に年齢を見せる**: 住所を順に引くと年齢で住民を探せる（T-05）。OQ-064 の答え「一定条件で」と食い違う。
- **見せるかを住民の設定にする**: 条件は安全性に基づいて秘書が決めることになっており、住民が守りを外せる設定は置かない（ADR-0078 の D3）。
- **年代だけ見せる**: 答えの「見せる」は年齢を見せることと読める。年代で丸めるかは表示の変化（OQ-078）で決める。
- **どちらの向きのブロックでも年齢を隠す**: ブロックされた側から年齢が消え、ブロックされたと分かる（T-06・ADR-0015 に反する）。
- **削除した `mailbox_items` の行を年齢のために残す／年齢を見せてよいという事実だけを持つ表を足す**: 削除した手紙の痕跡が残り、FR-099・データの最小化（NFR-002）とぶつかる。
- **(a) で配達回を見ない（`visible_at` だけで決める）**: `failed` の回に残った行（ADR-0092 の D7）で、郵便受けに出ていない手紙から年齢が見える。
- **`failed` にするときに、その回の `mailbox_items` を消す**: 中身を動かさない ADR-0092 の D7 とぶつかり、J6 の再試行中（`running` のまま枠の時刻を過ぎた間）の行は残るので、条件を足さないと防げない。
- **毎年ジョブで列を書き換える**: ジョブの失敗・やり直しで年齢がずれうる。読むときの計算で足りる。
- **モデレーターが年齢や誕生日を直せる経路を作る**: 答え「変更は不可」と食い違い、モデレーターの内部不正（T-12）の手段が増える。

## 決めていないこと

- 年齢の属性で何の表示が変わるか: OQ-078（持ち越し。マスターが決める。年齢で変わる表示を足す前に聞く。暫定は作らない）。
- 本人が誕生日の欄に載らないことを選べるか: OQ-070 (3)（持ち越し。組 1・2 を作る前にマスターに聞く。それまで断る設定は置かない）。
- 商店・団体のアカウント（段階 3、ADR-0029。登録を通らない）に年齢と誕生日を持たせるか: 担当者のログインと主体（OQ-069、持ち越し）とあわせて決める。
- 適用法令が年齢と誕生日の収集と表示について何を求めるか: OQ-032（持ち越し）。
