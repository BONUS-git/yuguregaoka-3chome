# 0072 — クローズドな手紙も審査し、LLM に渡さず復号の場面を限る

- 状態: 採用
- 日付: 2026-11-22

ADR-0026 を丸ごと置き換える。ADR-0026 の決定（D1〜D7）を今の状態に書き直し、同じ番号でこの ADR に移した。
照合の時点と方法（ADR-0026 の D3・D4 (b)）は ADR-0069 の決定に合わせた。

## 背景

OQ-003 の答え（2026-11-19）で、クローズドな手紙も審査の対象にすると決まった（原文）。

> 対象とする。ただし、LLMには渡さず、厳格なアクセス制御を行う

OQ-043 の答え（2026-11-19、ADR-0036）で、通報された手紙はモデレーターが条件付きで確かめてよいと決まった。
OQ-052・OQ-076・OQ-087 の答えで、手紙は送るときに API が 2 段で照合し、疑いに当たった手紙は送った人が頼めばモデレーターが確かめると決まった（ADR-0069）。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 審査の対象**（OQ-003 の答え）: 個人宛・グループ宛のクローズドな手紙も、配達の前に審査する（FR-078）。
   グループ宛の手紙（F-10、段階 2）は手紙ごとに 1 回審査し、結果はすべての宛先に同じく効く。
2. **D2 LLM に渡さない**（OQ-003 の答え）: 手紙の本文は、全文も一部も要約も LLM に渡さない（NFR-005）。
   - 手紙の照合の経路（投函のときの API の照合）には、LLM の分類器のアダプタを渡さない。手紙の経路から LLM を呼べる形にしない。
   - `moderation_queue`（LLM の経路）に手紙の行を入れない。DB の CHECK 制約（`content_kind <> 'letter'`）で守る（`db.md` §2）。
3. **D3 審査の方法**: 手紙はルール表（`security.md` §5）のうち手紙に当てる項目だけで照合する。照合の時点・段・送った人の y / n・モデレーターの確認は ADR-0069 で決める。
   - worker は手紙を照合しない。J4 は判定を見ずに `scheduled` の手紙をすべて準備する。
   - 安全網として、J5 は公開のトランザクションの最初に、この配達回の `scheduled` の手紙のうち J4 が準備しなかったもの（この配達回の `mailbox_items` がないもの）を次の受付中の配達回に移す。J5 が公開できず J6 になるときは、J6 が `scheduled` の手紙をすべて移す（`async.md` §4）。
4. **D4 本文を復号してよい場面**（OQ-003 の答えの「厳格なアクセス制御」）: 次の 4 つに限る（`security.md` §2.3）。
   - (a) 送った人と、受け取った人が自分の手紙を読む（web、C3 の手紙のサービス）。
   - (b) 送るときの API のルール表の照合。暗号化の前の平文をメモリの中だけで使い、復号しない。平文を DB・ログ・ジョブのペイロード・例外のメッセージに書かない（ADR-0069 の D2）。
   - (c) 通報された手紙を、モデレーターが確かめる（`GET /api/v1/admin/reports/{id}/letter`、`api.md` §7 F-08。OQ-043 の答え、ADR-0036 の D2）。
     - 条件: 通報が `open`・対象が手紙・モデレーターがその手紙の当事者（送った人・受け取った人・通報した人）でない・
       セッションが二要素認証を済ませている（ADR-0020）。1 回の操作で返すのは 1 通だけ。
     - 毎回 `moderation_actions` に `action = 'view_letter'` の行を書く。行を書けなければ本文を返さない（同じトランザクション）。
     - 応答には `Cache-Control: no-store` を付ける。
     - 条件に合わないときは 404 を返す（ADR-0014。存在を明かさない）。
   - (d) 送った人が確認を頼んだ `held` の手紙を、モデレーターが 1 通だけ確かめる（ADR-0069 の D5）。条件は (c) と同じ。
   - 本文の一覧・検索の経路は作らない。`blocked` と `pending` の手紙を見る経路は作らない。
5. **D5 送った人への見せ方**: 送信済みの表示で、`blocked` は「届けられませんでした」と見せる。当たった規則・理由は見せない。
   受け取るはずだった人には何も見せない（郵便受けに出ず、配達完了の通知の件数にも入らない）。
   `suppressed`（受取人のブロック）は「配達済み」と見せる（ADR-0015）。
6. **D6 段階**: MVP の M4（`roadmap.md` §4）で、掲示板の審査と一緒に作る。受け入れ条件は A-06・A-09。
7. **D7 要求の区分**: FR-078・NFR-005 は `[inferred]`（マスターの答え OQ-003 より）とし、根拠にこの ADR を書く。

## 理由

- 手紙を審査すること、本文を LLM に渡さないこと、アクセスを厳しく限ることは、OQ-003 の答えによる。
- LLM を外した残りの層はルール表で、決められた規則で決定的に判定できる。NFR-011（LLM の自由裁量に委ねない）にもかなう。
- 手紙の経路に LLM のアダプタを渡さず、DB の制約でも手紙の行を LLM の経路に入れなければ、実装の誤りで本文が LLM に渡ることを、型と DB の 2 か所で防げる。テストで「呼ばれたら失敗する」モックを差し込んで確かめられる。
- D3 の安全網は、J4 が準備しなかった手紙を落とさず次の便に回すため（冪等: 移したあとは対象が 0 行になる）。
- 送った人に規則を見せないのは、規則を探って避ける手がかりを与えないため。「届けられませんでした」と見せれば、届いたと思い込ませずに済む（`suppressed` と違い、隠す相手がいない）。
- 復号を限られた場面の 1 通に限り、毎回記録するのは、モデレーターの内部不正（`security.md` T-12）を抑え、後から確かめられるようにするため。

## 代わりの案（選ばなかった理由）

- **手紙も LLM に渡す**: OQ-003 の答え（LLM には渡さない）に反する。
- **手紙を審査しない**: OQ-003 の答え（対象とする）に反する。
- **当たった手紙を差し戻し（`returned`）として見せる**: `returned` は宛先が見つからないときの状態で、送った人が宛先を直せば届くと誤解させる。
- **E2EE にしてサーバーが読めないようにする**: 審査できなくなり、答え（対象とする）に反する（ADR-0006）。

## 決めていないこと

- 違法な物の取引の場にしないための守り: OQ-053（持ち越し、ADR-0036 の D6）。
- 違反した住民への処置: OQ-048（持ち越し、ADR-0032）。
