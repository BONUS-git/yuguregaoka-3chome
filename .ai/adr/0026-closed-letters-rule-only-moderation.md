# 0026 — クローズドな手紙も審査する。本文は LLM に渡さず、ルール表だけで照合し、復号できる場面を限る

- 状態: 採用（D4 (c) は ADR-0036 で暫定から決定にした。D3（締め切りのあとに J2 で照合する方法）と D4 (b) は ADR-0040 で置き換えた）
- 日付: 2026-11-19

## 背景

`requirements.md` の FR-078 は「クローズドな手紙をモデレーションの対象とする範囲は要回答」とし、
NFR-005 は「AI モデレーションにクローズドな手紙を処理させる場合、プライバシー保護の措置を明示する」としていた。
`open-questions.md` の OQ-003 でマスターに聞いていた。暫定は「手紙は審査の対象にしない。通報された手紙だけ、
モデレーターが 1 通だけ復号して確かめる。本文は LLM に渡さない」だった。

2026-11-19、マスターが OQ-003 に次のとおり答えた（原文）。

> 対象とする。ただし、LLMには渡さず、厳格なアクセス制御を行う

今の審査（ADR-0005、`security.md` §5.2）は「ルール表 → LLM のラベル → ルール表との突合」の 2 層で、
LLM を外すと手紙はルール表の層だけで審査することになる。審査の方法・結果の扱い・本文に触れられる経路・
送った人への見せ方は技術と設計の事柄なので秘書が決め、ここに残す。
答えに書かれていないこと（手紙で何を止めるか、止めた手紙や通報された手紙を人が見てよいか）は決めず、OQ-043 にした。
答えの「厳格なアクセス制御」は、人が手紙を読んでよいとは言っていない。閲覧の範囲は倫理と公開の範囲の事柄なので、
モデレーターが手紙を読む場面は決定にせず、暫定（通報された手紙を 1 通だけ確かめる）を続けた（D4 (c)）。
（追記 2026-11-19）OQ-043 の答えで、通報された手紙をモデレーターが確かめることは決定になった（ADR-0036 の D2）。
手紙で止める内容と、止めた手紙の閲覧は OQ-052（要回答）に移った。
（追記 2026-11-20）OQ-052 の答えで、手紙に当てる項目（スパム・外部リンク・成人向けの言葉）と、送るときに照合し、
当たったら送った人がモデレーターの確認を頼むかを選ぶ流れが決まった（ADR-0040）。D3 の照合の時点と方法・D4 (b)・D5 の `blocked` になる道筋は ADR-0040 で置き換えた。
審査すること（D1）・LLM に渡さないこと（D2）・送った人への見せ方（D5 の「届けられませんでした」）は変わらない。

## 決定

1. **D1 審査の対象**（マスターの答え）: 個人宛・グループ宛のクローズドな手紙も、配達の前に審査する（FR-078）。
   グループ宛の手紙（F-10、段階 2）は手紙ごとに 1 回審査し、結果はすべての宛先に同じく効く。
2. **D2 LLM に渡さない**（マスターの答え）: 手紙の本文は、全文も一部も要約も LLM に渡さない（NFR-005）。
   - 手紙の審査の経路（J2 の手紙の処理）には、LLM の分類器のアダプタを渡さない。手紙の経路から LLM を呼べる形にしない。
   - `moderation_queue` の手紙の行（`content_kind = 'letter'`）では `llm_label` を常に NULL にする。
     DB の CHECK 制約（`content_kind <> 'letter' OR llm_label IS NULL`）で守る（`db.md` §2）。
     （ADR-0040 で、`moderation_queue` に手紙の行を入れなくなった。CHECK 制約は `content_kind <> 'letter'` にし、手紙が LLM の経路に乗らないことを DB で守る）
3. **D3 審査の方法**（**ADR-0040 で置き換え**。照合は送るときに API で行い、当たったら送った人が y / n を選び、y の手紙をモデレーターが確かめる。
   `moderation_queue` に手紙の行は入れず、J2 は手紙を扱わず、J4 は判定を見ずに準備し、J5・J6 の移動にキューの行は伴わない。下は置き換える前の記録）:
   手紙はルール表（`security.md` §5）のうち、手紙に当てる項目だけで照合する。
   - 当たらない → `policy_decision = 'approved'`。そのまま配達する（J4・J5）。
   - 当たった → `policy_decision = 'blocked'`、`letters.state = 'blocked'`。配達しない。
     記録するのは、当たった規則の ID（`matched_rule_id`）とルール表の版（`rule_version`）だけで、本文の抜き書きは残さない。
   - 審査の打ち切り（04:00 / 16:00 JST）までに判定できない手紙は届けず、次の便へ持ち越す。
     - 動かすのは J2 ではない。J2 は判定を書かずに残すだけで、J2 が止まっていても打ち切りのあとに動かなくても持ち越しは起きる。
     - J4 は判定が `approved` の手紙だけを準備する。J5 が公開のトランザクションの中で、この配達回の `scheduled` の手紙のうち
       J4 が準備しなかったもの（この配達回の `mailbox_items` がないもの）を次の受付中の配達回に移す（`delivery_run_id` を変え、`scheduled` のまま）。
     - 移すかどうかは判定の有無で決めない。J2 は打ち切りのあとも動き続けることがあり、J4 の準備が済んだあとに `approved` を書くことがある。
       その手紙も準備されていなければ移り、移し先の配達回で審査し直される。J4 のあとで `blocked` を書いた手紙は `scheduled` でないので移らず、配達されない。
       J5 が公開できず J6 になるときは、J6 が `scheduled` の手紙をすべて移す。
     - 移した手紙の `moderation_queue` の行は、移し先の配達回で `ON CONFLICT DO NOTHING` で入れる（移し先の J1 がすでに動いていても審査に乗る）。
     - 冪等: 移動の条件は「この配達回・`scheduled`・この配達回の `mailbox_items` がない」で、公開と同じトランザクションの最初（退去で消す `mailbox_items` の削除より前）に行う。
       やり直しても同じ手紙を移し、移したあとは対象が 0 行になる。
     - J5 が `delivered` / `suppressed` / `returned` / `blocked` に確定させるのは J4 が準備した手紙（`mailbox_items` がある手紙と、`returned`・`suppressed`・`blocked` の手紙）だけで、移した手紙は確定の対象にしない（`async.md` §4 J5）。
     - M3（J2 がない段階）では、J4 は判定を見ずに `scheduled` の手紙をすべて準備する。判定の条件と移動の処理は M4 で足す（`roadmap.md` §4）。
   - 人の審査（`review`）の段はない。手紙の行は管理用の審査キュー（`GET /api/v1/admin/moderation-queue`）に出さない。
4. **D4 本文を復号してよい場面**（マスターの答えの「厳格なアクセス制御」）: 次の 3 つに限る（`security.md` §2.3）。
   (a)・(b) は答えで決まった審査と配達に要る場面で、決定。(c) は人が手紙を読む場面で、もとは答えに書かれていないので暫定だった。
   OQ-043 の答え（2026-11-19）で (c) も決定になった（ADR-0036 の D2）。
   - (a) 送った人と、受け取った人が自分の手紙を読む（web、C3 の手紙のサービス）。
   - (b) J2 のルール表との照合。worker の中だけで行い、平文はメモリの中だけに置く。
     平文を DB・ログ・ジョブのペイロード・例外のメッセージに書かない。照合の結果として残すのは D3 の ID と版だけ。
     （**ADR-0040 で置き換え**: 照合は送るときに API が暗号化の前の平文で行い、復号しない。worker は手紙を復号して照合しない。
     代わりに (d) 送った人が確認を頼んだ `held` の手紙を、モデレーターが 1 通だけ確かめる場面が加わった。条件は (c) と同じ）
   - (c) **決定**（OQ-043 の答え、2026-11-19、ADR-0036 の D2）: 通報された手紙を、モデレーターが確かめる（`GET /api/v1/admin/reports/{id}/letter`、`api.md` §7 F-08）。
     - 条件: 通報が `open`・対象が手紙・モデレーターがその手紙の当事者（送った人・受け取った人・通報した人）でない・
       セッションが二要素認証を済ませている（ADR-0020）。1 回の操作で返すのは 1 通だけ。
     - 毎回 `moderation_actions` に `action = 'view_letter'` の行を書く。行を書けなければ本文を返さない（同じトランザクション）。
     - 応答には `Cache-Control: no-store` を付ける。
     - 条件に合わないときは 404 を返す（ADR-0014。存在を明かさない）。
   - 本文の一覧・検索の経路は作らない。通報されていない手紙は、モデレーターも読めない
     （OQ-052 → 決定、2026-11-20、ADR-0040: 送った人が確認を頼んだ `held` の手紙だけは (d) として読める。`blocked` の手紙を見る経路は作らない）。
5. **D5 送った人への見せ方**: 送信済みの表示で、`blocked` は「届けられませんでした」と見せる。当たった規則・理由は見せない。
   受け取るはずだった人には何も見せない（郵便受けに出ず、配達完了の通知の件数にも入らない）。
   `suppressed`（受取人のブロック）は今のまま「配達済み」と見せる（ADR-0015）。
   これで `api.md` §9 の「`blocked` を送った人にどう知らせるか」が決まる。
6. **D6 段階**: MVP の M4（`roadmap.md` §4）で、掲示板の審査と一緒に作る。受け入れ条件は A-06・A-09 に足す。
7. **D7 要求の区分**: ADR-0024 の決定 5 に従い、FR-078・NFR-005 は `[inferred]`（マスターの答え OQ-003 より）とし、根拠にこの ADR を書く。

## 理由

- 手紙を審査すること、本文を LLM に渡さないこと、アクセスを厳しく限ることは、マスターの答え（上の原文）による。
- LLM を外した残りの層はルール表で、決められた規則で決定的に判定できる。NFR-011（LLM の自由裁量に委ねない）にもかなう。
- 手紙の経路に LLM のアダプタを渡さず、DB の制約でも `llm_label` を NULL に固めれば、
  実装の誤りで本文が LLM に渡ることを、型と DB の 2 か所で防げる。テストで「呼ばれたら失敗する」モックを差し込んで確かめられる。
- 結果に規則の ID と版だけを残せば、判定を再現でき、本文の写しが DB に増えない。
- 打ち切りまでに判定できない手紙を届けないのは、FR-080（承認されていないものは届けない）と、掲示板の投稿の扱い（ADR-0005）にそろえるため。
- 送った人に規則を見せないのは、規則を探って避ける手がかりを与えないため。「届けられませんでした」と見せれば、
  届いたと思い込ませずに済む（`suppressed` と違い、隠す相手がいない）。
- D4 (c) をもとは暫定にしたのは、人が手紙を読んでよいかは答えに書かれていない閲覧の範囲で、マスターが決めることだったから。
  OQ-043 の答え（2026-11-19）で決定になった（ADR-0036）。復号を通報された 1 通に限り、毎回記録するのは、モデレーターの内部不正（`security.md` T-12）を抑え、後から確かめられるようにするため。

## 代わりの案（選ばなかった理由）

- **手紙も LLM に渡す**: マスターの答え（LLM には渡さない）に反する。
- **手紙を審査しない（もとの暫定）**: マスターの答え（対象とする）に反する。
- **当たった手紙を人の審査に回す**: 止めた手紙を人が見てよいかは閲覧の範囲で、答えに書かれていなかった（OQ-052 → 決定、2026-11-20。送った人が y を選んだ手紙だけをモデレーターが確かめる、ADR-0040）。
- **当たった手紙を差し戻し（`returned`）として見せる**: `returned` は宛先が見つからないときの状態で、送った人が宛先を直せば届くと誤解させる。
- **E2EE にしてサーバーが読めないようにする**: 審査できなくなり、答え（対象とする）に反する（ADR-0006）。

## 決めていないこと

- 通報された手紙をモデレーターが読んでよいか: OQ-043 → 決定（2026-11-19、ADR-0036。D4 (c) の条件のまま確かめてよい）。
- 手紙で止める内容（ルール表のどの項目を手紙に当てるか）、止めた手紙をモデレーターが見てよいか（誤判定の確認・送った人の異議）、
  年齢や設定で守り方を変えるか: OQ-052 → 決定（2026-11-20）。手紙に当てる項目はスパム・外部リンク・成人向けの言葉で、送るときに照合し、
  当たったら送った人が y / n を選び、y の手紙をモデレーターが確かめる（ADR-0040）。年齢で守り方を変える（中身は OQ-063、ADR-0041）。
  残りはスパムの決め方・言葉の一覧の置き場など（OQ-065、持ち越し）。
- 違法な物の取引の場にしないための守り: OQ-053（持ち越し、別のチケット。ADR-0036 の D6）。
- 連絡先の共有の禁止（FR-101）は手紙に及ばない（OQ-041 → 決定、2026-11-19、ADR-0034）。FR-101 を理由にルール表に手紙の項目を足さない。
  外部リンクの項目（ADR-0040 の D1）にもメールアドレスと電話番号を含めない。
- 違反した住民への処置: OQ-037 は決定（2026-11-19、内容はマスターが後で決める、ADR-0032）。内容は OQ-048（持ち越し）。
