# 0068 — 使い終わった道具は片付ける

- 状態: 採用
- 日付: 2026-11-21

## 背景

ADR-0052 の D3 で、M0 から `sh scripts/check.sh` は使い捨ての PostgreSQL（`initdb`・`pg_ctl`。Unix ソケットだけで待ち受ける）を一時ディレクトリに起こして DB のテストを動かし、
道具がない機械では飛ばさずに失敗すると決めた。CI の設定と秘書のジョブの環境は秘書が変えられない（NFR-091）ので、`open-questions.md` の OQ-086 でマスターに、
(1) CI の実行の環境と (2) 秘書のジョブの環境に PostgreSQL のサーバーの道具を入れてもらえるか、入れられないなら `prepare.sh` で npm の依存として取り込む代わりの方法を選んでよいかを聞いた。
2026-11-21 に次のとおり答えが出た（原文）。

> dockerなど必要であれば用意する。が、ルールとして使い終わった道具は片付けることを徹底してほしい。

前半（必要な道具はマスターが用意する）は ADR-0052 の D3 の前提のとおりで、ADR-0052 の D3 を決定の書き方に直した。後半（使い終わった道具は片付ける）は新しい決まりで、この ADR で範囲を決める。

## 決定

1. **D1 片付けるもの** `[assumed]`: ジョブと `check.sh` が自分で起こしたもの・作ったもの。
   - 起こしたプロセス: 使い捨ての PostgreSQL、`dev-db.sh` の開発の DB、web、worker、Vite の開発サーバー。
   - 作った一時のもの: `mktemp` のディレクトリ、ソケット、ログ、レポジトリの外のファイル。
   - コンテナを使うときは、作ったコンテナ・イメージ・ボリューム・ネットワークも（今の設計ではコンテナを使わない、ADR-0052 の D2）。
2. **D2 いつ**: 遅くとも `check.sh` の 1 回、ジョブの 1 回の終わりまでに片付ける。成功・失敗・中断（INT・TERM・HUP）のどれでも片付ける。
3. **D3 `check.sh`** `[assumed]`:
   - 片付けの関数を `trap` で EXIT・INT・TERM・HUP に掛ける。
   - PostgreSQL を `pg_ctl stop -m fast` で止め、止まらなければ `-m immediate` で止めてから、一時ディレクトリを消す。
   - 関数は何度呼んでも同じに動く（もう止まっている・もう消えているときは何もしない）。
   - 止められない・消せないときは理由を出して `check.sh` を失敗させる。
4. **D4 ジョブ** `[assumed]`: ジョブで開発の DB やプロセスを起こしたら、ジョブの終わりまでに止め、`sh scripts/dev-db.sh clean` を動かす。
   `clean` は開発の DB を止めて `.local/pg/` を消し、作り直さない。`dev-db.sh` と `clean` は M0 で作る。
5. **D5 片付けないもの** `[assumed]`:
   - マスターが入れた道具（PostgreSQL のサーバーの道具など。環境は秘書が変えない、NFR-091）。**暫定**: 依頼で用意してもらった道具を使い終わったあとに外してもらうかは OQ-090（要回答）。
     答えまでは外してもらわず、置いたままにする。答えが「外す」なら、この項と D2（いつ）を新しい ADR で置き換える。
   - ジョブの間の `node_modules/`（`prepare.sh` が入れ、`check.sh` が使う）。
   - マスターの手元の `.local/pg/`（マスターが自分で起こした開発の DB）。

## 理由

- 片付けること（D1・D2）は、OQ-086 の答え（上の原文）による。片付けの範囲は答えに書かれていないので、ジョブと `check.sh` が起こしたもの・作ったものの細部は技術の細部として秘書が `[assumed]` で決めた（マスターが入れた道具の扱いは除く。次の項）。
- 「起こしたもの・作ったもの」に限る（D1・D5）のは、秘書は環境を変えない（NFR-091）ので、ジョブと `check.sh` が自分で片付けられるのはそれだけだから。
  答えは「dockerなど必要であれば用意する」の直後に「使い終わった道具は片付ける」と続くので、依頼で用意してもらった道具を使い終わったら外してほしいとも読める。
  どちらの読みかは構想の意図で秘書が決められないので OQ-090（要回答）で聞き、それまでは置いたままにする（暫定。外すと次のジョブと CI のたびに入れ直しが要る）。
- 失敗と中断でも片付ける（D2・D3）のは、テストが落ちたときや打ち切られたときに使い捨ての PostgreSQL が残りやすいから。`trap` を 1 か所に置けば、経路ごとに片付けを書かずに済む。
- 止められない・消せないときに失敗させる（D3）のは、片付けの失敗を見逃すと、残ったプロセスとディレクトリが次の実行まで積もるから。
- `clean` を作り直さない（D4）のは、ジョブの終わりに使うもので、次に使うときは `start` が初めてのときと同じに `initdb` するから。

## 代わりの案（選ばなかった理由）

- **CI だけの片付けの手順を作る**: `check.sh` の中身を手元と CI で同じにする方針（`environment.md` §5）に反し、秘書のジョブの環境が片付かない。
- **成功したときだけ片付ける**: 失敗と中断のときに残る。
- **マスターが入れた道具も、使い終わったら外してもらう**: 次のジョブと CI のたびに入れ直しが要る。答えがこの読みかもしれないので、選ばずに OQ-090（要回答）で聞く。
- **片付けに失敗しても `check.sh` を通す**: 残ったものが見えないまま積もる。

## 決めていないこと

- 依頼で用意してもらった道具（docker など）を、使い終わったあとに外してもらうか（OQ-090、要回答）。暫定は D5 のとおり置いたまま。
  答えで変わる箇所: D5 の 1 つ目・D2、NFR-092 の最後の文、`environment.md` §4.4 の「片付けないもの」と §5、`roadmap.md` の §4 の M0・A-01・§7。
