# 0002 — ログインしないだけでは空き家にしない

- 状態: 置き換え（→ 0060）
- 日付: 2026-11-19

## 背景

FR-006 は「一定期間ログインのない住所は空き家に分類する」と記録されており
[explicit] の区分がついている。しかし構想の原文には「空き家」という語しかなく、
ログイン不在による強制的な住所剥奪が意図されていたかは不明確である。

休んでいる住民の住所を別の人に割り当てれば、その住民が戻ったときに住所を失い
体験を大きく損なう。

## 決定

- アカウント削除は即時に住所を「削除済み空き家」とする
- ログイン不在は「休眠」状態として住所を保持する
- **12 か月**ログインがなければ住民にメール等で通知し、さらに **30 日**応答がなければ
  「休眠空き家」に移行する
- 住所転送の期間は引っ越しから **6 か月** とし、期間終了後に旧住所を「転送後空き家」とする
- 空き家（全種）は新規住民の住所割り当て候補となる

また、FR-006 の [explicit] 区分は言い過ぎである。
構想の「空き家」は住所が空いている状態を指すのみであり、強制剥奪は書かれていない。
この矛盾は open-questions OQ-027 に記録した。requirements.md の FR-006 の区分を直す（OQ-027）。

## 理由

- 休んでいる住民の住所を剥奪しない（住民体験の保護）
- 通知してから移行するため住民への影響を最小化できる
- 転送期間 6 か月は住民が新住所を関係者へ広める十分な時間として設定した

## 代わりの案

**ログイン不在で即時空き家**: 住民が知らない間に住所を失う。構想の体験と矛盾するため不採用。
**空き家を設けない**: 住所の再利用ができず、架空の街が「満員」になる可能性がある。不採用。

## 影響

- DB 設計: `addresses` に `status`（active / dormant / vacant_deleted / vacant_expired / vacant_forwarded）と
  `last_login_at`・`forwarding_expires_at` を持つ
- 非同期処理: 休眠判定バッチが定期実行される（`async.md` で設計）
- 時期: 休眠と空き家の再割り当ては段階 3（F-16）で入れる。MVP の候補は使われたことのない住所だけ（→ ADR-0023）
