# 0109 — CI の定義の担い手と外待ちの行のチケット

- 状態: 採用
- 日付: 2026-11-28

チケット YGO-100 による。仕分け 17 の K-021 を決め、`.ai/gaps.md` の G-081 を閉じる。ADR-0105 と ADR-0108 を丸ごと置き換える。
D1〜D5 は CI の定義の担い手と確かめの置き場（ADR-0105 の D1・D3 のまま引き継ぎ、D2 の担い手と D4 の確かめの置き場を変え、YGO-070 の取り下げを足す）。
D6〜D12 は外待ちの行のチケット（ADR-0108 の D1〜D7 を同じ順に引き継ぎ、ADR-0108 の D5 にあたる D10 の YGO-100 の待ちをなくす）。
ADR-0052（手元で再現できる環境、`check.sh` はネットワークなし）・ADR-0009（TypeScript・Fastify・Vitest）・ADR-0106（依存を足す・変える変更ごとのロックファイル）の決定は変えない。

## 背景

ADR-0105 の D2 は「CI の定義に `prepare.sh` の段を足すのはマスター」とし、CLAUDE.md（作り方の節）は「`.github/workflows/check.yml` は秘書の CI の決まった形の名前で、ジョブは書かない・変えない（秘書が入れたプロジェクトでは `scripts/check.sh` を push のたびに動かす）」とし、R-073 の案も「秘書が `check.yml` を入れる」とする。担い手が文書どうしで食い違っていた（K-021）。
ADR-0105 の D4 は、CI の定義に段があることの確かめを YGO-070 の受け入れ確認 1 に置いた。YGO-070 は変更 20261127-c384dc で範囲の外（out_of_scope）とされた。理由は、CI の定義（`.github/` の下）がジョブで変えられないことだった。ジョブが作れないファイルの確かめをチケットの受け入れ確認に置くと、そのチケットはジョブの変更で `done` にできない。
CLAUDE.md は変えられない（変えると破棄される）ので、担い手は CLAUDE.md に合わせる。

NFR-091 と CLAUDE.md の「変えないもの」（CI の設定を変えない）は、「秘書の変更の範囲の外」とあるとおり、ジョブ（秘書の変更のジョブ）が出す変更の決まりである。秘書がプロジェクトに決まった形の `check.yml` を入れることは、ジョブの変更ではなく、CLAUDE.md の作り方の節が決める秘書の仕事である。CI の実行の環境に道具を入れるのはマスター（OQ-086 → 決定、ADR-0068）で、`check.yml` を入れることとは別。

ADR-0108 は外待ちの行のチケットを決め（D1〜D4・D6・D7）、その D5 で、G-081 を YGO-100 で追い、YGO-078 が `状態: done` になり K-021 の ADR ができるまで実装の変更を出さず、そのあとで K-021 の ADR をさらに置き換えて YGO-070 を取り下げる 2 段とした。YGO-078 を待つ理由は、ADR-0105 の D2 の時機（秘書が YGO-078 の実装の前にマスターに伝える）だけだった。この ADR の D2 は担い手を秘書にし、マスターに伝えることをなくすので、待つ理由がなくなる。ADR-0108 の D5 を変えるので、ADR-0108 も置き換える。この変更の指示（秘書）は新しい ADR を 1 件とするので、ADR-0108 の残りの決定もこの ADR に引き継ぐ。

## 決定

### CI の定義の担い手と確かめの置き場

- **D1 CI は `prepare.sh` → `check.sh` の順に動かす**（ADR-0105 の D1 のまま）: CI の定義は、レポジトリを取り出したあと `sh scripts/prepare.sh` を動かし、そのあと `sh scripts/check.sh` を動かす。M1 のテストは Vitest と npm の依存（ADR-0009）で書き、依存なしの形にはしない。
- **D2 CI の定義の担い手は秘書**: CI の定義は、秘書の CI の決まった形 `.github/workflows/check.yml` が持ち、秘書が入れる（CLAUDE.md の作り方の節）。ジョブは `.github/` を書かない・変えない（CLAUDE.md・NFR-091。NFR-091 はジョブの変更の決まりで、秘書が決まった形を入れることを止めない）。マスターに段を足すよう頼むことはしない。新しい OQ・要回答は立てない。
  決まった形が `sh scripts/prepare.sh` の段を `sh scripts/check.sh` の前に置くことは `[assumed]`（CLAUDE.md は決まった形が `scripts/check.sh` を push のたびに動かすことだけを書く）。決まった形にその段がないと、`check.sh` は `node_modules/` がないとして失敗し（D3）、CI は緑にならず、M1 の達成（CI が緑）を止める。そのときは、決まった形に段を足すことを秘書に伝える（`.ai/gaps.md` の G-079 と準備書 `.ai/deploy/readiness.md` に書く。担い手が秘書なので、マスターへの要回答にはしない）。
- **D3 `check.sh` は依存を取り込まない**（ADR-0105 の D3 のまま）: `scripts/check.sh` は `prepare.sh` も `npm ci` も呼ばない。`node_modules/` がなければ、`sh scripts/prepare.sh` を先に動かすよう出して失敗する（`environment.md` §4.1 の 6。飛ばさない）。
- **D4 CI の定義の確かめは待つチケットの受け入れ確認に置かない**: `check.yml` に `sh scripts/prepare.sh` の行が `sh scripts/check.sh` の行より前にあることは、ジョブが作れないファイルの事実なので、どのチケットの受け入れ確認にも入れない。`.ai/gaps.md` の G-079 は D6 の行（外の作業を待ち、あとにジョブが作るものがある行）とし、題に G-079 を付けたチケット YGO-101 で追う。YGO-101 は秘書が `check.yml` を入れるのを待ち（入るまで実装の変更は出さない）、そのあとで `check.yml` を読み、確かめた事実を G-079 の行に記録し、段がないことを前提にした `environment.md` §5・準備書 `.ai/deploy/readiness.md`・`roadmap.md` の文を今の状態に書き直す。受け入れ確認はその記録と書き直しだけを見る。CI が緑かは M1 の達成の確認で見る。
- **D5 YGO-070 を取り下げる**: YGO-070 は題と範囲が CI の定義に段を置くこと（ジョブが書けない `.github/` の変更）で、受け入れ確認 1 が CI の定義の事実を見るので、D4 によりジョブの変更で `done` にできない。G-079 のあとの記録と書き直しは YGO-101 が受け持つ（D4）。YGO-070 は `.ai/gaps.md` の冒頭に書いた取り下げの形 `[assumed]` で取り下げる。

### 外待ちの行のチケット（ADR-0108 の D1〜D7）

- **D6 あとにジョブが作るものがあれば、外待ちの行でもチケットを切る**（ADR-0108 の D1 のまま）: gaps の行が外の作業（マスターや秘書の作業）を待っていても、それが済んだあとにジョブが作るもの（確かめた事実の記録、文書の今の状態の書き直し、ADR の置き換え、コード）があれば、冒頭の例外に当たらない。その行には、題に G-NNN を 1 つ付けたチケットを切る。チケットの依存の節には、待つ外の作業と「それが済むまで実装の変更は出さない」ことを書く。
- **D7 例外は、ジョブが作るものが何もない行に限る**（ADR-0108 の D2 のまま）: チケットを切らずに gaps の表と準備書で追うのは、外の作業が済めば閉じる条件の事実がそろい、ジョブが何も作らない行だけとする。そのような行は、閉じる条件の事実がそろったら閉じる。
- **D8 すでにあるチケットが行の仕事を受け持つなら、そのチケットの題に G-NNN を足す**（ADR-0108 の D3 のまま）: 行のジョブが作るものが、すでにある open のチケットの範囲と同じか、その範囲に寄せられるなら、新しいチケットを切らず、そのチケットの題に G-NNN を 1 つ足し、範囲と受け入れ確認に行の仕事と行を閉じることを足す。1 つのチケットの題に置く G-NNN は 1 つまでとする。
- **D9 G-080 は YGO-088 で追う**（ADR-0108 の D4 のまま）。
- **D10 G-081 は YGO-100 で追い、YGO-078 を待たない**: YGO-100 は、K-021 の決定（D1〜D4）と YGO-070 の取り下げ（D5）とそれを指す文書の直しを同じ変更で行い、G-079 の閉じる条件を D4 の事実にし、G-079 を YGO-101 に渡す。YGO-078 が `状態: done` になるのを待たない（背景）。
- **D11 G-082 は YGO-078 で追う**（ADR-0108 の D6 のまま、D8）: YGO-078 の題に G-082 を足し、範囲に R-074 の書き直しと G-082 の行を閉じることを足す。閉じる条件は G-082 の行のまま（G-080 が閉じ、YGO-078 が `状態: done`）。
- **D12 G-083 は YGO-072 で追う**（ADR-0108 の D7 のまま、D8）: YGO-072 の題に G-083 を足し、範囲に、`check.sh` の t062・t078・t072 の段を名前に依らない 1 つの段（テスト・コード・道具のどれかがあるなら、`package.json`・`package-lock.json`・`scripts/prepare.sh`・`vitest.config.ts`・`src/app.ts`・TC-033 のテストがすべてあり、Vitest の段のあとで `test-results/junit.xml` がある）にまとめることを足す。YGO-072 の依存（YGO-078 と同じ変更か、そのあと）は変えない。

## 理由

- CLAUDE.md は秘書とマスターのもので、ジョブは変えられない。食い違う ADR のほうを CLAUDE.md に合わせれば、文書どうしが一致する（D2）。
- 依存の取り込みを `prepare.sh` の 1 か所に置けば、CI でネットワークを使う段がそこだけになり、`check.sh` はネットワークなしのまま（NFR-063・CLAUDE.md）（D1・D3）。
- `check.sh` が `node_modules/` のないときに失敗すれば、`check.yml` に `prepare.sh` の段がないことが CI の結果ですぐに分かる。決まった形に段がないと分かったときに伝える先が秘書だと決めておけば、`[assumed]` が外れても止まる M（M1）と動く人が文書から読める（D2・D3・D4）。
- ジョブが作れないファイルの確かめをチケットの受け入れ確認に置くと、そのチケットは done にできず、範囲の外として何度も戻る（20261127-c384dc）。一方、秘書が `check.yml` を入れたあとも、G-079 の行に確かめた事実を書き、段がないことを前提にした `environment.md` §5・準備書を今の状態に書き直す仕事がジョブに残るので、G-079 は D7 ではなく D6 に当たる。受け入れ確認を記録と書き直しだけにすれば、待つチケットはジョブの変更で done にでき、M1 に向かう gaps の行がすべてチケットで追われる（D4・D5）。
- チケットは、ジョブが作るものを追うためのものである。外の作業を待つあいだも、あとで作るものがあるなら、チケットの依存の節で待ちを示せる（D6）。ジョブが作るもののない行をチケットにすると、待つだけの記録になり、秘書の決まりに反する（D7）。
- 同じ仕事を 2 つのチケットで追うと、範囲と受け入れ確認が食い違い、どちらを done にするかが決まらない。G-082 の仕事は YGO-078 の出し直しそのもので、G-083 の仕事は YGO-072 が触る `check.sh` の同じ段の並びにある。すでにあるチケットに寄せれば、点検が閉じ、範囲が 1 か所にまとまる（D8・D11・D12）。
- G-081 の仕事（ADR の置き換えと YGO-070 の取り下げ）は、YGO-078 の変更（`package.json` を入れる道具の追加）と分ける（秘書の決まり「道具の追加・ADR の置き換えを 1 つのチケットに入れない」）。待つ理由がなくなったので、K-021 と同じ変更で済ませる（D10）。

## 代わりの案（選ばなかった理由）

- **`scripts/check.sh` が `node_modules/` のないときに `prepare.sh` を呼ぶ（K-021 の案 (ii)）**: `check.sh` がネットワークを使うことになり、CLAUDE.md（`sh scripts/check.sh` はネットワークなしで通ること）・`environment.md` §5・NFR-063 に反する（ADR-0105 と同じ理由）。
- **段を足すのはマスターのままにする（ADR-0105 の D2）**: CLAUDE.md（`check.yml` は秘書の決まった形）と食い違ったままになる。
- **K-021 の ADR と G-081 の ADR を 2 件に分ける（ADR-0108 の D5 の予定）**: 待つ理由（ADR-0105 の D2 の時機）がこの決定でなくなり、同じ論点の ADR が 2 件続くだけになる。
- **ADR-0108 を置き換えず、採用のまま残す**: ADR-0108 の D5（YGO-078 を待つ）とこの ADR の D10 が食い違ったまま、どちらも採用になる。
- **YGO-070 を open のまま残し、秘書が `check.yml` を入れたあとに閉じる**: YGO-070 の題・範囲（CI の定義に段を置く）と受け入れ確認 1（CI の定義の事実）はジョブが作れないファイルを指し、ジョブの変更で done にできないまま残る。題と範囲を `.ai/` の記録と書き直しに限った YGO-101 に分ける。
- **G-079 を D7 の行にしてチケットを切らない**: `check.yml` が入ったあとに、G-079 の記録と `environment.md` §5・準備書の書き直しがジョブに残るので、D6 に当たる。チケットがないと M1 に向かう行が点検で ✗ になり、あとの仕事を追う場所もない。
- **G-082 を G-080 にまとめ、YGO-088 で追う（仕分け 16 の案 (b)）**: チケットの題に G-NNN を 1 つしか置けないので、G-082 の行が点検で ✗ のまま残る（ADR-0108 と同じ理由）。
- **外待ちの行の理由の列の頭に `外待ち:` の句を付け、チケットを切らない（仕分け 16 の案 (c)）**: 句で区別する点検は秘書の固定コードの変更が入るまで効かず、待ったあとにジョブが作るものを追う場所がない（ADR-0108 と同じ理由）。
