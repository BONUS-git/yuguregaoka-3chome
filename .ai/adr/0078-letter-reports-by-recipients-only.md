# 0078 — 手紙の通報は受取人だけ、確かめは条件付きで 1 通

- 状態: 採用
- 日付: 2026-11-22

ADR-0036 を丸ごと置き換える。ADR-0036 の決定（方針・通報された手紙の確かめ・住民を守る制限を外せる設定にしないこと・止める内容と年齢の扱い・違法な物の取引・要求の区分）は、今の状態に書き直してこの ADR の D1〜D7 に移した。
新しく決めたのは、手紙を通報できる人と、通報が指すもの（D8〜D10）。`reviews/0001-design-review.md` の R-004 による。

## 背景

OQ-003 の答え（ADR-0072）で、クローズドな手紙も審査し、本文は LLM に渡さず、ルール表だけで照合すると決まった。
OQ-043 では、(1) 手紙で止める内容、(2) 止めた手紙をモデレーターが見てよいか、(3) 住民が通報した手紙をモデレーターが本文を読んで確かめてよいか、をマスターに聞いた。

2026-11-19、マスターが OQ-043 に次のとおり答えた（原文）。

> 難しいね。方針としては、老若男女、少年少女が使える世界一オープンで安全なSNSにしたい。そのコンセプトであれば、むしろ厳しい閲覧はプラスに働くと思った。が、ある程度の秘匿性は担保しないと、利用者側としては気持ち悪よね。ユーザーの年齢や設定によって変える？設定を自分で変えてしまえる点は困るけど、逆に年齢設定正確にやれば、自動的にできることが限定されて、老人なら詐欺の防止、若者の子らは事件に巻き込まれないようにできる。別チケットにしてほしいけど、大麻や違法なものの取引場所にならないかは心配。その点も考慮したい

(1)(2) と年齢で変える案は、OQ-052・OQ-063・OQ-064 の答えで決まった（ADR-0069・ADR-0041・ADR-0057・ADR-0093）。

通報された手紙を確かめる条件は、モデレーターの側（通報が `open`・当事者でない・二要素認証済み）にしかなかった。通報する側には条件がなく、`reports.content_id` に手紙の ID を入れれば誰でも通報できた。
送った人は投函の応答で手紙の `{id}` を受け取る（`api.md` §2.4 F-04・§7 F-04）。そのため、送った人が自分の `blocked`・`pending`・`held` の手紙を通報すれば、
モデレーターがその本文を復号して読む経路ができる。これは、`blocked` を見る経路を作らないこと（ADR-0069 の D5）と、本文に触れる場面を限ること（NFR-005、`security.md` §2.3）に反する（R-004）。

## 決定

1. **D1 方針**（マスターの答え）: 老若男女・少年少女が使える、開かれていて安全な街を目指す。
   守りの仕組み（審査・通報・ブロック・送信の上限など）を決めるときは、この方針を理由に使う。
   この方針だけを理由に、新しい制限や閲覧の場面を足さない。
2. **D2 通報された手紙**（マスターの答えの「厳しい閲覧はプラスに働く」と「ある程度の秘匿性は担保しないと」より。`[inferred]`）:
   住民が通報した手紙は、モデレーターが本文を確かめてよい（ADR-0072 の D4 (c)）。
   - 通報が `open`・対象が手紙・モデレーターがその手紙の当事者（送った人・受け取った人・通報した人）でない・
     セッションが二要素認証を済ませている（ADR-0020）。1 回の操作で返すのは 1 通だけ（`GET /api/v1/admin/reports/{id}/letter`、`api.md` §7 F-08）。
   - 毎回 `moderation_actions` に `action = 'view_letter'` の行を書く。行を書けなければ本文を返さない（同じトランザクション）。
   - 応答には `Cache-Control: no-store` を付ける。条件に合わないときは 404 を返す（ADR-0014。存在を明かさない）。
   - 本文の一覧・検索の経路は作らない。通報されていない手紙をモデレーターが見る経路は、送った人が確認を頼んだ `held` の手紙だけ（ADR-0069 の D5）。
   - 通報の行ができるのは D8 の条件を満たす手紙だけなので、確かめられるのは受取人に届いた `delivered` の手紙だけになる。
3. **D3 住民を守る制限は、住民が自分で外せる設定にしない**（マスターの答えの「設定を自分で変えてしまえる点は困る」より。`[inferred]`）:
   住民を守るために置く制限（手紙と掲示板の審査・送信の上限・街の外の連絡先を渡させないこと など）は、
   住民が自分で外したり緩めたりできる設定にしない。
   ブロック（住民が自分で掛ける守り）を掛ける・外すのは住民が行う。
4. **D4 止める内容と止めた手紙の閲覧**: ADR-0069 で決まっている。手紙に当てる項目はスパム・外部リンク・成人向けの言葉・本当の情報で、送るときに照合する。
   `review` の段に当たって送った人が確認を頼んだ手紙（`held`）だけをモデレーターが D2 と同じ条件で確かめる。`blocked` の手紙を見る経路は作らない。
5. **D5 年齢で守りを変えない**: 年齢による違いは作らず、詐欺と事件の防止は全員に同じ共通のルールで行う（ADR-0057）。
   年齢と誕生日は登録で必須で、あとから変えられない（ADR-0093）。年齢で守りが変わらないので、D3 とはぶつからない。
6. **D6 違法な物の取引は別のチケット**（マスターの指示）: 街が違法な物（大麻など）の取引の場にならないための守りは、OQ-053（持ち越し）として記録し、
   別のチケットで設計する。この ADR では設計しない。
7. **D7 要求の区分**: ADR-0024 の決定 5 に従い、NFR-005 の (c) は `[inferred]`（マスターの答え OQ-043（2026-11-19）より）とし、根拠にこの ADR を書く。
8. **D8 手紙を通報できるのは、その手紙を受け取った住民だけ** `[assumed]`:
   `POST /api/v1/reports` の手紙の通報は、通報する住民の郵便受けの行が次のすべてを満たすときだけ `reports` に行を作る。
   - (a) 行が通報する住民のもの（`mailbox_items.resident_id` が呼んだ住民）
   - (b) 行が手紙（`kind = 'letter'`）で、見せ始めている（`visible_at <= now()`）、受取人が削除していない（`deleted_at IS NULL`）
   - (c) 行が指す手紙が `delivered`

   送った人は、自分の手紙の受取人でない限り通報できない（自分宛ての郵便受けの行がない）。転送された手紙は、実際に届いた住民の郵便受けの行で通報する。
9. **D9 手紙の通報は郵便受けの行の ID で指す** `[assumed]`:
   手紙の通報の要求は `mailbox_item_id` を受け取り、手紙の ID（`letter_id`）は受け取らない（受け取れば 400 `validation_failed`）。
   掲示板の投稿の通報は今のまま `board_post_id` で指す。`mailbox_item_id` と `board_post_id` の両方・どちらもなしは 400 `validation_failed`。
   `reports.content_id` には、API が郵便受けの行から引いた `letters.id` を書く（`content_kind = 'letter'`）。郵便受けの行の ID は保存しない。
   通報した人は `reports.reporter_id` に残り、D2 の当事者の判定に使う。
10. **D10 条件に合わない手紙の通報は、同じ 202 で何も保存しない** `[assumed]`:
    D8 を満たさない `mailbox_item_id`（ほかの住民の行・見せる前の行・削除した行・新聞や掲示板の行・存在しない ID）には、
    条件を満たすときと同じ 202 と同じ本文を返し、`reports` に行を作らない。ADR-0014 の 404 の例外で、通報した人に処理状態を返さない今の形（`api.md` §7 F-08）に合わせる。
    理由の絵文字（400）と `reject` の段（422 `content_rejected`、ADR-0070）の確かめは、行の確かめより前に行う。

## 理由

- D1 はマスターの答え（上の原文）の「方針としては」による。
- D2 は、答えが「厳しい閲覧はプラス」と「ある程度の秘匿性は担保」の両方を求めていることによる。通報された手紙だけを、
  当事者でないモデレーターが二要素認証のあとに 1 通ずつ確かめ、毎回記録を残す条件は、その両方を満たす。モデレーターの内部不正（`security.md` T-12）も抑える。
- D3 は、答えが「設定を自分で変えてしまえる点は困る」と書いていることによる。
- D4・D5 は、OQ-052・OQ-063・OQ-064 の答え（ADR-0069・ADR-0057・ADR-0093）による。
- D6 はマスターの指示（別チケット）による。
- D8 は、通報が「受け取った手紙が困るものだった」ことを知らせる仕組みだからである。受け取っていない住民（送った人・ほかの住民）に通報を許すと、
  届いていない手紙（`pending`・`held`・`blocked`）や他人の手紙をモデレーターに読ませる経路になり、NFR-005 と ADR-0069 の D5 が崩れる。
  見せる前（`visible_at` の前）の行は受取人もまだ読めないので、通報の対象にしない。削除した行は、受取人が手紙を手放したもので、ADR-0077 の D3 で消える手紙を通報で残す経路にもなるので対象にしない。
- D9 は、送った人が受け取る手紙の ID では通報できなくするため。郵便受けの行の ID は、受取人の `GET /api/v1/mailbox` でだけ返る。
  `content_id` に手紙の ID を書くのは、ADR-0077 の D4（`reports` の行がある手紙は消さない）と D2 の取得がそのまま使えるようにするため。
- D10 は、ほかの住民の郵便受けの行の ID を試して存在や状態を探れないようにするため（ADR-0014）。通報はもともと処理状態を返さないので、同じ 202 でも通報した人ができることは変わらない。

## 代わりの案（選ばなかった理由）

- **手紙の ID のまま、通報する人が受取人かを API で確かめる**: 条件は同じにできるが、送った人の持つ ID で要求でき、受取人かどうかで応答を分けると送った人に宛先の手がかりを与える。郵便受けの行の ID なら送った人は要求を組めない。
- **条件に合わなければ 404 を返す**: ほかの住民の郵便受けの行の ID があるかを探れる。通報は処理状態を返さないので、202 にそろえても困らない。
- **通報された手紙も読ませない**: 答えの「厳しい閲覧はプラスに働く」と食い違う。
- **削除した手紙も通報できる**: 受取人が手放した手紙を通報で残せると、ADR-0077 の D3 の削除を止める経路になる。削除する前に通報すればよい。

## 決めていないこと

- 違法な物の取引の場にしないための守り: OQ-053（持ち越し、別のチケット）。
- 違反した住民への処置: OQ-048（持ち越し、ADR-0032）。
- 照合の細部・長く確かめられない `held` の扱い: OQ-065（持ち越し）。不審な挙動への対処: OQ-075（持ち越し）。
- 適用法令が手紙の閲覧と未成年の扱いについて何を求めるか: OQ-032（持ち越し）。
- 通報の流量の制限: この ADR では決めない（`security.md` §3.5）。
