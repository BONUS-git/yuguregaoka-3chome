# 0035 — 新聞は全住民に定時に届け、通知も送る。手紙は午前・午後のランダムな時刻に届け、通知を新聞と手紙で分ける

- 状態: 採用（D13 の新聞の中身は OQ-051 → 決定（2026-11-20、ADR-0039）。残りは OQ-058〜OQ-062（OQ-058 はのちに決定、2026-11-20、ADR-0044）。OQ-058 はのちに決定、2026-11-20、ADR-0044）
- 日付: 2026-11-19

## 背景

OQ-002 の答え（2026-11-19、ADR-0025）で、配達のあとに住民へ通知を送り、郵便の件数を含めると決まった。
何を「郵便」として数えるか（手紙だけか、新聞も数えるか）・手紙が 0 通の住民にも送るか・件数のほかに何を載せるかは
答えに書かれておらず、`open-questions.md` の OQ-042 でマスターに聞いていた。
暫定は「(1) 手紙だけを数える (2) 0 通の住民には送らない (3) 中身は便（朝便・夕便）と件数だけ」だった。

2026-11-19、マスターが OQ-042 に次のとおり答えた（原文）。

> 何も届かないのは悲しいね。何かしら送りたい。例えば、興味があることを回収して、ニュースを加工して新聞にする。とか。新聞も知り合いの数がいないと成り立たない可能性がある。何かしら新聞を送る方向で考え、通知についても送る。手紙の配達と新聞の配達は時間を分ける。手紙については、出した時間に応じて午前、午後にランダム、新聞は一定の時間。新聞が配達されました！手紙が配達されました！（３通）みたいな形かな。

答えは通知の数え方だけでなく、配達の形も変える。今までの ADR-0004・0007・0014・0016・0017・0025 は
「手紙と新聞を 07:00 / 17:00 の公開で一斉に届ける」を前提にしていたので、この ADR で該当する箇所を置き換える。

## 決定

### 答えで決まること（マスターの答え）

1. **D1 新聞は全住民に届け、通知も送る**: 新聞（朝刊・夕刊）は、その便に手紙があるかにかかわらず全住民の郵便受けに届ける。
   新聞が届いたことも通知する（購読のある端末に）。
2. **D2 新聞は決まった時刻に届ける**: 新聞の配達は今までの定時（朝刊 07:00・夕刊 17:00 JST、ADR-0004）のままにする。
   手紙は新聞と時刻を分けて届ける（D3）。
3. **D3 手紙は出した時刻に応じて午前か午後に、ランダムな時刻で届く**: 午前・午後の振り分けは、今の締め切り（ADR-0004）で決める。
   朝便の締め切り 01:00 までに出した手紙（前日 14:00〜当日 01:00）は午前に、夕便の締め切り 14:00 までに出した手紙（01:00〜14:00）は午後に届く。
   時間帯の中の時刻はランダムにする（D8・D9）。
4. **D4 通知の文面は 2 つに分ける**:
   - 新聞: 「新聞が配達されました！」（件数なし）
   - 手紙: 「手紙が配達されました！（N通）」（N はその回にその住民に届いた手紙の数）
   どちらにも差出人・本文・住所は載せない。

### 答えから読み取ること

5. **D5 手紙が 0 通の住民には手紙の通知を送らない** [inferred]: 答えの例の文面は件数のある手紙の通知だけなので、0 通の「手紙が配達されました！（0通）」は送らない。
   新聞の通知は休刊の回を含めて全住民に届くので（D11）、0 通の住民にも「何も届かない」にはならない（答えの「何も届かないのは悲しい」に合う）。
6. **D6 ランダムの単位は配達回ごと・住民ごとに 1 つの時刻** [inferred]: 答えの例の「（３通）」から、同じ回の手紙はまとめて 1 度に届き、
   通知も 1 回にまとめると読む。手紙ごとに別の時刻にはしない。
7. **D7 P-1 は保つ** [inferred]: 手紙は今までどおり締め切りでまとめ、1 日 2 回の配達回（朝便・夕便）で届ける。
   届く時刻が時間帯の中でランダムなだけで、出してすぐには届かない。構想の「朝・夕の定時配達」は、1 日 2 回の配達回と新聞の定時として保つ、と解釈する。

### 秘書が技術と設計で決めること

8. **D8 時間帯** [assumed]: 午前の手紙は 08:00〜11:50、午後の手紙は 18:00〜20:50（JST、10 分刻みの枠の始まりの時刻）。
   新聞（07:00 / 17:00）より後にし、公開の打ち切り（07:15 / 17:15、ADR-0016）より後にする。時間帯の終わりは 12:00 / 21:00。
9. **D9 時刻の決め方** [assumed]: 10 分刻みの枠にする（午前 24 枠・午後 18 枠）。住民の枠は
   `SHA-256(run_id + ":" + resident_id)` を整数として枠の数で割った余りで決める（`resident_id` は内部の UUID で、外に出さない）。
   決定的なので、J4 をやり直しても同じ枠になる。乱数の状態を DB に持たない。
10. **D10 見える時刻**:
    - J4 が `mailbox_items.visible_at` を書く。新聞はその便の定時（07:00 / 17:00）、手紙は D9 の枠の時刻。
    - J5 の公開と状態の確定（`delivery_runs.status = 'done'`・手紙の `delivered` など、ADR-0017）は今のまま 07:00 / 17:00 に行う。
    - API は、配達回が `done` で、かつ `visible_at` を過ぎた項目だけを返す（郵便受けの一覧・詳細）。`visible_at` の前の項目は 404。
    - 送った人には、宛先の時刻を過ぎるまで「投函済み」と見せる。宛先ごとの時刻を送った人に明かさないよう、
      送信済みの一覧で「配達済み」に変えるのは、その回の手紙の時間帯の終わり（12:00 / 21:00）を過ぎてからにする。
    - 住民ごとの時刻（`visible_at`）は API で返さない。配達の時刻表 API は時間帯（08:00〜12:00 / 18:00〜21:00）だけを返す。
11. **D11 通知の送り方**: J15 `notify.delivery` の入力を `{run_id, kind, slot}` にする（`kind` は `newspaper` / `letter`）。
    - 新聞の通知: J5 が公開と同じトランザクションで積む（`slot` なし）。休刊の回（`newspapers.is_holiday = true`）にも積む [inferred]。
      休刊の回でも、J4 は全住民の郵便受けに新聞の項目（休刊の印）を届けるので、新聞の配達はある。文面は答えのまま（「新聞が配達されました！」）で、休刊の回だけ変えることはしない。
      `skipped` の便では J5 が動かず、郵便受けに何も届かないので送らない。
    - 手紙の通知: 公開済み（`done`）の配達回について、J0 が枠の時刻を過ぎた枠ごとに積む（`slot` は枠の始まりの時刻）。
      送る相手は、その枠に手紙の `mailbox_items` がある住民だけ。
    - 期限: 新聞は公開（`delivery_runs.finished_at`）から、手紙は枠の時刻から、それぞれ 30 分を過ぎたら送らない（Web Push の TTL も 30 分。ADR-0025 の D2 のまま）。
12. **D12 送った記録**: `delivery_notifications` に `kind`（`newspaper` / `letter`）を足し、
    UNIQUE を `(delivery_run_id, push_subscription_id, kind)` にする。1 回の配達回で、1 つの購読に新聞と手紙の通知が 1 通ずつまで。

### 決めないこと

13. **D13 新聞の中身（知り合いが少なくても成り立つ紙面）は OQ-051（要回答。のちに決定、ADR-0039）**: 答えの「興味があることを回収して、ニュースを加工して新聞にする」は例で、決定ではない。
    紙面を住民ごとに変えるか・住民の興味を集めるか・ニュースの出どころ（街の中だけか、実在の外のニュースか）・加工に LLM を使うかは、
    構想の意図・個人情報・著作権・費用にかかわるのでマスターに聞く。
    → 決定（2026-11-20、ADR-0039）。紙面は一人 1 枚にせず組ごとの版にし、知り合い 0 の組は興味で分け、ニュースは街の中と外から取り、記事の文字は LLM が作り、組版はサーバーで決定的に行う。残りは OQ-058〜OQ-062（OQ-058 はのちに決定、2026-11-20、ADR-0044）。

## 理由

- D1〜D4 は、マスターの答え（上の原文）による。構想の意図はマスターにしか決められない。
- D5 は、答えの例が件数のある手紙の通知だけで、新聞の通知で「何も届かない」を避けられるため。0 通の通知を足すと、知らせの数が増えるだけになる。
- D6 は、答えの例「（３通）」が複数の手紙をまとめた通知なので。手紙ごとに時刻を分けると通知が手紙の数だけ増え、P-1 から離れる。
- D7 は、手紙の締め切りと 1 日 2 回の配達回を変えないので、即時性は持ち込まないため。
- D8 は、新聞の定時と公開の打ち切りより後にして、新聞と手紙の時刻をはっきり分けるため。時間帯の長さは仮置きで、体験を見て変えられる。
- D9 は、冪等性（FR-025）を保つため。乱数を使うと J4 のやり直しで時刻が変わる。ハッシュなら同じ入力から同じ枠になり、状態を持たずに済む。
  枠の時刻を 10 分刻みにすると、J0（5 分ごと）が拾える。
- D10 は、ADR-0017 の「途中まで出さない」を保つため。公開（状態の確定）は今のまま 1 つのトランザクションで行い、見える時刻だけを行ごとにずらす。
  送った人に宛先の時刻を見せないのは、相手がいつ郵便受けに手紙を受け取ったかを送った人に知らせないため（即時性を持ち込まない、FR-017 と同じ考え）。
- D11 は、新聞の通知は公開と同じ時刻、手紙の通知は枠の時刻に送る必要があり、枠の時刻の関門は J0 が持つのが今の設計（ADR-0016）に合うため。
  休刊の回にも新聞の通知を送るのは、答えの「何も届かないのは悲しい…通知についても送る」に合わせ、D5（新聞の通知は全住民に届く）を休刊の回にも成り立たせるため。
  休刊の回に送らないと、その回に手紙が 0 通の住民は通知を 1 つも受け取らない。M3 は紙面が必ず休刊（ADR-0022）なので、M5 まで新聞の通知が 1 通も流れず、通知の経路を確かめられない。
  郵便受けには休刊の印が新聞の項目として届くので、「新聞が配達されました！」は事実と食い違わない。
- D12 は、新聞と手紙の通知を同じ配達回で別々に送るので、今の UNIQUE では 2 通目が弾かれるため。

## 代わりの案（選ばなかった理由）

- **新聞も郵便として件数に数え、通知を 1 回にまとめる**: 答え（新聞と手紙の配達の時間を分け、文面も分ける）と食い違う。
- **0 通の住民にも手紙の通知を送る**: 答えの例にない。新聞の通知で「何も届かない」は避けられる。
- **手紙ごとにランダムな時刻にする**: 答えの例「（３通）」と合わず、通知が増える。
- **手紙の時刻を J4 で乱数で決めて DB に持つ**: やり直しで時刻が変わるおそれがあり、冪等性の確かめが難しい。
- **手紙の枠ごとに配達回を分け、枠ごとに公開する**: 1 回の配達回が何十にも分かれ、締め切り・審査・持ち越し（ADR-0016・0017）の仕組みを作り直すことになる。
- **休刊の回は新聞の通知を送らない**: その回に手紙が 0 通の住民は何も知らされず、答えの「何も届かないのは悲しい」と食い違う。M3 では新聞の通知が 1 通も流れない。
- **新聞の中身（興味の収集・外のニュース・LLM での加工）をここで決める**: 答えでは例にとどまり、構想の意図・個人情報・著作権・費用にかかわる。OQ-051 にした。

## 決めていないこと

- 新聞の中身（知り合いが少なくても成り立つ紙面）: OQ-051 → 決定（2026-11-20、ADR-0039）。残りは OQ-058〜OQ-062（OQ-058 はのちに決定、2026-11-20、ADR-0044）。
- 時間帯の長さと枠の刻み（D8・D9）は仮置き [assumed]。実装と体験を見て変えるときは、この ADR を直す。
