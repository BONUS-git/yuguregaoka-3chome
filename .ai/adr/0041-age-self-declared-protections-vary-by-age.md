# 0041 — 年齢で守り方を変える。年齢は住民が設定した値をそのまま使い、確かめない。何を変えるかが決まるまで、年齢による違いと年齢の項目は作らない

- 状態: 採用
- 日付: 2026-11-20

## 背景

OQ-004 の答え（「年齢制限なし・特別な制限なし」、2026-11-19）で、未成年の利用を認め、年齢確認・保護者の同意・生年月日と年齢の収集を設けないと決めた（ADR-0027）。
OQ-043 の答え（2026-11-19）で、マスターが「ユーザーの年齢や設定によって変える？」と問い返し、年齢を正確に知れば、できることを自動で限って
高齢の住民を詐欺から、若い住民を事件から守れる、と書いた（ADR-0036）。この問い返しは ADR-0027 と食い違うので、`open-questions.md` の OQ-052 の (3) で、
年齢で守り方を変えるか・年齢をどう確かめるか・年齢の区切りを聞いていた。暫定は、年齢で変えない・生年月日と年齢は集めない、だった。

2026-11-20、マスターが OQ-052 に答えた（原文は ADR-0040 の背景）。この ADR は、答えの冒頭の段落と (3) を扱う。

> 20以上でも危険な機能は設けない想定なので、年齢はユーザーの入力信用すればいいと思う。理由としては、高齢者が若く設定や、若い人が高齢者として設定など、完全に架空の自分になることも許容したいから。設定と別々で持つ必要はなく、設定した年齢がそのままこの世界に反映される。
>
> ３：変える。

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと（新しい OQ） |
|---|---|---|
| 冒頭 | 年齢は住民の入力をそのまま信じ、確かめない。架空の年齢も許す。設定した年齢と別に「本当の年齢」を持たない。20 歳以上にも危険な機能は設けない | 登録のときに必須か・あとから変えられるか・ほかの住民に見せるか・年とともに進むか → OQ-064（要回答。のちに決定、2026-11-20、ADR-0048） |
| 3 | 年齢で守り方を変える | 何を変えるか（止める項目・使える機能）・年齢の区切り → OQ-063（要回答） |

答えの 3 は、ADR-0027 の D2（特別な制限を置かない）と D3（生年月日・年齢を集めない）を置き換える。D1（登録に年齢制限を置かない）は答えに書かれておらず、変えない。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 年齢で守り方を変える**（答え 3、`[inferred]`。ADR-0047 で置き換え。OQ-063 → 決定、2026-11-20: 年齢による違いは作らない）: 住民の年齢で守り方を変える。ADR-0027 の D2 のうち「特別な制限を置かない」を置き換える。
   - 何を変えるか（手紙と掲示板で止める項目・使える機能・マッチング（F-18）への参加）と年齢の区切りは、答えに書かれていない。OQ-063（要回答）で聞く。
   - **答えが出るまで、年齢による違いは作らない**。すべての住民に同じ守り（審査・ブロック・送信の上限など）が効く。
2. **D2 年齢は住民の設定をそのまま使う**（答えの冒頭、`[inferred]`）:
   - 年齢は住民が設定した値をそのまま使い、確かめない。本人確認の書類・外部の年齢確認・保護者の同意は設けない（ADR-0027 の D2 のこの部分は変わらない）。
   - 架空の年齢（高齢の人が若く、若い人が高齢として設定するなど）を許す。
   - 設定した年齢が、そのままこの世界での年齢になる。設定とは別の「本当の年齢」は持たず、推し量ることもしない。
3. **D3 危険な機能は設けない**（答えの冒頭「20以上でも危険な機能は設けない想定」、`[inferred]`）: どの年齢の住民にも、危険な機能を設けない。
   年齢で変えるのは守り方で、年齢を偽っても危険な機能には届かない。年齢を確かめないで済むのは、このため（答えの「なので」）。
4. **D4 集めるのは年齢で、生年月日は集めない**（秘書の判断）: 答えは「年齢設定」「設定した年齢」と書いており、生年月日は要らない。
   生年月日は個人を特定する手がかりが年齢より強く、使い道がない（データ最小化、NFR-002・`security.md` §2.2）。
5. **D5 年齢の項目と列は、使い道が決まるまで置かない**（秘書の判断）:
   登録とプロフィールの年齢の項目と、`residents` の年齢の列は、OQ-063（何を変えるか）と OQ-064（年齢の扱い）の答えが出るまで置かない。
   使い道のない個人情報を先に集めないため（ADR-0027 の D3 と同じ考え）。答えで変わるのは、登録・プロフィールの API（`api.md` §7 F-02）・`residents` の列（`db.md` §2）・
   `security.md` §2.1・§2.2・§4.2・`roadmap.md` の M1 と A-12。
   （追記 2026-11-20）OQ-063 → 決定（ADR-0047 の D5）で、待つ条件は OQ-064 の答えだけになった。
   （追記 2026-11-20）OQ-064 → 決定（ADR-0048、いまは ADR-0073）で、この D5 は置き換えた。登録で `age` と `birthday`（月日）を必須で受け取り、あとから変えられず、
   `residents` に `age_at_registration`・`age_base_date`・`birthday_month`・`birthday_day` を置いて誕生日に進め、ほかの住民には本人から手紙を受け取った住民にだけ見せる（ADR-0073 の D1〜D5）。
6. **D6 登録に年齢制限を置かない**: ADR-0027 の D1 は変えない。未成年の利用を認める。
7. **D7 要求の区分**: FR-113 を足し、FR-094・FR-064 を直す。どれも `[inferred]`（マスターの答え OQ-052（2026-11-20）より）。

## 理由

- D1 は答え 3 の「変える」による。何を変えるかと区切りは、構想の意図と倫理（誰に何を許すか）にかかわり、マスターにしか決められない。
  CLAUDE.md の「要回答の答えを前提にした決定をしない」に従い、答えまで違いを作らない。
- D2 は答えの冒頭による。確かめないので、年齢確認の費用（NFR-080）・本人確認の書類の保持はかからない。
- D3 は、年齢を偽っても危険がないから入力を信じてよい、という答えの理由をそのまま決定にしたもの。年齢で何かを「解き放つ」形にすると、この理由が崩れる。
- D4・D5 はデータ最小化（NFR-002・NFR-010）による。年齢の項目がなければ、漏れても年齢が知られることがない。

## 代わりの案（選ばなかった理由）

- **年齢を外部の年齢確認で確かめる**: 答えの「ユーザーの入力信用すればいい」と食い違い、費用もかかる（NFR-080）。
- **生年月日を集めて年齢を計算する**: 答えは年齢を設定するものとしている。生年月日は使い道がなく、個人情報が増える。
- **設定した年齢と別に「本当の年齢」を持つ**: 答えの「設定と別々で持つ必要はなく」と食い違う。
- **年齢の項目を今すぐ登録に置く**: 使い道（OQ-063）と扱い（OQ-064）が決まる前に個人情報を集めることになる。
- **年齢の区切りと変える中身を秘書が決める**: 誰に何を許すかは構想の意図と倫理で、マスターが決める（OQ-063）。

## 決めていないこと

- 年齢で何を変えるか（止める項目・使える機能・マッチングへの参加）と、年齢の区切り: OQ-063（要回答）。答えまで、年齢による違いは作らない。
  （追記 2026-11-20）OQ-063 → 決定（ADR-0047）: 年齢による違いは作らない。手紙と掲示板で止める基準・使える機能は全員に同じで、年齢の区切りも置かない。
  詐欺と事件の防止は全員に同じ共通のルール（スパム検知・不審な挙動への対処）で行い、不審な挙動への対処の中身は OQ-075（持ち越し）。
- 年齢の扱い（登録で必須か・あとから変えられるか・ほかの住民に見せるか・年とともに進むか）: OQ-064（要回答）。答えまで、年齢の項目と列は置かない。
  あとから自由に変えられると、守りを自分で外せることになり、ADR-0036 の D3（住民を守る制限は住民が自分で外せる設定にしない）とぶつかりうる。これも OQ-064 で聞く。
  （追記 2026-11-20）年齢で守り方を変えない（ADR-0047）ので、年齢を変えても守りは外れず、このぶつかりはなくなった。
  D5 の項目と列を待つ条件は OQ-064 の答えだけになった。年齢の属性で何の表示が変わるかも OQ-064 で聞く。
  （追記 2026-11-20）OQ-064 → 決定（ADR-0048、いまは ADR-0073）: 必須・変更は不可・一定の条件（本人から受け取った手紙が郵便受けに残っている住民。見る住民がブロックしていないこと）で見せる・誕生日に進む。
  誕生日を集めて新聞に載せるかは OQ-077 → 決定（ADR-0073・ADR-0074。誕生日（月日）は必須で変えられず、知り合いの紙面にだけ載せる）、年齢の属性で何の表示が変わるかは OQ-078（持ち越し）。
- 適用法令が未成年の利用について何を求めるか: OQ-032（持ち越し）。
