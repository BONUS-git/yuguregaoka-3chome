# 0019 — セッションはサーバー側に持つ。複数デバイスを許す。重要な操作では再認証する

- 状態: 採用
- 日付: 2026-11-19

## 背景

OQ-036「複数デバイス同時アクセスへの対応」は `security.md` で OQ-028（認証方式）とあわせて
決定する持ち越し項目だった（FR-100、security.md・api.md 担当）。

セッション管理の方式として次の選択肢が考えられた。

1. **サーバー側セッション**（セッション ID を Cookie に持ち、セッションの中身は DB に置く）
2. **JWT（署名付きトークン）**（トークン自体に情報を含め、サーバーに状態を持たない）

また、パスワード変更・退去申請などの重要な操作での再認証の仕組みも未定だった。

## 決定

### セッション方式

**サーバー側セッション**を採用する。

- セッション ID を乱数で生成し、`__Host-session` Cookie に格納する。
  Cookie は `HttpOnly`・`SameSite=Lax`・`Secure` を設定する。
- セッションの中身（住民 ID・作成日時・最終操作日時・再認証日時）は DB の `sessions` テーブルに置く。
- セッションの有効期限: **操作なしで 30 日、発行から 90 日** [assumed]。

### 複数デバイス

同時に複数のデバイスでセッションを持つことを**許す**。セッション一覧を住民自身が確認し、
個別に無効化できるようにする。

### セッションの無効化

退去時・強制ログアウト時は、`sessions` テーブルの `invalidated_at` を現在時刻に設定して
そのセッションを即時無効化する（ADR-0015 §4）。
API の認証チェックは `invalidated_at IS NULL` かつ有効期限内のセッションのみを通す。

### 再認証

**条件**: 直近 10 分以内にパスワードを入力していること [assumed]。
具体的には `sessions.reauthenticated_at` が `NOW() - INTERVAL '10 minutes'` より新しいことを確認する。

**再認証が必要な操作**:
- パスワード変更
- メールアドレス変更
- 退去申請（`DELETE /me`）
- モデレーターによる重要な処置（取り下げ・利用停止の実行）

## 理由

- **サーバー側セッションを選ぶ理由**:
  JWT はサーバーが発行したトークンを途中で無効化できない（有効期限まで有効になる）。
  退去時・セッションハイジャック検知時に即時無効化が必要（ADR-0015 §4）なので、
  サーバー側に状態を持つ方式を選ぶ。
- **複数デバイスを許す理由**:
  スマートフォン・PC など複数の端末で使うユースケースは自然であり、
  1 デバイス制限にしても利便性が下がるだけで安全性が大きく向上しない。
  セッション一覧・個別無効化で代替する。
- **再認証を 10 分とする理由**:
  短すぎると操作のたびにパスワードを入力させることになり体験が悪い。
  長すぎると放置した端末での不正操作を招く。10 分は標準的な値 [assumed]。

## 代わりの案（選ばなかった理由）

**JWT（ステートレストークン）**: サーバー側で即時無効化できない。
退去・強制ログアウトの要件（ADR-0015）に対応できない。不採用。
**1 デバイス制限（1 セッション制限）**: 複数端末の利用者の利便性を損なう。不採用。
**再認証なし**: パスワード変更・退去など高リスクの操作に追加の保護がなくなる。不採用。
**再認証の有効期間を 60 分に延ばす**: 離席中に不正操作される時間が長くなる。不採用。

## 影響

- DB 設計: `sessions` テーブルを追加する（security.md §9）。
  カラム: `session_id`・`resident_id`・`created_at`・`last_seen_at`・`expires_at`・
  `reauthenticated_at`・`invalidated_at`
- API 設計: `GET /auth/sessions`・`DELETE /auth/sessions/:id`・`POST /auth/reauth` を設ける。
- async.md: 退去処理（ADR-0015 §4）で `sessions` テーブルの無効化を最初に行うことを確認する。
- 配達完了の通知（ADR-0025）: セッションを無効にするとき（ログアウト・強制ログアウト・退去）は、
  そのセッションの購読（`push_subscriptions`）を同じトランザクションで消す。期限切れのセッションの購読は、送る前に J15 が外す。
- OQ-036: 本 ADR の決定により持ち越し → 決定に変更する。
