# 0027 — 未成年の利用を認め、年齢制限・特別な制限を置かない。生年月日・年齢は集めない

- 状態: 採用
- 日付: 2026-11-19

## 背景

`requirements.md` の FR-094 は「未成年の利用に関するポリシーは未確定」（`[assumed]`）とし、
`open-questions.md` の OQ-004 でマスターに聞いていた。質問は、未成年の利用を認めるか、
認めるなら利用制限（マッチング（F-18）への参加の制限など）や保護者の同意が要るか、
認めないなら年齢確認の方法（生年月日の入力だけか外部の確認か）だった。
暫定は「年齢制限なし・特別な制限なし」で、マッチングへの参加に年齢条件を置くかはこの OQ の答えで決めることにしていた
（恋愛のための年齢条件は OQ-001 → 決定、ADR-0024 で要らなくなっている）。

2026-11-19、マスターが OQ-004 に次のとおり答えた（原文）。

> 年齢制限なし・特別な制限なし

答えは今の暫定と同じなので、設計の中身は変わらない。記述を暫定から決定に書き換え、ここに残す。

## 決定

1. **D1 利用を認める**（マスターの答え）: 未成年の利用を認める。登録（F-02）に年齢制限を置かない。
2. **D2 特別な制限を置かない**（マスターの答え。「特別な制限を置かない」は ADR-0041 の D1 で置き換え。年齢確認・保護者の同意を設けないことは変わらない）: 未成年だけに効く機能の制限、保護者の同意の手続き、
   年齢確認（生年月日の入力も外部の確認も）は設けない。マッチング（F-18）への参加にも年齢条件を置かない（FR-064）。
3. **D3 生年月日・年齢は集めない**（年齢は ADR-0041 で置き換え。生年月日を集めないことは変わらない）: D1・D2 から、年齢を使う場面がない。登録とプロフィールに生年月日・年齢・保護者の同意の項目を設けない。
   `security.md` §2.2 の「収集しない」を確定させるもので、答えの範囲を越えない。
4. **区分**: ADR-0024 の決定 5 に従い、FR-094 は `[inferred]`（マスターの答え OQ-004（2026-11-19）より）とし、根拠にこの ADR を書く。

ブロック・通報・審査（ADR-0005・ADR-0072）と連絡先の共有の禁止（FR-101、ADR-0024）は、年齢に関係なくすべての住民に同じに効く（ADR-0041 の D1 で年齢で変えることにしたが、OQ-063 → 決定、2026-11-20、ADR-0047 で年齢による違いは作らないと決まった）。
この決定で外す守りの仕組みはない。

## 理由

- 年齢制限を置かないこと、特別な制限を置かないことは、マスターの答え（上の原文）による。
- D3 はデータ最小化（`security.md` §2.2、NFR-010）を当てはめたもの。使い道のない個人情報は集めない。
  年齢の項目がなければ、漏れても年齢が知られることがない。

## 代わりの案（選ばなかった理由）

- **マッチングだけ 18 歳以上にする**: 特別な制限にあたり、答え（特別な制限なし）と食い違う。
- **未成年に保護者の同意を求める**: 特別な制限にあたり、答えと食い違う。
- **制限はしないが、生年月日だけ入力させる**: 年齢を使う場面がなく、年齢確認の入口になる。答え（年齢制限なし）の意図とも食い違い、データ最小化にも反する。

## 決めていないこと

- 適用法令が未成年の利用について何かを求めるか: OQ-032（持ち越し）で、法令の範囲と合わせて調べる。
  デプロイしない間は要らない問いのため、新しい要回答にはしない。
  法令が制限を求めるとわかったら、この答えと食い違うので、そのとき新しい要回答としてマスターに出す。
- （追記 2026-11-19）OQ-043 の答えで、マスターが「ユーザーの年齢や設定によって変える？」と問い返し、年齢を正確に知れば、
  できることを自動で限って高齢の住民を詐欺から、若い住民を事件から守れる、と書いた（ADR-0036）。
  答えは問い返しの形で、この ADR の答え（年齢制限なし・特別な制限なし）と食い違うので、決定は変えない。
  年齢や設定で守り方を変えるかは OQ-052（要回答）で聞く。答えが出るまで D1〜D3（生年月日・年齢を集めないことを含む）は今のまま。
- （追記 2026-11-20）OQ-052 の答え（「３：変える。」と「年齢はユーザーの入力信用すればいい」）で、年齢で守り方を変えると決まった（ADR-0041）。
  - D1（登録に年齢制限を置かない）は変わらない。
  - D2 のうち、年齢確認（外部の確認も）・保護者の同意の手続きを設けないことは変わらない。年齢は住民が設定した値をそのまま使う（ADR-0041 の D2）。
    「特別な制限を置かない」は ADR-0041 の D1 で置き換えた。何を変えるかは OQ-063（要回答）で、答えまで年齢による違いは作らない。
  - D3 のうち、生年月日を集めないことは変わらない（ADR-0041 の D4）。年齢は集める方針に変わった。ただし年齢の項目と列は、OQ-063・OQ-064（要回答）の答えまで置かない（ADR-0041 の D5）。
  - マッチングへの参加に年齢条件を置かないこと（FR-064）は、OQ-063 の答えまで今のまま。
- （追記 2026-11-20）OQ-063 の答え（「暫定の通り「年齢による違いは作らない」で進めて」）で、年齢による違いは作らないと決まった（ADR-0047）。
  - 手紙と掲示板で止める基準・使える機能・マッチングへの参加の条件に年齢の条件を持たせず、年齢の区切りも置かない（ADR-0047 の D1・D2・D4）。
    ブロック・通報・審査と連絡先の共有の禁止は、年齢に関係なくすべての住民に同じに効く（決定）。
  - D2 の「特別な制限を置かない」は、ADR-0041 の D1 で置き換えていたが、ADR-0047 で実質もとに戻った（ADR-0047 の D6）。
  - 年齢の項目と列は、OQ-064（要回答）の答えまで置かない（ADR-0041 の D5。待つ条件は OQ-064 だけになった）。
- （追記 2026-11-20）OQ-064 の答え（「(1) 必須 (2) 変更は不可 (3) 一定条件で見せる (4) 進む」）で、年齢は登録で必須で集めることになった（ADR-0048）。
  - D3 の「年齢を集めない」は ADR-0048 の D7 で置き換えた。生年月日を集めないことは変わらない。誕生日を集めるかは OQ-077（要回答。暫定は集めない）。
  - 年齢は確かめず、年齢で使える機能を変えないので、D1（登録に年齢制限を置かない）と D2 の年齢確認・保護者の同意を設けないことは変わらない。
