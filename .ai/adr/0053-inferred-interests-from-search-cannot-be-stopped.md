# 0053 — 過去の新聞の検索から興味を推し量ることを、住民は止められない。止める手段を作らず、知らせて推し量ることを検索の処理に組み込む

- 状態: 採用
- 日付: 2026-11-21

## 背景

OQ-059 の答えで、興味は自分に届いた過去の新聞の検索から推し量って集め、住民には「興味から新聞を届けます！」と明るく開いた文で知らせ、個別の同意は取らず、推し量った興味を本人が見て消す仕組みは設けないと決めた（ADR-0045）。
もとの質問 (3) の 3 つ目「住民が止められるか」には答えがなかったので、`open-questions.md` の OQ-072 でマスターに次を聞いていた。
(i) 止められない（検索すると、いつも推し量る）。(ii) 設定で止められる。(iii) ほかの形（例: 検索ごとに推し量らない検索を選べる）。
暫定は、止める設定を置かない（ADR-0045 の D7）だった。

2026-11-21、マスターが OQ-072 に次のとおり答えた（原文）。

> 答えは (i) 止められない。
>
> 「本人が見て消せる仕組み」も設けない以上、個別に情報の扱いを拒否できる設定を設けるのは二重基準になるし、仕組みが複雑になる。仕組みの側が自然な振る舞いを受け止めるべきだし、余計な例外ルールを増やしたくない。
>
> 「興味から新聞を届けます！」とポジティブにオープンにすることを前提に、仕組みとして組み込んでおく。MVPには検索機能自体が含まれないから、今すぐ作る必要もない。S2-3 の設計段階で、この方針に沿った実装（検索と興味収集の連動）を整理して進めておいて。

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと |
|---|---|---|
| 「(i) 止められない」 | 検索すると、いつも推し量る。暫定（止める設定を置かない）がそのまま決定になる | — |
| 「個別に情報の扱いを拒否できる設定を設けるのは二重基準になる」「余計な例外ルールを増やしたくない」 | 止める設定も、検索ごとに推し量らない選択も、住民ごとの例外の分岐も作らない | ほかの情報（知り合いの紙面に載ること・誕生日）を本人が断れるか（OQ-070 (3)・OQ-077 (3)）。答えは検索から推し量ることについてのもので、これらの答えとは読まない |
| 「ポジティブにオープンにすることを前提に、仕組みとして組み込んでおく」 | 知らせることを前提に、照合と書き込みを検索の処理の一部にする | — |
| 「MVPには検索機能自体が含まれないから、今すぐ作る必要もない」「S2-3 の設計段階で…整理して進めておいて」 | MVP は変えない。S2-3 の設計で検索と興味の収集の連動を整理する | — |

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 止められない**（答え「(i) 止められない」、`[inferred]`（マスターの答え OQ-072 より））: 過去の新聞の検索（`GET /api/v1/newspapers?q=`、FR-119）をすると、いつも ADR-0045 の D3 の照合をし、当たれば `inferred_interests` に書く（ADR-0045 の D4）。
2. **D2 止める手段を何も作らない**（答えの理由「二重基準」「余計な例外ルールを増やしたくない」から、`[inferred]`）: 次のどれも作らない。
   - 推し量ることを止める設定の画面
   - `/api/v1/me` と `/api/v1/me/interests` の、止めるための項目
   - 止めるための経路
   - 推し量りを切る（照合を止める）検索の引数。並び替えや期間で絞るなど、照合を止めない引数を置くかは、S2-3 で検索のしかたを決めるときに決める（この決定はそれを限らない）
   - 止めたことを持つ列や表
   - 照合の中の、住民ごとの例外の分岐
3. **D3 知らせて推し量ることを、検索の処理に組み込む**（答え「仕組みとして組み込んでおく」、`[inferred]`）:
   - 照合と `inferred_interests` への書き込みは、検索の要求の処理の一部にする（ADR-0045 の D3・D4 のまま。ジョブにしない）。
   - 知らせの文（原文の「興味から新聞を届けます！」を含む）は、ADR-0045 の D7 のとおり検索の画面（入力欄のそば）と利用の案内に出す。文言は今までどおり S2-3 で決める。
   - 知らせの文に、止める方法の案内は入れない（止める手段がないため）。
4. **D4 段階**（答え「MVPには検索機能自体が含まれない」「S2-3 の設計段階で…整理して」、`[inferred]`（マスターの答え OQ-072 より））: MVP（M5）は変えない。
   S2-3 の設計で、検索と興味の収集の連動を整理し、`api.md`・`db.md` に書く。整理するのは、照合の位置（要求の処理の中のどこで照合するか）・書き込みに失敗したときの扱い（ADR-0045 の D4 のとおり検索の結果は返す）・知らせの文と画面・B-09 の確かめ方。
5. **D5 ほかの決定は変えない**: ADR-0045 の D1〜D6・D8 はそのまま（検索語を残さない・興味の ID だけを持つ・1 人 5 つ・30 日で J14 が消す・退去で J7 が消す・本人が見て消す経路を作らない）。
   推し量った興味についての NFR-010（自分のデータの削除）は、今までどおり J7 と J14 で満たす。
6. **D6 要求の区分**: FR-109 の「止められるか」を、暫定から決定（`[inferred]`、マスターの答え OQ-072（2026-11-21）より）に直す。新しい FR は足さない。
   区分は ADR-0024 の決定 5 のとおり、マスターの答えから決めたものなので `[explicit]`（構想にあるもの）にしない。

## 理由

- D1 は答えによる。
- D2 は答えの理由による。本人が見て消す仕組みを設けない（ADR-0045 の D8）のに止める設定だけを置くと、情報の扱いを本人が拒否できるかが手段ごとに分かれる（答えの「二重基準」）。検索の引数や住民ごとの分岐も、形を変えた止める手段なので作らない。
- D3 は、「ポジティブにオープンにすることを前提に」による。止められない分、知らせることが住民への説明のすべてになるので、知らせの文を検索の画面から外さない。
- D4 は答えによる。MVP に検索がないので、今作るものはない。
- D5 は、答えが止められるかだけに答えていて、ほかの守りを弱めることを求めていないため。

## 代わりの案（選ばなかった理由）

- **(ii) 設定で止められる**: 答えが (i) を選んだ。答えの「二重基準」に当たる。
- **(iii) 検索ごとに推し量らない検索を選べる**: 答えが (i) を選んだ。形を変えた止める手段で、例外のルールが増える。

## 決めていないこと

- 知らせの文言・検索のしかた（全文検索の方式・結果の並び・`q` とカーソルのほかに置く引数）: S2-3 で決める（ADR-0045 の D7 のまま）。どの引数を足しても、照合を止める引数にはしない（D2）。
- 止められないことと法令の求め（利用の停止の求めを含む）との関係: OQ-032（持ち越し）で調べる。食い違う求めがあれば、新しい要回答としてマスターに出す。
- 知り合いの紙面に自分の投稿が載ることを断れるか（OQ-070 (3)）・誕生日を新聞に載せないことを選べるか（OQ-077 (3)）: この答えの理由はかかわりうるが、答えは検索から推し量ることについてのもので、これらは決めない。
