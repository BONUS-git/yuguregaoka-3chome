# 0022 — 段階は features.md の 3 つのまま。MVP は作る順に M0〜M6 に分け、各段階は受け入れ条件・見直し・マスターの確認で閉じる

- 状態: 採用
- 日付: 2026-11-19

## 背景

`roadmap.md`（YGO-008）に、段階・依存・各段階の受け入れ条件を書く。段階は `features.md` §1.2 で
MVP・段階 2・段階 3 と決まっている。MVP は F-01〜F-09 の 9 機能で、そのまま 1 つの塊として作ると
途中で確かめられることが少ない。また、外部サービス（LLM・メール送信）と要回答の項目
（`open-questions.md`）の扱いを、受け入れ条件の中でどうするかを決める必要がある。

## 決定

1. 段階は `features.md` の 3 つ（MVP・段階 2・段階 3）のまま。新しい段階は作らない。
2. MVP の中を、作る順番として 7 つのマイルストーンに分ける:
   M0 基盤 → M1 住所・アカウント → M2 住所録・手紙 → M3 郵便受け・定時配達 →
   M4 モデレーション・掲示板 → M5 朝刊・夕刊 → M6 退去・保持。
   マイルストーンは段階ではない。マスターの確認は段階の終わりにだけ求める。
3. M3 では紙面をまだ作らない。M3 には J3 の休刊だけの経路（紙面を組まずに `newspapers` に
   `is_holiday = true` の行を入れる。ADR-0007、async.md §3 の `enqueue J3 (holiday)`）を入れ、
   どの配達回もこの経路を通って J4・J5 に進む。J2 は M4 まで作らないので、M3 の J0 は J2 を積まず、
   審査の打ち切り（04:00 / 16:00 JST）まで待ってから J3 に進む。
   M5 で J3 を本物の組版に広げる（締め切りに間に合わないときの休刊の経路は残す）。
   これで、新聞より先に配達の冪等性と持ち越しを確かめる。
4. 各段階は「受け入れ条件をすべて満たす → 見直し（`reviews/`）→ マスターの確認（NFR-088）」で閉じる。
5. 外部サービス（LLM・メール送信・鍵管理・オブジェクトストレージ）はアダプタの裏に置き、
   受け入れはモックかローカルの代わりで行う。
6. 要回答の答えを受け入れ条件にしない。答えがないと作れないもの（OQ-005・OQ-006・FR-064 の OQ-001）だけを
   「止まる」とし、それ以外は暫定のまま作る。

## 理由

- 段階を増やすと `features.md` と食い違い、マスターの確認の回数も増える。作る順番はマイルストーンで足りる。
- マイルストーンの順は `features.md` §1.3 の依存順（住所 → 手紙 → 配達 → 新聞）と、
  「公開コンテンツの前にモデレーション」を守る。掲示板（M4）は審査と同じマイルストーンに置く。
- 休刊の経路は ADR-0007 ですでに決まっていて、本番でも通る経路である。M3 でこれを使えば、
  仮の紙面を作って後で捨てる必要がない。J4 は `newspapers` の行があることを前提に積まれるので、
  休刊の行を入れる J3 の経路は M3 に欠かせない。
- 段階の分け方は構想に書かれておらず、構想の「開発ロードマップを作成する」と features.md §1.2 から
  読み取ったもの [inferred]。段階ごとのマスターの確認も、NFR-088 と構想の「重大な仕様変更は事前承認」から
  読み取ったもの [inferred]。
- `check.sh` はネットワークなしで通る必要がある（NFR-063）。外部サービスを受け入れ条件に入れると、
  受け入れが費用（NFR-080）と要回答（OQ-008・OQ-039）に縛られる。
- 要回答を待って段階を止めると、答えに関係しない部分まで進まない（CLAUDE.md）。

## 代わりの案（選ばなかった理由）

- **MVP を 2 つの段階（手紙と配達・新聞と掲示板）に分ける**: features.md の段階と食い違う。
  「朝、ポストを開ける」体験は新聞まで揃って成立するため、途中で閉じる意味が薄い。
- **新聞を配達より先に作る**: 紙面の素材（掲示板）と配達回がないと組版を確かめられない。
- **外部サービスを本物で受け入れる**: 費用と契約が要り、デプロイしない方針（NFR-071・NFR-072）に反する。

## 影響

- `roadmap.md` §1〜§4・§8 がこの決定に従う。
- `status.md` はマイルストーンごとに状態を書く。
- 答えで「止まる」項目が増えたら、この ADR と `roadmap.md` §8 を同じ変更で直す。
