# 0070 — 絶対NGと絵文字の入力不可を全ての書き込みに当てる

- 状態: 採用
- 日付: 2026-11-22

## 背景

OQ-076 の答え（2026-11-21）で、手紙は絶対NG（直接的な下ネタ・外部へのリンク・本当の居住地や年齢などを聞く）を確認に回さずに止め、絵文字を入力できないと決まった（いまは ADR-0069）。
手紙のほか（掲示板の投稿・商店街の発信・ニックネームや自己紹介）にも当てるかは答えに書かれておらず、OQ-087 で聞いた。
2026-11-22、マスターが次のとおり答えた（原文）。

> 絶対NGと絵文字不可を全てに適用。対象に連絡先や自分から書くことも含める。

「対象に連絡先や自分から書くことも含める」は `real_info` の中身で、ADR-0069 の D12 と ADR-0071 で決める。この ADR は「全てに適用」の範囲と、手紙のほかの書き込みでの止め方を決める。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 範囲**（答え「全てに適用」、`[inferred]`。並びは `[assumed]`）: 住民と商店・団体の担当者が書いて保存し、ほかの人（モデレーターを含む）か自分に見せる文字の入力の全てに当てる。
   - 手紙の本文（ADR-0069）
   - 掲示板の投稿の本文（`POST /api/v1/board/posts`）
   - 商店街の発信（段階 3、F-17）
   - ニックネームと自己紹介（`PATCH /api/v1/me`）
   - 住所録のメモ（`POST`・`PATCH /api/v1/address-book`）
   - 通報の理由（`POST /api/v1/reports`）
   - マッチングの自由記述（段階 3。設けるかは OQ-050。設けるならこの範囲に入る）
   - 範囲の外 `[assumed]`: 運用者の CLI が入れる文（興味の一覧・商店のアカウント・広告。広告の中身は OQ-084）、選ぶだけの項目（興味の `key`・年齢の数・住所の候補）、認証情報（メールアドレス・パスワード）。
2. **D2 絵文字**（答え「絵文字不可を全てに適用」、`[inferred]`）:
   - D1 の全ての入力と、検索語（住所録の `GET /api/v1/address-book?q=`・段階 2 の過去の新聞の `GET /api/v1/newspapers?q=`）に、ADR-0069 の D13 の定義で当てる。
   - 絵文字を含めば何も保存せず（検索なら検索せず）に 400（`validation_failed`）を返す。1 日の上限に数えない。
   - web（C1）のどの入力欄も絵文字を受け付けない（入力・貼り付けで入らない）。API の 400 は web を通らない要求への守り。
3. **D3 絶対NG**（答え「絶対NGを全てに適用」、`[inferred]`。応答の形は `[assumed]`）:
   - D1 の手紙のほかの入力に、書いたときに API がルール表の `reject` の段の規則（`external_link`・`adult_words`・`real_info`。ADR-0069 の D1・D10 と同じ規則）を当てる。LLM は呼ばない。
   - 当たれば何も保存せず（新しい行を作らず、値も変えず）に 422（`content_rejected`）を返す。規則の ID・種類・段・入力の位置は返さない。1 日の上限に数えない。web は決まった文面（文言は OQ-065）を出す。
   - 確かめる順番は、形式（字数・絵文字の 400）→ `reject` の段（422）→ 上限（429 `daily_limit_reached`）。
   - 掲示板の投稿と商店街の発信は、当たらなければ今のまま `awaiting_review` で保存し、締め切りのあとの J2 の審査（ルール表 → LLM → 人。`security.md` §5.2）に進む。J2 のルール表の掲示板向けの項目と LLM の基準は変えず、`real_info` は入れない `[assumed]`。
   - 手紙のほかの書き込みでは、`reject` の段に当たるはっきりした形だけを止める。`review` の段（疑いの形）は手紙だけに当てる。
   - プロフィール・住所録のメモ・通報の理由・マッチングの自由記述には `review` の段を当てない（当たらなければそのまま保存する）`[assumed]`。
   - 検索語には絶対NGを当てない（保存も表示もしないので）。
4. **D4 流量の制限**: 422 `content_rejected` は、手紙の 422（`letter_needs_review`・`letter_rejected`）と合わせて住民ごとに数え、超えたら 429（`rate_limited`）を返す（ADR-0069 の D7・`security.md` §7 の T-22）`[assumed]`。値は OQ-065。
5. **D5 当て直さない**: 保存済みの書き込み（ニックネーム・自己紹介・メモ・掲載済みの投稿）は、ルール表の版が上がっても当て直さない。新しい版は、そのあとの書き込みから効く（ADR-0069 の D3 と同じ考え）。
6. **D6 新聞**: J16 の LLM の出力に絵文字があれば、その記事を決まった形にする（ルール表に当たったときと同じ）。J17 は絵文字を含む外のニュースを保存しない（当たったときと同じ）。紙面に絵文字が出ない。
7. **D7 段階**（`[assumed]`）: 絵文字の検査は、各入力を作る段階から入れる（M1: ニックネーム・自己紹介。M2: 手紙・住所録のメモ・住所録の検索語。M4: 掲示板の投稿・通報の理由。M5: J16・J17。段階 2: 過去の新聞の検索語。段階 3: 商店街の発信・マッチングの自由記述）。
   `reject` の段の照合は、ルール表を作る M4 から、手紙・掲示板の投稿・ニックネーム・自己紹介・メモ・通報の理由に入れる（M1〜M3 の間の書き込みは照合しない。D5 のとおり当て直さない）。
8. **D8 年齢で変えない**: 年齢に関係なく全員に同じに当てる（ADR-0057 の D1）。

## 理由

- D1 は答えの「全てに」による。運用者の CLI の文と選ぶだけの項目を外すのは、住民が書く文ではなく、答えの守りたいもの（世界観・隠語・他 SNS との境目）にかからないため。通報の理由とメモも入れるのは、モデレーターや本人に見せる文で、「全て」の外に置く理由がないため。
- D2 で検索語にも当てるのは、入力欄に絵文字を入れられない形を全ての欄でそろえるため。絵文字の検索語は当たる文がない（保存した文に絵文字がない）。
- D3 で手紙の 422 と code を分けるのは、手紙は y / n の流れを持ち（ADR-0069 の D4）、ほかの書き込みは持たないので、web の扱いが違うため。掲示板の投稿で `review` の段を当てないのは、掲示板には手紙の y / n の流れがなく、締め切りのあとの J2 の審査（掲示板向けの項目・LLM・人）が別にあるため。J2 に `real_info` を足さないのは、LLM の基準に本当の情報の疑いを足すと誤判定が増え（答えの「ガチガチにすると誤判定に繋がる」）、答えの「絶対NG」は `reject` の段で守れるため。プロフィール・メモ・通報の理由に `review` の段を当てないのは、保留して人が読む流れを持たず、誤判定で書けなくなるのを避けるため（答えの「ガチガチにすると誤判定に繋がる」）。
- D4 は、入力ごとに別に数えると、規則を探る試しの回数が入力の数だけ増えるため。
- D5 は、書いた本人が知らないうちに保存済みの文が消える・変わる形を作らないため。
- D6 は、紙面も書き込みと同じに絵文字のない形にそろえるため。

## 代わりの案（選ばなかった理由）

- **掲示板の投稿も締め切りのあとの J2 だけで止める**: 答えの絶対NGは確認に回さずに止める形で、書いたときに止めれば審査の手間と保存する本文が減る。
- **全ての書き込みに `review` の段と y / n を当てる**: プロフィール・メモ・通報の理由に保留の状態と人が読む経路を足すことになり、読む人が増える。
- **手紙と同じ `letter_rejected` を返す**: 手紙のほかでは手紙の流れ（y / n・`held`）を持たず、code の名前が中身と合わない。
- **検索語にも絶対NGを当てる**: 検索語は保存も表示もしない（ADR-0045 の D4）。
- **保存済みの文を当て直して消す**: 本人の知らないうちに文が消える。

## 決めていないこと

- `content_rejected` の文面・流量の制限の値・連絡先と外部リンクの形の細部: OQ-065（持ち越し。M4 の前に秘書が決める）。
- マッチングの自由記述を設けるか: OQ-050（持ち越し）。
- 運用者が入れる広告の中身: OQ-084（持ち越し）。
