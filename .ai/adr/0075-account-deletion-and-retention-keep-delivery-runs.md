# 0075 — 退去処理とデータ保持期間（配達回は消さない）

- 状態: 採用
- 日付: 2026-11-22

ADR-0013 を丸ごと置き換える。ADR-0013 の決定（退去のときの処理・長期不在のときの処理・保持期間・新聞の組み直し）は、今の状態に書き直してこの ADR に移した。変えたのは配達回（`delivery_runs`）の保持だけで、30 日で消すのをやめ、消さないことにした（`reviews/0001-design-review.md` の R-002）。

## 背景

OQ-030「アカウント情報の保持期間・削除ポリシー」は `db.md` と `security.md` で定めるとされている（持ち越し）。

住民が退去する（アカウントを削除する）とき、次の問いに答える必要がある。

1. 住民が作ったデータ（手紙・掲示板の投稿）はどうするか。
2. 受取人の郵便受けに届いた手紙はどうするか。
3. その住民が載った新聞はどうするか。
4. それぞれのデータを何日持つか（NFR-009、FR-097）。

配達回（`delivery_runs`）は、次の 8 つの表から外部キーで指されている（`db.md` §2）: `letters`・`mailbox_items`・`delivery_notifications`・`newspapers`・`newspaper_articles`・`external_news_items`・`board_posts`・`moderation_queue`。
郵便受けの行は受取人が消すまで残り（FR-099）、紙面はバックナンバーとして残る（FR-039。保持期間は OQ-030 次第、仮に無期限）。
郵便受けとバックナンバーは、`delivery_runs.status = 'done'` の配達回の行だけを返す（`api.md`）。
このため、配達回を一定の期間で消すと、外部キーで DELETE が失敗する。CASCADE か SET NULL にすれば、今度は「`done` の回だけ返す」の条件が成り立たず、古い手紙とバックナンバーが郵便受けから消える。

## 決定

保持期間などの数値は、断りのない限りすべて `[assumed]`（仮に置いた値）とする。

### 住民のアカウント削除のとき（J7 `account.erase`）

| 対象 | 処理 |
|------|------|
| `residents` の行 | 即時に物理削除。`erasure_log` に記録 |
| 認証情報 | 即時に消す（`security.md` §2.4） |
| 未配達の手紙（`state = pending / scheduled`） | 即時に `returned` にする |
| 届いた手紙（受取人の郵便受けにあるもの） | そのまま残す。`letters.sender_id` を NULL にし、API では「退去済み」と示す |
| 確認待ちの手紙・却下の手紙（`state = held / blocked`） | 即時に本文と宛先ごと消す（届いていないので、受取人のために残す理由がない、ADR-0069 の D6） |
| 掲示板の投稿（掲載前） | 即時に `deleted` にし、`body` を消す |
| 掲示板の投稿（掲載済み） | 即時に `deleted` にし、`body` を消す。その投稿が載った版を組み直す（下の「新聞の組み直し」） |
| 住所録（持っているもの） | 即時に消す |
| ブロック（する側・される側） | 即時に消す |
| 通知の購読（`push_subscriptions`）・送った記録（`delivery_notifications`） | 即時に消す（ADR-0076） |
| 興味（`resident_interests`） | 即時に消す（ADR-0055 の D5） |
| 推し量った興味（`inferred_interests`、段階 2） | 即時に消す（ADR-0045 の D5） |
| その住民の投稿から作った記事（`newspaper_articles`） | 即時に消す。その記事が載った版をすべて組み直す（ADR-0055） |
| `tenancies`（居住記録） | アカウント削除から **1 年後**に消す |
| `addresses` | `status = vacant_deleted` にする。住所の行は消さない（ADR-0060 の D1） |
| 配達回（`delivery_runs`） | 消さない（住民の ID を持たない） |

### 長期不在で空き家になったあとの処理

`addresses.status = vacant_expired` になった住所の元住民について:

- 移ってから **12 か月後**に、アカウント削除と同じ処理（上の表）を当てる。
- 今は `dormant` から `vacant_expired` への移行を作らないので、この処理は起きない。OQ-088 の答えでこの移行を作るときだけ当てる（ADR-0060 の D3・ADR-0062）。

### データの保持期間

| データの種類 | 保持期間 |
|-------------|---------|
| アクセスログ・操作ログ（DB の外） | 30 日 |
| `delivery_runs`（配達回） | 消さない（期間を置かない。1 日 2 行で、住民の ID も本文も持たない） |
| `delivery_notifications`（配達完了の通知の記録、ADR-0076） | 指している配達回の `finished_at` から 30 日 |
| `newspaper_articles`（新聞の記事の文字、ADR-0055） | 紙面（`newspapers`・`newspaper_editions`）と同じ |
| `external_news_items`（取り込んだ外のニュース、ADR-0055） | 取り込みから 30 日（OQ-060 の利用の条件で変わる） |
| `inferred_interests`（過去の新聞の検索から推し量った興味、段階 2、ADR-0045） | 最後に当たってから 30 日（J14 が消す） |
| `moderation_queue` / `moderation_actions` | 1 年 |
| 却下の手紙（`letters.state = blocked`、本文と宛先、ADR-0069 の D6） | `blocked` にしてから 30 日 |
| 確認待ちの手紙（`letters.state = held`、ADR-0069） | モデレーターが操作するまで（長く確かめられないときの扱いは OQ-065） |
| `reports`（通報） | クローズの日から 1 年 |
| バックアップ | 30 日 |
| `erasure_log` | 60 日 |
| `tenancies`（退去した住民の分） | 退去から 1 年 |

### 配達回を消さないこと

1. J14 `retention.purge` も J7 `account.erase` も、`delivery_runs` の行を消さない。
2. `delivery_runs` を指す 8 つの外部キー（背景を参照）は、CASCADE にも SET NULL にもしない。今のまま（既定の制約）にする。
3. 郵便受けとバックナンバーが返す条件「`delivery_runs.status = 'done'` の配達回」は変えない。古い回の手紙と紙面も、配達回の行が残るので返り続ける。
4. 通知の記録（`delivery_notifications`）は、指している配達回の `finished_at` から 30 日で J14 が消す（ADR-0076 の D7）。配達回は残るので、消す順番の決まりは置かない。

### 新聞の組み直し

住民の掲示板の投稿が消えたとき、その投稿を素材に使った紙面を `newspaper_items` から探し、その投稿が載った版（`newspaper_editions`）をすべて描き直して、版の `storage_url` を上書きする。その投稿から作った `newspaper_articles` の行も消す。
ほかの素材は残すので、素材が減っても紙面を休刊として扱わない。

## 理由

- **届いた手紙を受取人の側に残す**: 受け取った手紙が突然消えると、受取人の体験を損なう。送った人が退去しても、受取人の郵便受けはその人のものである。
- **新聞を組み直す**: 退去した住民の投稿が配達のあとも載り続けると、その住民がいなくなったのに過去の新聞に残り続ける。
- **居住記録（tenancies）を 1 年持つ**: 住所録の配達先の解決（`registered_tenancy_id`、`db.md` §3）に、退去のあとも一定の期間 tenancy を指す必要がある。1 年は、その転送と解決が起こりうる期間として仮に置いた。
- **erasure_log を 60 日持つ**: バックアップ（30 日）より長く持てば、リストアのあとの再生に使える期間を確保できる（`db.md` §6）。
- **配達回を消さない**: 配達回は 1 日 2 行（年に約 730 行）で、`run_id`・`status`・開始と終了の時刻だけを持ち、住民の ID も本文も持たない。持ち続けても、個人情報を最小限にすること（NFR-002）に反せず、容量もほとんど増えない。消さなければ、8 つの外部キーも、郵便受けとバックナンバーの「`done` の回だけ返す」の条件も、今のまま成り立つ。

## 代わりの案

- **配達済みの手紙も消す**: 受取人の体験を損なうので採らない。
- **ソフトデリートだけにする（物理削除しない）**: NFR-010（データの削除の求め）・NFR-002（個人情報を最小限にする）に反するおそれがある。物理削除を基本にし、`erasure_log` で監査する。
- **手紙を住民ごとに暗号化し、退去のときに鍵を捨てる（per-letter key）**: ADR-0006 はサーバー鍵（鍵管理のサービスで管理）を採り、個別の鍵の仕組みを持たない。鍵を捨てるだけでは DB の行が残り、管理が複雑になる。採らない。
- **新聞を組み直さない**: 退去した住民の投稿が残り続けるので採らない。
- **配達回を 30 日で消し、外部キーを外す**: 郵便受けとバックナンバーの条件を「郵便受けの行があり `visible_at` を過ぎた」に変えれば、配達回がなくても手紙は返せる。だが、休刊（`skipped`）や失敗（`failed`）の回の紙面を出さないための条件を、配達回の状態の代わりに別の列で持つ必要が出て、8 つの表の整合を DB の制約で守れなくなる。消して得るもの（1 日 2 行）が小さいので採らない。
- **配達回を 30 日で消し、外部キーを CASCADE にする**: 郵便受けの手紙・紙面・記事まで 30 日で消え、FR-099（受取人が消すまで残す）と FR-039（バックナンバー）に反するので採らない。

## 影響

- DB: `db.md` §2 `delivery_runs` に「行は消さない」と書く。§4 のライフサイクル表の配達回の行は「消さない」、通知の記録の行は配達回の `finished_at` から 30 日。§5 の退去の処理は本 ADR を参照する。
- 非同期処理: `async.md` §4 の J14 の対象に `delivery_runs` を入れない。J7 は本 ADR の表に従う。§8 と §9 から配達回の保持の未確定を外す。
- API: 郵便受けとバックナンバーの条件（`done` の回だけ返す）は変わらない。
- ロードマップ: `roadmap.md` の A-13 に、31 日後の J14 のあとも配達回・郵便受けの手紙・紙面が残り、通知の記録が消えることを足す。
- セキュリティ: 認証情報を消す手順は `security.md` §2.4 で定める（OQ-028 と連携）。
- OQ-030 の扱い（持ち越し）は変えない。
