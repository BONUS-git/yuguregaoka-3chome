# 0099 — 段階は 3 つ、MVP は M0〜M6、要回答で止めない

- 状態: 採用
- 日付: 2026-11-26

ADR-0022 を丸ごと置き換える。`reviews/0001-design-review.md` の R-030、`gaps.md` の G-006（YGO-042）。
D1〜D6 の番号は ADR-0022 と同じにする（ほかの文書の「ADR-0022 の D2」などの参照は、この ADR の同じ番号として読む）。
すべて秘書の判断で、新しい要回答はない。

## 背景

`roadmap.md` に、段階・依存・各段階の受け入れ条件を書く。段階は `features.md` §1.2 で MVP・段階 2・段階 3 と決まっている。
MVP は F-01〜F-09 と F-19 の 10 機能で、そのまま 1 つの塊として作ると途中で確かめられることが少ない。
また、外部サービス（LLM・メール送信）と要回答の項目（`open-questions.md`）の扱いを、受け入れ条件の中でどうするかを決める必要がある。
ADR-0022 の D6 は、要回答で「止まる」ものを経緯の注記を重ねて書いており、OQ-081・OQ-086 の答えのあとの状態が書かれていなかった（R-030）。

## 決定

1. 段階は `features.md` の 3 つ（MVP・段階 2・段階 3）のまま。新しい段階は作らない [inferred]。
2. MVP（F-01〜F-09 と F-19）の中を、作る順番として 7 つのマイルストーンに分ける:
   M0 基盤 → M1 住所・アカウント → M2 住所録・手紙 → M3 郵便受け・定時配達 →
   M4 モデレーション・掲示板 → M5 朝刊・夕刊 → M6 退去・保持。
   マイルストーンは段階ではない。マスターの確認は段階の終わりにだけ求める。
   M の分け方を変えないこと、手紙の一続きと中心の体験の全体がどの M の終わりで通るかは ADR-0097。
3. M3 では紙面をまだ作らない。M3 には J3 の休刊だけの経路（紙面を組まずに `newspapers` に
   `is_holiday = true` の行を入れる。ADR-0098 の D2、`async.md` §3 の `enqueue J3 (holiday)`）を入れ、
   どの配達回もこの経路を通って J4・J5 に進む。J2 は M4 まで作らないので、M3 の J0 は J2 を積まず、
   審査の打ち切り（04:00 / 16:00 JST）まで待ってから J3 に進む。
   M5 で J3 を本物の組版に広げる（締め切りに間に合わないときの休刊の経路は残す）。
4. 各段階は「受け入れ条件をすべて満たす → 見直し（`reviews/`）→ マスターの確認（NFR-088）」で閉じる [inferred]。
5. 外部サービス（LLM・メール送信・鍵管理・オブジェクトストレージ）はアダプタの裏に置き、
   受け入れはモックかローカルの代わりで行う（LLM は ADR-0086、メール送信は ADR-0033）。
6. 要回答の答えを受け入れ条件にしない。答えがないと作れないものだけを「止まる」とし、それ以外は暫定のまま作る。
   - 今、要回答で止まるものはない。`open-questions.md` の一覧に状態が `要回答` の行はなく、`roadmap.md` §8 と同じ。
   - OQ-081（掲示板の経路）は決定（ADR-0065・ADR-0066）。M4 の掲示板の経路と M2 の相互にならない追加の停止は止まらない。
   - OQ-086（`check.sh` の DB のテストの道具）は決定（ADR-0052 の D3・ADR-0068）。M0 の DB のテストは止まらない。
   - これまで止まっていたものは、どれも答えで止まらなくなった: FR-064（OQ-001、ADR-0024）・地図の F-19（OQ-005、ADR-0083）・
     F-17 の商店の部分（OQ-056、ADR-0043。OQ-068・OQ-069 は持ち越しで、S3-2 の前に決める）。
   - F-17 のコミュニティの部分は止まらない。制約の中身（OQ-057、持ち越し）は S3-2 の前に秘書が決める。
   - 架空の店と張り紙（OQ-067、決定、ADR-0050）と新聞の入居者募集の広告（OQ-083、決定）は段階 3（S3-2）から作り、
     MVP には作らない。MVP の範囲は変わらない。細部（OQ-084、持ち越し）は S3-2 の前に決める。
   - MVP を確かめたあとに足す要回答は、今の M を止めるものだけにし、本文に `- 止める M:` の行を書く（CLAUDE.md）。
   - 答えで「止まる」ものが増えたら、この ADR を置き換える新しい ADR と `roadmap.md` §8 を同じ変更で直す。

## 理由

- 段階を増やすと `features.md` と食い違い、マスターの確認の回数も増える。作る順番はマイルストーンで足りる。
- マイルストーンの順は `features.md` §1.3 の依存順（住所 → 手紙 → 配達 → 新聞）と、
  「公開コンテンツの前にモデレーション」を守る。掲示板（M4）は審査と同じマイルストーンに置く。
- 休刊の経路は ADR-0098 の D2 で決まっていて、本番でも通る経路である。M3 でこれを使えば、
  仮の紙面を作って後で捨てる必要がない。J4 は `newspapers` の行があることを前提に積まれるので、
  休刊の行を入れる J3 の経路は M3 に欠かせない。
- 段階の分け方は構想に書かれておらず、構想の「開発ロードマップを作成する」と features.md §1.2 から
  読み取ったもの [inferred]。段階ごとのマスターの確認も、NFR-088 と構想の「重大な仕様変更は事前承認」から読み取ったもの [inferred]。
- `check.sh` はネットワークなしで通る必要がある（NFR-063）。外部サービスを受け入れ条件に入れると、
  受け入れが費用（NFR-080）と本番のサービスの選定に縛られる。
- 要回答を待って段階を止めると、答えに関係しない部分まで進まない（CLAUDE.md）。
- D6 を今の状態だけで書けば、止まるものがあるかを経緯の注記を読み解かずに確かめられる。

## 代わりの案（選ばなかった理由）

- **MVP を 2 つの段階（手紙と配達・新聞と掲示板）に分ける**: features.md の段階と食い違う。
  「朝、ポストを開ける」体験は新聞まで揃って成立するため、途中で閉じる意味が薄い。
- **新聞を配達より先に作る**: 紙面の素材（掲示板）と配達回がないと組版を確かめられない。
- **外部サービスを本物で受け入れる**: 費用と契約が要り、デプロイしない方針（NFR-071・NFR-072）に反する。
- **ADR-0022 を残し、D6 に OQ-081・OQ-086 の注記を足す**: CLAUDE.md は ADR に変えた項の注記を重ねることを禁じている。
