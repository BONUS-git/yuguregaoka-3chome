# 0016 — 配達回は時刻の関門と見回りのジョブで進める

- 状態: 採用
- 日付: 2026-11-19

## 背景

配達回（`delivery_runs`）は締め切り・審査・組版・準備・公開という複数の工程を経る。
これらをどう制御するかで 3 つの案があった。

1. **決まった時刻の cron だけ**: 各工程を固定時刻の cron ジョブとして並べる。
2. **工程が次の工程を積む鎖**: 各工程が完了したとき、次の工程のジョブを自分で積む。
3. **見回りジョブ（tick）と時刻の関門**: 定期的な見回りジョブが配達回の状態と現在時刻を
   見て、次の工程を 1 つずつ積む。

また、配達時刻に間に合わなかった場合の対処（休刊 / 持ち越し）も設計上の判断が必要だった。

## 決定

**J0 `delivery.tick`** を 5 分ごとに動かし、配達回ごとに次の工程を 1 つだけ
`singletonKey` で積む方式を採用する。

### 工程の順序と関門時刻（JST）

| 工程 | ジョブ | 開始の条件（関門）| 打ち切り / 締め切り |
|------|--------|----------------|-------------------|
| 締め切り | J1 | 01:00 / 14:00 以降 | — |
| 審査 | J2 | 02:00 / 15:00 以降 | 04:00 / 16:00 [assumed] |
| 組版 | J3 | J2 完了または審査打ち切り後 | 05:00 / 16:30 |
| 準備 | J4 | `newspapers` の行ができた後 | — |
| 公開 | J5 | 07:00 / 17:00 以降 かつ前の配達回が完了 | 07:15 / 17:15 [assumed] |
| 持ち越し | J6 | 公開の打ち切りを過ぎた場合 | — |
| 手紙の通知 | J15（`kind = letter`） | 公開済み（`done`）で、手紙の枠の時刻（08:00〜11:50 / 18:00〜20:50 の 10 分ごと）以降 | 枠の時刻から 30 分 [assumed] |

（ADR-0035 で置き換え）公開（J5）は今までどおり 07:00 / 17:00 に配達回を `done` にするが、その時刻に見えるのは新聞と掲示板だけになった。
手紙は住民ごとの枠の時刻（`mailbox_items.visible_at`）から見える。J0 は公開済みの配達回について、時刻を過ぎた枠ごとに手紙の通知（J15）を積む。
新聞の通知は J5 が公開と同じトランザクションで積む（休刊の回にも積む。郵便受けには休刊の印が届く。ADR-0035 の D11）。

打ち切り時刻は仮置き [assumed]。確認が取れたら ADR-0004 とこの ADR を更新する。

### 間に合わなかったときの対処

- **組版の締め切りまでに J3 が完了しない**: J0 が `is_holiday = true` の行を挿入して休刊にする。
  その配達回は紙面を届けない（ADR-0007）。（ADR-0035 で補足）郵便受けには休刊の印と手紙が届き、新聞の通知も送る。
- **公開の打ち切りまでに J5 が完了しない**: J0 が J6（持ち越し）を積む。その配達回の中身を
  次の受付中の配達回に移し、`delivery_runs.status` を `skipped` にする。

## 理由

- **再起動しても工程を再開できる**: 各工程の完了はテーブルの状態で分かるため、worker を
  再起動したあと J0 が見回れば止まっていた工程を正しく拾い直せる。cron だけの設計では
  worker を再起動した後に途中の工程を誰が拾うかが不明確になる。
- **鎖が一度切れても自動回復する**: 工程が次の工程を積む設計では、ジョブが失敗して
  次のジョブが積まれなかった場合に止まったまま自動回復しない。J0 の見回りがその保険になる。
- **時刻の制約と状態の確認を 1 か所に集められる**: J0 が「今何時か」と「どこまで進んだか」
  を組み合わせて判断するため、時刻ロジックが分散しない。

## 代わりの案（選ばなかった理由）

**決まった時刻の cron だけで動かす**: worker の再起動やジョブの失敗のあと、途中の工程を
再開する仕組みが別途必要になる。不採用。

**工程が次の工程を積む鎖だけにする**: 鎖が一度切れると止まる。監視と手動介入が必要になり、
運用コストが上がる。不採用。

## 影響

- `async.md` §3・§4（J0〜J6）でこの ADR の具体化を書く
- ADR-0004: 打ち切り時刻の確定時に合わせて数値を更新する（別チケット）
