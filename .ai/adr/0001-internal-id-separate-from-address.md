# 0001 — 内部 ID と住所を分ける

- 状態: 置き換え（→ 0082）
- 日付: 2026-11-19

## 背景

構想では「架空の街の住所をユーザー ID とする」と定められている（FR-001）。
しかし住所は引っ越し（FR-004）で変わる可能性があり、住所をシステム内部の一次 ID として
直接使うと、引っ越しのたびに手紙・住所録など全参照を書き換える必要が生じる。
住所割り当て方法（FR-010）が変わった場合も影響が広がる。

## 決定

システムは各住民に対して不変の内部 ID（UUID v4）を持つ。
住所は内部 ID に紐づく属性として管理し、住民 ID として画面には表示するが、
内部参照（外部キー）には使用しない。
住所割り当ては新規登録時に複数の候補を提示し、住民が選択する方式とする。

## 理由

- 引っ越し（FR-004）で住所が変わっても内部参照が壊れない
- 住所転送（FR-005）の実装がシンプルになる（旧住所 → 新住所のマッピングのみ）
- 住所割り当て方式の変更が内部参照に影響しない
- 住所選択式にすることで住民の「街に住む」体験を強化できる

## 代わりの案

**住所そのものを主 ID にする**: 引っ越しのたびに全参照を書き換えるか、
住所変更を不可能にするかのどちらかが必要。体験と矛盾するため不採用。

## 影響

- DB 設計: `users` テーブルに UUID の主キー。`addresses` テーブルを別に持ち `user_id` で参照
- API 設計: エンドポイントのパスには内部 ID を使い、住所は属性として返す
