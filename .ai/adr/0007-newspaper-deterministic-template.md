# 0007 — 新聞はテンプレートで決定的に組む

- 状態: 採用（全住民に届けることを ADR-0035 で追加。紙面の中身と LLM の扱いを ADR-0039 で置き換え）
- 日付: 2026-11-19

## 背景

FR-033 では組版バッチが朝刊を自動生成し、FR-037 では冪等性が要求されている。
組版に LLM を使う案と、テンプレートエンジンで決定的に生成する案がある。
また NFR-030 では「組版バッチが当日分の生成に失敗した場合の代替動作は未確定」とされていた。

## 決定

新聞の組版はテンプレートエンジン（静的なレイアウト定義）を使って決定的に生成する。
（ADR-0039 で置き換え）もとは「LLM による文章生成は行わない」だった。記事の文字（見出し・まとめ・外のニュースの記事）は LLM が作り、`newspaper_articles` に保存する。
組版はサーバー（C6）が保存した文字からテンプレートで決定的に行い、組版のやり直しでは LLM を呼ばない（ADR-0039 の D7）。
組版に失敗した場合は「休刊」として、その配達回は紙面を届けない（ADR-0035 で補足: 郵便受けには休刊の印と手紙が届き、新聞の通知も送る）。
LLM の失敗では休刊にせず、記事を決まった形で組む（ADR-0039 の D8）。

（ADR-0035 で追加）新聞は、その便に手紙があるかにかかわらず全住民の郵便受けに届ける（07:00 / 17:00）。
（ADR-0039 で置き換え）もとは「紙面は全住民に同じ」だった。紙面は一人 1 枚にせず、知り合いの数で分けた組ごとの版にし、知り合い 0 の組は興味で分ける。住民は 1 回の配達につき 1 つの版を受け取る（ADR-0039 の D1〜D3）。
休刊の回も、郵便受けには紙面の代わりに休刊の印が届き、新聞の通知「新聞が配達されました！」を送る（ADR-0035 の D11）。
知り合いが少なくても成り立つ紙面の中身（住民ごとに変えるか・興味を集めるか・ニュースの出どころ・加工に LLM を使うか）は
OQ-051 → 決定（2026-11-20、ADR-0039）。残りは OQ-058〜OQ-062（OQ-058 はのちに決定、2026-11-20、ADR-0044。OQ-059 ものちに決定、2026-11-20、ADR-0045。OQ-061 ものちに決定、2026-11-20、ADR-0046）。

**紙面の構成（案）**

| 面 | 内容 |
|----|------|
| 1 面 | 掲示板の最新投稿（カテゴリ別） |
| 2 面 | 商店街・団体からのお知らせ（段階 3 以降） |
| 外のニュースの面 | 取り込んだ実在の外のニュースの記事（ADR-0039 の D6。配信元は OQ-060 で、それまではテストの偽の記事だけ） |
| 興味の面 | 版の興味に結び付けた記事（興味の版だけ。共通の版にはない。ADR-0039 の D3） |
| 折込 | 住民募集・イベント募集投稿 |

## 理由

- LLM を使わないことで冪等性（FR-037）を保証しやすい（同じ入力 → 同じ出力）（ADR-0039 で置き換え: LLM の出力を保存し、組版はそこから決定的に行うことで冪等性を保つ）
- 組版失敗時に「休刊」とすることで、途中まで生成した壊れた紙面を届けるリスクを回避
- テンプレートは開発・テスト環境で LLM なし（NFR-063）でも動作する（ADR-0039 のあとも、文章アダプタはテストではモック）
- LLM による文章生成は幻覚リスクがあり、コンテンツポリシーとの整合が難しい（ADR-0039 で、出力の検査・ルール表・決まった形への切り替えと、投稿の本文を書き換えないことで扱う）

## 代わりの案

**LLM で記事を生成する**: 冪等性の保証が難しく、幻覚リスクもある。
また LLM の判断をコンテンツに組み込む形になり NFR-011 の精神と合わない。不採用。
（ADR-0039 で追記: マスターの答え OQ-051（2026-11-20）「文字だけLLMで作成し、新聞の生成部分はサーバーで行う」で、記事の文字に限って採用した。
LLM は公開してよいかを決めず、紙面全体を LLM に組ませることは今も不採用）
**組版失敗時に前日の紙面を流用**: 古い情報を届けることになり、住民を誤解させる可能性がある。不採用。

## 影響

- 非同期処理: `async.md` で組版バッチの入力仕様・テンプレート形式・「休刊」ロジックを設計する
- アーキテクチャ: 組版エンジンの技術選定は別途 ADR に記録する
