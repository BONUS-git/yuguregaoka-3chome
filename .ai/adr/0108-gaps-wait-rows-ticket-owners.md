# 0108 — 外待ちの行のチケットと G-081〜G-083 の担い手

- 状態: 採用
- 日付: 2026-11-28

チケット YGO-099 による。仕分け 17 の K-020 を決める。ADR-0107 を丸ごと置き換える（D1・D2 は ADR-0107 のまま引き継ぎ、G-081・G-082・G-083 の担い手を足す）。

## 背景

`.ai/gaps.md` の冒頭は、今の M に向かう行を、題に G-NNN を 1 つ付けたチケットで 1 行ずつ閉じると決めている。例外として、外の作業を待つだけでジョブが作るもののない行は、チケットを切らず、gaps の表と準備書 `.ai/deploy/readiness.md` で追う。秘書の決まりも「外の作業を待つだけのことはチケットにせず、ジョブが作るものがあるときだけチケットを切る」としている。
固定コードの点検（`check:consolidation`）は、M1 に向かう gaps の行のすべてにチケットを求める。ADR-0107 は冒頭の例外の決まり（外待ちでもあとにジョブが作るものがあればチケットを切る）を決め、G-080 を YGO-088 で追うとした。G-081・G-082・G-083 の担い手は決めず、点検の 3 件が仕分け 17 まで残った（R-072）。
3 行とも、外の作業が済んだあと（または `check.sh` を次に触るとき）にジョブが作るものがある。

- G-081: YGO-078 が `状態: done` になり、K-021 の ADR（ADR-0105 を置き換えたもの）ができたあと、その ADR を置き換えて YGO-070 を取り下げ、G-079 の閉じる条件の最後の形を書く。
- G-082: G-080 が閉じたあと、YGO-078 を出し直し、その変更で R-074 の書き直し（「31d9315 の見直しの指摘」の節の推測の部分を消す）を行う。これは YGO-078 そのものの仕事である。
- G-083: `scripts/check.sh` の t062・t078・t072 の段（チケットの名前に依る段）を、名前に依らない 1 つの段にまとめる。`check.sh` を次に触るのは M1 の YGO-072 である。

## 決定

- **D1 あとにジョブが作るものがあれば、外待ちの行でもチケットを切る**: gaps の行が外の作業（マスターや秘書の作業）を待っていても、それが済んだあとにジョブが作るもの（確かめた事実の記録、文書の今の状態の書き直し、ADR の置き換え、コード）があれば、冒頭の例外に当たらない。その行には、題に G-NNN を 1 つ付けたチケットを切る。チケットの依存の節には、待つ外の作業と「それが済むまで実装の変更は出さない」ことを書く。
- **D2 例外は、ジョブが作るものが何もない行に限る**: チケットを切らずに gaps の表と準備書で追うのは、外の作業が済めば閉じる条件の事実がそろい、ジョブが何も作らない行だけとする。そのような行は、閉じる条件の事実がそろったら閉じる。
- **D3 すでにあるチケットが行の仕事を受け持つなら、そのチケットの題に G-NNN を足す**: 行のジョブが作るものが、すでにある open のチケットの範囲と同じか、その範囲に寄せられるなら、新しいチケットを切らず、そのチケットの題に G-NNN を 1 つ足し、範囲と受け入れ確認に行の仕事と行を閉じることを足す。1 つのチケットの題に置く G-NNN は 1 つまでとする。
- **D4 G-080 は YGO-088 で追う**（ADR-0107 のまま）。
- **D5 G-081 は新しいチケット YGO-100 で追う**: YGO-100 は `状態: open` で、依存の節に、YGO-078 が `状態: done` になることと K-021 の ADR があることを書き、それまで実装の変更を出さない。範囲は G-081 の行の予定のとおり（K-021 の ADR を丸ごと置き換える新しい ADR・YGO-070 の取り下げ・それを指す文書の直し・G-079 の閉じる条件の最後の形）。
- **D6 G-082 は YGO-078 で追う**（D3）: YGO-078 の題に G-082 を足し、範囲に R-074 の書き直しと G-082 の行を閉じることを足す。閉じる条件は G-082 の行のまま（G-080 が閉じ、YGO-078 が `状態: done`）。
- **D7 G-083 は YGO-072 で追う**（D3）: YGO-072 の題に G-083 を足し、範囲に、`check.sh` の t062・t078・t072 の段を名前に依らない 1 つの段（テスト・コード・道具のどれかがあるなら、`package.json`・`package-lock.json`・`scripts/prepare.sh`・`vitest.config.ts`・`src/app.ts`・TC-033 のテストがすべてあり、Vitest の段のあとで `test-results/junit.xml` がある）にまとめることを足す。YGO-072 の依存（YGO-078 と同じ変更か、そのあと）は変えない。

## 理由

- チケットは、ジョブが作るものを追うためのものである。外の作業を待つあいだも、あとで作るものがあるなら、チケットの依存の節で待ちを示せる（D1）。ジョブが作るもののない行をチケットにすると、待つだけの記録になり、秘書の決まりに反する（D2）。
- 同じ仕事を 2 つのチケットで追うと、範囲と受け入れ確認が食い違い、どちらを done にするかが決まらない。G-082 の仕事は YGO-078 の出し直しそのもので、G-083 の仕事は YGO-072 が触る `check.sh` の同じ段の並びにある。すでにあるチケットに寄せれば、点検が閉じ、範囲が 1 か所にまとまる（D3・D6・D7）。
- G-081 の仕事（ADR の置き換えと YGO-070 の取り下げ）は、すでにあるどのチケットの範囲にもない。YGO-078 の変更（`package.json` を入れる道具の追加）とは分ける（G-081 の行の予定、秘書の決まり「道具の追加・ADR の置き換えを 1 つのチケットに入れない」）ので、新しいチケットにする（D5）。

## 代わりの案（選ばなかった理由）

- **G-082 を G-080 にまとめ、YGO-088 で追う（仕分け 16 の案 (b)）**: チケットの題に G-NNN を 1 つしか置けないので、G-082 の行が点検で ✗ のまま残る。YGO-088 の範囲（一覧が動くのを確かめる）は YGO-078 の出し直しを含まない。
- **外待ちの行の理由の列の頭に `外待ち:` の句を付け、チケットを切らない（仕分け 16 の案 (c)）**: 句で区別する点検は秘書の固定コードの変更が入るまで効かず、それまで行が点検で ✗ のまま残る。待ったあとにジョブが作るものを追う場所がない。
- **G-082・G-083 にも新しいチケットを切る**: 新しいチケットの範囲が YGO-078・YGO-072 と重なり、同じ変更を 2 つのチケットで追うことになる。どちらを done にするかが決まらない。
- **外の作業を待つ行はすべてチケットにしない／すべてチケットにする**: 前者は点検が閉じず、後者はジョブが何も作らない行のチケットが待つだけの記録になる（ADR-0107 と同じ理由）。

## 影響

- `.ai/gaps.md` の冒頭の例外の文と G-080〜G-083 の行を、この ADR の D1〜D7 にそろえる。
- YGO-078 の題に G-082、YGO-072 の題に G-083 を足し、範囲と受け入れ確認をそろえる。YGO-078 の題を引く YGO-062 の受け入れ確認 12 を同じ題にそろえる。
- YGO-100（G-081）を `状態: open` で切る。YGO-070 の取り下げの書き方（取り下げの状態の行の形）は、まだ取り下げたチケットがないので、YGO-100 の変更が置き換える ADR で決める `[assumed]`。
- YGO-088 の ADR-0107 の参照を ADR-0108 にする。
