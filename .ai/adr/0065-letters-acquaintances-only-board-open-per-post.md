# 0065 — 手紙は知り合いにだけ。掲示板は投稿ごとにオープンにする

- 状態: 採用
- 日付: 2026-11-21

ADR-0049 を丸ごと置き換える。ADR-0049 の決定（D1〜D9）は同じ番号でこの ADR に移した。
書き直したのは D2・D4・D5・D6・D7・D9。D1・D3・D8 は ADR-0049 と同じ。D10〜D15 を足した。
相互にならない住所録の追加を止めることは、別の決定として ADR-0066 に書いた。

## 背景

ADR-0042 で、地図に自分の家・登録のときの候補・知り合い（自分の住所録に入れた住民）の家の印を付けると決めた。
範囲が答えになかった部分は、`open-questions.md` の OQ-066 で次の 4 点を聞いていた。
(1) どの家について、誰に、空き家か人がいるかを見せるか。(2) 何を「空き家」とするか（休眠・転送中の家の扱い、いつの状態か）。
(3) 知り合いの家の印に、相手の同意は要るか（相手が断れるか）。(4) 登録のときに地図の印から住所を選ぶか。
暫定は、(1)(2) 空き家・入居を表示しない（ADR-0042 の D10）、(3) 同意は求めない（ADR-0042 の D11）、(4) 一覧から選ぶ（ADR-0042 の D7）だった。

このとき、ほかの文書は次のとおりだった。住所録への追加に相互の承認は要らない（FR-052）。住民は他の住民宛に手紙を書ける（FR-012）。
手紙の宛先の確認は住所の形式と存在まで（`api.md` §7 F-04）。誰が自分を住所録に入れたかを知らせるかは OQ-040（持ち越し。暫定は MVP では知らせない）。

2026-11-20、マスターが OQ-066 に次のとおり答えた（原文）。

> 自由には手紙は出させない。掲示板経由、互いに住所検索で知り合い登録している場合のみ出せる。住所検索→追加に関しては、従来の鍵アカウントに近い形式で、その形式をデフォルトとして扱う
>
> また、従来の鍵アカウントと違う点としては、申請来ていることを確認できなくする。掲示板などで知り合って、手紙交換しましょう。となった場合は、許可する形にしたい。基本的には互いに追加を行う必要がある。
> そのため、通常の追加経路と、掲示板で相手がオープンにしている場合の毛色の２つ必要になる

答えは問いの (1)(2)(4) には触れておらず、(3) の「相手の同意」を広げて、手紙を誰に出せるかと、知り合いの登録の仕方を決めている。
答えから読み取れることと、読み取れないことを分ける。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 手紙は知り合いにだけ**（答え、`[inferred]`）: `POST /api/v1/letters` は投函のときに、宛先が送る人の知り合い（D2。掲示板の経路は D7）かを確かめる。
   段階 2 のグループ宛て（F-10）では、宛先の全員が知り合いかを確かめる。マッチング・商店・団体のアカウントとの手紙は OQ-082 で決める。
2. **D2 ふつうの経路は互いに住所録に入れること（既定）**（答え、`[inferred]`）: 住民 A と B が知り合いなのは、
   A の住所録のエントリの `address_book.registered_tenancy_id` が B の今の居住記録（`tenancies.is_current = true`）を指し、
   かつ B の住所録のエントリが A の今の居住記録を指すときだけとする。
   - 組にする 2 つのエントリは、どちらも住所を入れたエントリか、片方が投稿から足したエントリ（D7）で、もう片方がその経路で届いた手紙から足したエントリ（D15）のときだけ（OQ-081 の答えのあとの秘書の判断、`[assumed]`）。住所を入れたエントリと、住所を見せないエントリ（D7・D15）は組にしない（D13）。
   - この定義は ADR-0044 の D2（新聞の知り合い）と同じだが、**ブロックの条件は入れない**（秘書の判断）。ブロックは今までどおり配達のときの `suppressed` で扱い、送った人に気づかせない（`security.md` §7 の T-06）。
   - 新聞の知り合い（ADR-0044 の D2）だけは、これまでどおり、どちらかがブロックしていれば知り合いにしない。
   - 知り合いを表に保存しない。住所録と居住記録から、そのつど求める（ADR-0044 の D7 と同じ考え）。
3. **D3 足されたことは相手に知らせない**（答え「申請来ていることを確認できなくする」、`[inferred]`）: 足された側には、通知・一覧・件数・「申請」の資源・承認の経路のどれも作らない。
   足し返すことが承認にあたる。OQ-040（誰が自分を住所録に加えたかを知らせるか）は、これで決定にする（知らせない）。
4. **D4 足した側に見せるもの**（秘書の判断。上限を置くことは OQ-081 の答え 3）: `GET /api/v1/address-book` の各エントリに `acquainted`（真偽値）を足す。
   `acquainted` は「このエントリの相手に、本人が今このエントリ宛てに手紙を出せるか（D2 か、このエントリについて D7 を満たすか）」とする。宛先を選ぶとき（FR-053）に使う（地図の印には使わない。OQ-071 → 決定、2026-11-20、ADR-0051 の D3）。
   - 互いに足したときに初めて、足した側にも知り合いだと分かる。これは答えの「互いに追加」から避けられない。この程度の分かり方は許す（D13、OQ-081 の答え 3）。
   - 住所を入れた `POST /api/v1/address-book` は、住所がない・空き家・相手が足していない、のどの場合も同じ 201 と `acquainted: false` を返す（住所の列挙を防ぐ。`security.md` §7 の T-05）。D2 を満たせば `acquainted: true` を返す。住所を入れたエントリには D7 は効かない（D7 は投稿から足したエントリだけ）。
   - 住所録への追加は JST の暦日ごとに 1 日 20 件まで。上限を置くことは答え 3「上限の設定いいね」で決まり、値の 20 は `[assumed]`。超えたら 429 `daily_limit_reached`（探りを大量にできなくする）。
     数えるのは、エントリを作った `POST`（住所を入れたものも、投稿から足したもの（D7）も）と、住所を変えた `PATCH /api/v1/address-book/{id}`（`registered_tenancy_id` を取り直すので、同じ探りに使える）の両方。
     数は、エントリを消しても減らない別の表 `address_book_daily_counts`（住民と JST の暦日ごとに 1 行、`db.md` §2）に足す。`address_book` の `created_at` では数えない（消して足し直せば上限を越えられるため）。
     住所を変えない `PATCH`（メモだけ）・400・429 の要求は数えない。超えた `PATCH` は何も変えずに 429 を返す。
5. **D5 知り合いでない宛先**（秘書の判断）: 宛先が知り合いでないときは 422 `not_acquainted` を返し、何も保存せず、1 日の上限にも数えない。
   - 住所がない・空き家・どちらも足していない・片方だけ足している・投稿から足したエントリの投稿がオープンの掲載中でなくなった、のどの場合も同じ決まった文面にする（T-05）。
   - 確かめる順番は、形式の確認 → 知り合いの確認 → ルール表の照合（ADR-0069）。こうすると、知り合いでない相手への本文をルール表に当てない。
   - 確かめるのは投函のときだけ。投函したあとで知り合いでなくなった手紙（`pending`・`held` のものも、承認されたものも）は、そのまま配達の振り分け（`db.md` §3）に進める（ADR-0069 の D3 と同じ考え）。
6. **D6 住所録から消したとき・引っ越し・オープンを外したとき**（秘書の判断）: エントリを消すと、その時点から両方とも D2 の知り合いでなくなる。相手には知らせない（相手の画面では `acquainted` が false になるだけ）。
   引っ越しのあとは、ADR-0044 の D2 と同じく知り合いから外れる。手で住所を直せば（`PATCH /api/v1/address-book/{id}`）、そのときの居住記録に取り直し、相手も今の居住記録を指していれば戻る。転送との関係は段階 3（OQ-082）。
   投稿者がその投稿のオープンを外す・投稿を消す・退去する・引っ越すと、その時点からその投稿の D7 は効かない（投稿から足したエントリの `acquainted` は、D2 を満たさなければ false になる）。それより前に投函した手紙は D5 のとおり届く。
   投稿を消しても、投稿が物理削除されても（`db.md` §4）、投稿から足したエントリは消さない（住民が消すまで保持、ADR-0003）。投稿者が届いた手紙から X を足し返していれば（D15）、D2 の知り合いのまま。
7. **D7 掲示板の経路**（OQ-081 の答え 1「a」・2「a」、`[inferred]`。投稿に結び付ける形は `[assumed]`）: 住民 X は、Y のオープンの掲載中の投稿 P から、Y を住所録に足せる（`POST /api/v1/address-book` に住所ではなく `board_post_id = P` を渡す。D12）。
   そのエントリは `address_book.board_post_id = P` と、足したときの Y の居住記録（`registered_tenancy_id`）を持つ。
   そのエントリの `registered_tenancy_id` が Y の今の居住記録を指し、P が `status = 'published'`・`accepts_letters = true` の間、X はそのエントリ宛てに Y へ手紙を出せる。
   - 経路は投稿に結び付く。効くのは、そのオープンの投稿から足したエントリだけ。住所を入れて足したエントリや、ほかの投稿から足したエントリでは、P のオープンは効かない。
     このため、P を見ていない住民（Y の住所を知っているだけの住民・前から片方だけ Y を足していた住民）は、この経路では Y に出せない（答え 1「この投稿を見た人から手紙を受け取る」）。
   - 向きは X から Y だけ（D10）。ブロックは見ない（D2 と同じ。T-06）。
   - この関係は表に保存せず、住所録・居住記録・掲示板の投稿から、そのつど求める（D2 と同じ考え）。
   - X に住所録への追加を求めるのは、答えの「足し返す」を成り立たせるため。X のエントリは Y の居住記録を指すので、Y が X からの手紙で X を足し返すと（D15）D2 の互いの追加になる。
8. **D8 地図の知り合いの家の印**: 答えで、手紙を出せる知り合いには相手の同意（互いの追加か、掲示板でのオープン）が要ると決まった。答えは地図に触れていないので、地図の印は決めない。ADR-0042 の D11 は、この区別に合わせて書き直す。
   印を (i) 住所録のすべてのエントリに付けるか、(ii) D2 の知り合い（`acquainted: true`）だけに付けるかは OQ-071 にした。
   （追記 2026-11-20）OQ-071 → 決定（ADR-0051）: (i) 住所録のすべてのエントリに付ける（マスターの OQ-054 の答え「2:1」、ADR-0042 の D1 (c) のまま）。地図と手紙・新聞で「知り合い」の定義を分け、地図の印は `acquainted` で変えない。
   このため、地図の「知り合いの家」の印は手紙を出せる知り合いと一致しないことがある（片方だけ足した相手の家にも印が付く）。印は本人の住所録だけから描くので、相手について新しく分かることはない。
9. **D9 要求の区分**: FR-012・FR-052・FR-053・FR-058・FR-114・FR-115 を直し、FR-121（手紙は知り合いにだけ）と FR-122（2 つの経路と、足されたことを知らせないこと）を `[inferred]`（マスターの答え OQ-066（2026-11-20）より）として足す。
   OQ-081 の答え（2026-11-21）で、FR-121・FR-122・FR-053・FR-120 を直し、FR-125（相互にならない追加の停止、ADR-0066）を足す。
10. **D10 向きと許し方**（OQ-081 の答え 2「a。オープンにした時点で許したことになる形」、`[inferred]`）: 投稿者 Y から X へ出すには、D2（Y が X からの手紙で X を足し返す、D15）か、X 自身のオープンの掲載中の投稿から Y が X を足したこと（Y から見た D7）が要る。
    Y が投稿をオープンにした時点で、その投稿を見た住民（その投稿から Y を住所録に足した住民。D7）からの手紙を許したことになる。
    一人ずつ許す経路・申請・承認の経路は作らない（D3 と同じ。`api.md` §8）。
11. **D11 オープンの付け方・続く間・取り下げ**（`[assumed]`）:
    - `POST /api/v1/board/posts` は、任意の `accepts_letters`（真偽値、既定は false）を受け取る。
    - オープンが効くのは、投稿が `published` の間だけ（審査の前と、掲載の前は効かない）。期限は置かない。
    - 投稿者は `PATCH /api/v1/board/posts/{id}` で、いつでも `accepts_letters` を切り替えられる。受け取るのは `accepts_letters` だけで、ほかの項目があれば 400 `validation_failed`。
      本人以外（ほかの住民・モデレーター）と、`deleted` の投稿には 404 を返す（存在を明かさない）。
    - 本文は変わらないので、切り替えても審査し直さない。掲示板の投稿の 1 日の上限にも数えない。
12. **D12 オープンの投稿の示し方**（`[assumed]`）:
    - 掲示板の応答（`GET /api/v1/board`・`GET /api/v1/board/posts/{id}`・`GET /api/v1/me/board-posts`）は、各投稿の `accepts_letters` を返す。
    - 投稿者の住所は、オープンの投稿でも返さない。投稿と住所（ユーザー ID）を結び付けて見せない。宛先は投稿の ID で指す。
    - web は、オープンの掲載中の投稿に、住所録に足す導線を出す。足すのは `POST /api/v1/address-book` に `board_post_id` を渡す要求（住所は渡さない）。
      サーバーは、その投稿がオープンの掲載中で、投稿者が今住んでいて、本人の投稿でないときだけエントリを作る。そうでなければ 404 `not_found`（`GET /api/v1/board/posts/{id}` と同じ。オープンかどうかは掲示板で誰にでも見えるので、新しく漏れるものはない）。
    - 投稿から足したエントリは、住所録の応答で住所を返さず（`address: null`）、`source: "board_post"` と `board_post_id` を返す。web はそのエントリを「掲示板の投稿から足した相手」として、投稿の本文の冒頭とともに示す。
      投稿が消された・物理削除された（`board_post_id` が null）ときは、本文の冒頭の代わりに決まった文面「消えた掲示板の投稿から足した相手」と、足した日付・メモを示す（消えた本文の写しは持たない）。
    - そのエントリ宛ての手紙は、`POST /api/v1/letters` の宛先にエントリの ID（`address_book_entry_id`）を渡す。送信済みの一覧・詳細でも、そのエントリ宛ての手紙には宛先の住所を返さない。
    - 地図の知り合いの家の印は住所録の応答の住所から描く（ADR-0051）ので、住所を返さないエントリには印が付かない。
    - そのエントリの住所を `PATCH /api/v1/address-book/{id}` で入れると、住所を入れたエントリになり、`board_post_id` を外す（D7 は効かなくなる）。
13. **D13 探り**（OQ-081 の答え 3「上限の設定いいね」「ボーナスに判断を委ねる」）:
    - 足した側が、`acquainted` で相手もすでに自分を足していたと知れる程度は許す。守りは、D4 の上限と ADR-0066（相互にならない追加の停止）。
    - 投稿から足したエントリが D2 で true になるのは、投稿者がその経路で届いた手紙から足し返したエントリ（D15）と組になるときだけ（D2 の組の条件）。投稿者が前から住所を入れて X を足していても、組にしない。
      もし組にすると、オープンを外したあとも true のままのことで、X は「匿名の投稿 P の投稿者は、前から自分を足している住民だ」と分かり、自分が住所を入れて足したエントリの `acquainted` と突き合わせて、P の投稿者の住所まで絞れる。これは D12 の「投稿と住所を結び付けて見せない」と両立しないので、防ぐ。
    - このため、掲示板の経路で新しく分かるのは、投稿から足したエントリの `acquainted` が、投稿がオープンの掲載中の間は true で、取り下げると false に戻ること（オープンは掲示板で誰にでも見える）と、投稿者が届いた手紙から足し返したこと（投稿者が選んだ返事で、相手の住所は分からない）だけ。
      住所を入れたエントリの `acquainted` は掲示板のオープンでも投稿から足したエントリでも変わらないので、住所の列挙と探りの面は増えない。投稿者の側でも、住所を入れたエントリの `acquainted` は X が投稿から足しても変わらない。
14. **D14 新聞の知り合い**（OQ-070 (4)、秘書の判断）: 掲示板の経路（D7）だけの相手は、新聞の知り合いに含めない（ADR-0044 の D2 のまま）。
    D7 は片向きで、互いの繋がりではなく、足し返せば D2 になるため。
    投稿から足したエントリと手紙から足したエントリの組（D2・D15）も、新聞の知り合いに含めない。新聞の知り合いは、住所を入れたエントリどうしの組だけ（住所を見せない相手を、紙面で住民として結び付けて見せない）。
15. **D15 投稿者の足し返し方**（OQ-081 の答え 2「投稿者は足し返したら返事を出せる」、足し方は `[assumed]`）:
    - 掲示板の経路で届いた手紙（`letter_recipients.route = 'board_post'`）には、受け取った投稿者の郵便受けで差出人の住所を返さず、どの自分の投稿から届いたか（`board_post_id`）を返す。
    - 投稿者 Y は、その手紙の郵便受けの項目の ID（`mailbox_item_id`）を `POST /api/v1/address-book` に渡して、差出人 X を住所録に足せる（住所は渡さない・見えない）。エントリは X の今の居住記録を指し、`address: null`・`source: "letter"` を返す。
      差出人が退去・引っ越していた、掲示板の経路で届いた手紙でない、本人の郵便受けの項目でない（消したものを含む）ときは 404 `not_found`。同じ手紙から 2 度は足せない。1 日 20 件（D4）と ADR-0066 の停止に数える。
    - そのエントリと X の投稿から足したエントリは D2 の組になり、互いに `acquainted: true` になる（投稿のオープンを外しても続く）。Y はそのエントリ宛て（`address_book_entry_id`）に返事を出す。送信済みと X の郵便受けでも、Y の住所は返さない。
    - web はそのエントリを「掲示板の投稿に手紙をくれた相手」として、自分の投稿の本文の冒頭（消えていれば決まった文面）と、足した日付・メモとともに示す。
    - 足し返すことは X に通知しない（D3）。X は Y からの手紙か `acquainted` で分かる。
    - 住所を見せないエントリに住所を `PATCH` で入れると、住所を入れたエントリになり、相手の住所を見せないエントリとは組にならない（D2）。

## 理由

- D1〜D3 は OQ-066 の答えの原文による。「鍵アカウントに近い形式」で「申請来ていることを確認できなくする」と、承認は相手を足し返すことだけになる。申請の資源を作らなければ、申請の件数も一覧も生まれない（P-2）。
- D2 で居住記録を使うのは、ADR-0044 の D2 と同じく、住所録の住所の文字列は登録した時点のままで（ADR-0003）、今その住所に住んでいる人が知り合いとは限らないため（`db.md` §3）。
- ブロックを手紙の知り合いの条件に入れないのは、入れると、ブロックされた側の手紙が 422 になってブロックが分かってしまうため（T-06）。新聞はブロックした相手の投稿を本人だけの紙面に出さないためにブロックを入れており（ADR-0044 の D2）、見えるのは本人だけなので、そのまま変えない。D7 も同じ理由でブロックを見ない。
- D4・D5 で、どの場合も同じ 422・同じ 201 を返すのは、宛先の確認が「住所の形式と存在」まで分かる形より、住所を列挙しにくくするため（T-05）。
  1 日 20 件は手紙の 1 日 20 通（ADR-0004）にそろえた値。答え 3 で値を見直すよう任されたが、続けて探ることは ADR-0066 で止めるので、1 日の値を下げて住民のふつうの追加を窮屈にしなくてよい。
  数えを消しても残る表に置き、住所を変える `PATCH` も数えるのは、どちらかが抜けると上限が探りを止めないため。数えの表には住所を書かず、件数だけを置く（何を探ったかを残さない）。
- D5 で知り合いの確認をルール表より先にするのは、送れない手紙の本文を照合に使わず、`letter_needs_review` から「宛先は知り合い」と推し量らせないため。
- D6 は、足し返すことが承認なら、消すことが取り下げになるため。オープンを外すことも同じく取り下げ。知らせないのは D3 と同じ理由。
- D7・D10 は答え 1・2 による。答え 1 は「この投稿を見た人から手紙を受け取る」なので、経路を投稿から足したエントリに結び付け、投稿を見ていない住民には開かない。投稿を消せばオープンも終わる。
  X に住所録への追加を求めるのは、答え 2 の「足し返す」には、まず X が Y を足していることが要るため。住所録を通せば、宛先を選ぶ画面（FR-053）と 1 日の上限（D4）もそのまま使える。
- D11 で `published` の間だけにするのは、「この投稿を見た人」がいるのは掲載の間だけで、審査の前に住所を出さないため。期限を置かないのは、投稿者がいつでも外せ、投稿を消せば終わるので、期限の値とジョブを足さずに済むため。
  切り替えで審査し直さないのは、審査（ADR-0005）は本文に当てるもので、本文が変わらないため。
- D12 は、掲示板の投稿はほかでは投稿者を示しておらず、投稿と住所（ユーザー ID）を結び付けて見せるかは公開の範囲で、答えが触れていないため。宛先を投稿の ID とエントリの ID で指せば、住所を見せずに「見た人から手紙を受け取る」が成り立つ。
- D13 は答え 3 による。答え 3 が許したのは、足した側が相手もすでに自分を足していたと知れる程度で、匿名の投稿と住所を結び付けることは含まない。D2 の組を `source` で分ければ、D7 で分かることは掲示板で誰にでも見えることと投稿者が選んだ返事だけになり、探りの面は増えない。
- D15 は、答え 2 の「足し返す」に、住所を見せずに成り立つ道を作るため。届いた手紙は投稿者がオープンにして受け取ったもので、差出人は投稿者に手紙を出すことを選んでいるので、その手紙から足せれば足りる。住所を入れて足す道にすると、差出人の住所を投稿者に見せることになり、D13 の組の条件で組にならない。
- D6・D12 で投稿が消えてもエントリを残すのは、住所録は住民が消すまで保持する（ADR-0003）ためと、足し返されたエントリの D2 を投稿の保持期間で切らないため。
- D14 は、新聞の知り合いが「コミュニティ内の繋がり（双方向性）を可視化して楽しむための機能」（OQ-071 の答え）で、片向きの D7 はその繋がりに当たらないため。足し返せば D2 になり、新聞の知り合いにも入る。

## 代わりの案（選ばなかった理由）

- **申請の一覧と承認の経路を作る（ふつうの鍵アカウントの形）**: 答えの「申請来ていることを確認できなくする」に反する。
- **知り合いでない宛先の手紙も受け付けて、黙って届けない**: 送る人を欺くことになり、答えの「自由には手紙は出させない」（出せないことが分かる形）とも合わない。
- **知り合いの条件にブロックを入れる（新聞と同じにする）**: 422 でブロックが分かる（T-06）。
- **知り合いでない理由ごとに別の応答にする（住所がない・空き家・相手が足していない）**: 住所の列挙と、相手が自分を足したかの探りに使える（T-05）。
- **知り合いを表に保存する**: 住所録・引っ越し・オープンの切り替えのたびに直す処理が要る。そのつど求めれば足りる（ADR-0044 の D7 と同じ）。
- **`acquainted` を返さない**: 宛先を選ぶ画面（FR-053）で、どのエントリに出せるかが分からず、送るたびに 422 を受けることになる。互いに足したことは、送ってみれば分かるので、返さなくても守りにならない。
- **オープンを住民の設定にする（答え 1 の (b)）**: 答え 1 が (a) を選んだ。
- **最初の手紙が届いたら両方向に出せる（答え 2 の (b)）**: 答え 2 が (a) を選んだ。
- **投稿者が手紙を出したい相手を一人ずつ許す**: 答え 2「オープンにした時点で許したことになる形」と食い違う。許す操作は、足された側に「申請」を見せる形にもなる（D3）。
- **住所録に足さずに、オープンの投稿から直接手紙を出せるようにする**: 宛先を選ぶ画面と 1 日の上限が別に要り、投稿者が足し返して D2 になる道が分かれる。住所録を通せば同じ仕組みで済む。
- **オープンに期限を置く（例: 30 日）**: 期限の値と、期限を切るジョブが要る。投稿者はいつでも外せる。
- **掲載の前（`approved`）からオープンを効かせる**: その投稿はまだ誰にも見えておらず、「この投稿を見た人」がいない。
- **投稿者がオープンの掲載中の投稿を持てば、Y を足しているどの住民からも出せる**: 投稿を見ていない住民（住所を知るだけの住民・前から片方だけ足していた住民）にも開き、答え 1 の「この投稿を見た人」より広い。住所を入れたエントリの `acquainted` が掲示板のオープンで変わるので、探りにも使える。
- **オープンの投稿に投稿者の住所を出す**: 投稿と住所（ユーザー ID）を結び付けて全住民に見せることになり、公開の範囲を広げる。宛先を ID で指せば要らない。
- **住所録の 1 日の上限を下げる（例: 10 件）**: 続けて探ることは ADR-0066 で止めるので、ふつうの追加を窮屈にするだけ。
- **住所を入れたエントリと投稿から足したエントリも D2 の組にする**: 投稿者が前から X を足していると、オープンを外したあとも true のままになり、匿名の投稿と住所を結び付けられる（D13）。
- **届いた手紙に差出人の住所を示し、投稿者は住所を入れて足し返す**: 差出人の住所を投稿者に見せ、住所を入れたエントリと住所を見せないエントリの組にもなる（D13・D15）。
- **投稿の物理削除で投稿から足したエントリも消す（`ON DELETE CASCADE`）**: 足し返されて知り合いになった相手が、黙って住所録から消える（D6）。
- **新聞の知り合いに掲示板の経路を含める**: 片向きの経路で、相手の投稿を見ただけの住民の紙面に、その相手を知り合いとして出すことになる（D14）。

- 地図の印を、住所録のすべてのエントリに付けるか、知り合いだけに付けるか: OQ-071 → 決定（2026-11-20、ADR-0051）。(i) 住所録のすべてのエントリ（D8）。
