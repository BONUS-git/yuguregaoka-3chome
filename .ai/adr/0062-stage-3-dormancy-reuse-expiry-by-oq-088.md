# 0062 — 休眠と再割り当ては段階 3、長期不在の退去は OQ-088 次第

- 状態: 採用
- 日付: 2026-11-21

ADR-0023 を丸ごと置き換える。ADR-0023 の決定のうち、MVP の住所の候補・MVP で起きる遷移・再割り当てを入れるときの受け入れ条件は、同じ中身でこの ADR に移した。

## 背景

ADR-0060 は、休眠（`dormant`）を入居と扱い、ログインしないだけでは空き家にしないと決めた（D2）。
休眠から空き家（`vacant_expired`）に移すか・その閾値は OQ-088（持ち越し）の答えまで決めず、答えまでその移行とジョブを作らない（D3）。
空き家（`vacant_deleted`・`vacant_forwarded`）は新しい住民の割り当て候補になる（D5）。
`features.md` は空き家と再割り当て（FR-071・FR-072・FR-074）を F-16（段階 3）に置いている。
この ADR は、これらをどの段階で作るかを決める。

## 決定

1. **D1 段階 3 で作るもの**: 休眠（J10・J12）・転送の期限切れ（J11）・空き家の再割り当て（`vacant_*` → `active`）は段階 3（F-16）に置く。
2. **D2 長期不在の退去**: 長期不在の退去（J9、`vacant_expired` から 12 か月たった元住民の J7）は、OQ-088 の答えで `dormant` から `vacant_expired` への移行を作るときだけ、その移行と同じ変更で作る（ADR-0060 の D3）。答えまで、どの段階でも作らない。
3. **D3 MVP の候補**: MVP の住所の候補（`GET /api/v1/addresses/candidates`）は、使われたことのない住所だけを返す。
4. **D4 MVP の遷移**: MVP で起きる住所の遷移は「割り当て（→ `active`）」と「アカウント削除（`active` → `vacant_deleted`、J7）」の 2 つだけ。
   `vacant_deleted` の住所は段階 3 まで候補に戻さない。
5. **D5 再割り当ての受け入れ条件**: 段階 3 で再割り当てを入れるときは、引っ越しと転送（J11）と同じ変更で、db.md §3 の居住記録による振り分けの
   テスト（前の住民あての手紙が新しい住民に届かないこと）を受け入れ条件にする（roadmap.md C-04）。

## 理由

- 休眠・再割り当て・転送は同じ住所の状態遷移（db.md §4）と同じ毎日のジョブの群（J10〜J12）で、
  まとめて作るとテストもまとめられる。
- D2 は ADR-0060 の D3 による。`vacant_expired` になる住所が出ない間、その元住民を退去させるジョブは動く対象がない。
- 休眠は 12 か月たたないと起きない（ADR-0060 の D2）。MVP の体験（朝、ポストを開ける）には関係しない。
- 再割り当ては、住所録の古い住所あての手紙が新しい住民に届く事故の元になる。居住記録による振り分けを、
  転送と一緒に確かめてから入れるほうが安全である。
- 休眠の通知は、バッチが住民へ定期的に送るメール（ADR-0033。本番のサービスはマスターの事前承認を得て選ぶ）である。
  段階 3 に置くと、MVP がメール送信に頼る範囲が認証の流れ（登録の確認・パスワードの再設定）と
  漏えい時の連絡（security.md §6.4）だけになる。
- 想定規模（ADR-0012、住民 1 万人）に対し、使われたことのない住所のプールを十分に用意できる [assumed]。

## 代わりの案（選ばなかった理由）

- **J9 を段階 3 で先に作っておく**: `vacant_expired` への移行がないので動く対象がなく、OQ-088 の答えで閾値や扱いが変われば作り直しになる。
- **MVP から休眠と再割り当てを入れる**: MVP の範囲が広がるうえ、転送のない状態で再割り当てを入れることになり、
  振り分けの組み合わせを 2 回に分けて確かめることになる。
- **空き家を作らない（`vacant_deleted` も作らない）**: ADR-0060 の D1・ADR-0013 のアカウント削除の扱いと食い違う。

## 決めていないこと

- 休眠を空き家にするか・その閾値（J9 を作るかを含む）: OQ-088（持ち越し）。

## 影響

- ADR-0023: 状態を `置き換え（→ 0062）` にする。ADR の README の一覧。
- ADR-0013 の「長期不在による空き家化後の処理」: J9 と同じく、OQ-088 で `vacant_expired` への移行を作るときだけ当てる（ADR-0060 の D3）。
- `async.md` §2: J10〜J12 は段階 3、J9 は OQ-088 の答えで作るときだけ。
- `architecture.md` §5・`api.md` §2.2 と §7 F-01・`db.md` §4 と §7・`features.md`・`roadmap.md`: ADR-0023 の参照をこの ADR に付け替える。
