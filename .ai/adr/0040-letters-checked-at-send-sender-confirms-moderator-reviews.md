# 0040 — 手紙は送るときにルール表に当てる。当たったら送った人に確認を頼むかを選んでもらい、頼んだ手紙をモデレーターが確かめる

- 状態: 置き換え（→ 0056）
- 日付: 2026-11-20

## 背景

OQ-003 の答え（ADR-0026）で、クローズドな手紙も配達の前に審査し、本文は LLM に渡さずルール表だけで照合すると決まった。
OQ-043 の答え（ADR-0036）で、通報された手紙はモデレーターが条件付きで確かめてよいと決まった。
答えに書かれていなかった次の 3 点を、`open-questions.md` の OQ-052 でマスターに聞いていた。
(1) 手紙で止める内容（ルール表のどの項目を手紙に当てるか）。
(2) ルール表に当たって止めた手紙を、モデレーターが見てよいか（誤判定の確認・送った人の異議）。
(3) 住民の年齢で守り方を変えるか（年齢の扱いは ADR-0041）。
暫定は、本番のルール表に手紙に当てる項目を置かない（テストは偽の規則）・止めた手紙は人が見ない・年齢は集めない、だった。
手紙は締め切りのあとに worker の J2 で照合し、当たれば `blocked` にして配達しない形だった（ADR-0026 の D3）。

2026-11-20、マスターが OQ-052 に次のとおり答えた（原文）。

> 20以上でも危険な機能は設けない想定なので、年齢はユーザーの入力信用すればいいと思う。理由としては、高齢者が若く設定や、若い人が高齢者として設定など、完全に架空の自分になることも許容したいから。設定と別々で持つ必要はなく、設定した年齢がそのままこの世界に反映される。
>
> １：手紙で止めるのは一般的なスパムや外部リンク、18禁ワード等
> ２：送った人の異議は有用だね。ただ、配達に影響するので、送信時点でチェック、引っ掛かったらポップアップでy/n選んでもらって、モデレーター確認かな
> ３：変える。

この ADR は (1)(2) を扱う。冒頭の段落と (3) は ADR-0041 で扱う。
答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと |
|---|---|---|
| 1 | 手紙に当てる項目は、スパム・外部リンク・成人向けの言葉 | 「等」に入るもの（この変更では足さない）・スパムの決め方・言葉の一覧の中身と置き場 → OQ-065（持ち越し） |
| 2 | 照合は送るとき。当たったら、送った人がポップアップで y / n を選ぶ。そのあとモデレーターが確かめる | y と n がそれぞれ何を指すか（下の D4 で読み取った）・ポップアップの文言・長く確かめられない手紙の扱い → OQ-065（持ち越し） |

答えの 2 は、送った人の異議を配達の前に受ける形を選んでいる。止めたあとで異議を受けると、配達が遅れる（「配達に影響するので」）。
そこで、送るときに照合し、当たった手紙はその場で送った人に選んでもらう。
これは ADR-0026 の D3（締め切りのあとに J2 で照合し、当たれば `blocked`）と、D4 の (b)（worker の中の照合）を置き換える。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 手紙に当てる項目**（答え 1、`[inferred]`）: 本番のルール表で手紙に当てる項目は、次の 3 種類にする（`security.md` §5.1）。
   - `spam`: 一般的なスパム（宣伝や勧誘の決まり文句・同じ文の繰り返しなど）。
   - `external_link`: 街の外へのリンク（URL の形の文字列）。
   - `adult_words`: 成人向け（18 禁）の言葉。
   - メールアドレスと電話番号は `external_link` に含めない（秘書の判断）。連絡先の共有の禁止は手紙に及ばない（ADR-0034 の D2）ので、それとそろえる。偽の連絡先を含む手紙は今までどおり届く（`roadmap.md` A-06）。
   - 成人向けの言葉の一覧は、公開レポジトリに置かない（秘書の判断。一覧を置くと、避け方の手引きになり、レポジトリに成人向けの言葉が並ぶ）。テストは偽の規則（例: 目印の文字列 `EXAMPLE_LETTER_RULE_DO_NOT_USE`）で確かめる。
   - 答えの「等」に入る項目は、この変更では足さない。足すときは、この ADR を改めて理由を書く。違法な物の取引の守りは OQ-053（持ち越し、別のチケット）のまま。
   - スパムの決め方・外部リンクの形の細部・言葉の一覧の置き場は OQ-065（持ち越し）。
2. **D2 照合は送るとき、API で行う**（答え 2「送信時点でチェック」、`[inferred]`）:
   - `POST /api/v1/letters` で、API（C3 の手紙のサービス）が本文を暗号化する前に、ルール表のうち手紙に当てる項目に当てる。
   - 平文はメモリの中だけに置き、DB・ログ・ジョブのペイロード・例外のメッセージに書かない。照合のために本文を復号することはない（暗号化の前の平文を使う）。
   - LLM は呼ばない（ADR-0026 の D2 は変わらない。API の経路で LLM を呼ばない、`api.md` §1 の 5）。
   - 照合に使ったルール表の版を `letters.rule_version` に、当たった規則の ID を `letters.matched_rule_id` に残す（当たらなかった手紙は版だけ）。本文の抜き書きは残さない。
   - worker は手紙を照合しない。J1 は `moderation_queue` に手紙の行を入れず、J2 は手紙を扱わず、J4 は判定を見ずに `scheduled` の手紙をすべて準備する（`async.md` §4）。
3. **D3 送ったときに当たらなかった手紙は、配達の前に当て直さない**（秘書の判断）:
   ルール表の版が上がっても、すでに受け付けた手紙（`pending` / `scheduled`）は当て直さない。
   当て直すと、送った人が y / n を選べないまま止まる手紙が出て、答えの 2 の流れと食い違う。新しい版は、そのあとに送る手紙から効く。
4. **D4 当たったときの y / n**（答え 2「引っ掛かったらポップアップでy/n選んでもらって」、`[inferred]`）:
   - 当たったら、API は何も保存せずに 422（`letter_needs_review`）を返す。どの規則に当たったか・理由は返さない。1 日の上限にも数えない。
   - web はポップアップで、モデレーターに確かめてもらって送るか（y）、送らないか（n）を送った人に選んでもらう。
     y を選ぶと、モデレーターが本文を読むことをポップアップに書く（文言は OQ-065）。
   - **n**: 何も保存しない（秘書の判断）。手紙は送られず、下書きも残さない。送った人は本文を直して送り直せる（直した本文はもう一度照合する）。
   - **y**: web が同じ本文と宛先に `request_review: true` を付けて送り直す。API はもう一度照合し、当たれば `held`（確認待ち）で保存する。
     `held` の手紙は配達回に入れず（`delivery_run_id` は NULL）、1 日の上限に数える（送った手紙なので）。送った人の送信済みには「確認中」と見せる。
     送り直した本文がどの規則にも当たらなければ、ふつうの手紙として `pending` で保存する。
   - 「y / n」を「確認を頼んで送る / 送らない」と読むのは秘書の読み方。答えの「モデレーター確認」は y のあとの段と読んだ。
5. **D5 モデレーターの確認**（答え 2「モデレーター確認」、`[inferred]`）:
   - 経路は `/api/v1/admin/held-letters` の下の 3 つ（`api.md` §7 F-08）。
     - 一覧（`GET /api/v1/admin/held-letters`）: 本文を含めず、ID・送った日時・当たった規則の ID だけを返す。呼んだモデレーターが当事者の手紙は出さない。総件数は返さない。
     - 1 通の取得（`GET /api/v1/admin/held-letters/{id}`）: 本文を 1 通だけ復号して返す。
     - 操作（`POST /api/v1/admin/held-letters/{id}/actions`）: `approve` / `reject` だけ。ほかの値は 400。
   - 条件は、通報された手紙を確かめる経路（ADR-0026 の D4 (c)・ADR-0036 の D2）と同じ: 手紙が `held`・モデレーターがその手紙の当事者（送った人・宛先の住民）でない・
     セッションが二要素認証を済ませている・1 回の操作で 1 通だけ・取得のたびに `moderation_actions` に `view_letter` の行を書く（書けなければ本文を返さない）・
     応答は `Cache-Control: no-store`・条件に合わなければ 404。
   - `approve`: `held` → `pending` にし、`nextDeliveryRun(now)` の配達回に入れる（送るときと同じ `FOR SHARE` の手順、`api.md` §2.3）。次の配達回で届く。
   - `reject`: `held` → `blocked`。送った人には「届けられませんでした」と見せ、当たった規則・理由は見せない（ADR-0026 の D5 のまま）。受け取るはずだった人には何も見せない。
   - 操作は `moderation_actions` に `letter_id` 付きで残す（`db.md` §2）。
   - モデレーターが見てよい手紙は、通報された手紙と、送った人が y を選んで確認を頼んだ `held` の手紙だけ。`blocked` になった手紙・`pending` の手紙を見る経路は作らない。
6. **D6 保持**:
   - `held` の手紙は、モデレーターが操作するまで保つ。長く確かめられないときの扱いは OQ-065（持ち越し）。
   - `blocked` の本文と宛先は、`blocked` にしてから 30 日で消す（J14、ADR-0013）`[assumed]`。
   - 送った人が退去したら、その住民の `held` と `blocked` の手紙は本文と宛先ごと消す（J7）。届いていないので、受け取った人を守るために残す理由（ADR-0013）がない。
7. **D7 流量の制限**: 422（`letter_needs_review`）は、規則を探る手がかりになる（`security.md` §7 の T-22）。住民ごとに数え、超えたら 429（`rate_limited`）を返す。値は OQ-065（持ち越し）。
8. **D8 段階**: MVP の M4 で作る（`roadmap.md` §4）。M2 の投函は照合なしで作り、M4 で送るときの照合・`held`・モデレーターの経路を足す。
9. **D9 要求の区分**: FR-112 を足す。FR-078・FR-080・NFR-005 を直す。どれも `[inferred]`（マスターの答え OQ-052（2026-11-20）より）。

## 理由

- D1 は答え 1 による。メールアドレスと電話番号を外部リンクに含めないのは、OQ-041 の答え（連絡先の共有の禁止は手紙に及ばない）と食い違わないようにするため。
  言葉の一覧を公開しないのは、公開レポジトリの決まり（CLAUDE.md）と、一覧が避け方の手引きになることによる。
- D2 は答え 2 の「送信時点でチェック」による。API は投函のときに平文を受け取っているので、照合のために復号する場面が増えない。
  worker の照合（ADR-0026 の D4 (b)）がなくなるので、復号の場面は減る。照合は決められた規則で決定的に行い、LLM を使わない（NFR-011）。
  送るときの照合は即時に止めるものではない（送った人が選び、止めるかはモデレーターが決める）ので、FR-077（非同期のモデレーション）とも食い違わない。
- D3 は、答え 2 の流れ（当たったら送った人が選ぶ）を、すべての止める場面に保つため。
- D4 の n で何も保存しないのは、送られなかった手紙の本文を DB に残さないため（データ最小化、NFR-002）。
  y で `held` にするのは、送った人が確認を頼んだ手紙だけを人が読む形にするため。答えの「送った人の異議は有用」を、異議を出した手紙だけを人が見る形で受ける。
  ADR-0036 の「ある程度の秘匿性は担保しないと」にもかなう（読むのは、送った人が頼んだ手紙だけ）。
- D5 の条件を通報された手紙とそろえるのは、モデレーターの内部不正（`security.md` T-12）への抑えを同じにするため。`blocked` を見る経路を作らないのは、確かめ終わった手紙を見る目的がないため。
- D6 の 30 日は、送った人の問い合わせと、モデレーターの操作の確かめ（`moderation_actions` は 1 年）のための短い期間として仮に置いた。
- D7 は、ルール表を公開しない（D1）ことを、試し送りで崩されないようにするため。

## 代わりの案（選ばなかった理由）

- **今のまま締め切りのあとに J2 で照合し、当たれば止める**: 答え 2 の「送信時点でチェック」と食い違う。送った人が選べない。
- **当たった手紙を、送った人に聞かずに `held` にしてモデレーターが見る**: 答え 2 の「y/n選んでもらって」と食い違う。送った人が頼んでいない手紙を人が読むことになる。
- **n を選んだ手紙を `blocked` として残す**: 送らないと選んだ手紙の本文が DB に残る。残す目的がない。
- **当たった規則を 422 で送った人に返す**: 規則を探る手がかりになる（ADR-0026 の D5 と同じ理由）。
- **ルール表の版が上がったら、受け付けた手紙を当て直す**: 送った人が選べないまま止まる手紙が出る（D3）。
- **メールアドレス・電話番号も外部リンクとして止める**: OQ-041 の答え（ADR-0034）と食い違う。
- **成人向けの言葉の一覧をレポジトリに置く**: 公開レポジトリで、避け方の手引きになる。

## 決めていないこと

- スパムの決め方・外部リンクの形の細部・成人向けの言葉の一覧の置き場・ポップアップの文言・D7 の流量の制限の値・長く確かめられない `held` の手紙の扱い・
  モデレーターが `reject` した手紙への異議: OQ-065（持ち越し。M4 の前に秘書が決める）。
- 年齢で手紙に当てる項目を変えるか: OQ-063（要回答、ADR-0041）。答えまで、すべての住民に同じ項目を当てる。
  （追記 2026-11-20）OQ-063 → 決定（ADR-0047 の D1）: 年齢で変えない。D1 の項目は、送る人・受け取る人の年齢に関係なく全員に同じに当て、ルール表に年齢の条件を持たせない。
  答えの「一律、問題がある記載は一才許可しない」が、当たった手紙を送った人の確認とモデレーターの承認でも届けず一律に止めるという意味かは読み切れないので、
  OQ-076（要回答）で聞く。暫定（答えまで）は D4・D5 の流れのまま。一律に止めるなら D4（y で `held` にする）・D5（`approve` で届ける）が変わる（ADR-0047 の D1）。
- 違法な物の取引の場にしないための守り: OQ-053（持ち越し、別のチケット）。
- 違反した住民への処置: OQ-048（持ち越し、ADR-0032）。
- `blocked` の本文の保持（30 日）は仮置き `[assumed]`。
