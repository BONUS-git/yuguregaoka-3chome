# 0103 — 最初のロックファイルは依存を足す変更で作る

- 状態: 採用
- 日付: 2026-11-26

仕分け 9 回目の K-018（`.ai/triage.md`）による。出どころは `.ai/retros.md` の 2026-11-26 の YGO-062 の 2 節。
ADR-0052（手元で再現できる環境、`check.sh` はネットワークなし）の決定は変えない。この ADR は、ADR-0052 が前提にしているロックファイルを最初にどう作るかを決める。

## 背景

`environment.md` §3.1 は依存をロックファイルで固定し、依存を変えるときは `scripts/prepare.sh` とマニフェスト・ロックファイルを同じ変更で直すと決めている。§3.2 の 1 と §5 は、ネットワークを使うのを `prepare.sh` の依存の取り込み（`npm ci` と、IaC のコードを書いたあとの `tofu init -backend=false`。ADR-0052 の D3・D6）だけとしていた。
`npm ci` はロックファイルがないと失敗する。最初のロックファイルを作るにはネットワークを使う `npm install` が要るが、それをいつ・誰が動かすかがどの文書にもなかった。
YGO-062（M1 のテストの土台）の 1 回目はロックファイルがなく依存の準備で止まり、2 回目は変更を 1 つも作らずに終わった（`retros.md`）。

## 決定

最初のロックファイルを作る手順を次のとおりにする。

- **D1 依存を足す変更の中で 1 回だけ作る**: `package.json` を書いたあと、その変更の中で `npm install --package-lock-only --ignore-scripts` を 1 回試す。ADR-0052 が `prepare.sh` に認めるネットワークの利用（`npm ci` と、IaC のコードを書いたあとの `tofu init -backend=false`。ADR-0052 の D3・D6）のほかに、ネットワークを使ってよい例外はこの 1 つのコマンドだけで、`sh scripts/check.sh` はネットワークなしのまま（NFR-063）。作れたら、できた `package-lock.json` を `package.json` と同じ変更に入れる。終える前に `sh scripts/prepare.sh` と `sh scripts/check.sh` を動かし、どちらも終了コード 0 で終わることを確かめる。
- **D2 作れなかったら止まった段を残す**: ロックファイルを手で書かない。止まった段（ロックファイルの作成）と出たエラーの行をそのままチケットの「確かめた事実」に書き、それまでの段のファイルを変更として出す（変更 0 件で終えない）。秘書の準備の段階がロックファイルを作ることは当てにしない。
- **D3 `prepare.sh` はロックファイルを作らない**: `package.json` があり `package-lock.json` がないとき、`scripts/prepare.sh` はロックファイルを作らず、「依存を変える変更の中でロックファイルを作ってコミットする」と出して終了コード 1 で止まる。ロックファイルがあるときは `npm ci` だけを動かす。

## 理由

- ロックファイルを依存の変更と同じ変更に入れれば、秘書の準備の段階・CI・手元のどれでも `npm ci` で同じ依存が入る（ADR-0052 の手元で再現できる環境）。
- `--package-lock-only --ignore-scripts` は `node_modules` を作らず、依存の install のスクリプトも動かさないので、ジョブの中で動かしても作業のディレクトリを汚さず、外のコードを実行しない。
- 1 回目に観測した準備の段階の出力は、ロックファイルを作らずに失敗し、変更の側がコミットすることを求めていた。準備の段階が作ってくれるという前提はこの出力と合わない。
- 手で書いたロックファイルは整合性のハッシュが本物と合わず、`npm ci` が失敗するか、確かめていない中身を固定してしまう。止まった段を残せば、次の変更が同じところから進められる（`retros.md` の 2 回目の再発防止）。
- `prepare.sh` がロックファイルを作ると、変更に入っていないロックファイルで検証が通り、コミットされたものと検証したものが食い違う。

## 代わりの案（選ばなかった理由）

- **秘書の準備の段階が `npm install` でロックファイルを作る**: 観測した準備の段階の動きと合わず、作ったロックファイルが変更に入らない。
- **ロックファイルを使わず `npm install` で入れる**: 依存の版が日ごとに変わり、手元と CI で同じにならない（ADR-0052）。
- **ネットワークの例外を作らない**: 最初のロックファイルを作る手段がなくなり、YGO-062 が進まない。

## 影響

- `environment.md` §3.1・§3.2 の 1・§5 に、この例外と `prepare.sh` の動きを書く。
- YGO-062 の範囲と受け入れ確認に D1〜D3 を足すのは、次の YGO-062 の実装の変更の始め（`retros.md` の再発防止のとおり）。`check.sh` の確かめ（ロックファイルがない・依存の名前がロックファイルにない）も、その変更で足す。
