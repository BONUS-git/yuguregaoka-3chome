# 0005 — モデレーション方針

- 状態: 採用
- 日付: 2026-11-19

## 背景

構想では「AI による非同期モデレーション」と「セキュリティ上の判断を LLM の自由裁量に
依存させない」の両方が求められている（FR-076, FR-079, NFR-011）。
モデレーションの実行タイミング・LLM の役割・違反ユーザーへの対応が未確定だった。

## 決定

### 実行タイミング

配達の締め切りから配達時刻までの間にモデレーションを完了させる。
承認されていないコンテンツは届けない（FR-080）。

### LLM の役割

LLM は分類ラベル（`ok` / `review` / `block` のいずれか）を返すだけとする。
公開してよいかの最終判断は、ラベルとポリシールール表の突合により決定する（NFR-012）。
LLM がラベルの根拠を返しても、公開可否の自由裁量は与えない。

### クローズドな手紙（ADR-0026 で追記、2026-11-19）

クローズドな手紙も配達の前に審査するが、LLM は使わない。手紙の本文は LLM に渡さず、ルール表だけで照合する
（当たらなければ配達、当たれば `blocked`、打ち切りまでに判定できなければ次の便へ持ち越す）。
上の「LLM の役割」は掲示板の投稿だけに当てはまる。詳細は ADR-0026。

### 安全機能

- **ブロック**: 住民は他の住民をブロックでき、ブロック済み住民からの手紙は届かない
- **通報**: 住民は投稿・手紙を通報できる（通報先はモデレーター；ロールは ADR-0020 で決定、OQ-031）
- **1 日の送信上限**: 住民 1 人あたり手紙を 1 日 20 通まで、掲示板投稿は 1 日 5 件まで

## 理由

- 配達前完了により、問題のあるコンテンツが住民に届く前に止められる
- LLM がラベルを返すだけにすることで、LLM の誤判定が直接ポリシー適用に影響しない
- ブロック・通報・送信上限はハラスメント対策として基本的な機能
- 送信上限はスパム抑止と冪等性設計の単純化にも寄与する

## 代わりの案

**配達後にモデレーションして遡及削除**: 住民が一度受け取った内容を後から消すと
体験を損なう。不採用。
**LLM が公開判断まで行う**: NFR-011 に反するため不採用。

## 影響

- 非同期処理: `async.md` でモデレーションバッチと LLM インターフェースを設計する
- セキュリティ: `security.md` でポリシールール表とブロック・通報の仕様を定義する
- API 設計: ブロック・通報・送信上限チェックの API を設ける
