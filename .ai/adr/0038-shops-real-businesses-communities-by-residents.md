# 0038 — 商店には実在の企業・個人のお店を迎えることを目指す。コミュニティ（団体）は住民が趣味などで作り、作ることに制約を置く

- 状態: 採用（D1 の迎え方は ADR-0043 で決めた）
- 日付: 2026-11-20

## 背景

OQ-006 の答え（ADR-0029）で、商店・団体のアカウントは管理者が運用者の CLI で作り、住民は開けないと決まった。
答えに書かれていない次の 2 点を、`open-questions.md` の OQ-045 でマスターに聞いていた。
(1) 商店街の商店・団体は誰か（実在の企業・お店／運営が作る架空の店・団体／住民の団体／その組み合わせ）。
(2) 管理者が作ったあと、商店・団体として発信するのは誰か。
暫定はなく、F-17（段階 3 の S3-2）は OQ-045 の答えまで止まっていた（ADR-0022 の決定 6）。

2026-11-20、マスターが OQ-045 に次のとおり答えた（原文）。

> 商店に関しては実在の企業や個人ショップ経営者を入れるのが理想。コミュニティは趣味などでユーザーが作る。無制限は難しいので、何かの制約を設けたい

答えから読み取れることと、読み取れないことを分ける。

- 「商店に関しては実在の企業や個人ショップ経営者を入れるのが理想」: 商店には実在の企業・個人のお店を迎えることを目指す。
  「理想」と書かれていて、どう選ぶか・本物であることをどう確かめるか・契約や利用料・実在の店が来るまでの扱い・作ったあと誰が発信するか・
  商業の発信で何を許すか（広告・折込チラシ（F-20、FR-083）との境）・経営者など実在の人の情報をどこまで出すかは書かれていない。
- 「コミュニティは趣味などでユーザーが作る」: コミュニティは住民が作る。構想 §2-A の「趣味のコミュニティ」・§2-C の「商店街・地域コミュニティ」と合う。
  OQ-045 の問い (1) の例 (c)「住民の団体（サークル・町内会のような集まり）」に当たるので、秘書の読み方として、答えの「コミュニティ」を F-17 の「団体」と読む。
  ADR-0029 の D1「住民は商店・団体を開けない」のうち、団体の部分がこの答えで変わる。
- 「無制限は難しいので、何かの制約を設けたい」: コミュニティを作ることに制約を置く。制約の中身は書かれていない。
- 問い (2)（作ったあと誰が発信するか）には、商店については答えがない。コミュニティについては、住民が作ることまでは読み取れるが、誰が発信できるかは書かれていない。

## 決定

1. **D1 商店は実在の企業・個人のお店を迎えることを目指す**（マスターの答えの「実在の企業や個人ショップ経営者を入れるのが理想」より、`[inferred]`）:
   商店街の商店には、実在の企業・個人のお店を迎えることを目標とする。答えが「理想」と書いているので、目標として決め、迎え方は決めない。
   迎え方（選び方・本物であることの確かめ方・契約や利用料・実在の店が来るまでの扱い・作ったあと誰が発信するか・商業の発信で許すことと F-20 との境・実在の人の情報の出し方）は、
   法・倫理・費用・公開の範囲にかかわるので OQ-056（要回答）にする。暫定は置かず、商店の部分は OQ-056 の答えまで作らない（止まる）。
   商店のアカウントを作れるのは、ADR-0029 の D1・D2 のまま運用者の CLI だけで、住民の登録とどの API からも作れない。
   （2026-11-20 更新: OQ-056 の答えで迎え方が決まった（ADR-0043）。契約と利用料はメモだけ、架空の店を置いてよい、空いた区画に入居者募集の張り紙、発信はお店の担当者、出せるものはランクで変える、商店は実在の情報を出してよい。
   商店の部分は、もう要回答では止まらない。S3-2 で OQ-068 の答えと OQ-069 の ADR のあとに作る）
2. **D2 コミュニティ（団体）は住民が作る**（マスターの答えの「コミュニティは趣味などでユーザーが作る」より、`[inferred]`）:
   住民は趣味などでコミュニティを作れる。「コミュニティ」を F-17 の「団体」と読むのは秘書の読み方（背景のとおり）。
   ADR-0029 の D1 のうち「住民は団体を開けない」をこの決定で置き換える（商店の部分は変えない）。
   コミュニティを作る経路は住民の API で、運用者の CLI・管理者画面（C10）に代わりに作る経路は置かない。モデレーターは住民としてだけ作れる（`security.md` §4.2）。
3. **D3 コミュニティを作ることに制約を置く**（マスターの答えの「無制限は難しいので、何かの制約を設けたい」より、`[inferred]`）:
   コミュニティは無制限には作れないようにする。制約の中身（1 人が作れる数・作る条件・コミュニティが住所を持つか・誰が発信できるか・作った住民が退去したときの扱い）は答えに書かれていないので、
   OQ-057（持ち越し）にする。技術と設計で決められるので、段階 3 の S3-2 を始める前に秘書が ADR で決める。
   制約に費用を取るもの（利用料など）を含めるなら、費用にかかわるのでマスターに聞く。中身が決まるまで、コミュニティを作る経路は作らない。
4. **D4 発信の審査**（秘書の判断）: コミュニティと商店の発信は、掲示板の投稿（FR-049・ADR-0005）と同じく配達の前に審査し、承認の前には出さない（`security.md` §5.1）。
   審査の流れは掲示板と同じにし、新しい流れは作らない。
5. **D5 実在の名前を入れない**（秘書の判断）: レポジトリ・テスト・シードのデータに、実在の企業・お店・人の名前を入れない。
   テストでは本物と見分けのつく偽の名前（例: `EXAMPLE_SHOP_DO_NOT_USE`）を使う（CLAUDE.md の「公開レポジトリ」、NFR-083）。
6. **D6 要求の区分**: ADR-0024 の決定 5 に従い、FR-104 は `[inferred]`（マスターの答え OQ-006（2026-11-19）・OQ-045（2026-11-20）より）とし、根拠にこの ADR を足す。
   コミュニティの要求として FR-107 を足し、`[inferred]`（マスターの答え OQ-045（2026-11-20）より）とする。

## 理由

- D1 は、答えの「実在の企業や個人ショップ経営者を入れるのが理想」による。実在の店を迎えるには、選び方・本物であることの確認・契約や利用料・商業の発信の扱い・実在の人の情報の公開が要り、
  どれも法・倫理・費用・公開の範囲にかかわる。マスターにしか決められないので、CLAUDE.md の「要回答の答えを前提にした決定をしない」に従い、迎え方は決めず、商店の部分は止める。
  答えがないと作れないので「止まる」とする（ADR-0022 の決定 6）。
- D2 は、答えの「コミュニティは趣味などでユーザーが作る」による。答えの「ユーザー」は住民（利用者）と読む。
  運用者・モデレーターの特権の経路を置かないのは、住民の作るものを住民の権限だけで扱い、特権の経路を増やさないため（ADR-0020・ADR-0029 の D2 と同じ考え）。
- D3 は、答えの「無制限は難しいので、何かの制約を設けたい」による。中身は技術と設計で決められる（数・条件・住所・発信の権限・退去の扱い）ので、要回答にせず持ち越しにする。
  費用を取る制約は費用にかかわるので、CLAUDE.md に従いマスターに聞く。
- D4 は、商店街の発信も掲示板と同じく誰でも読める公開の内容になり、公開の内容は配達の前に審査する（FR-079・FR-080・features.md §1.3 のルール 3）から。
- D5 は、公開レポジトリに実在の団体を書かない決まり（CLAUDE.md・NFR-083）による。実在の店を迎えることを目指しても、迎えた店の情報は運用のデータで、レポジトリには入れない。

## 代わりの案（選ばなかった理由）

- **実在の店の迎え方をこの変更で決める（例: 申し込みを受けて運用者が確かめて作る）**: 答えに書かれておらず、法・費用・公開の範囲にかかわる（OQ-056）。
- **実在の店が来るまで、運営が作る架空の店を置く**: 答えに書かれていない。実在の店を目指す答えと合うかはマスターにしか決められない（OQ-056 (2)）。
  （2026-11-20 更新: OQ-056 の答え「架空でOK」で、置いてよいと決まった（ADR-0043 の D2）。いつ・どう置くかは OQ-067）
- **コミュニティも管理者が作る（ADR-0029 の D1 のまま）**: 答えの「ユーザーが作る」と食い違う。
- **コミュニティの制約の中身をこの変更で決める**: 答えに書かれていない。S3-2 を始めるまで要らないので、持ち越しにする（OQ-057）。
- **商店街の発信を審査しない**: 公開の内容を審査の前に出すことになり、FR-079・FR-080 と食い違う。

## 決めていないこと

- 実在の店の迎え方（OQ-056 → 決定、2026-11-20、ADR-0043）。
  残りは、架空の店と張り紙をいつ・どう出すか（OQ-067、要回答）、契約・利用料・ランクの中身（OQ-068、持ち越し）、
  担当者のログイン・主体・権限、区画の割り当てと広さ、実在の情報の項目、新聞への載せ方（OQ-069、持ち越し）。
- コミュニティの制約の中身（OQ-057、持ち越し）。S3-2 を始める前に秘書が ADR で決める。
  答えで変わる箇所: FR-107・FR-047（コミュニティが住所を持つか）、`security.md` §4.2 の「コミュニティを作る」の行の上限と発信の権限、
  退去の扱い（ADR-0013）、`roadmap.md` の S3-2 と C-08。
