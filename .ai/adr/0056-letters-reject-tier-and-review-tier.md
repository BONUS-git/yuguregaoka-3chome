# 0056 — 手紙の照合を絶対NGと疑いに分け、疑いだけ確認に回す

- 状態: 採用
- 日付: 2026-11-21

ADR-0040 を丸ごと置き換える。ADR-0040 の決定（D1〜D9）は、OQ-076 の答えに合わせて今の状態に書き直し、同じ番号でこの ADR に移した。OQ-076 の答えから新しく決めたことは D10〜D13。

## 背景

OQ-003 の答え（ADR-0026）で、クローズドな手紙も配達の前に審査し、本文は LLM に渡さずルール表だけで照合すると決まった。
OQ-043 の答え（ADR-0036）で、通報された手紙はモデレーターが条件付きで確かめてよいと決まった。
OQ-052 の答え（2026-11-20、ADR-0040）で、手紙は送るときにスパム・外部リンク・成人向けの言葉に当て、当たったら送った人がポップアップで y / n を選び、y の手紙をモデレーターが確かめると決まった（原文の抜き書き）。

> １：手紙で止めるのは一般的なスパムや外部リンク、18禁ワード等
> ２：送った人の異議は有用だね。ただ、配達に影響するので、送信時点でチェック、引っ掛かったらポップアップでy/n選んでもらって、モデレーター確認かな

OQ-063 の答え（2026-11-20、ADR-0047。いまは ADR-0057）の「一律、問題がある記載は一才許可しない」が、当たった手紙を送った人の確認とモデレーターの承認でも届けず一律に止めるという意味かは読み切れなかったので、
`open-questions.md` の OQ-076 でマスターに次を聞いていた。
(i) 年齢で例外を作らない（当たった手紙は今のとおり y / n と、モデレーターの承認で届く）。(ii) 当たった手紙は一律に止める。(iii) ほかの形（例: 項目によって分ける）。
あわせて、掲示板の投稿の審査も同じ問いに入れるかを聞いていた。暫定は (i) だった。

2026-11-21、マスターが OQ-076 に次のとおり答えた（原文。例の 2 語は伏せた）。

> 1の方針。だが、ガチガチにすると誤判定に繋がるため、分離しようと思っている。
> 例）
> 〔直接的な性的な言葉の例 2 語。公開レポジトリに書かないので伏せた〕など直接的な下ネタ→絶対NG
> 外部へのリンク→絶対NG、世界観を保つことと、他SNSと絶対的な境目を設けたいため
> 絵文字→NG。入力不可これも世界観保つためと、隠語などに繋がるため
> 本当の居住地や年齢などを聞く→NG
> 上記の疑いがある場合はモデレーター確認

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと |
|---|---|---|
| 「1の方針」 | 土台は (i)。当たったら送った人が y / n を選び、y なら確認待ちにし、モデレーターが承認すれば届く（D4・D5） | — |
| 「ガチガチにすると誤判定に繋がるため、分離」 | 照合を 2 段に分ける。はっきり当たるもの（絶対NG）と、疑いのあるもの（モデレーター確認）（D10） | どの規則をどちらの段に置くか・「疑い」の形の細部 → OQ-065（持ち越し） |
| 直接的な下ネタ → 絶対NG | 直接的な性的な言葉は `reject` の段（D10・D11） | 言葉の一覧の中身と置き場 → OQ-065（持ち越し） |
| 外部へのリンク → 絶対NG | 外部へのリンクは `reject` の段（D10・D11） | — |
| 絵文字 → NG。入力不可 | 手紙の本文に絵文字を入力できない（D13） | 手紙のほか（掲示板・商店街の発信・ニックネームや自己紹介）にも当てるか → OQ-087（要回答） |
| 本当の居住地や年齢などを聞く → NG | 本当の居住地・本当の年齢を聞く文は `reject` の段（D10・D12） | 「など」に入るもの・自分から書くことも止めるか → OQ-087（要回答） |
| 上記の疑い → モデレーター確認 | 上の 3 つの疑いがある本文は `review` の段で、今の y / n とモデレーターの確認の流れ（D10） | — |

答えは掲示板の投稿の審査に触れていない。絶対NGと絵文字の入力不可を手紙のほかにも当てるかは OQ-087（要回答）で聞き、暫定は手紙だけに当てる（掲示板の審査は変えない）。
`spam` は答えの絶対NGに入っていないので、「1の方針」のまま `review` の段だけに置く。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 手紙に当てる項目**（OQ-052 の答え 1・OQ-076 の答え、`[inferred]`）: 本番のルール表で手紙に当てる項目は、次の 4 種類にする（`security.md` §5.1）。段は D10。
   - `spam`: 一般的なスパム（宣伝や勧誘の決まり文句・同じ文の繰り返しなど）。`review` の段だけ。
   - `external_link`: 街の外へのリンク（URL の形の文字列）。URL の形のものは `reject`、崩した形など疑いのあるものは `review`。
   - `adult_words`: 成人向け（18 禁）の言葉。直接的な性的な言葉は `reject`、言い換えなど疑いのあるものは `review`。
   - `real_info_request`: 本当の居住地や本当の年齢を聞く文（D12）。はっきり聞くものは `reject`、疑いのあるものは `review`。
   - メールアドレスと電話番号は `external_link` に含めない（秘書の判断）。連絡先の共有の禁止は手紙に及ばない（ADR-0034 の D2）ので、それとそろえる。OQ-076 の答えはこの点に触れていないので変えない。偽の連絡先を含む手紙は今までどおり届く（`roadmap.md` A-06）。
   - 言葉の一覧と本物の規則は、公開レポジトリに置かない（秘書の判断。一覧を置くと、避け方の手引きになり、レポジトリに成人向けの言葉が並ぶ）。答えの例の 2 語も書かない。
     テストは偽の規則で確かめる: `review` の段は目印の文字列 `EXAMPLE_LETTER_RULE_DO_NOT_USE`、`reject` の段は `EXAMPLE_LETTER_REJECT_RULE_DO_NOT_USE` に当たる規則 `[assumed]`。
   - OQ-052 の答えの「等」・OQ-076 の答えの「など」に入る項目は、この変更では足さない（「など」は OQ-087）。違法な物の取引の守りは OQ-053（持ち越し、別のチケット）のまま。
   - スパムの決め方・外部リンクの形の細部・言葉の一覧の置き場・どの規則をどちらの段に置くか・「疑い」の形の細部は OQ-065（持ち越し）。
2. **D2 照合は送るとき、API で行う**（OQ-052 の答え 2「送信時点でチェック」、`[inferred]`）:
   - `POST /api/v1/letters` で、API（C3 の手紙のサービス）が本文を暗号化する前に、ルール表のうち手紙に当てる項目に当てる。
   - 平文はメモリの中だけに置き、DB・ログ・ジョブのペイロード・例外のメッセージに書かない。照合のために本文を復号することはない（暗号化の前の平文を使う）。
   - LLM は呼ばない（ADR-0026 の D2 は変わらない。API の経路で LLM を呼ばない、`api.md` §1 の 5）。
   - 照合に使ったルール表の版を `letters.rule_version` に、当たった規則の ID を `letters.matched_rule_id` に残す（当たらなかった手紙は版だけ）。本文の抜き書きは残さない。`reject` の段に当たった手紙は保存しないので、何も残らない（D11）。
   - worker は手紙を照合しない。J1 は `moderation_queue` に手紙の行を入れず、J2 は手紙を扱わず、J4 は判定を見ずに `scheduled` の手紙をすべて準備する（`async.md` §4）。
3. **D3 送ったときに当たらなかった手紙は、配達の前に当て直さない**（秘書の判断）:
   ルール表の版が上がっても、すでに受け付けた手紙（`pending` / `scheduled`）は当て直さない。
   当て直すと、送った人が y / n を選べないまま止まる手紙が出て、OQ-052 の答え 2 の流れと食い違う。新しい版は、そのあとに送る手紙から効く。
4. **D4 `review` の段に当たったときの y / n**（OQ-052 の答え 2・OQ-076 の答え「1の方針」「疑いがある場合はモデレーター確認」、`[inferred]`）:
   - `reject` の段に当たらず、`review` の段に当たったら、API は何も保存せずに 422（`letter_needs_review`）を返す。どの規則に当たったか・理由は返さない。1 日の上限にも数えない。
   - web はポップアップで、モデレーターに確かめてもらって送るか（y）、送らないか（n）を送った人に選んでもらう。
     y を選ぶと、モデレーターが本文を読むことをポップアップに書く（文言は OQ-065）。
   - **n**: 何も保存しない（秘書の判断）。手紙は送られず、下書きも残さない。送った人は本文を直して送り直せる（直した本文はもう一度照合する）。
   - **y**: web が同じ本文と宛先に `request_review: true` を付けて送り直す。API はもう一度照合し、`review` の段だけに当たれば `held`（確認待ち）で保存する。
     `held` の手紙は配達回に入れず（`delivery_run_id` は NULL）、1 日の上限に数える（送った手紙なので）。送った人の送信済みには「確認中」と見せる。
     送り直した本文がどの規則にも当たらなければ、ふつうの手紙として `pending` で保存する。送り直したときに `reject` の段に当たれば D11 のとおり 422（`letter_rejected`）。
   - 「y / n」を「確認を頼んで送る / 送らない」と読むのは秘書の読み方。答えの「モデレーター確認」は y のあとの段と読んだ。
5. **D5 モデレーターの確認**（OQ-052 の答え 2「モデレーター確認」・OQ-076 の答え、`[inferred]`）:
   - 確認待ちの手紙は `review` の段からだけ出る。`reject` の段に当たった手紙は保存しないので、モデレーターの確認に回らない（D11）。
   - 経路は `/api/v1/admin/held-letters` の下の 3 つ（`api.md` §7 F-08）。
     - 一覧（`GET /api/v1/admin/held-letters`）: 本文を含めず、ID・送った日時・当たった規則の ID だけを返す。呼んだモデレーターが当事者の手紙は出さない。総件数は返さない。
     - 1 通の取得（`GET /api/v1/admin/held-letters/{id}`）: 本文を 1 通だけ復号して返す。
     - 操作（`POST /api/v1/admin/held-letters/{id}/actions`）: `approve` / `reject` だけ。ほかの値は 400。
   - 条件は、通報された手紙を確かめる経路（ADR-0026 の D4 (c)・ADR-0036 の D2）と同じ: 手紙が `held`・モデレーターがその手紙の当事者（送った人・宛先の住民）でない・
     セッションが二要素認証を済ませている・1 回の操作で 1 通だけ・取得のたびに `moderation_actions` に `view_letter` の行を書く（書けなければ本文を返さない）・
     応答は `Cache-Control: no-store`・条件に合わなければ 404。
   - `approve`: `held` → `pending` にし、`nextDeliveryRun(now)` の配達回に入れる（送るときと同じ `FOR SHARE` の手順、`api.md` §2.3）。次の配達回で届く。
   - `reject`: `held` → `blocked`。送った人には「届けられませんでした」と見せ、当たった規則・理由は見せない（ADR-0026 の D5 のまま）。受け取るはずだった人には何も見せない。
     モデレーターが確かめて絶対NGと見た手紙も、この `reject` で止める。
   - 操作は `moderation_actions` に `letter_id` 付きで残す（`db.md` §2）。
   - モデレーターが見てよい手紙は、通報された手紙と、送った人が y を選んで確認を頼んだ `held` の手紙だけ。`blocked` になった手紙・`pending` の手紙を見る経路は作らない。
6. **D6 保持**:
   - `held` の手紙は、モデレーターが操作するまで保つ。長く確かめられないときの扱いは OQ-065（持ち越し）。
   - `blocked` の本文と宛先は、`blocked` にしてから 30 日で消す（J14、ADR-0013）`[assumed]`。
   - 送った人が退去したら、その住民の `held` と `blocked` の手紙は本文と宛先ごと消す（J7）。届いていないので、受け取った人を守るために残す理由（ADR-0013）がない。
7. **D7 流量の制限**: 422（`letter_needs_review`・`letter_rejected`）は、規則を探る手がかりになる（`security.md` §7 の T-22）。2 つを合わせて住民ごとに数え、超えたら 429（`rate_limited`）を返す `[assumed]`。値は OQ-065（持ち越し）。
8. **D8 段階**: 照合・`held`・モデレーターの経路は MVP の M4 で作る（`roadmap.md` §4）。M2 の投函は照合なしで作り、M4 で送るときの照合（2 段）・`held`・モデレーターの経路を足す。
   絵文字の入力の検査（D13）は M2 の投函から入れる。
9. **D9 要求の区分**: FR-112 は `[inferred]`（マスターの答え OQ-052（2026-11-20）・OQ-076（2026-11-21）より）。FR-124 を足す（`[inferred]`、OQ-076 の答えより）。FR-078・FR-080・NFR-005 はこの流れに合わせる。
   マスターの答えから決めたものなので `[explicit]`（構想にあるもの）にしない。
10. **D10 2 段の区分と優先**（OQ-076 の答え「分離しようと思っている」、`[inferred]`。項目の持ち方は `[assumed]`）:
    - ルール表の手紙の項目は、種類のほかに段（`tier`）を持つ。値は `reject`（絶対NG）と `review`（疑い。モデレーター確認）の 2 つ。
    - 照合は、まず `reject` の段の項目に当て、当たれば D11。当たらなければ `review` の段の項目に当て、当たれば D4。両方の段に当たる本文は `reject` を先にする。
    - 段は種類ごとに決めず、規則ごとに持つ（同じ種類に、はっきりした形の規則と疑いの形の規則を置ける）。`spam` の規則は `review` の段だけに置く。
11. **D11 `reject` の段に当たったら、確認に回さずに止める**（OQ-076 の答え「絶対NG」、`[inferred]`。応答の形は `[assumed]`）:
    - API は何も保存せずに 422（`letter_rejected`）を返す。`request_review: true` が付いていても同じ（y / n を出さない）。
    - 規則の ID・種類・本文の位置・段の名前は返さない。1 日の上限に数えない。D7 の流量の制限で、`letter_needs_review` と合わせて数える。
    - web は決まった文面（例:「この手紙は送れません。本文を直してください」。文言は OQ-065）を出し、どの規則に当たったかは出さない。送った人は本文を直して送り直せる。
    - 何も保存しないので、`letters` の行・`matched_rule_id`・モデレーターの確認・`moderation_actions` の行はできない。件数の見張り（`security.md` §7.1）は規則の ID ごとの数だけを数える（本文は見ない）。
12. **D12 `real_info_request`**（OQ-076 の答え「本当の居住地や年齢などを聞く→NG」、`[inferred]`。名前は `[assumed]`）:
    - 手紙の本文で、相手の本当の居住地（街の外の住まい）や本当の年齢を聞く文を止める。対象はこの 2 つだけ（「など」に入るものは OQ-087（要回答）。暫定はこの 2 つだけ）。
    - 自分から本当の居住地や年齢を書くことは、この項目の対象にしない（OQ-087 の暫定）。
    - これは FR-101（マッチングの中で連絡先の共有を禁止する）を理由にした項目ではない。FR-101 の禁止はマッチングの中だけのまま（ADR-0034 の D3）。
    - 架空の街の住所や、住民が設定した年齢（ADR-0048）を聞くことは対象にしない（街の中の情報なので）。どの文を「聞く」と見るかの形の細部は OQ-065（持ち越し）。
13. **D13 手紙の本文に絵文字を入力できない**（OQ-076 の答え「絵文字→NG。入力不可」、`[inferred]`。絵文字の定義は `[assumed]`）:
    - ルール表の照合ではなく、入力の検査として扱う。web の入力欄は絵文字を受け付けない（入力・貼り付けで入らない）。API は絵文字を含む本文に 400（`validation_failed`）を返し、何も保存しない。
    - 400 はほかの形式の検査と同じで、1 日の上限に数えない。照合の前に確かめる（確かめる順番は形式 → 知り合い → ルール表、ADR-0065 の D5）。
    - 絵文字は、Unicode の `Emoji_Presentation` の性質を持つ文字（ふだん絵の形で出る文字。例 U+1F600・⭐ U+2B50・☕ U+2615）と、U+FE0F（異体字セレクタ 16。前の文字を絵の形で出す）・U+20E3（囲みのキーキャップ）・`Emoji_Modifier`（肌の色の修飾）・`Regional_Indicator`（国旗の地域指示子）の文字とする。これらを 1 文字でも含む本文を弾く。
    - ふだん文字の形で出る記号（★ U+2605・♪ U+266A・♥ U+2665・☀ U+2600・☎ U+260E・✉ U+2709・©・®・™ など）は、それだけなら通す。U+FE0F を後ろに付けて絵の形にしたもの（例 ☀ U+2600 U+FE0F）は U+FE0F を含むので弾く。
    - 顔文字（記号と文字の組み合わせ、例 `(^_^)`）は絵文字に入れない。
    - 当てるのは手紙の本文だけ（OQ-087 の暫定）。

## 理由

- D1 は OQ-052 の答え 1 と OQ-076 の答えによる。メールアドレスと電話番号を外部リンクに含めないのは、OQ-041 の答え（連絡先の共有の禁止は手紙に及ばない）と食い違わないようにするため。OQ-076 の答えはこの点に触れていない。
  言葉の一覧と答えの例の 2 語を公開しないのは、公開レポジトリの決まり（CLAUDE.md）と、一覧が避け方の手引きになることによる。
- D2 は OQ-052 の答え 2 の「送信時点でチェック」による。API は投函のときに平文を受け取っているので、照合のために復号する場面が増えない。照合は決められた規則で決定的に行い、LLM を使わない（NFR-011）。
  送るときの照合は投稿の即時ブロックではなく、送る前の入力の確かめにあたる（届いた手紙を止めるのではない）ので、FR-077（非同期のモデレーション）とも食い違わない。
- D3 は、OQ-052 の答え 2 の流れ（当たったら送った人が選ぶ）を、すべての止める場面に保つため。
- D4 の n で何も保存しないのは、送られなかった手紙の本文を DB に残さないため（データ最小化、NFR-002）。y で `held` にするのは、送った人が確認を頼んだ手紙だけを人が読む形にするため（ADR-0036 の「ある程度の秘匿性は担保しないと」）。
- D5 の条件を通報された手紙とそろえるのは、モデレーターの内部不正（`security.md` T-12）への抑えを同じにするため。
- D6 の 30 日は、送った人の問い合わせと、モデレーターの操作の確かめ（`moderation_actions` は 1 年）のための短い期間として仮に置いた。
- D7 で 2 つの 422 を合わせて数えるのは、どちらも当たったという事実を返し、段の違いで規則を探る手がかりが増えるため。
- D10 は答えの「ガチガチにすると誤判定に繋がるため、分離」による。はっきり当たる形だけを確認なしに止め、疑いのあるものは人が確かめるので、誤判定で届かない手紙を減らせる。両方に当たれば `reject` を先にするのは、絶対NGを y で確認に回せないようにするため。
- D11 は答えの「絶対NG」による。確認に回さないので、本文を人が読む場面も、保存する本文も増えない。応答に規則を出さないのは T-22 と同じ理由。
- D12 は答えの「本当の居住地や年齢などを聞く→NG」による。この街は架空の自分で暮らすことを許す（ADR-0041・ADR-0048）ので、街の外の本当の情報を聞き出す手紙を止める。「など」と自分から書く場合は、答えから読み切れず、公開の範囲にかかわるので OQ-087 で聞く。
- D13 は答えの「入力不可」による。入力の時点で受け付けないので、照合の 2 段とは別の形式の検査にした（送った人の確認に回すものではない）。定義を Unicode の性質で決めると、テストと実装が 1 通りに決まる。★・♪・♥ などの文字の形の記号は日本語の文でふつうに使い、絵の形では出ないので、通して誤判定を減らす（答えの「ガチガチにすると誤判定に繋がる」）。

## 代わりの案（選ばなかった理由）

- **当たった手紙をすべて一律に止める（OQ-076 の (ii)）**: 答えが「1の方針」を土台にし、疑いはモデレーター確認とした。
- **段を種類ごとに決める（`adult_words` はすべて `reject` など）**: 答えは「疑いがある場合はモデレーター確認」としており、同じ種類の中にはっきりした形と疑いの形がある。
- **`spam` も `reject` の段に置く**: 答えの絶対NGに入っていない。
- **`reject` の段に当たった手紙を `blocked` として残す**: 送られなかった手紙の本文が DB に残る。残す目的がない。
- **当たった段や規則を 422 で返す**: 規則を探る手がかりになる（ADR-0026 の D5 と同じ理由）。
- **絵文字をルール表の `reject` の段に置く**: 答えは「入力不可」で、入力の時点で受け付けない形のほうが答えに近い。規則の版や流量の制限に絵文字を混ぜずに済む。
- **絵文字を `Extended_Pictographic` の性質で決める**: ★・♪・♥・☀・☎・✉・©・®・™ など、日本語の文でふつうに使う文字の形の記号まで弾き、誤判定が増える。
- **顔文字も絵文字として止める**: 文字と記号の組み合わせで、ふつうの文と分けられない（誤判定につながる）。
- **絶対NGと絵文字の入力不可を掲示板などにも当てる（今決める）**: 答えは手紙についての問いへの答えで、ほかへの当て方は書かれていない。OQ-087 で聞く。
- **メールアドレス・電話番号も外部リンクとして止める**: OQ-041 の答え（ADR-0034）と食い違う。OQ-076 の答えはこの点に触れていない。
- **成人向けの言葉の一覧・答えの例の語をレポジトリに置く**: 公開レポジトリで、避け方の手引きになる。
