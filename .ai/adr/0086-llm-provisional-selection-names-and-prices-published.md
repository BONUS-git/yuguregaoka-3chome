# 0086 — 外部 LLM の暫定の選定と見積もり、名前と料金を載せる

- 状態: 採用
- 日付: 2026-11-25

ADR-0031 を丸ごと置き換える。ADR-0031 の決定（見積もりの置き場所・秘書の暫定の選定・本番のアダプタは承認のあと・変わらないこと・区分の D1〜D5）は、今の状態に書き直してこの ADR に同じ番号で移した。
新しく決めたのは、外部 LLM の事業者・モデルの名前と日付つきの料金を公開の文書に載せること（D6）。`open-questions.md` の OQ-091 と OQ-092 のマスターの答え（2026-11-25）による。

## 背景

`requirements.md` の NFR-077 は、AI モデレーションに使う LLM の費用の見積もりを含めることを求めている（`[inferred]`）。
`open-questions.md` の OQ-008 で、費用の見積もりをロードマップに含めてよいか、サービスの選定を秘書に任せるかをマスターに聞き、2026-11-19 に次のとおり答えがあった（原文）。

> 費用見積もりをロードマップに含め、サービス選定は秘書に任せる（暫定）

このレポジトリは公開で、NFR-020・NFR-090 はソースに実在の組織名を含めないとしている。設計のレビューの R-024 は、契約先になりうる事業者の名前と料金がこれに当たるおそれを指摘した。
OQ-091 で、名前と日付つきの料金を公開の文書に載せてよいかをマスターに聞き、2026-11-25 に次のとおり答えがあった（原文）。

> 事業者、モデル名、日付つきの料金をすべて載せる。

CLAUDE.md の「公開レポジトリ」の決まりは実在の団体を書かないとしており、OQ-091 の答えとどちらを優先するかを OQ-092 でマスターに聞き、2026-11-25 に次のとおり答えがあった（原文）。

> OQ-091 の答えを優先する。外部 LLM の事業者・モデルの名前と料金に限って載せる

## 決定

1. **D1 費用の見積もりはロードマップに置く**（OQ-008 の答え）: 外部 LLM の費用の見積もりは `roadmap.md` §9.1 に書く。
   NFR-077 の置き場所を `roadmap.md` §9.1 にする。メール送信（OQ-039）・画像加工（NFR-078）・ホスティングの費用は `environment.md` に置く。
2. **D2 サービスは秘書が暫定で選ぶ**（答えは「秘書に任せる（暫定）」。選んだものは秘書の判断）:
   - サービスは Anthropic API、モデルは Claude Haiku 5.5（`claude-haiku-5-5`）。
   - 出力は構造化出力（JSON のスキーマ）で `ok` / `review` / `block` の 3 つのラベルのどれか 1 つに限る。推論の量の設定は最小（`low`）。
     それでも受け取った値はラベルの種類だけを検証し、失敗・想定外の値は人の審査に倒す（`security.md` §1 原則 2・§5.2）。
   - 一括処理（バッチ）の API は使わない。1 件ずつ同期で呼ぶ（呼ぶのは worker の J2 だけ）。
     新聞の記事の文字を作る J16 `newspaper.write` も外部の LLM を呼ぶ（worker だけ、ADR-0039）。
     J16 のモデル・プロンプトはこの選定とは別に OQ-062（持ち越し）で決める。
   - 「暫定」は、確定をマスターの確認に残すという意味で扱う。確定の時期と手続きは OQ-047（持ち越し）。
3. **D3 本番のアダプタは承認のあとに作る**（秘書の判断）: C5 の LLM の分類器のうち、Anthropic API を呼ぶ本番のアダプタは、
   デプロイと契約の承認（NFR-080）のあとに作る。それまでは分類器のインターフェースとモックだけを作り、M4 はモックの LLM で受け入れる（受け入れ条件 A-06・A-07 は変わらない）。
4. **D4 変わらないこと**:
   - 契約と支出はマスターの事前承認を得る（NFR-080）。この ADR は契約も支出もしない。
   - テストはモックの LLM を使い、`sh scripts/check.sh` はネットワークなしで通る（NFR-063・NFR-065）。
   - LLM はラベルを返すだけ（ADR-0005）。LLM に渡すのは掲示板の投稿の本文だけで、手紙は渡さない（ADR-0072）。
     J16 に渡すものは ADR-0055 の D8 のとおり（承認済みの投稿の本文・取り込んだ外のニュース・版の興味の名前。手紙・住所・ID・ニックネーム・住民ごとの興味は渡さない）。
   - LLM の API キーは worker だけが持つ（`security.md` §6.1）。
5. **D5 区分**: ADR-0024 の決定 5 に従い、NFR-077 は `[inferred]`（マスターの答え OQ-008（2026-11-19）より）とし、根拠にこの ADR を書く。NFR-020・NFR-083・NFR-090 は区分を分けて書く。含めないことの規則は `[explicit]`（CLAUDE.md「公開レポジトリ」規則）、外部 LLM の事業者・モデルの名前と日付つきの料金の例外（D6）は `[inferred]`（マスターの答え OQ-091・OQ-092（2026-11-25）より）とし、根拠にこの ADR を書く。
6. **D6 名前と日付つきの料金を公開の文書に載せる**（OQ-091 の答え）:
   - 外部 LLM の事業者の名前（Anthropic）・モデルの名前（Claude Haiku 5.5、`claude-haiku-5-5`）と、日付つきの料金を、`.ai/` の公開の文書に書く。
     事業者の名前に一般の語を付けただけのサービスの名前（Anthropic API）は、事業者の名前として扱う `[assumed]`。
     製品の機能や API の項目の名前は載せる対象の外で、役割の名前（例: 一括処理（バッチ）の API・構造化出力）で書く `[assumed]`。
   - 料金は、料金表を読んだ日を時点として書く `[assumed]`。今の見積もりは 2026-11-03 時点の料金表で、入力 100 万トークンあたり $0.10、出力 100 万トークンあたり $0.50（`roadmap.md` §9.1）。契約の前に最新の料金で計算し直す（OQ-047）。
   - 対象は外部 LLM だけ（OQ-092 の答え）。ホスティング・メール送信などの本番の事業者は、決まるまで役割の名前で書く（OQ-085・OQ-049）。
   - CLAUDE.md の「公開レポジトリ」の決まりと NFR-020・NFR-083・NFR-090（実在の団体・組織名を含めない）の例外とし、この例外が優先する（OQ-092 の答え、2026-11-25）。例外は 1 つ目の箇条の範囲（外部 LLM の事業者・モデルの名前と料金）に限る。言語・DB・ライブラリ・ツールの名前は今までどおり書く。
   - git の履歴は書き換えない `[assumed]`。名前と料金を載せると決まったので、過去のコミットから消す理由がない。

## 理由

- 見積もりをロードマップに置くこと、選定を秘書に任せること（暫定）、名前と料金を載せることは、マスターの答え（上の原文）による。
- Haiku にしたのは、LLM の仕事が掲示板の投稿を 3 つのラベルに分けることだけで（ADR-0005）、手紙は渡さない（ADR-0072）ので、
  いちばん安い今のモデルで足りると見たため。公開してよいかはルール表との突合で決まり、LLM の誤りは人の審査に倒れる（NFR-011・NFR-012）。
- 構造化出力で 3 つのラベルに限るのは、想定外の値を減らし、出力のトークンを少なくするため。検証は残す。
- 一括処理（バッチ）の API を使わないのは、審査の時間（J2 の開始から審査の打ち切りまで、朝便は 02:00〜04:00 の 2 時間、夕便は 15:00〜16:00 の 1 時間。ADR-0016・`async.md` §3）の中で
  終わる保証がないため。終わらなかった投稿はすべて人の審査か次の便に回り、体験を損なう。
- 本番のアダプタを先に作らないのは、デプロイしない方針（NFR-071）で使う場面がなく、選定が暫定で変わりうるため。
- 料金に時点を書くのは、料金が変わりうるので、見積もりがどの料金表によるかを読み手が確かめられるようにするため。

## 代わりの案（選ばなかった理由）

- **Sonnet 5.5 など上位のモデル**: 3 つのラベルへの分類には過ぎ、費用が数倍になる。誤りは人の審査で受け止める設計なので、上位のモデルの利点が小さい。
- **一括処理（バッチ）の API で安くする**: 上のとおり、審査の時間の中で終わる保証がない。
- **ほかの事業者の LLM**: 比べて選ぶ理由が今はない。暫定なので、OQ-047 で確定するときに見直せる。
- **LLM を自分で動かす（セルフホスト）**: GPU のホスティングの費用と運用が要り、デプロイしない方針と費用の面で合わない。
- **名前と料金を書かず、一般の呼び名と変数の式で書く（OQ-091 の (a)）**: マスターの答え（OQ-091・OQ-092）が、外部 LLM の事業者・モデルの名前と料金を載せるだったため選ばない。名前がないと選定と見積もりを読み手が確かめられない。

## 決めていないこと

- 暫定の選定をいつ・どの手続きで確定するかと、LLM の費用の上限を置くか: OQ-047（持ち越し）。契約の前にマスターに聞く。
- 掲示板の投稿が外部のサービス（Anthropic API）で審査されることを住民に知らせる必要があるか（規約・プライバシーの説明）: OQ-032（持ち越し、適用法令）で合わせて調べる。
