# 0054 — 新聞の LLM の文に印を付けず、投稿の記事は見出しだけ書く

- 状態: 採用
- 日付: 2026-11-21

ADR-0046 を丸ごと置き換える。ADR-0046 の決定（D1〜D8）は、D5・D6 を OQ-074 の答えで決めたうえで、同じ番号でこの ADR に移した。OQ-074 の答えから新しく決めたことは D9〜D12。

## 背景

OQ-051 の答え（ADR-0039 の D7）で、新聞の記事の文字（見出し・まとめ・外のニュースの記事）は LLM が作ると決まった。
LLM が書いた文の扱いは OQ-061 でマスターに聞き、2026-11-20 に次のとおり答えが出た（原文。ADR-0046）。

> １：示さなくて良い。規約次第なので、要確認。
>
> ２：住民の掲示板の投稿本文は、書き換えずにそのまま載せる。LLMが手を加えるのはあくまでニュース記事などの生成部分のみ。住民の生の声を勝手に加工して、あたかも本人が書いたように見せることはしない。

「規約」を外部のサービス（LLM のサービス・外のニュースの配信元）の規約と読むのは秘書の読み方。この街の利用規約の意味だったら、OQ-073 でマスターに聞き直す。
答え 2 は、もとの質問の「（書き換えて）よい場合」に当たらないので、投稿した住民に知らせるか・断れるかは問いとして残らない。

住民の投稿を素材にした記事で、LLM が見出しとまとめを書くことが「生成部分」に入るかは答えから読み切れなかったので、`open-questions.md` の OQ-074 でマスターに次を聞いていた。
(i) 書いてよい。(ii) 見出しだけ書いてよい（まとめは書かない）。(iii) 書かない（見出しは「掲示板から」のような決まった形）。(iv) ほかの形。
暫定は (i)（見出しとまとめを LLM が書き、投稿の枠の外に置く。ADR-0046 の D5）だった。

2026-11-21、マスターが OQ-074 に次のとおり答えた（原文）。

> (ii) 見出しだけ書いてよい（まとめは書かない）

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと |
|---|---|---|
| OQ-061 の 1 | 紙面で LLM の文であることを示さない（記事ごとの印も、欄外のまとめての記載も置かない） | どの規約が示すことを求めるか・求めたときの示し方 → OQ-073（持ち越し） |
| OQ-061 の 2 | 投稿の本文は書き換えずにそのまま載せる。LLM が手を加えるのは生成部分だけ。LLM の文を住民本人が書いたように見せない | 投稿の記事の見出しとまとめ → OQ-074（下の行で決定） |
| OQ-074「見出しだけ書いてよい」 | 投稿を素材にした記事の見出しは LLM（J16）が書く。見出しは新聞の文で、投稿の枠の外に置く | 見出しのプロンプトと長さの上限 → OQ-062（持ち越し、もとから決める予定のもの） |
| OQ-074「まとめは書かない」 | 投稿を素材にした記事に、LLM のまとめを書かせず、持たず、載せない | — |

OQ-074 の答えは投稿を素材にした記事についてのもので、外のニュースの記事（見出しと文を LLM が書く。ADR-0039 の D7、いまは ADR-0055 の D7）は変えない。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 印を付けない**（OQ-061 の答え 1、`[inferred]`）: 紙面（J3 のテンプレート）は、LLM が書いた見出し・まとめ・外のニュースの記事に「AI が書いた文」の印を付けない。紙面の欄外にまとめて書くこともしない。
2. **D2 規約を確かめる**（OQ-061 の答え 1「規約次第なので、要確認」、秘書の判断）: OQ-073（持ち越し）にする。
   - 確かめるもの: J16 に使う LLM のサービスの規約（暫定の選定は ADR-0031。モデルは OQ-062）と、外のニュースの配信元の規約（配信元は OQ-060 と一緒に）。
   - 時期: 本番の文章アダプタを作る前（デプロイと契約の承認、NFR-080 の前）に、秘書が規約を読み、結果をマスターに出す。M5 とテストはモックの文章アダプタなので、それまで作業は止まらない。
   - 規約が AI の文であることを示すよう求めるなら、示し方はマスターに聞く（倫理と公開の範囲）。
3. **D3 `written_by` は残す**（秘書の判断）: `newspaper_articles.written_by`（llm / template）は、決まった形になった記事の割合を見張る（`async.md` J16 の監視・`security.md` §7.1）のに使うので残す。紙面には出さない。
   OQ-073 で印が要ることになっても、この列で LLM の文を見分けられるので、表を変えずに済む。
4. **D4 投稿の本文は書き換えない**（OQ-061 の答え 2、`[inferred]`）: 住民の掲示板の投稿の本文は、`board_posts.body` をそのまま載せる。要約・書き直し・言い換え・切り詰めをしない。
5. **D5 LLM が書くのは生成部分だけ**（OQ-061 の答え 2・OQ-074 の答え、`[inferred]`）: LLM（J16）が書くのは、外のニュースの記事の見出しと文、と、住民の投稿を素材にした記事の見出しだけ。
   投稿を素材にした記事のまとめは書かない。住民の投稿の本文には手を加えない。
6. **D6 LLM の文を本人の文に見せない**（OQ-061 の答え 2「あたかも本人が書いたように見せることはしない」、秘書の判断）:
   - 紙面のテンプレート（C6）は、投稿の本文を 1 つの枠（投稿の枠）に入れ、その枠には `board_posts.body` だけを入れる。LLM の見出しは枠の外に、新聞の文として置く。
   - 見出しを住民の言葉として書かせない（一人称で本人になりかわる・本人の発言として引用の形にする、をしない）ことを、OQ-062 でプロンプトを決めるときの条件にする。
7. **D7 段階**: M5 の範囲は変わらない（印を描かない・J16 が投稿の素材に見出しだけを書き、投稿の行の `body` を NULL にする）。
   受け入れ確認の `roadmap.md` A-17 (4) に投稿の決まった形を足し、A-17 (6) で、投稿の本文がそのまま載ること・投稿の枠に LLM の文が入らないこと・印がないこと・投稿の行の `body` が NULL であること・モックの文章アダプタが返したまとめ（目印の文字列）が DB と紙面のどこにも出ないこと、を確かめる。
8. **D8 要求の区分**: FR-111 は `[inferred]`（マスターの答え OQ-061（2026-11-20）・OQ-074（2026-11-21）より）。新しい FR は足さない。
   マスターの答えから決めたものなので `[explicit]`（構想にあるもの）にしない。
9. **D9 投稿の記事はまとめを持たない**（OQ-074 の答え「まとめは書かない」、`[inferred]`）:
   - 投稿の素材には、プロンプトでまとめを求めない。文章アダプタ（C12）の投稿の素材の出力は見出しだけにする。
   - 文章アダプタが見出しのほかのもの（まとめ・本文など）を返しても、J16 は保存せず、紙面にも出さない（捨てる）。
   - `newspaper_articles` の投稿の行（`source_kind = 'board_post'`）の `body` は NULL にする。LLM の行（`written_by = 'llm'`）も決まった形の行（`template`）も同じ。
10. **D10 投稿の決まった形**（秘書の判断）: LLM の失敗・検査に外れた出力・記事の打ち切りのとき（ADR-0055 の D8。ADR-0039 を置き換え）、投稿の記事は、見出しを決まった文「掲示板から」`[assumed]`、`body` を NULL、`written_by = 'template'` にする。
    `board_posts` には題がないので、外のニュースのように「素材の題」を見出しにできない。紙面は決まった見出しと投稿の本文（投稿の枠）になる。外のニュースの決まった形（素材の題と本文そのまま）は変えない。
    J3 が記事の打ち切りのあとに入れる `template` の行（ADR-0055 の D8）も同じ中身にする。
11. **D11 DB の制約**（秘書の判断）: `newspaper_articles.body` を NULL を許す列にし、`CHECK ((source_kind = 'board_post') = (body IS NULL))` を置く。投稿の行にまとめが入らず、外のニュースの行には本文が必ずある。
12. **D12 LLM に渡すもの**（秘書の判断）: 見出しを書くために、承認済みの投稿の本文は今までどおり J16 で LLM に渡す（ADR-0055 の D8。J2 ですでに渡している範囲）。手紙・住所・ID・ニックネーム・住民ごとの興味は渡さない。

## 理由

- D1 は、OQ-061 の答え 1「示さなくて良い」による。
- D2 は、OQ-061 の答え 1「規約次第なので、要確認」による。規約は外部のサービスの条件で、本番のアダプタを作るまでは使わないので、持ち越しにして本番の前に確かめる。示し方は住民に見せる紙面の形で、構想の意図にかかわるのでマスターに聞く。
- D3 は、印を付けないこととデータを持つことは別で、見張りに要り、規約の答えで印が要ることになったときに作り直しが要らないため。
- D4・D5 は、OQ-061 の答え 2 と OQ-074 の答えによる。
- D6 は、OQ-061 の答え 2 の「あたかも本人が書いたように見せることはしない」を紙面の形で守るため。印を付けない（D1）ので、どの文が住民の文かは置き場所で分かるようにする。
  まとめを書かなくても、見出しで本人になりかわれば答え 2 と食い違うので、プロンプトの条件は見出しに当てる。枠に入れるものを `board_posts.body` だけに決めると、テストで確かめられる（A-17 (6)）。
- D9 は OQ-074 の答えによる。まとめを書かないことを、保存と紙面の両方で守る。アダプタが返した余分な出力を捨てるのは、本番のモデル（OQ-062）がプロンプトに従わなかったときにも、まとめが紙面に出ないようにするため。
- D10 は、投稿に題がないため。決まった文は、OQ-074 の選択肢 (iii) の例と同じにした。文言は仮置き。
- D11 は、まとめを持たないことを DB で守り、空の文字列とまとめの区別をなくすため。
- D12 は、見出しを書くには投稿の本文を読む必要があり、渡す範囲は J2 より広がらないため。

## 代わりの案（選ばなかった理由）

- **記事ごとに「AI が書いた文」の印を付ける（ADR-0039 の D9 の暫定）・紙面の欄外にまとめて書く**: OQ-061 の答え 1「示さなくて良い」と食い違う。規約が求めるなら OQ-073 でマスターに聞き直す。
- **投稿の本文を LLM で要約・書き直して載せる**: OQ-061 の答え 2「書き換えずにそのまま載せる」と食い違う。
- **`written_by` を消す**: 見張りに使っており、OQ-073 で印が要ることになったときに LLM の文を見分けられなくなる。
- **規約を今すぐ読んで決める**: 本番の LLM のモデル（OQ-062）と外のニュースの配信元（OQ-060）が決まっておらず、読むべき規約が定まらない。
- **投稿の記事に見出しとまとめを書く（OQ-074 の (i)、暫定のまま）・見出しも決まった形にする（(iii)）**: 答えが (ii) を選んだ。
- **投稿の行の `body` を空の文字列にする**: まとめがないことと空のまとめの区別がつかず、CHECK で守りにくい。NULL にする。
- **アダプタがまとめを返したら記事を決まった形にする**: 見出しは使えるのに捨てることになる。余分な出力だけを捨てる。

## 決めていないこと

- 規約が AI の文であることを示すよう求めるか、求めるならどう示すか（OQ-073、持ち越し。本番の文章アダプタを作る前に秘書が規約を読む）。
- 見出しのプロンプト（D6 の条件を含む）・長さの上限: OQ-062（持ち越し、M5 の前に秘書が ADR で決める）。
- 決まった形の見出しの文言（「掲示板から」は仮置き `[assumed]`）。
- 紙面に投稿者（ニックネームなど）を出すか: 今の文書のまま。
- 外のニュースを LLM で要約・書き直してよいか（配信元の利用の条件）: OQ-060（持ち越し）のまま。
- 住民への説明（利用の案内に、新聞の文を LLM が書くことを書くか）: OQ-032（持ち越し）のまま。
