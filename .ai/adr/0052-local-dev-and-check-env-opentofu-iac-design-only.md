# 0052 — 開発とテストは手元に入れた PostgreSQL で動かし、`check.sh` は使い捨ての DB を起こす。IaC は OpenTofu で設計だけ書き、事業者は選ばない

- 状態: 採用
- 日付: 2026-11-21

## 背景

YGO-009 で `environment.md`（開発・検証環境の構築計画。スタックの計画と IaC の設計まで）を書く。
いくつもの文書が細部を `environment.md` に任せていた: サーバーの大きさ（ADR-0010・ADR-0012）、ホスティングと IaC の道具（ADR-0008・`architecture.md` §6）、鍵管理のサービス（ADR-0006）、
鍵の入れ替えの手順（ADR-0021・`security.md` §6.3）、プッシュサービスの許可のホストと VAPID の鍵の置き場（ADR-0025）、バックアップの方法（`db.md` §6）、
監視の閾値と知らせる先（`async.md` §7）、メール送信と画像加工の費用の見積もり（ADR-0031・ADR-0033・NFR-078・NFR-079）。

前提の制約は次のとおり。

- デプロイ・クラウドのアカウント・費用・ドメインは使わない（NFR-071・NFR-072・NFR-076）。費用のかかる操作はマスターの事前承認（NFR-080）。
- `sh scripts/check.sh` がネットワークなしで通る（NFR-063）。依存は `scripts/prepare.sh` が先に入れる。
- `.env*`・CI の設定は秘書の変更の外（NFR-091・CLAUDE.md）。
- 公開レポジトリで、実在の団体を書かない（NFR-083・NFR-090）。

## 決定

1. **D1 環境は 4 つ**: `development`・`test` は作る（M0）。`staging`・`production` は設計だけで作らない（`environment.md` §2）。
   `staging`・`production` で偽の鍵（`EXAMPLE_` で始まる値）を見つけたら、プロセスは起動に失敗する。
2. **D2 開発は手元に入れた PostgreSQL で動かす**: コンテナの実行環境と Compose を要らないものにする。PostgreSQL は OS に入れたサーバーの道具（`initdb`・`pg_ctl`）で、
   レポジトリの中の無視するディレクトリにデータを置き、ループバックと Unix ソケットだけで待ち受ける。web と worker はふつうのプロセスとして別々に起こす（ADR-0008）。
3. **D3 `check.sh` は使い捨ての PostgreSQL を起こす**: コードができたら、一時ディレクトリに `initdb` し、TCP で待ち受けず Unix ソケットだけで起こし、終わったら必ず消す（片付けの範囲は ADR-0068）。
   PostgreSQL の道具がなければ、飛ばさずに失敗する。道具は `check.sh` を動かす機械（手元・CI・秘書のジョブの環境）にあらかじめ入れておく。CI と秘書のジョブの環境にはマスターが入れる（OQ-086 → 決定）。
   `prepare.sh`（M0 で作る）は npm の依存を入れ、IaC のコードを書いたあとは `tofu init -backend=false` も行う。OS の道具は入れない。テストの設定はテストの準備のコードが偽の値で渡し、`.env.test` は使わない。CI は `prepare.sh` と `check.sh` だけを動かす（`environment.md` §4・§5）。
4. **D4 IaC の道具は OpenTofu**: 宣言の IaC で、事業者ごとのプロバイダを差し替えられる。モジュールは network・identity・database・object_storage・keys・secrets・web・worker・monitoring に分け、
   `envs/staging`・`envs/production` から呼ぶ（`environment.md` §7）。
5. **D5 事業者は選ばず、IaC のコードはまだ書かない**: 本番の事業者（クラウド・鍵管理・秘密管理・ログ）は、費用と契約にかかわるので、デプロイの準備のときにマスターに聞く（OQ-085、持ち越し）。
   IaC のコード（`infra/`）は、事業者が決まり、デプロイの準備をマスターが承認してから書く。それまでは設計を文書に書くだけ。
6. **D6 IaC は確かめるだけで、CI から適用しない**: IaC のコードを書いたら、`prepare.sh` が `tofu init -backend=false` でプロバイダを取り込み、`check.sh` が `tofu fmt -check` と `tofu validate` をネットワークなしで動かす。
   `tofu plan`・`tofu apply` は、マスターの承認のあとに運用者が手で動かす。
7. **D7 秘密は IaC の状態に入れない**: IaC は秘密の入れ物と、プロセスごとの最小の権限だけを作る。値は運用者が秘密管理に入れる。状態は環境ごとに分け、暗号化してロック付きで置く。
   各プロセスは `security.md` §6.1 の自分の秘密だけを読み、自分のものでない秘密が渡されたら起動に失敗する（web は LLM の API キーなど、worker はセッションの署名の鍵・HMAC の鍵など）。
8. **D8 鍵の入れ替えは 2 段で版を足し、`keys.reencrypt` で 1,000 件ずつ再暗号化する**: 新しい版をまず全プロセスに復号用として配り、そのあとで暗号化の版を切り替える。
   再暗号化は運用者の CLI が積む worker のジョブ `keys.reencrypt`（`async.md` §2）で、1,000 件ずつのトランザクションで行う。古い版は、行がなくなったら使わないようにし、
   バックアップの保持の 30 日（ADR-0013）のあいだは復元のためだけに残して、そのあとに消す。漏えいしたときは 30 日を待たずに消す（`environment.md` §8.3）。

## 理由

- D1: 本番と検証環境を作ると、アカウントと費用が要る（NFR-072）。設計だけにすれば、構想の「スタックの計画と IaC の設計まで」の範囲に収まる。偽の鍵で本番を起こしてしまう誤りは、起動のときに止めるのがいちばん早い。
- D2: コンテナのイメージを取り込むにはネットワークとエンジンの常駐が要り、道具が 1 つ増える（NFR-055・NFR-059）。PostgreSQL の道具だけなら、手元と CI で同じ手順になる。
  本番はコンテナで動かす想定（ADR-0008）だが、アプリは環境変数だけで設定するので、手元のプロセスとの違いは起動の仕方だけになる。
- D3: 受け入れ条件の多くは DB を使う統合テスト（`roadmap.md` A-01〜A-19）。DB がないときに飛ばすと、通ったように見えてしまう。TCP で待ち受けなければ、ネットワークなしで動き、ほかのプロセスとポートでぶつからない。
  `.env.test` を使わないのは、`.env*` が秘書の変更の外で、テストの値をコードに置けばレポジトリの中で完結するため。
- D4: 事業者が決まっていないので、特定の事業者だけの道具は選べない。OpenTofu はオープンソースの許諾で、宣言の形で差分（plan）と適用（apply）を分けられ、状態の暗号化を持つ。
- D5: 事業者のないまま IaC のコードを書くと、プロバイダを決めることになり、どのみち確かめられない（`validate` にもプロバイダが要る）。事業者の選定は費用と契約にかかわるので、秘書が決めない（NFR-080）。
  デプロイしない間は要らないので、要回答でなく持ち越しにする。
- D6: 適用はクラウドの認証情報と費用が要る操作で、CI に任せるとマスターの承認を通らずに起きうる（NFR-087）。`fmt`・`validate` はネットワークなしで動くので `check.sh` に入れられる。
- D7: 状態のファイルに秘密が入ると、状態の置き場が秘密の置き場になる。入れ物と値を分ければ、状態を見られても秘密は漏れない。プロセスごとの権限は `security.md` §1 原則 3（LLM の API キーは worker だけ）を基盤の側でも守る。
- D8: 版を足すのと切り替えるのを 1 度に行うと、入れ替えのあいだに、新しい版を知らないプロセスが新しい版の手紙を読めなくなる。1,000 件ずつにすれば、1 つのトランザクションが短く、配達の処理とのロックの待ちが短い。
  古い版をすぐに消すと、30 日のバックアップから戻したときに手紙が読めなくなる。漏えいのときは、鍵を残す危うさのほうが大きい。

## 代わりの案（選ばなかった理由）

- **Terraform**: 書き方は同じ HCL だが、許諾がオープンソースでなく、公開レポジトリで道具の条件が変わりうる。状態の暗号化を持たない。
- **Pulumi（TypeScript で書く IaC）**: 言語をアプリにそろえられるが、状態の置き場とランタイムの依存が増え、宣言の差分を読むのがアプリのコードを読むのと同じ手間になる。
- **事業者ごとの IaC の道具**: 事業者を先に決めることになる（D5 に反する）。
- **Docker Compose で開発の DB を動かす**: 手元でよく使われるが、イメージの取り込みにネットワークが要り、`check.sh` をネットワークなしで通す条件（NFR-063）と CI の条件が分かれる。エンジンの常駐が要る。
- **埋め込みの DB（プロセスの中で動く PostgreSQL の代わり）**: advisory lock・`FOR UPDATE SKIP LOCKED`・pg-boss の動きが本物とずれうる。テストが通っても本番で違う動きをする。
- **SQLite でテストする**: ADR-0010 のとおり、複数のプロセスの同時の書き込みとキューを確かめられない。
- **IaC のコードを今書く（事業者を仮に決める）**: 承認のない選定になり、確かめられないコードが増える。
- **`.env.example`・`.env.test` を置く**: `.env*` は秘書の変更の外。変数の一覧は `environment.md` §8.1 の表に置く。
- **古い鍵の版を、再暗号化が終わったらすぐに消す**: バックアップから戻した手紙が読めなくなる。

## 決めていないこと

- 本番の事業者・検証環境を作るか・費用の上限・アラートを知らせる先・ドメイン: OQ-085（持ち越し。デプロイの準備の前にマスターに聞き、そのとき要回答にする）。
- サーバーの大きさ・閾値・バックアップの日数などの値は `[assumed]`。デプロイの準備で見直す。
