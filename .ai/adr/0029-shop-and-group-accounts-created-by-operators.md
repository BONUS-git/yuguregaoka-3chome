# 0029 — 商店・団体のアカウントは管理者（運用者の CLI）が作る。住民は商店・団体を開けない

- 状態: 採用（D1 のうち「住民は団体を開けない」は ADR-0038 で置き換え。団体（コミュニティ）は住民が作る。商店の部分は変えない）
- 日付: 2026-11-19

## 背景

構想（brief §2-C）に「商店街・地域コミュニティ」とあり、`requirements.md` の FR-046（商店・団体が情報を発信できる場）・
FR-047（商店・団体も住所を持ち、掲示板・住所録から見つけられる）と、`features.md` の F-17（商店街、段階 3）がある。
`open-questions.md` の OQ-006 でマスターに、商店・団体のアカウントを誰が作成・管理するか（一般の住民がお店を「開く」形式か、管理者が設定する形式か）を聞いていた。
暫定は「段階 3 で設計するため、住民と同じ方法でアカウントを作成できると仮置きする」で、`roadmap.md` §8 と ADR-0022 の決定 6 では「止まる」に入れていた。

2026-11-19、マスターが OQ-006 に次のとおり答えた（原文）。

> 管理者作成で良いと思う。これって、企業とかが商店、団体になるんだっけ？

前半（管理者作成）を決定として扱う。後半はマスターからの問い返しで、答えではない。
今の文書は、企業が商店・団体になるとは決めていない（構想 §2-C は「商店街・地域コミュニティ」とだけ書き、
企業が出てくるのは §2-共通 の「将来的な企業広告・折込チラシ」（FR-083、F-20、範囲外）だけ。FR-046・FR-047 も「商店・団体」としか書いていない）。
答えに書かれていないこと（誰が商店・団体になるか・作ったあと誰が発信するか）は決めず、OQ-045 にした。

（追記 2026-11-20）OQ-045 の答え「商店に関しては実在の企業や個人ショップ経営者を入れるのが理想。コミュニティは趣味などでユーザーが作る。無制限は難しいので、何かの制約を設けたい」で、
商店には実在の企業・個人のお店を迎えることを目指し、コミュニティ（F-17 の団体と読む）は住民が作り、作ることに制約を置くと決まった（ADR-0038 の D1〜D3）。
この ADR の D1 のうち「住民は団体を開けない」は ADR-0038 の D2 で置き換えた。商店のアカウントを管理者が運用者の CLI で作り、住民が開けないこと（D1・D2 の商店の部分）は変わらない。
実在の店の迎え方は OQ-056（要回答）に、コミュニティの制約の中身は OQ-057（持ち越し）に移った。

## 決定

1. **D1（マスターの答え）**: 商店・団体のアカウントは管理者が作る。住民の登録（M1 の登録の経路）とどの API からも、商店・団体のアカウントは作れない。
   （2026-11-20 更新: 団体の部分は ADR-0038 の D2 で置き換えた。団体（コミュニティ）は住民が作る。商店の部分はこのまま）
2. **D2（秘書の判断）**: 作る手段は運用者の CLI だけにする。ロールの付与（ADR-0020）と同じ考えで、API が侵害されても作れないようにする。
   管理者画面（C10、モデレーター専用）に開設の機能は足さず、モデレーターに作る権限を与えない（`security.md` §4.2）。
3. **D3（区分）**: ADR-0024 の決定 5 に従い、FR-104 は `[inferred]`（マスターの答え OQ-006（2026-11-19）より）とし、根拠にこの ADR を書く。

## 理由

- 管理者が作り、住民は開けないこと（D1）は、マスターの答え（上の原文）による。
- 運用者の CLI にする（D2）のは、ADR-0020 にアプリの中の管理者のロールがなく、C10 はモデレーター専用で、特権の操作は API から行えないから。
  ロールを増やさず（ADR-0020）、権限の規則表を C3 の 1 か所に保てる。

## 代わりの案（選ばなかった理由）

- **住民が自分で商店・団体を開く**: 答え（管理者作成）と食い違う。
- **C10（管理者画面）から作る**: モデレーターの権限が広がり、API に特権の経路が増える。
- **アプリに管理者のロールを新しく作る**: ADR-0020 で選ばなかった案。

## 決めていないこと

OQ-045 の 2 点を聞いていた（OQ-045 → 決定、2026-11-20、ADR-0038）。

1. 誰が商店・団体になるか（企業・お店か、運営が作る架空の店・団体か、住民の団体か）。→ 商店は実在の企業・個人のお店を目指し、団体（コミュニティ）は住民が作る（ADR-0038 の D1・D2）。
2. 作ったあと誰が商店・団体として発信するか（管理者が代わりに書くか、担当者に渡すか）。→ 商店は OQ-056（要回答）、コミュニティは OQ-057（持ち越し）。

残りは、実在の店の迎え方（OQ-056、要回答。商店の部分は止まる）と、コミュニティの制約の中身（OQ-057、持ち越し）。
答えで変わるもの（ADR-0038 の「決めていないこと」に引き継いだ）:

- 発信する主体の認証（C2）と、ロール・主体の種類（ADR-0020、`security.md` §4）
- F-20（FR-083、広告・折込チラシ）との境
- 商店・団体の住所の割り当て方（FR-047）
- 発信の審査（FR-049 を当てるか）
- FR-046・FR-047・FR-104、`roadmap.md` の S3-2 と C-08
