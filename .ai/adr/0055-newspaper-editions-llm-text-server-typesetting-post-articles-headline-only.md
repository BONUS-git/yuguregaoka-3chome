# 0055 — 新聞は一人 1 枚にせず組ごとの版にする。知り合いのない組は興味で分け、ニュースは街の中と外から取る。記事の文字は LLM が作り、組版はサーバーで決定的に行う。投稿の記事は見出しだけで、本文の欄を持たない

- 状態: 採用
- 日付: 2026-11-21

ADR-0039 を丸ごと置き換える。ADR-0039 の決定（D1〜D13）は、ADR-0044・ADR-0045・ADR-0046（→ ADR-0054）で置き換えた箇所を入れたうえで、同じ番号でこの ADR に移した。
OQ-074 の答え（2026-11-21、ADR-0054）で変わったのは D7・D8・D9。ほかの決定の中身は ADR-0039 のまま。
番号を変えないので、ほかの文書の「ADR-0039 の Dn」は、この ADR の同じ番号の決定として読む。

## 背景

OQ-051 の答え（2026-11-20、原文は ADR-0039 と `open-questions.md` の OQ-051）で、新聞は組ごとの版にし、記事の文字は LLM が作り、組版はサーバーで行うと決まった（ADR-0039）。
そのあと、組と知り合い（OQ-058 → ADR-0044）・興味の集め方（OQ-059 → ADR-0045、OQ-072 → ADR-0053）・LLM の文の扱い（OQ-061 → ADR-0046）が決まり、ADR-0039 の一部を置き換えた。

2026-11-21、マスターが OQ-074 に次のとおり答えた（原文。ADR-0054）。

> (ii) 見出しだけ書いてよい（まとめは書かない）

ADR-0039 の D7 は「J16 が素材ごとに見出しと記事の文字を作る」、D8 は「決まった形は素材の題と本文そのまま」としていて、素材が投稿のときも当たる。
答えで投稿の記事は見出しだけになり、投稿には題がないので、D7・D8 は投稿について書き直しが要る。一部の置き換えが重なって ADR-0039 が読みにくくなったので、丸ごと置き換える。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 組ごとの版**（OQ-051 の答え 1、`[inferred]`）: 紙面は住民ごとに組まない。配達回ごとに、組ごとの版（edition）を組む。
   版の数は「共通の版 1 + 興味の版（興味の一覧の数まで）」で、住民の数では増えない。組 1・2 の版は住民ごとに組む（`acquaintance:<resident_id>`、ADR-0044 の D4）ので、「住民の数によらない」は組 0 の版だけに当たる。MVP では組 1・2 を作らない（ADR-0044 の D1）。
   興味の一覧は 30 種まで `[assumed]`。理由はサーバーの負荷（想定規模は ADR-0012 の住民 1 万人）。
2. **D2 3 つの組**（OQ-051 の答え 1、`[inferred]`）: 住民を「知り合いで埋まる組」「一部埋まらない組」「知り合い 0 の組」に分ける。
   MVP では全住民を知り合い 0 の組として扱う。知り合い・載せるもの・組の境・足りない分の埋め方は ADR-0044（D1〜D7）。組 1・2 を作る時期は OQ-070（持ち越し）。
3. **D3 知り合い 0 の組は興味で分ける**（OQ-051 の答え 1、`[inferred]`。(a)・(b) は秘書の判断）: 知り合い 0 の組の住民には、興味の版を届ける。
   - (a) 興味を選んでいない（推し量った興味もない）住民には、共通の版を届ける。
   - (b) 興味が複数ある住民には、`SHA-256(run_id + ":" + resident_id)` を整数として興味の数で割った余りで、興味を 1 つ選ぶ（興味は `interest_categories.sort_order, id` の順に並べる）。決定的で、配達回ごとに変わり、J4 をやり直しても同じ版になる。乱数の状態を DB に持たない（ADR-0035 の D9 と同じ考え）。
   - 「興味」は、選んだ興味（`resident_interests`）と、段階 2 で過去の新聞の検索から推し量った興味（`inferred_interests`）を合わせた集合（ADR-0045 の D6）。
4. **D4 興味の集め方**（OQ-051 の答え 2・OQ-059 の答え、`[inferred]`）: 興味は、登録のとき（任意）と、あとからの設定で集める。
   - 運用者が CLI で保つ一覧（`interest_categories`）から選ぶ。自由記述にしない（秘書の判断）。シードには架空の一般的な名前だけを入れる。一覧の中身は OQ-062。
   - 1 人 5 つまで `[assumed]`。
   - 興味の一覧（`GET /api/v1/interest-categories`）は認証なしで呼べる経路に足す（4 つ目。一覧だけを返し、住民の情報と件数は返さない）。
   - 段階 2 で、自分に届いた過去の新聞の検索から興味を推し量り、当たった興味の ID だけを `inferred_interests` に持つ（ADR-0045）。住民は止められない（ADR-0053）。住所録の検索からは集めず、検索語を DB・ログに残さない。
5. **D5 興味の守り**（秘書の判断）: 興味は個人情報として扱う。
   - 選んだ興味を見て変えられるのは本人だけ。推し量った興味は本人にも返さず、本人が消す経路も作らない（ADR-0045 の D8）。
   - ほかの住民・モデレーターには見せず、LLM にも渡さない（LLM が受け取るのは版の興味の名前だけで、住民と結び付けない）。
   - 興味ごとの住民の数などの件数を、どの応答にも載せない（P-2）。
   - 退去すると即時に消す（ADR-0013）。
6. **D6 ニュースの出どころ**（OQ-051 の答え 3、`[inferred]`）: 素材は、街の中（承認済みの掲示板の投稿。商店街は段階 3。商店の記事の頻度と大きさはランクで決め（ADR-0043）、新聞への載せ方は OQ-069。架空の店は発信せず新聞に載らない（ADR-0050 の D3・D4）。運営の入居者募集の広告を素材に足す（ADR-0050 の D5。段階 3 から（OQ-083 → 決定（2026-11-21））、細部は OQ-084））と、実在の外のニュース。運営が書く架空の記事は使わない。
   - 外のニュースを取り込むのは worker の J17 `news.fetch` だけで、送り先は許可した一覧の中に限る。取り込んだ記事は、組版の前にルール表（`security.md` §5.1）に当てる。
   - 外のニュースは、取り込んだ配達回（`external_news_items.delivery_run_id`）に結び付ける。J16・J3 の素材はその回に取り込んだ行だけ（UNIQUE(source_key, external_id)）。J17 が行を入れられるのは取り込みの打ち切り（04:00 / 16:00 `[assumed]`）より前だけで、J0 は J17 が完了・失敗するか打ち切りを過ぎるまで J16 を積まない。
   - 配信元・利用の条件・費用は OQ-060（持ち越し）。**それまで本番のアダプタは作らない**。テストと M5 では、偽の記事（`EXAMPLE_NEWS_DO_NOT_USE`）を返すアダプタを使う。
7. **D7 記事の文字は LLM、組版はサーバー**（OQ-051 の答え 4・OQ-074 の答え、`[inferred]`）:
   - J16 `newspaper.write` が、素材ごとに記事の文字を作り、`newspaper_articles` に保存する。作るものは素材の種類で分ける。
     - 外のニュース（`source_kind = 'external_news'`）: 見出し（`headline`）と記事の文（`body`）。
     - 住民の掲示板の投稿（`source_kind = 'board_post'`）: 見出し（`headline`）だけ。まとめは書かず、`body` は NULL（ADR-0054 の D9）。紙面では、見出しを投稿の枠の外に置き、枠には `board_posts.body` をそのまま入れる（ADR-0054 の D4・D6）。
   - J3 `newspaper.typeset` は、保存した文字から、版ごとにテンプレートで決定的に組む（ADR-0011 の組版エンジン）。J3 と J8 をやり直しても LLM は呼ばない。
   - 1 つの素材の記事は、1 回の配達につき 1 つにし、版どうしで使い回す（UNIQUE(delivery_run_id, source_kind, source_id)）。
   - 冪等性（FR-037・NFR-022）は、LLM の出力を保存し、組版をそこから決定的に行うことで保つ。
8. **D8 LLM に渡すもの・確かめること**（秘書の判断）:
   - 渡すのは、承認済みの掲示板の投稿の本文（J2 ですでに外部の LLM に渡している範囲、ADR-0031。投稿の見出しを書くのに要る、ADR-0054 の D12）・取り込んだ外のニュース・版の興味の名前だけ。
     手紙・住所・ID・ニックネーム・住民ごとの興味は渡さない。
   - 出力は、長さの上限・文字だけであること（HTML は使わず、組版のときにエスケープする）・ルール表の掲示板向けの項目、を確かめる。
     投稿の素材では見出しだけを使い、文章アダプタが返したほかのもの（まとめ・本文など）は保存せず、紙面にも出さない（ADR-0054 の D9）。
   - 確かめて外れたとき、または LLM の失敗・打ち切り（記事の打ち切り 04:30 / 16:15 `[assumed]`）のときは、記事を決まった形（`written_by = 'template'`）で組む。LLM のせいでは休刊にしない。決まった形は素材の種類で分ける。
     - 外のニュース: 見出しは素材の題、`body` は素材の本文そのまま。
     - 投稿: 見出しは決まった文「掲示板から」`[assumed]`、`body` は NULL（`board_posts` には題がないため。ADR-0054 の D10）。紙面は決まった見出しと投稿の本文（投稿の枠）になる。
   - J16 が `newspaper_articles` に行を入れられるのは記事の打ち切りより前だけ（入れるトランザクションの中で確かめる。D6 の J17 の取り込みの打ち切りと同じ形）。
     打ち切りまでに作れなかった素材には、J3 が組む前に `written_by = 'template'` の行（上の決まった形。投稿なら「掲示板から」と `body` NULL）を `ON CONFLICT DO NOTHING` で入れ、それから組む。
     これで J3 が組んだあとに記事が変わらず、J3 の再試行・J8 の組み直しでも同じ版の HTML になる（FR-037・NFR-022）。
   - `newspaper_articles` は `CHECK ((source_kind = 'board_post') = (body IS NULL))` で、投稿の行に本文の欄がなく、外のニュースの行に本文が必ずあることを守る（ADR-0054 の D11）。
   - LLM は公開してよいかを決めない（NFR-011・ADR-0005）。公開してよいかは、今までどおり J2 の審査とルール表で決まる。
9. **D9 投稿の本文と LLM の文の印**（OQ-061 の答え・OQ-074 の答え、`[inferred]`。ADR-0054）:
   住民の投稿の本文は書き換えずに `board_posts.body` をそのまま載せる。LLM が書くのは、外のニュースの記事の見出しと文、と、投稿を素材にした記事の見出しだけ（投稿のまとめは書かない）。
   LLM の文には印を付けない。投稿の本文は投稿の枠に入れ、LLM の見出しは枠の外に新聞の文として置き、本人の文に見せない。
   規約が示すことを求めるかは OQ-073（持ち越し、本番の文章アダプタを作る前に秘書が確かめる）。
10. **D10 モデルとプロンプト**は OQ-062（持ち越し、M5 の前に秘書が ADR で決める。投稿の見出しを住民の言葉として書かせない条件を含む、ADR-0054 の D6）。それまではモックの文章アダプタで作る。
    本番のアダプタは、デプロイと契約の承認（NFR-080）のあとに作る（ADR-0031 の D3 と同じ）。参考の見積もりは `roadmap.md` §9.1 に書き、費用の上限は OQ-047 と一緒にマスターに聞く。
11. **D11 版を見られる人**（秘書の判断）: 住民が見られるのは、自分の郵便受けに届いた版だけで、ほかの版は 404。バックナンバー（F-12）も同じ。
    API はどの版か（`edition_key`）を返さない。版からほかの住民の興味が分からないようにするため。
12. **D12 段階**: MVP の M5 に入れる（モックの LLM・偽の外のニュース）。登録の興味の項目と、興味の設定の API も M5 で足す。M3・M4 の J0・J3 は今のまま。
    投稿の記事を見出しだけにすることも M5 の範囲で、受け入れ確認は `roadmap.md` A-17 (4)・(6)（ADR-0054 の D7）。
13. **D13 要求の区分**: FR-106・FR-108〜FR-111 は `[inferred]`（マスターの答え OQ-051（2026-11-20）より。FR-111 は OQ-061（2026-11-20）・OQ-074（2026-11-21）の答えも）。新しい FR は足さない。

## 理由

- D1〜D6・D10・D11 の理由は ADR-0039 の理由のまま（組ごとの版はサーバーの負荷、興味を一覧から選ぶのは審査と版の数と個人の特定、興味の守りは P-2、外のニュースの取り込み先を限るのは SSRF（T-19）、版を見られる人を限るのは興味を推し量らせないため）。置き換えた箇所の理由は ADR-0044・ADR-0045・ADR-0053・ADR-0054。
- D7 は、OQ-051 の答え「文字だけLLMで作成し、新聞の生成部分はサーバーで行う」と、OQ-074 の答え「見出しだけ書いてよい（まとめは書かない）」による。LLM の出力を保存してから組むことで、組版のやり直し（J3・J8）が同じ紙面になる（FR-037・NFR-022）。素材ごとに 1 回だけ呼ぶのは、費用を版の数で掛け算しないため。
- D8 は、LLM に渡す個人情報を J2 より広げないため（NFR-002・ADR-0026）、出力の作り話・プロンプトインジェクション・XSS を紙面に出さないため（T-20）。決まった形に倒すのは、新聞を全住民に届けること（ADR-0035）を LLM の失敗で止めないため。
  投稿の決まった形を「掲示板から」にするのは、投稿に題がなく、外のニュースのように素材の題を見出しにできないため（ADR-0054 の D10）。J3 が打ち切りのあとに入れる行も同じ形にしないと、投稿の行にまとめの代わりの文が入り、CHECK と食い違う。
- D9 は、OQ-061 の答え 2 と OQ-074 の答えによる（ADR-0054 の理由）。
- ADR-0039 を一部の置き換えのままにせず丸ごと置き換えるのは、D7・D8 の文が投稿にも当たり、注記だけでは ADR-0054 の D9〜D11 と食い違って読めるため。番号を保つのは、ほかの文書の参照（「ADR-0039 の Dn」）の意味を変えないため。

## 代わりの案（選ばなかった理由）

- ADR-0039 の代わりの案（一人 1 枚の紙面・全住民に同じ紙面・LLM に紙面全体を組ませる・組版のたびに LLM を呼ぶ・興味を自由記述にする・外のニュースの本番のアダプタを今作る・LLM が失敗したら休刊にする）は、ADR-0039 に書いた理由のまま選ばない。
- **ADR-0039 を採用のまま、状態の行と D7・D8 に注記を足す**: D7・D8 の本文が投稿にも当たるまま残り、ADR-0054 の D9〜D11 と食い違う。注記が状態の行に積み重なって読みにくい。
- **投稿の決まった形を、投稿の本文の先頭を切り取った見出しにする**: 投稿の本文を切り詰めて別の場所に載せることになり、ADR-0054 の D4（書き換え・切り詰めをしない）と食い違うおそれがある。
- **番号を振り直す**: ほかの文書の「ADR-0039 の Dn」の参照がずれる。

## 決めていないこと

- 組 1・2 をいつ作るか・負荷の見積もり・知り合いの側の同意（OQ-070、持ち越し）。
- 外のニュースの配信元・利用の条件・費用（OQ-060、持ち越し）。暫定は置かず、本番のアダプタは作らない。
- 規約が AI の文であることを示すよう求めるか（OQ-073、持ち越し）。
- 新聞の LLM のモデル・プロンプト（投稿の見出しの長さの上限を含む）と、記事と興味の結び付け方・興味の一覧の中身（OQ-062、持ち越し）。M5 の前に秘書が ADR で決める。
- 興味の一覧の上限（30 種）・1 人の上限（5 つ）・記事の打ち切り（04:30 / 16:15）・外のニュースの取り込みの打ち切り（04:00 / 16:00）・`external_news_items` の保持（30 日）・投稿の決まった見出し「掲示板から」は仮置き `[assumed]`。
