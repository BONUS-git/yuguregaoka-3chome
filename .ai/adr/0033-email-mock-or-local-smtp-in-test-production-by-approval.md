# 0033 — メール送信は、テスト環境ではモックかローカルの SMTP を使う。本番のサービスはマスターの事前承認を得て選ぶ

- 状態: 採用
- 日付: 2026-11-19

## 背景

`features.md` の F-02 は、確認メール・パスワード再設定メール・休眠通知メール（段階 3、J12）を送る。
`security.md` §6.4 の漏えい時の住民への連絡もメールで行う。送るための外部のメール送信サービスは決めていなかった。
`open-questions.md` の OQ-039 で、サービスの選定を秘書に任せるか、マスターが指定するかを聞いていた。
暫定は「テスト環境ではモックまたはローカルの SMTP サーバーを使う。本番向けサービスの選定は `environment.md` で行うが、
外部サービスとの契約・費用発生はマスターの事前承認を得る（NFR-080 に準じる）」だった。

2026-11-19、マスターが OQ-039 に次のとおり答えた（原文）。

> テスト環境はモックまたはローカルのSMTPサーバーを使い、本番はマスターの事前承認を得て選定する

## 決定

1. **D1 テスト環境はモックかローカルの SMTP**（マスターの答え）: 開発・CI・`sh scripts/check.sh` のメール送信は、
   モックのメールかローカルの SMTP サーバーだけを使う。外部のメール送信サービスは呼ばない。
2. **D2 本番のサービスはマスターの事前承認を得て選ぶ**（マスターの答え）: この ADR では本番のサービスを選ばず、候補も挙げない。
   候補の出し方・承認を求める時期と手続き・費用の上限は OQ-049（持ち越し）とする。
3. **D3 作るアダプタはモックとローカルの SMTP の 2 つだけ**（秘書の判断）:
   - ローカルの SMTP のアダプタの宛先は、ループバック（`localhost`・`127.0.0.1`・`::1`）に限る。
     それ以外のホストを設定すると、プロセスは起動に失敗する。
   - 外部のサービスを呼ぶ本番のアダプタは、選定がマスターに承認されたあとに作る。
4. **D4 受け入れはモックのメールで行う**（秘書の判断）: `check.sh` の受け入れ条件（`roadmap.md` の M1 の登録の確認、A-07、段階 3 の C-03）は
   モックのメールで確かめる。ローカルの SMTP は手元で文面や送信を確かめるための選択肢で、受け入れ条件にはしない。
5. **D5 変わらないこと**: メールの送信はアウトボックス形式のまま、J12 は「まれに 2 通届く」ことを許すまま（`async.md` J12）、
   休眠の通知は段階 3 のまま（ADR-0023）、配達完了の通知は Web Push のまま（ADR-0025）。
   メール送信の費用の見積もりは今までどおり `environment.md` に置く（ADR-0031 の D1）。契約と支出はマスターの事前承認を得る（NFR-080）。

## 理由

- D1・D2 は、マスターの答え（上の原文）による。
- 本番のサービスの候補を挙げないのは、答えが「マスターの事前承認を得て選定する」で、選ぶ主体を秘書に任せていないため（OQ-008 の LLM とは違う）。
  秘書が暫定で選ぶと、承認の前に選定を決めたことになる。
- ローカルの SMTP の宛先をループバックに限るのは、設定の誤りで外部のサービスに届き、承認のない送信や費用が起きるのを防ぐため。
  起動に失敗させれば、テスト環境の設定がテスト環境の外を向いていることに、送る前に気づける。
- 受け入れをモックで行うのは、`check.sh` がネットワークなしで、追加のサーバーなしで通る必要があるため（NFR-063）。
  ローカルの SMTP を受け入れに入れると、CI と手元にサーバーを立てることが条件になる。

## 代わりの案（選ばなかった理由）

- **秘書が本番のサービスを暫定で選び、ADR に書いておく**: 答えと食い違う（選定はマスターの事前承認を得て行う）。
- **本番のアダプタを先に作り、設定で切り替える**: サービスが決まっていないので、どの API に合わせるかを先に決めることになる。
- **ローカルの SMTP の宛先を制限しない**: 設定を誤ると、テスト環境から外部のサービスへ承認のないメールが出る。
- **受け入れをローカルの SMTP で行う**: `check.sh` がサーバーの起動に頼る。モックで確かめられることは変わらない。

## 決めていないこと

- 本番のサービスの候補を誰がどう出すか・承認を求める時期と手続き・メール送信の費用に上限を置くか: OQ-049（持ち越し）。

## 影響

本番のサービスが承認されたら、次を直す。

- `security.md` §6.1 のメール送信サービスの認証情報（保管方法と、どのプロセスが持つか）・§8。
- `async.md` J12 と §8 の「通知の手段（J12）」。
- `roadmap.md` §1 の 4・§8・§9 と、本番のアダプタを作る段階。
- `roadmap.md` の A-07（本番のアダプタの扱いと、宛先の制限の範囲）と、§4 の M0 のアダプタの列。
- `environment.md` の費用の見積もり。
- `features.md` §5 の F-02 のメール送信。

この ADR で直したもの: `open-questions.md`（OQ-039 を決定に、OQ-049 を足す）・`roadmap.md`（A-07 に、メールのアダプタがモックとローカルの SMTP だけで、
宛先がループバック以外なら起動に失敗することの確認を足す。M0 のアダプタにローカルの SMTP を足す）・`security.md`・`async.md`・`features.md`・ADR-0022・ADR-0023・ADR-0025。
