# 0066 — 相互にならない住所録の追加は自動で止める

- 状態: 採用
- 日付: 2026-11-21

## 背景

住所録に住所を足すと、足した側は自分のエントリの `acquainted` で、相手がすでに自分を足していたかを知れる（ADR-0065 の D4）。
これを使って、多くの住所を足し、相手が自分を足しているかを探れる（`security.md` §7 の T-23）。守りは、追加と住所を変える更新を合わせた 1 日 20 件の上限で、消しても数えは減らない（ADR-0065 の D4）。
1 日の上限だけでは、毎日続けて探ることは止まらない（20 件 × 7 日で 140 件）。

`open-questions.md` の OQ-081 (3) で、この程度の分かり方を許すかを聞いていた。2026-11-21、マスターが次のとおり答えた（原文）。

> 3:上限の設定いいね。ボーナスで検討して。あとは履歴確認して、極端に相互にならない人（毎日20件足す→相手から足されたのが2%未満など）はロジックで判定して機能を停止させるアプローチもいいのではと思った。ボーナスに判断を委ねる。

答えは、相互にならない追加を自動で判定して止める案を出し、取るかと中身を秘書に任せた。
OQ-075（持ち越し）は、詐欺と事件の防止のための「不審な挙動への対処」の中身を、M4 の前に秘書が ADR で決めることにしていた。この ADR は、そのうち住所録の追加による探りの部分を決める。

## 決定

1. **D1 判定**（答え 3「極端に相互にならない人…ロジックで判定して機能を停止させる」、`[inferred]`。値は `[assumed]`。2% は答えの例から取った）:
   - 判定は、数える要求（エントリを作る `POST /api/v1/address-book` と、住所を変える `PATCH /api/v1/address-book/{id}`）のたびに、1 日の上限と同じ住民ごとの `pg_advisory_xact_lock` の中で行う。
   - N は、今日を含む直近 7 日（JST の暦日）の `address_book_daily_counts.count` の合計。
   - M は、本人の住所録のエントリのうち、`counted_at`（D5）がその 7 日に入り、今その相手と互いに足している（ADR-0065 の D2 を満たす）ものの数。
   - N ≥ 100 かつ M < N × 2%（M × 50 < N）なら止める。例: N = 100 で M = 1 なら止め、M = 2 なら止めない。
   - エントリを消しても N は減らず、消したエントリは M に入らない。消して割合を上げることはできない。
2. **D2 応答**:
   - 止めたときは 429 `add_suspended` と、決まった文面だけを返す。割合・件数・残り・解除の時刻は返さない（`api.md` §5、ADR-0014）。
   - 何も変えず、1 日の数えにも入れない。
   - 確かめる順番は、400 の検査 → 止める判定 → 1 日の上限（`daily_limit_reached`）。止めているあいだは、1 日の上限に届いていても `add_suspended` を返す。
3. **D3 止める範囲**: エントリの追加と、住所を変える `PATCH` だけ。
   エントリの削除・メモだけの `PATCH`・住所録の読み出し・知り合いへの手紙・掲示板（オープンの切り替えを含む）は止めない。
4. **D4 戻り方**:
   - 止めた状態は保存せず、要求のたびに D1 で求める。
   - 数えた日が 7 日の窓から外れるか（N が 100 を下回る）、足した相手が足し返して M が増えれば、自然に戻る。続けて足さなければ、最長 7 日で戻る。
   - 手で解除・延長する経路は作らない（住民・モデレーター・運用者のどれにも）。
5. **D5 記録**:
   - `address_book.counted_at`（timestamptz）を足す。エントリを作った `POST` と、住所を変えた `PATCH` のときに、その時刻を書く（数えと同じトランザクション）。
   - `address_book_daily_counts` は 7 日分持つ。J14 は `jst_date` が今日（JST）より 7 日以上前の行を消す（`async.md` の J14）。
   - 誰を足したか・何を探ったかは新しく残さない。`counted_at` は本人の住所録の行の中だけにあり、行を消せば消える。
   - 指標は、429 `add_suspended` を返した回数だけ（住民の ID を付けない。`security.md` §7.1）。
6. **D6 処置との違い**:
   - 止めたことを、足された側にもモデレーターにも、住民ごとには知らせない。
   - これはアカウントの停止や警告ではなく、1 つの機能を一時的に止めるだけ。住民への処置（停止・警告など）の中身は OQ-048（持ち越し、ADR-0032）のまま。
   - 年齢の条件は持たせない（ADR-0057）。
7. **D7 OQ-075 との関係**: OQ-075 のうち、住所録の追加による探り（相互にならない追加）の部分を、この ADR で決める。ほかの挙動（知らない多くの住民への手紙・422 の繰り返し・多くのブロックや通報など）は OQ-075（持ち越し）のまま。

## 理由

- D1 は答え 3 の例「毎日20件足す→相手から足されたのが2%未満」による。答えの「相互」と「相手から足された」に合わせ、M は互いに足した（D2）エントリだけを数える。
  7 日にするのは、1 日の上限（20 件）だけでは止まらない、続けて探ることを見るため。7 日で 100 件は、1 日の上限に近い追加を 5 日以上続けたときにだけ当たり、ふつうの追加では当たらない。
  N ≥ 100 を置くのは、件数が少ないうちは割合がぶれ、登録したばかりの住民が数件足しただけで止まらないようにするため。
- D1 の N を消しても減らない数えにするのは、1 日の上限と同じく、消して足し直す・書き換えるで判定を逃れさせないため。M を `counted_at` で窓に入れるのは、N と同じ期間の追加だけを比べるため。
- D2 で割合・件数・時刻を返さないのは、返すと判定の境目を探れ、件数を見せることになる（P-2・ADR-0014）ため。
  1 日の上限より先に判定するのは、止めているあいだの応答を 1 つにし、どちらに当たっているかで状態を読ませないため。
- D3 で追加と住所を変える `PATCH` だけを止めるのは、探りに使えるのはこの 2 つだけで、ほかを止めると住民のふつうの使い方を損なうため。
- D4 で状態を保存しないのは、表とジョブを足さずに済み（NFR-055）、窓から外れれば自然に戻るため。
- D5 で誰を足したかを新しく残さないのは、何を探ったかの記録を持たない（ADR-0065 の D4）考えを変えないため。
- D6 は、答え 3 が「機能を停止させる」と書いており、住民への処置は OQ-048 でマスターが決めることになっているため。

## 代わりの案（選ばなかった理由）

- **止めない（1 日の上限だけにする）**: 毎日続けて探ることが止まらない。答え 3 の案を取らない理由がない。
- **M に掲示板の経路（ADR-0065 の D7）の相手も入れる**: オープンの投稿の投稿者を足せば M を上げられ、判定を逃れられる。答えの「相手から足された」にも当たらない。
- **1 日ごとに判定する（その日の 20 件で 2%）**: 1 日の件数では割合がぶれる（20 件の 2% は 0.4 件）。
- **止めた状態を表に保存し、期間を決めて解除する**: 表と解除のジョブが要る。そのつど求めれば、窓から外れたときに自然に戻る。
- **止めたことと解除の時刻を住民に見せる**: 判定の境目と件数を探れる。
- **モデレーターに知らせ、人が判断する**: 住民への処置は OQ-048 で決めることで、この ADR は 1 つの機能を一時的に止めるだけ。知らせると、誰が何を足したかを人が見ることになる。
- **足した相手の一覧を残し、相互になったかをあとから調べる**: 何を探ったかの記録を持つことになる。`counted_at` と今の住所録だけで足りる。

## 決めていないこと

- 7 日・100 件・2% は `[assumed]`。実際の使われ方を見て見直す（デプロイしない間はテストの偽の値で確かめる）。
- 住所録のほかの不審な挙動への対処: OQ-075（持ち越し）。住民への処置の中身: OQ-048（持ち越し）。
- 新しい要回答はない。
