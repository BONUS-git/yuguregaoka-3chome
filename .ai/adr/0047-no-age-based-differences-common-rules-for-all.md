# 0047 — 年齢による違いは作らない。手紙と掲示板で止める基準・使える機能は全員に同じにし、詐欺と事件の防止も全員に同じ共通のルールで行う。年齢の区切りは置かない

- 状態: 採用
- 日付: 2026-11-20

## 背景

OQ-052 の答え「３：変える。」（2026-11-20）で、住民の年齢で守り方を変えると決めた（ADR-0041 の D1）。
何を変えるか・年齢の区切りは答えに書かれていなかったので、`open-questions.md` の OQ-063 でマスターに次の 3 点を聞いていた。
(1) 年齢で、手紙と掲示板で止める項目を変えるか。(2) 年齢で、使える機能を変えるか（高齢の住民を詐欺から、若い住民を事件から守る守りを含む）。(3) 年齢の区切りは何歳か。
暫定は、年齢による違いを作らない（すべての住民に同じ守り・同じ手紙の項目）だった。

2026-11-20、マスターが OQ-063 に次のとおり答えた（原文）。

> 暫定の通り「年齢による違いは作らない」で進めて。
>
> (1) 手紙と掲示板のブロック対象は、年齢に関係なく全ユーザー共通の基準でフィルタリングする。特定の年齢層だけに別の言葉を出すような複雑なことはしない。一律、問題がある記載は一才許可しない
> (2) 機能の解放条件も年齢に紐付けない。詐欺防止や事件防止についても、年齢で制限するのではなく、システム全体の共通ルール（スパム検知や不審な挙動への対処）として実装すること。
> (3) 年齢による区切りは設けない。
>
> 「年齢で守り方を変える」という言葉の意図は、将来的に「もし変えるとしたら」という拡張性や、データ構造として年齢を持っておくこと、あるいは年齢によって（属性として）表示が変わる可能性を含んでいるだけで、実装レベルで年齢ごとにフィルタリングロジックを分岐させるコストは払わない。シンプルに、全員に同じルールを適用する。

答えから読み取れることと、読み取れないことを分ける。

| 答え | 読み取れること（決定） | 読み取れないこと（新しい OQ・既存の OQ） |
|---|---|---|
| 冒頭・末尾 | 年齢による違いは作らない。全員に同じルールを当てる。年齢ごとに照合の処理を分ける費用は払わない | 「データ構造として年齢を持っておくこと」: 項目を置くか・必須か・変えられるか・見せるか・進むか → OQ-064（要回答）のまま |
| 1 | 手紙と掲示板で止める基準は、年齢に関係なく全員に共通。年齢層ごとに別の言葉の一覧を当てない | 「一律、問題がある記載は一才許可しない」が、年齢で例外を作らないという意味か、当たった手紙を送った人の確認とモデレーターの承認でも届けず一律に止めるという意味か → OQ-076（要回答） |
| 2 | 使える機能（解放の条件）を年齢に結び付けない。詐欺と事件の防止は、年齢での制限でなく、システム全体の共通ルール（スパム検知・不審な挙動への対処）で行う | 「不審な挙動への対処」の中身（何を不審とするか・何をするか） → OQ-075（持ち越し） |
| 3 | 年齢の区切りを置かない | — |
| 末尾 | 年齢によって（属性として）表示が変わる可能性は、将来の可能性として残る | 何の表示が変わるか → OQ-064 の (3) に足す（要回答） |

答えは、ADR-0041 の D1（年齢で守り方を変える）を置き換える。D2〜D4・D6（年齢は住民の設定をそのまま使う・危険な機能は設けない・生年月日は集めない・登録に年齢制限を置かない）は変わらない。

## 決定

区分は ADR-0024 の決定 5 に従う。

1. **D1 止める基準を年齢で変えない**（答え 1、`[inferred]`）: 手紙（ADR-0040 の D1）と掲示板（ADR-0005・ADR-0031）で止める基準は、送る人・受け取る人の年齢に関係なく、全員に同じにする。
   - ルール表（`security.md` §5.1）の項目に年齢の条件を持たせない。年齢層ごとに別の言葉の一覧を持たない。
   - 「一律、問題がある記載は一才許可しない」は、年齢で例外を作らない（どの年齢の住民の手紙・投稿にも同じ基準を当てる）とも、
     当たった手紙を送った人の確認とモデレーターの承認でも届けず一律に止めるとも読める。どちらに読むかは構想の意図にかかわるので、OQ-076（要回答）でマスターに聞く。
   - **暫定（OQ-076 の答えまで）**: 当たった手紙を送った人が y / n を選び、y の手紙をモデレーターが確かめて承認すれば届く流れ（ADR-0040 の D4・D5）と、
     掲示板の審査の流れ（`security.md` §5.2）は変えない。答えが「一律に止める」なら、ADR-0040 の D4・D5、`api.md` の 422 `letter_needs_review` と `held`、
     `security.md` §5.1、`roadmap.md` の A-06 (iii)(iv) が変わる（OQ-076 の「答えで変わる箇所」）。年齢の条件を持たせないこと（この D1 の本体）は、どちらの答えでも変わらない。
2. **D2 使える機能を年齢で変えない**（答え 2、`[inferred]`）: 機能を使える条件・権限（`security.md` §4.2・C3 の権限の規則）に年齢の条件を持たせない。
   マッチング（F-18）への参加にも年齢条件を置かない（FR-064）。
3. **D3 詐欺と事件の防止は、全員に同じ共通のルールで行う**（答え 2、`[inferred]`）: 高齢の住民を詐欺から、若い住民を事件から守ること（OQ-043 の答え、ADR-0036）は、
   年齢での制限でなく、全員に同じに効く仕組みで行う。今ある仕組みは、手紙のスパム・外部リンクの照合（ADR-0040 の D1）・掲示板の審査・送信の上限（ADR-0005）・
   通報・ブロック・マッチングで街の外の連絡先を渡させないこと（FR-101、ADR-0034）。どれも住民が自分で外せない（ADR-0036 の D3）。
   - 「不審な挙動への対処」の中身は今の文書に設計がない。OQ-075（持ち越し）にし、M4 を始める前に秘書が ADR で決める（秘書の判断）。
     そこで決めるのは、どの挙動を不審と見るか・何をするか（流量の制限・モデレーターへの知らせなど）で、年齢の条件は持たせない。
   - 住民への処置（アカウントを止めるなど）の中身は、今までどおり OQ-048（持ち越し、ADR-0032）でマスターが決める。OQ-075 では処置を決めない。
4. **D4 年齢の区切りを置かない**（答え 3、`[inferred]`）: 何歳未満・何歳以上という区切りを、文書・設定・コードに置かない。
5. **D5 ADR-0041 の D1 を置き換える**: ADR-0041 の D1「年齢で守り方を変える」は、この ADR の D1〜D4 で置き換える。
   - ADR-0041 の D2（年齢は住民の設定をそのまま使い、確かめない）・D3（危険な機能は設けない）・D4（生年月日は集めない）・D6（登録に年齢制限を置かない）は変わらない。
   - ADR-0041 の D5（年齢の項目と `residents` の列は置かない）は、待つ条件を OQ-064 の答えだけにする。答えの「データ構造として年齢を持っておくこと」は意図に含まれるが、
     必須か・変えられるか・見せるか・進むかは OQ-064（要回答）で、その答えを前提に項目を置かない（CLAUDE.md の「要回答の答えを前提にした決定をしない」）。
6. **D6 ADR-0027 の「特別な制限を置かない」**: ADR-0041 の D1 で置き換えていた ADR-0027 の D2 の「特別な制限を置かない」は、この ADR で実質もとに戻る（年齢で違いを作らないので、未成年だけに効く制限もない）。
   ADR-0027 の D3 の「年齢を集めない」は、ADR-0041 の D5 のとおり、OQ-064 の答えまで今のまま（項目を置かない）。
7. **D7 要求の区分**: FR-064・FR-094・FR-113 を直し、FR-120（詐欺と事件の防止は全員に同じ共通のルールで行う）を足す。どれも `[inferred]`（マスターの答え OQ-063（2026-11-20）より）。

## 理由

- D1〜D4 は答えのとおり。年齢ごとにルール表と権限を分けないので、照合と権限の規則が 1 通りで済み、テストも 1 通りで済む（答えの「コストは払わない」）。
- D1 の暫定: 「一才許可しない」を「当たったら送った人にも確認を頼ませない」と読むと、ADR-0040 の D4・D5（OQ-052 のマスターの答え 2）を取り消すことになる。
  どちらに読むかは秘書には決められない（構想の意図）ので OQ-076 で聞き、答えまでは、すでにマスターの答えで決まっている ADR-0040 の流れを保つ。
  M4 を作るまでコードはないので、暫定で作業は止まらない。
- D3 は、年齢を確かめない（ADR-0041 の D2）ので、年齢で制限しても年齢を偽れば外れる。全員に同じに効く仕組みなら、年齢を偽っても外れない。
  「不審な挙動への対処」は技術と設計で決められるので、秘書が持ち越しで決める（CLAUDE.md の「要回答」の範囲の外）。
- D5 は、年齢の項目を今置くと、OQ-064 の答え（必須か・変えられるか）を前提にすることになるため。年齢で守りを変えないので、項目がなくても守りは欠けない。

## 代わりの案（選ばなかった理由）

- **成人向けの言葉を、ある年齢より下の住民の手紙にだけ当てる**: 答え 1「特定の年齢層だけに別の言葉を出すような複雑なことはしない」と食い違う。
- **マッチングを一定の年齢以上に限る**: 答え 2「機能の解放条件も年齢に紐付けない」と食い違う。
- **当たった手紙を送った人の確認も許さずに止める（今決める）**: 答えから読み切れず、ADR-0040 の流れ（OQ-052 の答え 2）を取り消すことになる。OQ-076 の答えで選ぶことはできる。
- **年齢で例外を作らないという読み方で決める（今決める）**: 秘書の読み方で構想の意図を決めることになる。OQ-076 の答えまで暫定にとどめる。
- **年齢の項目を今置く（データとして持っておく）**: OQ-064 の答えを前提にすることになる。
- **「不審な挙動への対処」の中身をこの ADR で決める**: 何を不審と見るかは、手紙の照合の細部（OQ-065）・違法な物の取引の守り（OQ-053）とあわせて決めるほうがそろう。

## 決めていないこと

- ルール表に当たった手紙を、送った人の確認とモデレーターの承認で届けてよいか、一律に止めるか: OQ-076（要回答。暫定は ADR-0040 の流れのまま。M4 の前に答えを確かめる）。
- 年齢の扱い（登録で必須か・あとから変えられるか・ほかの住民に見せるか・年とともに進むか）と、年齢の属性で何の表示が変わるか: OQ-064（要回答）。答えまで、年齢の項目と列は置かない。
- 「不審な挙動への対処」の中身（何を不審と見るか・何をするか）: OQ-075（持ち越し。M4 を始める前に秘書が ADR で決める）。
- 住民への処置の中身: OQ-048（持ち越し）。手紙の照合の細部: OQ-065（持ち越し）。違法な物の取引の守り: OQ-053（持ち越し）。
- 適用法令が未成年の利用について何を求めるか: OQ-032（持ち越し）。
