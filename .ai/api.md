## §1 原則

1. **即時性を持ち込まない**（P-1、FR-014、FR-030）[explicit]
   - WebSocket、SSE、ロングポーリングは作らない。
   - 「新着があるか」を問い合わせるエンドポイントも作らない。
   - 住民がアプリを開いたときに郵便受けを取りに行く形にする。
   - 配達の通知（OQ-002・OQ-042 → 決定、ADR-0025・ADR-0035）は、worker（J15）が新聞の通知を配達回の公開のあとに、手紙の通知を受取人の手紙の時刻のあとに送る。API からは通知を送らない。
   - 郵便受けは、配達回が `done` で、かつ `visible_at` を過ぎた項目だけを返す（手紙は午前・午後の受取人ごとの時刻から、新聞は 07:00 / 17:00 から。ADR-0035）。受取人ごとの時刻は返さない。
     API が受けるのは、通知の購読の登録と削除だけ（§7 F-05）。

2. **数値の評価を返さない**（P-2、FR-017、FR-038、FR-044、FR-055）[explicit]
   - 返さないもの: 既読フラグ、未読件数、総件数、閲覧数、反応数、住所録への登録数、1 日の上限の残り回数。
   - 配達完了の通知に載せる郵便の件数は、通知の中身にだけ載せる。API の応答には載せない（ADR-0025 の D5）。

3. **同期で返すのは「受け付けた」まで**（ADR-0004、ADR-0008）[explicit]
   - 配達・審査・組版は worker が定時に行う。API は受付の状態（pending / awaiting_review）まで。
   - 例外として、手紙は投函のときに API がルール表の手紙の項目に当てる（LLM は使わない）。当たったら保存せずに 422 を返し、送った人が確認を頼んだときだけ `held` で保存する（OQ-052 → 決定、ADR-0040）。

4. **外から見える識別子は住所文字列のみ**（ADR-0001、db.md §3）[inferred]
   - 内部の UUID や `registered_tenancy_id` はレスポンスに含めない。

5. **API の経路で LLM を呼ばない**（NFR-011）[explicit]
   - 認可やポリシーの判断に LLM を使わない。

## §2 API・DB・バッチの責務の分け方

### §2.1 3 者の責務の表

| | 行うこと | 行わないこと |
|---|---|---|
| **API（web、C2 → C3）** | 認証、認可（本人のものか・ロール）、入力の検証（JSON Schema）、上限の確認（2,000 字・1,000 字・1 日 20 通・1 日 5 件・住所録の追加の 1 日 20 件）、手紙の投函のときの知り合いの確認（ADR-0049）とルール表の照合（暗号化の前、LLM なし。ADR-0040）、受付の状態での保存、配達済みの物の読み出し、手紙の復号（本人に返すときと、通報された手紙・確認待ちの手紙をモデレーターに 1 通だけ返すときだけ。ADR-0026・ADR-0040）、確認待ちの手紙へのモデレーターの操作（`approve` で `pending` に・`reject` で `blocked` に）、すぐに実行するジョブの投入（ID だけを同じトランザクションで積む） | 配達、審査（手紙の投函のときの照合を除く）、LLM の呼び出し、組版、画像の加工、時刻で決まる状態の変更、配達先の決定（転送・差し戻し・ブロックによる抑止）、物理削除の実行 |
| **DB（C7）** | 正本、一意の制約（配達・組版の冪等性）、外部キー、状態の値の制約、ジョブのキュー | 業務ロジックをトリガーやストアドプロシージャに置くこと [assumed]。理由: C3 に集めてテストしやすくするため（NFR-061） |
| **バッチ（worker、C4 → C3）** | JST の cron で動く処理（締め切り、審査、組版、配達、休眠の判定、保持期間による削除）と、すぐに実行するジョブ（退去時の消去、組み直し） | HTTP の受け付け、住民の権限での操作（システムの権限で動く） |

### §2.3 締め切りの境目

- API は共有の関数 `nextDeliveryRun(now)` で配達回 ID を決める。
- `delivery_runs` の行がなければ `INSERT … ON CONFLICT DO NOTHING`（`status=pending`）で作る。
- 同じトランザクションの中でその行を `FOR SHARE` で読み、`pending` でなければ次の便の配達回にする。
- 締め切り処理は `status=running` に更新するので、共有ロックの解放を待つ。こうして、締め切った配達回に書き込みが紛れ込まないようにする [inferred]。詳しくは async.md に引き継ぐ。

### §2.4 同期でやること・非同期でやることの流れ

**F-04 手紙の投函**
1. API: 宛先住所の形式を確かめ、宛先が送る人の知り合いかを確かめる（ADR-0049 の D5。ブロックは見ない）
   - 知り合いでない（住所がない・空き家・どちらも足していない・片方だけ足している）→ 何も保存せずに `422`（`not_acquainted`）を返す。1 日の上限に数えず、本文はルール表に当てない
2. API: 暗号化の前に、本文をルール表の手紙の項目（スパム・外部リンク・成人向けの言葉）に当てる（ADR-0040。平文はメモリの中だけ。LLM は使わない）
   - 当たり、`request_review` がない → 何も保存せずに `422`（`letter_needs_review`）を返す。web はポップアップで y / n を聞く（n なら何もしない）
   - 当たり、`request_review: true` → 本文を暗号化し、`held` 状態で保存する（`delivery_run_id` は NULL、`matched_rule_id`・`rule_version` を書く）。`202` と `{id}` を返す
   - 当たらない → 3 へ
3. API: 本文を暗号化し、`pending` 状態で `letters` に保存する（`rule_version` を書く）。同じトランザクションで `nextDeliveryRun` を呼び `delivery_runs` 行を冪等に作る（§2.3）
4. API: `202` と `{id, delivery_run_id}` を返す
5. worker: 締め切り時刻に `scheduled` → 公開の時刻（07:00 / 17:00）に `delivered` / `suppressed` / `returned` に遷移させる。受取人の郵便受けに見えるのは、その受取人の手紙の時刻（午前 08:00〜11:50・午後 18:00〜20:50 の枠、ADR-0035）を過ぎてから。worker は手紙を照合し直さない（ADR-0040 の D3）
6. `held` の手紙: モデレーターが `approve` すると、API が `pending` にして `nextDeliveryRun` の配達回に入れ（§2.3 の手順）、5 に進む。`reject` すると `blocked` になる（§7 F-08）

**F-07 掲示板の投稿**
1. API: 本文（1,000 字以内）を検証し、`awaiting_review` 状態で `board_posts` に保存する
2. API: `202` と `{id}` を返す
3. worker: 締め切り処理でモデレーション → `approved` / `rejected` → 配達時に `published`

**退去（DELETE /me）**
1. API: `residents.deleted_at` を設定、セッションを無効化、`account.erase` ジョブを同一トランザクションで積む
2. API: `202` を返す
3. worker: `account.erase` ジョブを受け取り、ADR-0013 の表に従い消去・組み直しを行う

### §2.5 コードの置き場所

- ルートのハンドラは薄くする: 解析 → 認証 → C3 のサービスを呼ぶ → エラーの対応付け。
- 本人のものかの確認と、クエリを本人の分に絞ること（`WHERE owner_id = $me` など）は、C3 のサービスの関数で必ず行う。
- worker も同じ C3 を使う（ADR-0008）。

## §3 API の形

- HTTPS と JSON、資源ごとの区切り、接頭辞は `/api/v1` [assumed]。
- スキーマは Fastify の JSON Schema で、型はクライアントと共有する（ADR-0009）。

**時刻**
- ISO 8601 の `+09:00` で返し、JST だけに対応する（OQ-034、NFR-048）。
- メッセージは日本語のみ（NFR-047）。
- 受取人に見せるのは「書いた時刻」ではなく配達回（例: `2026-11-19-morning`）[inferred]。

**キャッシュ**
- 住民の情報には `Cache-Control: no-store` を付ける。

## §4 認証と権限の確認の位置

- 認証は Fastify の preHandler で行う。方式はメールアドレス＋パスワード（ADR-0018、OQ-028 は決定）。
  セッションはサーバー側に持ち、複数の端末で同時に持てる（ADR-0019、OQ-036 は決定）。詳細は security.md §3。
- 認証なしで呼べるのは次の 4 つだけ（NFR-014）: 住所の候補、登録、ログイン、興味の一覧（登録の画面で選ぶため。一覧だけを返し、住民の情報と件数は返さない、ADR-0039）。
- 本人のものかの確認は C3 で行う。本人のものでないときや存在しないときは `404` を返し、存在するかどうかを明かさない [inferred]。
- `/api/v1/admin/*` はロールで確認する。ロールは住民とモデレーターの 2 つで、admin 経路はモデレーターだけが呼べる（ADR-0020、security.md §4、OQ-031 は決定）。`403` を返すのは admin 経路のときだけ。
- ブロックの判断は API ではしない。送った人にブロックを気づかれないよう、送信は受け付け、配達のときに `suppressed` にする（db.md §3）。
  投函のときの知り合いの判定（ADR-0049 の D2・D5）と、住所録の `acquainted` でもブロックを見ない（ブロックで 422 や `acquainted` が変わると、ブロックが分かるため。security.md T-06）。
  - architecture.md C2 の「ブロック」は「ブロックの登録を受け付けること」と読む。§10 で文言の整理を提案する。

## §5 エラーの形

```json
{ "error": { "code": "...", "message": "日本語のメッセージ", "details": {} } }
```

| 状態コード | code |
|---|---|
| 400 | `validation_failed`、`body_too_long` |
| 401 | `unauthenticated` |
| 403 | `forbidden`（admin 経路のみ） |
| 404 | `not_found` |
| 409 | `conflict`（住所を選ぶときの競合など） |
| 422 | `letter_needs_review`（手紙がルール表の手紙の項目に当たった。何も保存していない。当たった規則・理由は返さない、ADR-0040）、`not_acquainted`（手紙の宛先が送る人の知り合いでない。何も保存していない。住所がない・空き家・知り合いでない、のどれも同じ決まった文面、ADR-0049 の D5） |
| 429 | `daily_limit_reached`（手紙・投稿・住所録の追加の JST の暦日ごとの上限）、`rate_limited`（登録の要求・ログイン試行・パスワード再設定・確認メール送信・手紙の `letter_needs_review` の流量の制限、security.md §3.5、ADR-0030・ADR-0040）。どちらも残りの数・解除までの時間は返さない |
| 500 | `internal` |
| 503 | `unavailable` |

スタックトレース、内部 UUID、`registered_tenancy_id` は返さない。

## §6 ページング

- カーソル方式。`?cursor=&limit=`、limit は既定 20・最大 50 [assumed]。
- 応答は `{ items, next_cursor }` で、総件数は返さない。
- 並びは決定的にし、人気の順は使わない。
  - 郵便受け: 配達回の新しい順 → 新聞 → 手紙 → id
  - 掲示板: 掲載された配達回の新しい順 → `created_at` → id
- 1 日の上限の数え方: JST の暦日ごとに数え、住民ごとに `pg_advisory_xact_lock` で直列にする [assumed]。
  住所録の追加は、消しても減らない `address_book_daily_counts`（`db.md` §2）で数え、住所を変える `PATCH /api/v1/address-book/{id}` も数える（ADR-0049 の D4）。

## §7 MVP の機能ごとのエンドポイントの概略（F-01〜F-09・F-19）

### F-01 架空の住所・プロフィール

| メソッド | パス | 要約 | 状態コード | FR / ADR |
|---|---|---|---|---|
| `GET` | `/api/v1/addresses/candidates` | 住所の候補（OQ-022）。MVP では使われたことのない住所だけを返す。空き家の再割り当ては段階 3（ADR-0023） | 200 | FR-002, FR-003 |
| `GET` | `/api/v1/profiles/{address}` | 住所・ニックネーム・自己紹介だけを返す。空き家も存在しない住所も 404。今の年齢（`age`）は、下の見せる条件を満たすときだけ返し、満たさないときは項目そのものを返さない（`null` も返さない）（ADR-0048 の D4） | 200, 404 | FR-008, FR-113, ADR-0048 |

年齢の見せる条件（ADR-0048 の D4。OQ-064 → 決定、2026-11-20）: 見る住民がプロフィールの住民本人でないとき、次をすべて満たすときだけ `age` を返す。
(a) 見る住民の `mailbox_items`（`kind = 'letter'`、`visible_at` を過ぎたもの、`deleted_at IS NULL` の行だけ）に、プロフィールの住民が送った手紙が 1 通以上ある。見る住民が郵便受けから削除した手紙は数えない（FR-099・ADR-0013）。
(b) その手紙の `created_at` が、プロフィールの住民の今の居住記録（`tenancies.is_current`）の `started_at` 以後である（引っ越す前の手紙では見せない、ADR-0003）。
(c) 見る住民が、プロフィールの住民をブロックしていない。
プロフィールの住民が見る住民をブロックしても、`age` の有無は変えない（ブロックを気づかせない、security.md T-06・ADR-0015）。
条件に当たるかで状態コードと応答の形を変えない（`age` の有無だけが変わる）。見せるかどうかの住民の設定は置かない。

### F-02 アカウント

| メソッド | パス | 要約 | 状態コード | FR / ADR |
|---|---|---|---|---|
| `POST` | `/api/v1/registrations` | 住所の選択と認証情報の登録。認証情報は security.md で決める。開放式で、招待トークン・紹介者は受け取らない（ADR-0030）。任意で `interests`（興味の一覧の `key` を 5 つまで）を受け取り、`source = 'registration'` で保存する。一覧にない値・上限を超えた数は 400（`validation_failed`）（ADR-0039）。`age`（整数、0〜999）を必須で受け取る。ない・整数でない・範囲の外は 400（`validation_failed`）（ADR-0048 の D1） | 201, 400 | FR-001, FR-091, FR-109, FR-113, ADR-0001, ADR-0030, ADR-0039, ADR-0048 |
| `POST` | `/api/v1/sessions` | ログイン | 200 | FR-011 |
| `DELETE` | `/api/v1/sessions/current` | ログアウト | 204 | — |
| `GET` | `/api/v1/me` | 自分のプロフィールを返す。今の年齢（`age`、登録の日から JST の日付で進めたもの）を含む（ADR-0048 の D3・D4） | 200 | FR-008, FR-113, ADR-0048 |
| `PATCH` | `/api/v1/me` | ニックネーム・自己紹介を更新する。`age` は受け取らず、要求にあれば 400（`validation_failed`）で、何も変えない（ADR-0048 の D2） | 200, 400 | FR-009, FR-113, ADR-0048 |
| `DELETE` | `/api/v1/me` | 退去を受け付ける（§2.4 参照） | 202 | FR-093, ADR-0013 |
| `GET` | `/api/v1/interest-categories` | 興味の一覧（`active` なものの `key`・`label`）だけを返す。認証なしで呼べる。興味ごとの住民の数などの件数は返さない | 200 | FR-109, ADR-0039 |
| `GET` | `/api/v1/me/interests` | 自分が選んだ興味を返す（本人だけ。登録のときに選んだか設定かも返さない）。過去の新聞の検索から推し量った興味（`inferred_interests`）は返さない（ADR-0045 の D8） | 200 | FR-109, ADR-0039, ADR-0045 |
| `PUT` | `/api/v1/me/interests` | 自分が選んだ興味を置き換える（一覧の `key` を 0〜5 個、`source = 'settings'`）。一覧にない値・`active` でない値・上限を超えた数は 400（`validation_failed`）。変更は次の配達回の J4 から効く。推し量った興味には触れない | 204, 400 | FR-109, ADR-0039, ADR-0045 |

興味は本人だけが読み書きできる。ほかの住民・モデレーターの興味を返す経路は作らない（§8、security.md §4.2）。
登録とプロフィール（`PATCH /api/v1/me`）に生年月日の項目は置かない（ADR-0041 の D4）。誕生日の項目も置かない（OQ-077 の暫定、ADR-0048 の D5）。
年齢は登録で必須で受け取り、あとから変える経路はどこにも作らない（モデレーター・運用者の CLI を含む。OQ-064 → 決定、2026-11-20、ADR-0048 の D1・D2）。年齢を確かめる経路は作らない（ADR-0041 の D2）。
今の年齢は C2 が読むときに `age_at_registration` と `age_base_date` から時計のアダプタで計算する（ADR-0048 の D3）。年齢は本人の `GET /me` と、F-01 の見せる条件を満たす `GET /profiles/{address}` だけが返す。
住所録・地図・掲示板・新聞・通知・検索・admin の応答には入れない（ADR-0048 の D4）。
どの経路も、要求した住民や相手の年齢で応答・権限・照合の結果を変えない（ADR-0047 の D1・D2）。
住所録の検索（`GET /api/v1/address-book?q=`）からは興味を集めず、検索語を DB・ログに残さない（ADR-0045 の D1。OQ-059 → 決定、2026-11-20）。
興味を推し量るのは、段階 2 の自分に届いた過去の新聞の検索だけ（§7 F-06）。推し量った興味を本人・ほかの住民・モデレーターに返す経路と、本人が消す経路は作らない（§8、ADR-0045 の D8）。

### F-03 郵便受け

### F-04 個人宛の手紙

| メソッド | パス | 要約 | 状態コード | FR / ADR |
|---|---|---|---|---|
| `POST` | `/api/v1/letters` | 本文（2,000 字以内）と宛先と、任意の `request_review`（真偽値）を受け付ける。ルール表の手紙の項目に当てて、当たらなければ `pending` で保存し `{id, delivery_run_id}` を返す。当たり `request_review` がなければ何も保存せずに 422（`letter_needs_review`）。当たり `request_review: true` なら `held` で保存し `{id}` を返す（ADR-0040）。宛先が知り合いでなければ、照合の前に何も保存せずに 422（`not_acquainted`）（ADR-0049） | 202, 400, 422, 429 | FR-011, FR-012, FR-112, FR-121, ADR-0004, ADR-0040, ADR-0049 |

| `GET` | `/api/v1/letters/sent/{id}` | 送信済み手紙の詳細 | 200, 404 | FR-018 |

**宛先の確認**（ADR-0049 の D5。OQ-066 → 決定、2026-11-20）: 確かめる順番は、形式の確認 → 知り合いの確認 → ルール表の照合（下の投函のときの照合）。
宛先が送る人の知り合い（互いの住所録のエントリが相手の今の居住記録を指す。ブロックは見ない、ADR-0049 の D2）でなければ 422 `not_acquainted` を返す。
住所がない・空き家・どちらも足していない・片方だけ足している、のどれも同じ決まった文面で、何も保存せず、1 日の上限にも数えない（security.md T-05）。
知り合いを確かめるのは投函のときだけ。投函したあとで知り合いでなくなった手紙（`pending`・`held`・承認されたもの）は、そのまま配達のときの振り分け（届く・転送・差し戻し・`suppressed`、db.md §3）に進む。  
「配達済み」（`delivered`・`suppressed`）は、その配達回の手紙の時間帯の終わり（朝便 12:00・夕便 21:00）を過ぎてから見せる。
それまでは「投函済み」と見せ、宛先ごとの時刻（`letter_recipients.delivered_at`）は返さない（ADR-0035 の D10）。  
`suppressed` は「配達済み」として見せる。`held`（送った人が確認を頼んだ手紙）は「確認中」、`blocked`（モデレーターが却下した手紙）は「届けられませんでした」と見せ、
どちらも当たった規則・理由は返さない（ADR-0026 の D5・ADR-0040 の D4・D5）。

**投函のときの照合**（ADR-0040）:
- 照合は暗号化の前に、ルール表の手紙の項目だけで行う。LLM は呼ばない。平文はメモリの中だけに置き、ログ・例外のメッセージに書かない。
- 422 `letter_needs_review` の応答は、決まった文面だけで、当たった規則・項目の種類・本文の位置を含めない。手紙は保存せず、1 日の上限にも数えない。
- `request_review: true` で `held` にして、モデレーターの承認で届ける流れは、OQ-076（要回答）の答えまでの暫定（ADR-0047 の D1）。答えが「一律に止める」なら、`request_review`・`held`・「確認中」・`/api/v1/admin/held-letters` の経路（§7 F-08）がなくなり、当たった手紙は 422 だけになる。
  住民ごとの流量の制限を超えると 429 `rate_limited`（security.md §3.5。値は OQ-065）。
- web は 422 を受けたら、モデレーターに確かめてもらって送るか（y）・送らないか（n）をポップアップで聞く。y を選ぶとモデレーターが本文を読むことを書く（文言は OQ-065）。
  n なら何も送らない。y なら同じ本文と宛先に `request_review: true` を付けて送り直す。
- `request_review: true` でも、本文がどの規則にも当たらなければ、ふつうの手紙として `pending` で保存する。`held` の手紙は 1 日の上限に数える。
- 送ったときに当たらなかった手紙は、あとでルール表の版が上がっても当て直さない（ADR-0040 の D3）。

**通報された手紙の取得**（`GET /api/v1/admin/reports/{id}/letter`、ADR-0026 の D4 (c)）
- この経路は決定（OQ-043 の答え、2026-11-19、ADR-0036 の D2）。住民が通報した手紙は、モデレーターが下の条件で確かめてよい。
- 返すのは、通報が `open`・対象が手紙・呼んだモデレーターがその手紙の当事者（送った人・受け取った人・通報した人）でない・
  セッションが二要素認証を済ませている、のすべてを満たすときだけ。満たさなければ 404（存在を明かさない）。
- 1 回の呼び出しで返すのは、その通報の手紙 1 通だけ。複数の手紙をまとめて返す経路・本文の一覧・本文の検索は作らない。
- 呼ぶたびに `moderation_actions` に `view_letter` の行を書く。書けなければ本文を返さない（同じトランザクション）。
- 応答には `Cache-Control: no-store` を付ける。
- 通報されていない手紙を見る経路は、次の確認待ちの手紙の経路だけ。`blocked`・`pending` などほかの状態の手紙を見る経路はない（OQ-052 → 決定、2026-11-20、ADR-0040 の D5）。

**確認待ちの手紙の確認**（`/api/v1/admin/held-letters`、ADR-0040 の D5）
- 送った人が投函のときに確認を頼んだ（`request_review: true`）手紙だけが対象。
- 取得と操作は、手紙が `held`・呼んだモデレーターがその手紙の当事者（送った人・宛先の住民）でない・セッションが二要素認証を済ませている、のすべてを満たすときだけ。満たさなければ 404。
- 取得のたびに `moderation_actions` に `letter_id` 付きの `view_letter` の行を書く。書けなければ本文を返さない（同じトランザクション）。応答には `Cache-Control: no-store` を付ける。
- 1 回の呼び出しで返す本文は 1 通だけ。一覧は本文を返さない。本文の検索は作らない。
- `approve`: `held` → `pending` にし、`nextDeliveryRun(now)` の配達回に入れる（§2.3 の `FOR SHARE` の手順）。`moderation_actions` に `approve` を書く。次の配達回で届く。
- `reject`: `held` → `blocked` にし、`decided_at` を書く。`moderation_actions` に `reject` を書く。送った人には「届けられませんでした」と見せる。
- 状態の更新は `WHERE id=$1 AND state='held'` で行う。すでに操作された手紙への操作は 404（2 人のモデレーターが同時に操作しても 1 回だけ効く）。

### F-19 架空の街の地図

| 知り合いの家 | `GET /api/v1/address-book` のすべてのエントリの住所（`acquainted` によらない。登録した時点の住所、ADR-0003。OQ-071 の暫定 (i)） | M2 |

空き家・入居の表示（FR-115）は、範囲が決まるまで（OQ-079、要回答）作らず、それを返す経路も作らない（§8）。

OQ-066 の答え（2026-11-20、ADR-0049）で、知り合いには相手の同意（互いの追加か掲示板でのオープン）が要ると決まり、`GET /api/v1/address-book` の各エントリに `acquainted` が入った（§7 F-09）。

## §8 作らない API

| 経路 / 機能 | 理由 |
|---|---|

| 既読フラグの操作・記録 | FR-017 に反する |
| 総件数（ページングの `total`） | P-2 に反し、カーソル方式で不要 |
| いいね・反応 | P-2 に反する（FR-038） |
| 誰が自分を住所録に登録しているか（一覧・件数・通知） | FR-058。足されたことは知らせない（ADR-0049 の D3、OQ-066・OQ-040 → 決定） |
| 住所録の申請の一覧・承認の経路 | 申請を見せない（OQ-066 の答え「申請来ていることを確認できなくする」、ADR-0049 の D3）。承認は足し返すこと |
| 配達・組版を今すぐ起こす操作 | ADR-0004 の定時配達に反する |
| 通知を今すぐ送る・試しに送る操作 | 通知は worker が配達回ごとに新聞と手紙の 1 回ずつだけ送る（ADR-0025 の D2・ADR-0035 の D11） |
| 住民ごとの手紙の時刻（`visible_at`・`delivered_at`）を返す経路 | 受け取った時刻を送った人に知らせない（ADR-0035 の D10） |
| LLM の判断をそのまま返す経路 | NFR-011 に反する |
| ほかの住民の興味を返す経路 | 興味は本人だけのもの（ADR-0039 の D5） |
| 興味ごとの住民の数 | P-2 に反し、興味を推し量れる（ADR-0039 の D5） |
| 版の一覧・どの版かを返す経路 | 版からほかの住民の興味が分かる（ADR-0039 の D11） |
| 検索の履歴 | 検索語を残さない（ADR-0045 の D4。住所録の検索からは興味を集めない） |
| 推し量った興味（`inferred_interests`）を返す・消す経路 | 本人が見て消す仕組みは設けない（OQ-059 の答え 4、ADR-0045 の D8）。本人・ほかの住民・モデレーターのどの経路にも返さず、エクスポート（F-15）にも入れない |
| 地図の経路・住所ごとの位置の一覧 | 位置は C1 の静的な配置の定義と計算で求める（ADR-0028 の D3・ADR-0042 の D4） |
| 年齢を変える経路（本人・モデレーター・運用者のどれも） | 答え「変更は不可」（OQ-064、ADR-0048 の D2） |
| 年齢で住民を探す・並べる・絞る経路 | 年齢で住民を探せる（security.md T-05）。年齢は D4 の条件のプロフィールでだけ見せる（ADR-0048 の D4） |
| 空き家・入居の一覧（地図の表示） | 範囲が決まるまで作らない。住んでいる住所の一覧になり、住所の列挙（security.md T-05）になりうる（OQ-079、ADR-0042 の D10） |

## §9 未確定事項

- **締め切り直前の書き込みの扱いの詳細**: 競合状態の正確な手順は async.md に引き継ぐ。
- **掲載済み投稿を本人が削除したときの組み直し**: ADR-0013 と同じ組み直しジョブを使う予定 [assumed]。
- **投函の取り消し API を作るか**: 範囲外。別チケットで検討する。
- **`returned`・`blocked` を送った人にどう知らせるか**: 決定。`returned` は「差し戻し」、`held` は「確認中」、`blocked` は「届けられませんでした」と見せ、当たった規則は見せない（ADR-0026 の D5・ADR-0040、§7 F-04）。
- **クローズドな手紙の審査**: OQ-003 は決定（対象とする・LLM には渡さない・厳格なアクセス制御、ADR-0026・§7 F-08）。
  通報された手紙はモデレーターが条件付きで 1 通だけ確かめてよい（OQ-043 → 決定、2026-11-19、ADR-0036・§7 F-08）。
  手紙で止める内容と、止めた手紙の閲覧は OQ-052 → 決定（2026-11-20、ADR-0040）: 投函のときにスパム・外部リンク・成人向けの言葉に当て、当たったら 422 で送った人に確認を頼むかを聞き、
  頼まれた手紙（`held`）をモデレーターが `/api/v1/admin/held-letters` で確かめる（§7 F-04・F-08）。照合の細部（ポップアップの文言・流量の制限の値など）は OQ-065（持ち越し）。
- **年齢**: 年齢による違いは作らない（OQ-063 → 決定、2026-11-20、ADR-0047）。年齢は住民の設定をそのまま使う（ADR-0041）。年齢の扱いは OQ-064 → 決定（2026-11-20、ADR-0048）: 登録で必須・変えられない・登録の日から進む・本人から手紙を受け取った住民にだけ見せる（§7 F-01・F-02）。
  誕生日を集めて新聞に載せるかは OQ-077（要回答。暫定は集めず載せない）、年齢の属性で何の表示が変わるかは OQ-078（持ち越し。暫定は作らない）。
- **一般的な流量の制限と CSRF 対策**: security.md に引き継ぐ。
- **管理者のロール定義**: OQ-031 は決定（住民とモデレーターの 2 つ、付与は運用者 CLI のみ、ADR-0020・security.md §4）。
- **認証の方式**: OQ-028 は決定（メールアドレス＋パスワード、ADR-0018・security.md §3）。
- **複数の端末のセッション管理**: OQ-036 は決定（複数の端末で持てる、ADR-0019・security.md §3.3）。
- **プッシュ通知**: OQ-002 は決定（配達完了の通知を Web Push で送り、郵便の件数を含める。ADR-0025・§7 F-05）。
  OQ-042 も決定（新聞の通知「新聞が配達されました！」と手紙の通知「手紙が配達されました！（N通）」に分け、0 通の住民には手紙の通知を送らない。ADR-0035）。
  API の形は変わらない（購読の API だけ）。
- **新聞の中身**: OQ-051 → 決定（2026-11-20、ADR-0039）。登録の `interests`、興味の一覧と自分の興味の経路を足し、新聞の `{id}` を版にした（§7 F-02・F-06）。
  検索から興味を集めることは OQ-059 → 決定（2026-11-20、ADR-0045）: 段階 2 の過去の新聞の検索（`GET /api/v1/newspapers?q=`、§7 F-06）からだけ推し量り、推し量った興味を返す経路は作らない。住民が止められるかは OQ-072（要回答。暫定は止める設定を置かない）。知り合いの組は OQ-058 → 決定（2026-11-20、ADR-0044）: MVP では全住民を知り合い 0 の組として扱い、組 1・2 の住民ごとの版は作らない（作る時期は OQ-070）。
  作るときも経路は足さず、住民ごとの版は本人だけが `{id}` で見られ、ほかの住民とモデレーターには 404。`edition_key` は返さない（ADR-0044 の D4）。
- **地図の印**: OQ-054 → 決定（2026-11-20、ADR-0042）。経路は足さず、すでにある `me`・候補・住所録の応答を C1 が使う（§7 F-19）。
  手紙を出せる知り合いに相手の同意が要ることは OQ-066 → 決定（2026-11-20、ADR-0049）。地図の印を付けるエントリ（印に同意を求めるか）は OQ-071（要回答。暫定は (i) 住所録のすべてのエントリ、ADR-0049 の D8）。
  空き家・入居の表示の範囲は OQ-079（要回答）。答えまで、空き家・入居を返す経路は作らない。登録のときに地図の印から選ぶかは OQ-080（要回答。暫定は一覧から選ぶ）。
- **手紙の宛先**: OQ-066 → 決定（2026-11-20、ADR-0049）。手紙は知り合いにだけ出せ、知り合いでなければ 422 `not_acquainted`（§2.4・§7 F-04）。住所録の `acquainted` と 1 日 20 件の追加の上限を足した（§7 F-09）。
  掲示板の経路の中身は OQ-081（要回答。答えまで作らない）。マッチング・商店・団体との手紙と転送のときの知り合いは OQ-082（持ち越し）。
