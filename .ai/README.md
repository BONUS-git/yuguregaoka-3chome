# .ai — 設計と計画

| ファイル | 中身 |
|----------|------|
| `INDEX.md` | 地図（知りたいこと → 図 → 文書の節）と、`.ai/` のすべてのファイルの一覧。最初に読む |
| `diagrams/<題>.md` | 図（Mermaid。1 図 1 ファイル。各図に対応する FR・ADR と確かめた M） |
| `tests/test-plan.md` | テスト項目書（今の M の FR ごとの TC。テストの名前に TC-NNN を入れる） |
| `deploy/readiness.md` | デプロイの準備書（デプロイしない前提。サーバー側の項目の状態と、計画の正本 `environment.md` の節・持ち越しの OQ の対応。確かめた M） |
| `brief.md` | マスターの構想の原文（変えない） |
| `requirements.md` | プロダクト要求仕様書（機能要件・非機能要件。各要求に [explicit]（構想にある）・[inferred]・[assumed] の区別） |
| `features.md` | 機能一覧と優先順位（最初に動かす最小の範囲と、その後） |
| `open-questions.md` | 不足仕様・未確定事項・矛盾・リスクの一覧（マスターに聞くものに「要回答」の印。自分で決めたものは決めた理由と ADR） |
| `architecture.md` | システムアーキテクチャと技術選定（選んだ理由は ADR） |
| `db.md` | DB 設計方針（データのライフサイクル: 作る・保つ・消す） |
| `api.md` | API 設計方針（API・DB・バッチの責務の分け方） |
| `async.md` | 非同期処理の設計（定時の処理・夜間のバッチ・モデレーションなど構想にあるもの。冪等性と、やり直したときの動き） |
| `security.md` | セキュリティ設計（セキュリティの判断を LLM の裁量にしない。個人情報・認証・権限・モデレーション） |
| `roadmap.md` | 開発ロードマップ（段階・依存・各段階の受け入れ条件） |
| `environment.md` | 開発・検証環境の構築計画（スタックの計画と IaC の設計まで。適用・クラウドの契約はしない） |
| `adr/NNNN-<題>.md` | 設計判断の記録（ADR）。書き方は `adr/README.md` |
| `reviews/NNNN-<題>.md` | 設計・コードのレビュー（重大・中・軽微） |
| `mvp.md` | MVP の定義（中心の体験・M ごとの FR・状態） |
| `brief-map.md` | ブリーフの対応（構想の各文 → FR・機能） |
| `triage.md` | レビューの残り事項の仕分け（秘書の仕分けのジョブが書く） |
| `gaps.md` | 持ち越し（暫定・後回しにしたものと向かう M） |
| `tickets/YGO-NNN-<題>.md` | 変更のチケット（目的・範囲・受け入れ確認・状態） |
| `status.md` | 実装済み・未実装・暫定対応 |
| `retros.md` | 失敗の記録（問題・根本原因・気づけなかった理由・再発防止） |
| `report.md` | 完成の報告（動作確認・テスト・既知の問題・未実装・デプロイと運用の手順） |

段階: 設計 → 設計のレビュー → 実装 → 動作確認。段階を進めるのはマスターの確認。
