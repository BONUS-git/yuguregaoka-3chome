## §1 方針

### §1.1 入れない機能の基準

次の原則（`requirements.md` §1.3）に反する機能は入れない。入れなかった機能は §4 に列挙する。

| 原則 | 内容 |
|------|------|
| P-1 | 即時性を持ち込まない（リアルタイム通知・チャット・即時配信を設けない。配達は 1 日 2 回の配達回で、新聞は定時・手紙は午前・午後の時間帯の中のランダムな時刻（ADR-0035）。配達の通知は新聞と手紙のそれぞれの配達のあとに、配達回ごとに 1 回だけ、ADR-0025・ADR-0035） |
| P-2 | 数値の評価を持ち込まない（いいね・フォロワー数・スコアなどを表示しない） |
| P-3 | 外見の情報に頼らない（顔写真を身元情報として使わない。画像は新聞写真風に加工する） |

### §1.2 段階の分け方

| 段階 | 位置づけ |
|------|----------|
| MVP（段階 1） | 「朝、自分の家のポストを開ける」体験が成立する最小の範囲 |
| 段階 2 | MVP のデータモデルを拡張する機能 |
| 段階 3 | データのライフサイクルやアルゴリズムの確定を待つ機能 |
| このフェーズの範囲外 | 明示的に範囲外とされた機能（§1.4、FR-090） |

### §1.3 優先順位の判定ルール

機能の段階を決める際は次の順で判断する。

1. 「朝、自分の家のポストを開ける」体験が成立するか
2. 依存順: 住所 → 手紙 → 配達 → 新聞
3. 公開コンテンツが出る前にモデレーション・画像加工を配置する
4. 未確定の事項・マスターの回答待ちの事項を後ろに回す

### §1.4 広告・折込チラシについて

FR-083〜FR-090 の広告・折込チラシはこのフェーズの実装範囲外（`requirements.md` §1.4）。運営の新聞の入居者募集の広告（FR-123）は F-20 に含めず、F-17 の一部として段階 3 から出す（ADR-0050 の D5、OQ-083 → 決定）。
要件は記録するが実装しない。F-20 として「このフェーズの範囲外」に分類する。
商店が出せるものは広さと料金によるランクで変え、折込チラシはランクの最高に置く（ADR-0043 の D5、OQ-056 → 決定）。ランクの段数とそれぞれで出せるものは OQ-068（持ち越し）で、F-20 の範囲は今は変えない。

## §3 優先順位と理由

### MVP（段階 1）

F-01〜F-09 と F-19 の 10 機能が最小範囲。選定理由は次のとおり。

- **体験の中心から逆算**: 「朝、自分の家のポストを開ける」には住所（F-01）・アカウント（F-02）・郵便受け（F-03）・手紙（F-04）・配達バッチ（F-05）・新聞（F-06）が必要。
- **町内掲示板（F-07）を MVP に含める理由**: 掲示板の投稿が組版バッチ（F-06）のコンテンツ源となるため（FR-035）。掲示板なしでは新聞が空になる。新聞は全住民に届ける（FR-106、ADR-0035）が、住民や投稿が少ないと紙面が成り立たないおそれがある。掲示板のほかの紙面の中身は、実在の外のニュースと、興味の版の記事（ADR-0039、OQ-051 → 決定、2026-11-20）。外のニュースの配信元は OQ-060 で、それまで本番では掲示板の投稿だけが素材になる。
- **住所録（F-09）を MVP に含める理由**: 住所録が手紙の宛先選択（FR-053）の手段であり、MVP から手紙を使えるためには住所録が必要。
- **モデレーション（F-08）を MVP に含める理由**: MVP は掲示板という公開コンテンツを含む（FR-079、FR-080）。公開コンテンツが出る前にモデレーション層を置く（§1.3、ルール 3）。LLM はネットワークなしでテストが通るようモックにする（NFR-063、NFR-065）。クローズドな手紙も配達の前にルール表だけで審査する（FR-078、ADR-0072。照合は送るときで、絶対NGに当たった手紙は送れず、疑いに当たった手紙は送った人が頼めばモデレーターが確かめる、FR-112・ADR-0069）。
- **地図（F-19）を MVP に含める理由**: マスターの答え（OQ-005、2026-11-19「静的な画像として実装し、開発の初期段階で行う」）による。静的な画像で、DB の地図の表を持たず、API は入居の一覧（住所の状態から読む）だけなので、住所（F-01）と同じ M1 に置く（ADR-0063）。住民が投稿する画像ではないので、P-3 の画像加工（F-11）を待たない。
- **画像は MVP に含めない理由**: P-3（外見の情報に頼らない）により、画像加工（F-11）が整うまで画像添付は受け付けない。段階 2 で画像加工と一緒に追加する。

### 段階 2

F-10〜F-15 の 6 機能。MVP のデータモデルを拡張する。

- **グループ宛て手紙（F-10）**: テキスト手紙（F-04）の宛先を複数に拡張するだけで、コアのデータモデル変更が小さい。
- **画像添付と加工（F-11）**: 画像加工（P-3）が揃って初めてユーザーへ開放できる。バックナンバー（F-12）・掲示板カテゴリ（F-13）・データエクスポート（F-15）はいずれも MVP の機能拡張。
- **異議申し立て（F-14）**: モデレーション（F-08）の補完機能。MVP の公開後に追加するのが自然。

### 段階 3

F-16〜F-18 の 3 機能。データのライフサイクルかアルゴリズムの確定を先に要する。

- **引っ越し・転送・空き家（F-16）**: 転送の期間（FR-075）と、休眠にする暫定の期間（FR-072）は ADR-0060 にある。休眠は入居で空き家にせず、休眠を空き家にするかとその期間は OQ-088（持ち越し）。休眠・転送・空き家の再割り当ては同じ住所の状態遷移と毎日のジョブ（`async.md` J10〜J12。J9 は OQ-088 の答えで作るときだけ）で、居住記録による振り分け（`db.md` §3）と一緒に確かめるため段階 3 に置く（ADR-0062）。MVP の住所の候補は使われたことのない住所だけ。住所録の自動更新（FR-057）はしないと決まった（ADR-0003）。
- **商店街（F-17）**: 商店のアカウントは管理者が作る（OQ-006 → 決定、ADR-0067）。商店には実在の企業・個人のお店を迎えることを目指し、コミュニティ（団体）は住民が趣味などで作り、作ることに制約を置く（OQ-045 → 決定、ADR-0038）。
  実在の店の迎え方は決まった（OQ-056 → 決定、ADR-0043）。商店の部分は、契約・利用料・ランクの中身（OQ-068）と担当者のログイン・区画など（OQ-069）を決めてから作る。MVP には作らない（OQ-067 → 決定、ADR-0050。架空の店・張り紙・新聞の入居者募集の広告も段階 3 から。広告の時期は OQ-083 → 決定）。コミュニティの部分は、制約の中身（OQ-057、持ち越し）を S3-2 の前に秘書が ADR で決める。
- **マッチング（F-18）**: アルゴリズム未確定（FR-066）。恋愛のカテゴリは設けない（OQ-001 → 決定、ADR-0024）。連絡先の共有の禁止（FR-101）は、街の外の連絡先だけ・全ての書き込み（OQ-041・OQ-087 → 決定、ADR-0071）。守り方の細部は OQ-050（持ち越し、止まらない）。

  （ADR-0039、OQ-051、2026-11-20 のマスターの答え）。組 1・2 は OQ-058（のちに決定、次の項目）、検索からの興味は OQ-059（のちに決定、次の次の項目）、配信元は OQ-060、LLM の文の印は OQ-061（のちに決定、下の FR-111 の項目）、モデルは OQ-062 に残る。M5 に入れる。
- **FR-108・FR-118（知り合いの組と画像の元データ）**: MVP（M5）では全住民を知り合い 0 の組として扱う。知り合いは互いに住所録に入れた住民（どちらかがブロックしていれば外す）で、組 1・2 の紙面に載せるのは知り合いの承認済みの掲示板の投稿だけ（手紙は載せない）。
  組 1・2 は住民ごとに組み（本人だけが見られる）、組 2 の足りない分は、組 0 なら受け取る版（興味の版か共通の版）の記事で埋める。組は J3 が記事の枠の数で配達回ごとに計算し、保存しない。
  アップロードした画像は新聞用に加工し、元の画像は加工が終わるか失敗した時点で消す（段階 2）
  （ADR-0044、OQ-058、2026-11-20 のマスターの答え「暫定通りで。全住民を「知り合い0の組」として扱う」「知り合いの定義は b」「手紙はDMなので新聞には載せない」「アップロードした画像は新聞用に加工し、元データは保持しない方針」「共通の記事と興味の記事」）。組 1・2 を作る時期は OQ-070 に残る。地図の知り合いの定義は OQ-071 → 決定（2026-11-20、ADR-0051）で、地図は自分の住所録に入れた住民のまま、新聞と定義を分ける。
- **FR-109・FR-119（検索から興味を集めること）**: 興味は、自分に届いた過去の新聞（バックナンバー、F-12、段階 2）の検索から推し量って集める。住所録の検索・手紙・ブロック・通報などからは集めない。
  検索語は API がメモリの中だけで興味の一覧の名前と語に照合し（LLM は使わない）、当たった興味の ID だけを持ち（1 人 5 つまで・最後に当たってから 30 日で消す、仮置き）、検索語は DB・ログに残さない。新聞の版は、選んだ興味と推し量った興味を合わせて選ぶ。
  検索の画面と利用の案内で明るく開いた文で知らせ、個別の同意は取らない。推し量った興味を本人が見て消す仕組みは設けない
  （ADR-0045、OQ-059、2026-11-20 のマスターの答え「1:過去の新聞」「知らせるが、個別に同意は取らない。興味から新聞を届けます！と、ポジティブにオープンにする」「4: 設けない。」）。
  住民は推し量ることを止められない。止める設定・検索ごとに推し量らない選択・住民ごとの例外は作らず、検索と興味の収集の連動は S2-3 の設計で整理する
  （ADR-0053、OQ-072 → 決定、2026-11-21 のマスターの答え「答えは (i) 止められない。」「「本人が見て消せる仕組み」も設けない以上、個別に情報の扱いを拒否できる設定を設けるのは二重基準になるし、仕組みが複雑になる。」「S2-3 の設計段階で、この方針に沿った実装（検索と興味収集の連動）を整理して進めておいて。」）。M5 は変わらず、S2-3 に入れる。
- **FR-111（投稿の本文と LLM の文の示し方）**: 住民の掲示板の投稿の本文は書き換えずに `board_posts.body` をそのまま載せる。LLM が書くのは生成部分（外のニュースの記事の見出しと文・投稿の記事の見出し）だけ。
  LLM の文を本人の文に見せない（投稿の枠には投稿の本文だけを入れ、LLM の文は枠の外に新聞の文として置く）。紙面に「AI が書いた文」の印は付けない
  （ADR-0046、OQ-061、2026-11-20 のマスターの答え「１：示さなくて良い。規約次第なので、要確認。」「２：住民の掲示板の投稿本文は、書き換えずにそのまま載せる。…あたかも本人が書いたように見せることはしない。」）。規約の確認は OQ-073 に残る。住民の投稿を素材にした記事では、LLM は見出しだけを書き（枠の外に置く）、まとめは書かない
  （ADR-0054、OQ-074 → 決定、2026-11-21 のマスターの答え「(ii) 見出しだけ書いてよい（まとめは書かない）」）。M5 の範囲は変わらない。
- **FR-078・NFR-005（クローズドな手紙の審査）**: 個人宛・グループ宛の手紙も配達の前に審査する。本文は LLM に渡さず、ルール表だけで照合し、本文を復号してよい場面を限る（ADR-0072、OQ-003、2026-11-19 のマスターの答え）。F-08 として MVP（M4）に入れる。
- **NFR-005 の通報された手紙の閲覧**: 住民が通報した手紙は、モデレーターが条件付き（通報が `open`・当事者でない・二要素認証済み・1 通だけ・毎回記録）で確かめてよい。住民を守る制限は、住民が自分で外せる設定にしない（ADR-0036、OQ-043、2026-11-19 のマスターの答え）。手紙で止める内容と止めた手紙の閲覧は下の FR-078・FR-112（ADR-0069）。
- **FR-078・FR-112（手紙で止める内容と、止めた手紙の閲覧）**: 手紙に当てる項目はスパム・外部リンク・成人向けの言葉・本当の情報（`real_info`。メールアドレスと電話番号はこちらで扱う）。照合は送るときに API が行い、
  当たったら保存せずに送った人に知らせ、送った人がモデレーターの確認を頼むか（y）・送らないか（n）を選ぶ。y の手紙は確認待ち（`held`）になり、モデレーターが通報された手紙と同じ条件で確かめて、
  承認なら次の配達回で届け、却下なら「届けられませんでした」と見せる。確かめ終わった手紙（`blocked`）を見る経路はない
  （ADR-0069、OQ-052、2026-11-20 のマスターの答え「手紙で止めるのは一般的なスパムや外部リンク、18禁ワード等」「送信時点でチェック、引っ掛かったらポップアップでy/n選んでもらって、モデレーター確認かな」）。照合の細部は OQ-065 に残る。M4 に入れる。
- **FR-112・FR-124（当たった手紙の扱いと絵文字）**: 照合を絶対NG（`reject` の段）と疑い（`review` の段）の 2 段に分ける。絶対NGは、直接的な性的な言葉・外部へのリンク・本当の情報（`real_info`: 本当の居住地・本当の年齢・街の外の連絡先を、聞く・自分から書く・ほかの人のものを書くのどれも）で、
  当たったら何も保存せずに 422 `letter_rejected` を返し、y / n を出さない（`request_review` があっても同じ）。疑いと `spam` は `review` の段で、上の y / n とモデレーターの確認の流れのまま。両方に当たれば `reject` を先にする。
  手紙の本文に絵文字を入力できない（web の入力欄は受け付けず、API は 400 `validation_failed`。顔文字は止めない。M2 の投函から入れる）
  （ADR-0069、OQ-076 → 決定、2026-11-21 のマスターの答え「1の方針。だが、ガチガチにすると誤判定に繋がるため、分離しようと思っている」「外部へのリンク→絶対NG」「絵文字→NG。入力不可」「本当の居住地や年齢などを聞く→NG」「上記の疑いがある場合はモデレーター確認」と、OQ-087 → 決定、2026-11-22 のマスターの答え「対象に連絡先や自分から書くことも含める」）。
  段の細部は OQ-065 に残る。照合の 2 段は M4、絵文字の検査は M2 に入れる。
- **FR-124・FR-126（手紙のほかの書き込み）**: 絵文字の入力不可と絶対NGを、全ての書き込み（掲示板の投稿・商店街の発信・ニックネームと自己紹介・住所録のメモ・通報の理由・マッチングの自由記述）に当てる。絵文字は検索語にも当て、400 `validation_failed`。
  絶対NGに当たれば何も保存せずに 422 `content_rejected`。掲示板の投稿と商店街の発信は、当たらなければ今の審査に進む。ほかの書き込みには疑いの段を当てない
  （ADR-0070、OQ-087 → 決定、2026-11-22 のマスターの答え「絶対NGと絵文字不可を全てに適用」）。絵文字の検査は各入力を作る段階（M1・M2・M4・段階 2・段階 3）、絶対NGの照合は M4 から入れる。
- **FR-094（未成年の利用ポリシー）**: 未成年の利用を認め、登録に年齢制限を置かない。年齢確認・保護者の同意の手続きはなく、生年月日は集めない（ADR-0027、OQ-004、2026-11-19 のマスターの答え）。
- **FR-113（年齢）**: 年齢は住民が設定した値をそのまま使い、確かめず、架空の年齢も許す。どの年齢にも危険な機能は設けない
  （ADR-0041、OQ-052、2026-11-20 のマスターの答え「年齢はユーザーの入力信用すればいいと思う」）。年齢の扱いは OQ-064 に残っていた（OQ-064 → 決定、2026-11-20、ADR-0048。下の項目）。
- **FR-113・FR-008（年齢の扱い）**: 年齢は登録で必須（0〜999）にし、あとから変えられない。登録の日から 1 年ごとに進み、読むときに計算する。本人には `GET /me` で見せ、
  ほかの住民には、本人から受け取った手紙が郵便受けに残っていて（削除した手紙は数えない。その手紙が本人の今の居住記録の始まり以後に出され）、見る住民が本人をブロックしていないときだけプロフィールで見せる。
  本人が見る住民をブロックしても見え方は変えない（ブロックを気づかせない、T-06）。ほかの画面・モデレーター・LLM・ログには出さない
  （ADR-0048、OQ-064、2026-11-20 のマスターの答え「(1) 必須」「(2) 変更は不可」「(3) 一定条件で見せる。一定条件は安全性に基づき秘書が決定する」「(4) 進む」）。M1（登録・`/me`）と M3（プロフィール）に入れる。
- **FR-113・FR-094・FR-120（年齢で変えるもの）**: 年齢による違いは作らない。手紙と掲示板で止める基準・使える機能（マッチングへの参加を含む）は全員に同じで、年齢の区切りを置かない。
  詐欺と事件の防止は、年齢での制限でなく全員に同じ共通のルール（スパム検知・不審な挙動への対処）で行う
  （ADR-0057、OQ-063、2026-11-20 のマスターの答え「暫定の通り「年齢による違いは作らない」で進めて」「機能の解放条件も年齢に紐付けない」「年齢による区切りは設けない」）。不審な挙動への対処の中身は OQ-075 に残る。M1・M4 の中身は変わらない。
- **F-19（架空の街の地図）**: 1 枚の静的な画像として、MVP（M1）で作る（FR-103、ADR-0063、OQ-005、2026-11-19 のマスターの答え）。画像は全住民で共有する 1 枚の白黒の画像とし、ゲーム風の地図は今は作らない（ADR-0061、OQ-044、2026-11-19 のマスターの答え）。ゲーム風の地図は OQ-055 に残る。
- **FR-114（地図の印）**: 自分の家の印と登録のときの候補の印は M1、知り合いの家の印は M2 で作る（印を付けるのは住所録のすべてのエントリ。手紙を出せる知り合いに相手の同意が要ることは ADR-0065、地図との関係は ADR-0065 の D8）。地図は自分の家を中心に置き、土台の画像は全住民で同じまま、印は C1 が重ねる。
  地図の「知り合い」は自分の住所録に入れた住民で、新聞の知り合い（互いに住所録に入れた住民、ADR-0044 の D2）・手紙を出せる知り合い（互いに住所録に入れた住民か、掲示板で相手がオープンにした住民、ADR-0065 の D2）と定義を分ける。印の有無・形・見出し・代替テキストは `acquainted` で変えない（地図の印から相手が自分を住所録に入れたかを推し量らせない）
  （ADR-0051、OQ-071 → 決定、2026-11-20 のマスターの答え「(i) 地図は (a) のまま。新聞と地図で定義は分ける」「地図は「自分が知っている人を表示する」というシンプルな振る舞いに留める」）。
  印の付け方は ADR-0064（OQ-054、2026-11-20 のマスターの答え「1:MVP」「2:1」「3:どちらもyes, 登録時に選択可能かつ、地図を表示する際は中心に置き印もつける」）。
- **FR-114（登録のときの選び方）**: 住民は登録の画面の地図の候補の印を押して住所を選ぶ（ADR-0064 の D7・ADR-0063 の D1 (a)、OQ-080 → 決定、2026-11-21 のマスターの答え「b」）。
  候補の一覧も残して一覧からも選べ、候補の印はキーボードでも選べる。地図と一覧の選択は 1 つの状態。押して選べるのは候補の印だけで、拡大・移動・検索はせず、API の経路は足さない（`[assumed]`）。
  M1 に入れる。空き家の印も選べるかは OQ-089 に残る。
- **FR-115・FR-006（地図の空き家・入居の表示）**: 街のすべての家について、空き家か人が住んでいるかを名前なしの 2 値で示し、登録の前の人（登録の画面）にもログインした住民（地図の画面）にもいつでも見せる。
  入居は `active`・`dormant`（休眠は空き家にしない）、空き家は使われたことのない住所と `vacant_*` で、要求を受けたときの状態を示す。経路は認証なしの `GET /api/v1/addresses/occupancy`（住所と `occupied` だけ、番・号の順、件数なし）で、C1 が入居の層として白黒の 2 つの形で重ねる
  （ADR-0064 の D10・D13〜D15、ADR-0063 の D3、OQ-079 → 決定、2026-11-21 のマスターの答え「1:これは全員にいつでも公開してOK。登録前、後いつでも確認が可能にする。」「2：休眠は空き家にしない。長くログインしていない判定に対する閾値などはMVP後に検討。いずれ空き家判定にする可能性はある。」）。
  M1 に入れる。休眠を空き家にする判定と閾値・転送中の旧住所の表示は OQ-088 に残る。
- **FR-104（商店のアカウントの主体）**: 管理者が運用者の CLI で作り、住民は開けない（ADR-0067、OQ-006、2026-11-19 のマスターの答え）。
- **FR-104・FR-107（商店・団体は誰か）**: 商店には実在の企業・個人のお店を迎えることを目指す。コミュニティ（団体）は住民が趣味などで作り、作ることに制約を置く。発信は配達の前に審査し、レポジトリ・テスト・シードに実在の名前を入れない
  （ADR-0038、OQ-045、2026-11-20 のマスターの答え「商店に関しては実在の企業や個人ショップ経営者を入れるのが理想。コミュニティは趣味などでユーザーが作る。無制限は難しいので、何かの制約を設けたい」）。実在の店の迎え方は OQ-056（のちに決定、次の項目）、制約の中身は OQ-057 に残る。
- **FR-104・FR-116・FR-117（実在の店の迎え方）**: 実在の店とは契約を結び、利用料を場所の広さ・新聞に載る頻度・記事の大きさに比例させる考えをメモとして残す（MVP では仕組みを作らない）。架空の店を置いてよく、空いている商店の区画に入居者募集の張り紙を出す（中身は頻度と大きさで暫定、金額は載せず LP などの問い合わせから資料で伝える）。
  発信はお店の担当者で、アカウントは運用者の CLI で作って渡す。出せるものは広さと料金のランクで変え、折込チラシを最高に置く。商店は実在の情報を出してよい
  （ADR-0043、OQ-056、2026-11-20 のマスターの答え）。残りは OQ-067（のちに決定、次の項目）・OQ-068・OQ-069（持ち越し）。
- **FR-116・FR-123（架空の店と入居者募集の張り紙の出し方）**: 架空の店と張り紙は段階 3（S3-2）から作り、MVP には作らない。架空の店には「入居者募集」の張り紙を出し、それで架空と分かるようにする。架空の店は発信せず（発信の経路も担当者のアカウントも作らず、手紙の宛先にもならない）、新聞に載らない。

  （ADR-0050、OQ-067、2026-11-20 のマスターの答え「MVP時点では架空の店も張り紙も作らない。段階3から開始する」「架空の店であることがわかるようにする（「入居者募集」の張り紙が出ている状態にする）」「架空の店は発信しない」「新聞に入居者募集の広告は出す」）。残りは OQ-084（持ち越し）。
- **FR-123（新聞の入居者募集の広告の時期）**: 広告は段階 3（S3-2）から出し、MVP の紙面（C6）に広告の枠を置かない（ADR-0050 の D5、OQ-083 → 決定、2026-11-21 のマスターの答え「a」）。MVP（M5）の範囲は変わらない。載せ方と中身は OQ-084 に残る。
- **FR-091（新規登録の方式）**: 開放式。招待なしで誰でも登録でき、招待トークン・紹介者は受け取らない（ADR-0030、OQ-007、2026-11-19 のマスターの答え）。メールの確認が済まない登録が住所を押さえる期限は OQ-046（持ち越し、M1 の前に決める）。
- **FR-101（連絡先の共有の禁止）の範囲**: 禁止する「連絡先」は街の外の連絡先だけで、街の住所は含まない。禁止は全ての書き込みに及び、ルール表の `real_info` で止める（ADR-0071、OQ-041、2026-11-19 のマスターの答え「街の外の連絡先のみ」と、OQ-087、2026-11-22 のマスターの答え「絶対NGと絵文字不可を全てに適用。対象に連絡先や自分から書くことも含める。」）。マッチングの中での守り方の細部は OQ-050 に残る。
- **D-001〜D-010（秘書が ADR で決める事項）**: ADR-0001・0002・0004・0007・0012・0018 で決定した（`open-questions.md` §6 の対応表）。段階の変更には影響しない。
