## §1 方針

### §1.1 入れない機能の基準

次の原則（`requirements.md` §1.3）に反する機能は入れない。入れなかった機能は §4 に列挙する。

| 原則 | 内容 |
|------|------|
| P-1 | 即時性を持ち込まない（リアルタイム通知・チャット・即時配信を設けない。配達は 1 日 2 回の配達回で、新聞は定時・手紙は午前・午後の時間帯の中のランダムな時刻（ADR-0035）。配達の通知は新聞と手紙のそれぞれの配達のあとに、配達回ごとに 1 回だけ、ADR-0025・ADR-0035） |
| P-2 | 数値の評価を持ち込まない（いいね・フォロワー数・スコアなどを表示しない） |
| P-3 | 外見の情報に頼らない（顔写真を身元情報として使わない。画像は新聞写真風に加工する） |

### §1.2 段階の分け方

| 段階 | 位置づけ |
|------|----------|
| MVP（段階 1） | 「朝、自分の家のポストを開ける」体験が成立する最小の範囲 |
| 段階 2 | MVP のデータモデルを拡張する機能 |
| 段階 3 | データのライフサイクルやアルゴリズムの確定を待つ機能 |
| このフェーズの範囲外 | 明示的に範囲外とされた機能（§1.4、FR-090） |

### §1.3 優先順位の判定ルール

機能の段階を決める際は次の順で判断する。

1. 「朝、自分の家のポストを開ける」体験が成立するか
2. 依存順: 住所 → 手紙 → 配達 → 新聞
3. 公開コンテンツが出る前にモデレーション・画像加工を配置する
4. 未確定の事項・マスターの回答待ちの事項を後ろに回す

### §1.4 広告・折込チラシについて

FR-083〜FR-090 の広告・折込チラシはこのフェーズの実装範囲外（`requirements.md` §1.4）。
要件は記録するが実装しない。F-20 として「このフェーズの範囲外」に分類する。

## §3 優先順位と理由

### MVP（段階 1）

F-01〜F-09 と F-19 の 10 機能が最小範囲。選定理由は次のとおり。

- **体験の中心から逆算**: 「朝、自分の家のポストを開ける」には住所（F-01）・アカウント（F-02）・郵便受け（F-03）・手紙（F-04）・配達バッチ（F-05）・新聞（F-06）が必要。
- **町内掲示板（F-07）を MVP に含める理由**: 掲示板の投稿が組版バッチ（F-06）のコンテンツ源となるため（FR-035）。掲示板なしでは新聞が空になる。新聞は全住民に届ける（FR-106、ADR-0035）が、住民や投稿が少ないと紙面が成り立たないおそれがある。掲示板のほかの紙面の中身は OQ-051（要回答）で、暫定は掲示板の投稿だけ（ADR-0007）。
- **住所録（F-09）を MVP に含める理由**: 住所録が手紙の宛先選択（FR-053）の手段であり、MVP から手紙を使えるためには住所録が必要。
- **モデレーション（F-08）を MVP に含める理由**: MVP は掲示板という公開コンテンツを含む（FR-079、FR-080）。公開コンテンツが出る前にモデレーション層を置く（§1.3、ルール 3）。LLM はネットワークなしでテストが通るようモックにする（NFR-063、NFR-065）。クローズドな手紙も配達の前にルール表だけで審査する（FR-078、ADR-0026）。
- **地図（F-19）を MVP に含める理由**: マスターの答え（OQ-005、2026-11-19「静的な画像として実装し、開発の初期段階で行う」）による。静的な画像で、API・DB を持たないので、住所（F-01）と同じ M1 に置く（ADR-0028）。住民が投稿する画像ではないので、P-3 の画像加工（F-11）を待たない。
- **画像は MVP に含めない理由**: P-3（外見の情報に頼らない）により、画像加工（F-11）が整うまで画像添付は受け付けない。段階 2 で画像加工と一緒に追加する。

### 段階 2

F-10〜F-15 の 6 機能。MVP のデータモデルを拡張する。

- **グループ宛て手紙（F-10）**: テキスト手紙（F-04）の宛先を複数に拡張するだけで、コアのデータモデル変更が小さい。
- **画像添付と加工（F-11）**: 画像加工（P-3）が揃って初めてユーザーへ開放できる。バックナンバー（F-12）・掲示板カテゴリ（F-13）・データエクスポート（F-15）はいずれも MVP の機能拡張。
- **異議申し立て（F-14）**: モデレーション（F-08）の補完機能。MVP の公開後に追加するのが自然。

### 段階 3

F-16〜F-18 の 3 機能。データのライフサイクルかアルゴリズムの確定を先に要する。

- **引っ越し・転送・空き家（F-16）**: 期間（FR-072、FR-075）は ADR-0002 で決まった。休眠・転送・空き家の再割り当ては同じ住所の状態遷移と毎日のジョブ（`async.md` J9〜J12）で、居住記録による振り分け（`db.md` §3）と一緒に確かめるため段階 3 に置く（ADR-0023）。MVP の住所の候補は使われたことのない住所だけ。住所録の自動更新（FR-057）はしないと決まった（ADR-0003）。
- **商店街（F-17）**: 商店・団体のアカウントは管理者が作る（OQ-006 → 決定、ADR-0029）。誰が商店・団体になるか・作ったあと誰が発信するか（OQ-045、要回答）が決まるまで作らない（止まる）。
- **マッチング（F-18）**: アルゴリズム未確定（FR-066）。恋愛のカテゴリは設けない（OQ-001 → 決定、ADR-0024）。連絡先の共有の禁止（FR-101）は、街の外の連絡先だけ・マッチングの中だけ（OQ-041 → 決定、ADR-0034）。守り方の細部は OQ-050（持ち越し、止まらない）。

### 段階を進める際の条件

各段階への移行にはマスターの確認を要する（NFR-088）。各段階の依存・受け入れ条件・作る順は `roadmap.md` に書く（ADR-0022）。

## §5 未確定

未確定の事項を以下に列挙する。各項目の扱いは `open-questions.md` にある。段階への影響は `roadmap.md` §7・§8 にまとめる。

- **FR-046・FR-047・FR-104（商店・団体）**: 誰が商店・団体になるか・作ったあと誰が発信するかが未確定（OQ-045、要回答）。暫定なし（F-17 は作らない）。
- **FR-103 の住所の場所（架空の街の地図）**: 地図の上で、自分の住所の場所や登録のときの住所の候補の場所を示すかが未確定（OQ-044、要回答）。暫定は示さない（全住民に同じ 1 枚の画像）。
- **FR-106 の新聞の中身（知り合いが少なくても成り立つ紙面）**: 紙面を住民ごとに変えるか・住民の興味を集めるか・ニュースの出どころ（街の中だけか、実在の外のニュースか）・加工に LLM を使うかが未確定（OQ-051、要回答）。暫定は ADR-0007 のまま（全住民に同じ紙面を、掲示板の投稿からテンプレートで組む）。
- **FR-101（連絡先の共有の禁止）のマッチングの中での守り方**: 範囲は決定（下の決定済みを参照、ADR-0034）。参加の登録に自由記述の欄を設けるか（設けるなら、そこに書かれた街の外の連絡先をどう扱うか）と、成立後に最初の手紙を出す方法（提案に相手の街の住所を載せるか）が未確定（OQ-050、持ち越し。S3-3 のアルゴリズムの ADR で決める）。
- **FR-078 の手紙で止める内容と、手紙の閲覧**: ルール表のどの項目を手紙に当てるか・止めた手紙をモデレーターが見てよいか・通報された手紙をモデレーターが読んでよいかが未確定（OQ-043、要回答）。暫定は、本番のルール表に手紙に当てる項目を置かない（テストは偽の規則）・止めた手紙は人が見ない（送った人には「届けられませんでした」とだけ見せる）・通報された手紙はモデレーターが 1 通だけ確かめる（YGO-007 からの暫定）。
- **FR-058（誰が自分を住所録に登録しているかの通知）**: 未確定（OQ-040、持ち越し）。暫定として MVP では知らせない（`api.md` §8）。
- **FR-081 の処置（違反した住民への処置）**: 処置の内容（種類・重さ・住民への通知・異議の手続き）はマスターが後で決める（OQ-037 → 決定、2026-11-19 のマスターの答え「処置の内容は未定（後ほど決定）」、ADR-0032）。内容は未確定（OQ-048、持ち越し）。決まるまで、住民への処置を実行する手段（停止・警告など）は作らない。投稿の取り下げ・ブロック・モデレーターの操作の記録は今までどおり。
- **F-02 のメール送信**: テスト環境はモックかローカルの SMTP を使い、本番のサービスはマスターの事前承認を得て選ぶ（OQ-039 → 決定、2026-11-19 のマスターの答え「テスト環境はモックまたはローカルのSMTPサーバーを使い、本番はマスターの事前承認を得て選定する」、ADR-0033）。確認メール・再設定メール・休眠通知に使う本番のサービスは未確定（OQ-049、持ち越し）。選定が承認されるまで、本番のアダプタは作らない。

次は決定済み（未確定から外した）:

- **FR-057（住所録の自動更新）**: 自動更新しない（ADR-0003、OQ-011）。
- **FR-100（複数デバイス同時アクセス）**: 複数の端末でセッションを持てる（ADR-0019、OQ-036）。
- **FR-064（恋愛マッチング）**: 恋愛のカテゴリを設けないため、恋愛のための年齢条件は要らない（ADR-0024、OQ-001、2026-11-19 のマスターの答え）。参加にも年齢条件を置かない（FR-094、ADR-0027）。
- **FR-028（配達完了の通知）**: 通知を送り、郵便の件数を含める（ADR-0025、OQ-002、2026-11-19 のマスターの答え）。F-05 として MVP に入れる。手段は Web Push（FR-102）。
- **FR-028 の数え方と中身・FR-105・FR-106（配達の時刻と通知）**: 新聞は全住民に定時（07:00 / 17:00）に届けて「新聞が配達されました！」を通知し（休刊の回も、郵便受けに休刊の印が届くので送る）、
  手紙は出した時刻に応じて午前（08:00〜12:00）か午後（18:00〜21:00）のランダムな時刻に届けて「手紙が配達されました！（N通）」を通知する。0 通の住民には手紙の通知を送らない
  （ADR-0035、OQ-042、2026-11-19 のマスターの答え）。新聞の中身は OQ-051 に残る。
- **FR-078・NFR-005（クローズドな手紙の審査）**: 個人宛・グループ宛の手紙も配達の前に審査する。本文は LLM に渡さず、ルール表だけで照合し、本文を復号してよい場面を限る（ADR-0026、OQ-003、2026-11-19 のマスターの答え）。F-08 として MVP（M4）に入れる。手紙で止める内容と、手紙の閲覧（止めた手紙・通報された手紙）は OQ-043 に残る。
- **FR-094（未成年の利用ポリシー）**: 未成年の利用を認め、年齢制限・特別な制限を置かない。年齢確認・保護者の同意の手続きはなく、生年月日・年齢は集めない（ADR-0027、OQ-004、2026-11-19 のマスターの答え）。
- **F-19（架空の街の地図）**: 1 枚の静的な画像として、MVP（M1）で作る（FR-103、ADR-0028、OQ-005、2026-11-19 のマスターの答え）。全住民に同じにするか・住所の場所を示すかは OQ-044 に残る（暫定は全住民に同じで、示さない）。
- **FR-104（商店・団体のアカウントの主体）**: 管理者が運用者の CLI で作り、住民は開けない（ADR-0029、OQ-006、2026-11-19 のマスターの答え）。残りは OQ-045。
- **FR-091（新規登録の方式）**: 開放式。招待なしで誰でも登録でき、招待トークン・紹介者は受け取らない（ADR-0030、OQ-007、2026-11-19 のマスターの答え）。メールの確認が済まない登録が住所を押さえる期限は OQ-046（持ち越し、M1 の前に決める）。
- **FR-101（連絡先の共有の禁止）の範囲**: 禁止する「連絡先」は街の外の連絡先だけで、街の住所は含まない。禁止はマッチングの中だけで、掲示板・手紙には及ばない（ADR-0034、OQ-041、2026-11-19 のマスターの答え「街の外の連絡先のみ。禁止はマッチングの中のみ。掲示板・手紙への禁止は及びません。」）。ルール表に FR-101 を理由にした項目を置かない（ほかの理由で個人情報を止める項目を置くかは、この決定の範囲の外）。守り方の細部は OQ-050 に残る。
- **D-001〜D-010（秘書が ADR で決める事項）**: ADR-0001・0002・0004・0007・0012・0018 で決定した（`open-questions.md` §6 の対応表）。段階の変更には影響しない。
