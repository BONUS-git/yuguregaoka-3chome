# 0004 秘書の段階の評価（2026-11-27・実装・M1）

- 日付: 2026-11-27
- 出どころ: 秘書の段階の評価（DLG-18）。秘書がこの段階を外から評価したもの
- この変更では指摘を直さない。行き先が「チケット」の指摘はチケットを `open` で出し、「マスターの判断」の指摘は `open-questions.md` に要回答として立て、「持ち越し」の指摘はここに書くだけにする（仕分けが扱う）
- 指摘の文は評価の記録で、中の「直し方」はあとの変更への案である

## 観点ごとの所見

- **方向性**: M1 は 18 の FR（住所・登録・認証・プロフィール）を持つ。それなのに、コードは経路のない Fastify の 1 関数だけで、FR は 1 つも実装されていない。最近の変更は準備書・道具の一覧・CI 待ちのチケットなど、周りの文書ばかりで、中心の体験に近づいていない。M1 が中心の体験（投函→配達→郵便受け）に届かない構造（E-008）も残っている。
- **妥当性**: 前回の E-014（J18）・E-015（使用中のメールの 201）・E-016（`mvp.md` の参照）は、`async.md`・`api.md`・`check.sh` で直った。一方で、`check.sh` は `package.json` がないと Vitest の段を黙って飛ばす。そのため `test/` と `src/` にコードがあっても `check: ok` になり、「確かめた」と言える根拠にならない。
- **チケットの質**: YGO-062 は 111 行ある。YGO-065 は、8 表のマイグレーション・使い捨ての PostgreSQL・ドライバの追加・ADR-0105 の置き換え・4 文書の直しを 1 枚に詰めていて、1 回の変更の大きさを超えている。YGO-064・YGO-067（「今決める 0 件」を記録するだけ）と YGO-070（マスターの作業を待つだけ）は作る中身のないチケットで、M1 のチケットの数を増やしているだけである。
- **成果物の質**: `test-plan.md` の TC は 66 件だが、テストは TC-033 の 1 件しかない。しかもそれも、`package.json` がないため一度も動いていない。達成の条件の「TC のテストがすべて通る」「CI が緑」は、どちらも手が付いていない。
- **進め方**: YGO-062 は、ジョブの環境で Bash と Node が使えないため 3 回止まった。それでも同じ止まり方を待ったまま、仕分け 9〜11・準備書・道具の一覧など、文書の変更が 10 回近く続いた。止まる原因（環境）を秘書の側で解かないまま、段階の点検を埋める変更を重ねている。

## 重大

### R-065 — 実行環境に Node がなく M1 の実装が始められない
- 区別: 重大
- 評価の ID: E-019
- 観点: 進め方
- 行き先: 持ち越し（仕分け）
- 場所: `.ai/tickets/YGO-062-m1-test-harness.md` の「残り」・`.ai/retros.md` 2026-11-26 の 3 節
- 根拠の箇所: `.ai/tickets/YGO-062-m1-test-harness.md`、`.ai/retros.md`、`.ai/gaps.md`
- 何が: YGO-062 は「Permission to use Bash has been denied」と node がないことで 3 回止まった。`package.json`・`package-lock.json` はまだない。YGO-065 以降の FR のチケットはどれも YGO-062 の done を待つ。そのため、M1 の 18 の FR に向けた実装の変更は 1 つも出ていない。それでも、そのあとの変更は文書のそろえ（YGO-063〜070・仕分け 9〜11）を続けている。
- 直し方の案: ジョブの環境に Node.js 26 と npm を入れ、Bash を使えるようにする。それが済むまでは、FR のチケット（実装の変更）を提案しない。済んだら、最初の変更で YGO-062 を仕上げる。
- 同じ論点の OQ: OQ-086（決定。CI と秘書のジョブの環境に要る道具はマスターが用意する、ADR-0068）。新しい要回答は立てない。

### R-066 — M1 の FR が 1 つも実装されず TC のテストは 1 件
- 区別: 重大
- 評価の ID: E-020
- 観点: 成果物の質
- 行き先: チケット（YGO-071）
- 場所: `src/app.ts`・`test/`・`.ai/tests/test-plan.md`
- 根拠の箇所: `src/app.ts`、`test/test_TC_033_no_oauth_webauthn_routes.test.ts`、`.ai/tests/test-plan.md`、`.ai/roadmap.md`

- 直し方の案: 環境の問題が解けたら、YGO-062 → DB のスキーマ → 住所の候補（FR-007・FR-010）→ 登録（FR-001・FR-091）の順に、チケットを小さく切る。それぞれの変更で、その TC のテストを足して通す。

## 中

### R-067 — package.json がないと check.sh がテストを飛ばして通る
- 区別: 中
- 評価の ID: E-021
- 観点: 妥当性
- 行き先: チケット（YGO-072）
- 場所: `scripts/check.sh` の 1 の段・6 の段（`if [ -e package.json ]`）
- 根拠の箇所: `scripts/check.sh`、`test/test_TC_033_no_oauth_webauthn_routes.test.ts`、`vitest.config.ts`
- 何が: `test/`・`src/`・`vitest.config.ts` が入っているのに、`package.json` がなければ Node の段と Vitest の段をどちらも飛ばし、`check: ok` を出す。YGO-062 自身も「check: ok は Vitest の土台が動くことの裏付けではない」と書いている。CI が緑でも、テストが動いたことにはならない。
- 直し方の案: `test/` に `*.test.ts` があるのに `package.json` がないときは、`check.sh` を失敗させる。

### R-069 — 中身のない記録だけのチケットで M1 を埋めている
- 区別: 中
- 評価の ID: E-023
- 観点: 進め方

### R-070 — M0 の土台を M1 のチケットに混ぜ範囲が曖昧
- 区別: 中
- 評価の ID: E-024
- 観点: チケットの質
- 行き先: チケット（YGO-074）
- 場所: `.ai/tickets/YGO-062`・`YGO-065` の範囲・`.ai/roadmap.md` §4 の M0
