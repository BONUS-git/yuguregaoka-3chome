## 観点ごとの所見

- **方向性**: M1 の範囲（住所・アカウントの 18 の FR）は MVP から外れていない。ただし 18 の FR はどれもまだ実装されていない。最近の変更は、止まった YGO-078 の記録を書き直すことと仕分けの記録だけで、中心の体験には一歩も近づいていない。
- **妥当性**: gaps の冒頭の例外（G-081）と決まり rl-7d57a518 は「外の作業を待つ行にはチケットを切らない」としている。一方で固定コードは「M1 の gaps の行にはすべてチケットがある」ことを求めていて、G-080〜G-082 がこのぶつかりで ✗ のまま残る。`check.sh` は `package.json` がなければ今も Vitest を飛ばし、`check: ok` を出す。
- **チケットの質**: YGO-065 は分けられた。M0 の部品も M1 のチケット（YGO-080〜086）として依存の順に切られた。どちらも直っている。ただし YGO-078 は、止まった 6 回の変更 ID と「確かめた事実」の時点の記録が積み重なった経緯の文書になっている。本文がレポジトリにない見直しの指摘 R3-F1 を、推測で扱っている。
- **成果物の質**: `src/app.ts` は経路のない Fastify のままで、テストは TC-033 の 1 件だけ。`package.json`・`package-lock.json`・`.github/` はない。テストが一度も動いていないので、M1 の達成の条件はほぼ全部が残っている。
- **進め方**: YGO-078 は、Bash が拒まれて同じ段で止まると分かっているのに 6 回出し直された。そのうち 3 回は直近の git log にあり、どれも文書の書き直しとしてマージされた。retros にこの繰り返しの記録はない。計画のジョブでは npm が動き、実装のジョブでは拒まれるという権限の違いが、根本で解かれていない。

### R-072 — チケットを切らない決まりが固定コードの点検とぶつかる
- 区別: 中
- 評価の ID: E-026
- 観点: 妥当性
- 行き先: 持ち越し（仕分け）
- 場所: `.ai/gaps.md` G-080〜G-082・G-081 の冒頭の例外・決まり rl-7d57a518
- 根拠の箇所: `.ai/gaps.md`、`.ai/triage.md`
- 何が: rl-7d57a518 と G-081 は「外の作業を待つだけのことはチケットにしない」とし、G-080・G-082 にはわざとチケットを切っていない。一方で固定コードの check:consolidation は、M1 に向かう gaps の行にすべてチケットを求める。そのため、何をしても「M1 に向かう gaps の行にすべてチケットがある」は ✗ のまま。仕分け 13〜15 も、この ✗ を毎回同じ文で繰り返している。

### R-076 — check.shにチケットごとの確かめが積み重なる

- 観点: 成果物の質

- 場所: `scripts/check.sh` の t062・t078・t072 の段
- 根拠の箇所: `scripts/check.sh`
