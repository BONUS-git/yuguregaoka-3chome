## 1. 目的と範囲

### 1.1 目的

夕暮ヶ丘三丁目は、架空の街の住所をユーザー ID にした非同期型 SNS。
現代 SNS の即時性と数値評価を排除し、アナログな不便さと手触り感を楽しむ場をつくる。

ユーザーの中心的な体験は「朝、自分の家のポストを開けること」。
住民は架空の街に住み、手紙のやり取り・新聞の閲覧・掲示板・住所録を通じて非同期的に交流する。

### 1.2 利用体験

| 体験 | 軸 | 具体例 |
|------|----|--------|
| A. 大人の秘密基地 | 趣味・サブカルチャー・住民同士の交流 | 住所録でつながる、趣味のコミュニティ、手紙でやり取り |
| B. 家族・友人の生活圏 | 個人・グループ宛の手紙、クローズドな交流 | 個人間の手紙、グループ宛の手紙、家族間のやり取り |
| C. もう一つの生活圏 | 町内掲示板・商店街・マッチング | 掲示板への投稿、イベント募集、趣味・友人・恋愛のマッチング |

### 1.3 全体に効く原則

| ID | 原則 |
|----|------|
| P-1 | **即時性を持ち込まない**: リアルタイム通知・チャット・既読状態は設けない。配達は定時にのみ行う |
| P-2 | **数値の評価を持ち込まない**: いいね・フォロワー数・スコアなどの定量的評価は表示しない |
| P-3 | **外見の情報に頼らない**: 顔写真を身元情報として使わない。画像は新聞写真風に加工する |

### 1.4 範囲の外

- デプロイ・クラウドアカウントの契約・費用の発生（スタックの計画と IaC の設計までで止める）
- 広告・折込チラシ（将来の機能として要件を記録するが、このフェーズでは実装しない）

## 2. 用語

| 用語 | 定義 |
|------|------|
| **住所** | 架空の街の住所（例: 夕暮ヶ丘三丁目 2-5）。各住民のユーザー ID |
| **住民** | 住所を持つアカウント |
| **郵便受け** | 住民が手紙・新聞を受け取る場所。各住民のホーム画面 |
| **手紙** | 住民から住民（またはグループ）への非同期メッセージ |
| **朝便** | 朝の定時配達。朝刊と手紙を郵便受けに届ける |
| **夕便** | 夕方の定時配達。夕刊と手紙を郵便受けに届ける |
| **朝刊** | 朝便で配達される新聞 |
| **夕刊** | 夕便で配達される新聞 |
| **夜間の組版** | 夜間に翌朝の朝刊コンテンツを自動生成するバッチ処理 |
| **新聞写真風の加工** | 投稿された画像をモノクロ・ハーフトーンなどで加工し、外見の情報を間引く処理 |
| **町内掲示板** | 街全体または地区向けの公開掲示板。住民が投稿・閲覧できる |
| **商店街** | 架空の街の商業地区。地域コミュニティの拠点 |
| **住所録** | 住民が手動で管理する連絡先リスト。フォロー概念の代わり |
| **空き家** | アカウント削除または長期間ログインのない住所。新規住民の割り当て候補 |
| **引っ越し** | 住所（ユーザー ID）の変更 |
| **住所転送** | 旧住所に届いた手紙を新住所へ転送する設定 |
| **AI モデレーション** | LLM を使った非同期のコンテンツ審査 |
| **折込チラシ** | 将来の機能。企業や商店が新聞に同封する広告 |

## 3. 機能要件

### 3.1 住民と住所 (FR-001〜FR-010)

| ID | 要求 | 区分 |
|----|------|------|
| FR-001 | システムは各住民に対して架空の街の住所を一意のユーザー ID として割り当てる | [explicit]（構想 §2-A「架空の街の住所をユーザー ID とする」） |
| FR-002 | 住所の形式は架空の地名＋番地の組み合わせとする（例: 夕暮ヶ丘三丁目 2-5） | [inferred] |
| FR-003 | 住所は同時に 2 人以上の住民に割り当てられない（一意制約） | [inferred] |
| FR-004 | 住民は引っ越し（住所変更）を申請できる | [explicit]（構想 §2-共通「引っ越し」） |
| FR-005 | 引っ越し後、旧住所への手紙は住所転送設定に従い転送される | [explicit]（構想 §2-共通「住所転送」） |
| FR-006 | 一定期間ログインのない住所は空き家に分類される | [explicit]（構想 §2-共通「空き家」） |
| FR-007 | 空き家は転送期間終了後、新規住民の割り当て候補となる | [inferred] |
| FR-008 | 住民のプロフィールは住所・自己紹介文・住所録のみを含む。顔写真は必須としない | [inferred]（P-3 より） |
| FR-009 | 住民の表示名は住所のみとし、ニックネームは任意で設定できる | [inferred] |
| FR-010 | 住所の割り当て方法（ランダム・連番・選択など）は未確定（open-questions へ） | [assumed] |

### 3.2 郵便受けと手紙 (FR-011〜FR-020)

| ID | 要求 | 区分 |
|----|------|------|
| FR-011 | 各住民は郵便受けを持つ。郵便受けは定時配達で届いた手紙と新聞の一覧を表示する | [explicit]（構想 §2「ユーザーの中心的な体験は朝、自分の家のポストを開けること」） |
| FR-012 | 住民は他の住民宛に手紙を書ける | [explicit]（構想 §2-A「手紙による非同期コミュニケーション」） |
| FR-013 | 住民は複数住民を宛先とするグループ宛手紙を書ける | [explicit]（構想 §2-B「グループ宛ての手紙」） |
| FR-014 | 手紙は次の定時配達まで保留され、配達時刻に郵便受けへ届く（即時配信しない） | [explicit]（構想 §2「非同期型」、P-1） |
| FR-015 | 手紙には本文と任意の画像を添付できる | [inferred] |
| FR-016 | 手紙に添付された画像は新聞写真風に加工される | [explicit]（構想 §2-共通「画像の新聞写真風加工」） |
| FR-017 | 手紙の既読状態は送信者に通知されない（P-1） | [inferred]（P-1 より） |
| FR-018 | 手紙の送受信履歴は住民自身のみが閲覧できる | [assumed] |
| FR-019 | クローズドな手紙（個人・グループ間）は他の住民から閲覧できない | [explicit]（構想 §2-B「クローズドなコミュニケーション」） |
| FR-020 | 手紙の文字数の上限は未確定（open-questions へ） | [assumed] |

| ID | 要求 | 区分 |
|----|------|------|

| FR-022 | 朝便は朝刊と手紙を郵便受けへ届ける | [explicit]（構想 §2-共通「朝刊」「朝・夕の定時配達」） |
| FR-023 | 夕便は夕刊と手紙を郵便受けへ届ける | [explicit]（構想 §2-共通「夕刊」「朝・夕の定時配達」） |
| FR-024 | 配達の時刻は秘書が ADR に記録して決定する（open-questions へ） | [assumed] |
| FR-025 | 配達は非同期バッチとして実装し、冪等性を保証する | [explicit]（構想 §4「非同期処理の冪等性を保証する」） |
| FR-026 | 配達バッチの締め切りより後に書かれた手紙は次の配達回で届く | [inferred] |
| FR-027 | 配達の締め切り時刻は秘書が ADR に記録して決定する（open-questions へ） | [assumed] |
| FR-028 | 配達完了後に住民へプッシュ通知を送るかどうかは要回答 | [assumed] |
| FR-029 | 配達バッチの失敗時は再実行し、重複配達が起きないよう冪等に設計する | [inferred]（§4 より） |
| FR-030 | 定時以外の配達は行わない（P-1） | [inferred]（P-1 より） |

## 4. 非機能要件
