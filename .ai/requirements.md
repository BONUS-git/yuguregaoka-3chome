## 1. 目的と範囲

### 1.1 目的

夕暮ヶ丘三丁目は、架空の街の住所をユーザー ID にした非同期型 SNS。
現代 SNS の即時性と数値評価を排除し、アナログな不便さと手触り感を楽しむ場をつくる。

ユーザーの中心的な体験は「朝、自分の家のポストを開けること」。
住民は架空の街に住み、手紙のやり取り・新聞の閲覧・掲示板・住所録を通じて非同期的に交流する。

### 1.2 利用体験

| 体験 | 軸 | 具体例 |
|------|----|--------|
| A. 大人の秘密基地 | 趣味・サブカルチャー・住民同士の交流 | 住所録でつながる、趣味のコミュニティ、手紙でやり取り |
| B. 家族・友人の生活圏 | 個人・グループ宛の手紙、クローズドな交流 | 個人間の手紙、グループ宛の手紙、家族間のやり取り |
| C. もう一つの生活圏 | 町内掲示板・商店街・マッチング | 掲示板への投稿、イベント募集、趣味・友人のマッチング（興味のある人どうしが連絡を取る手段。恋愛のためのものではない、ADR-0024） |

### 1.3 全体に効く原則

| ID | 原則 |
|----|------|
| P-1 | **即時性を持ち込まない**: リアルタイム通知・チャット・既読状態は設けない。配達は 1 日 2 回の配達回（朝便・夕便）でのみ行う。新聞は定時（07:00 / 17:00）に届け、手紙は締め切りでまとめて午前・午後の時間帯のランダムな時刻に届ける（FR-105、ADR-0035）。配達の通知は新聞と手紙のそれぞれの配達のあとに、配達回ごとに 1 回だけ送る（FR-028、ADR-0076・ADR-0035） |
| P-2 | **数値の評価を持ち込まない**: いいね・フォロワー数・スコアなどの定量的評価は表示しない |
| P-3 | **外見の情報に頼らない**: 顔写真を身元情報として使わない。画像は新聞写真風に加工する |

### 1.4 範囲の外

- デプロイ・クラウドアカウントの契約・費用の発生（スタックの計画と IaC の設計までで止める）
- 広告・折込チラシ（将来の機能として要件を記録するが、このフェーズでは実装しない）。運営の入居者募集の広告（FR-123、ADR-0050 の D5）は含めない

## 2. 用語

| 用語 | 定義 |
|------|------|
| **住所** | 架空の街の住所（例: 夕暮ヶ丘三丁目 2-5）。各住民のユーザー ID |
| **住民** | 住所を持つアカウント |
| **郵便受け** | 住民が手紙・新聞を受け取る場所。各住民のホーム画面 |
| **手紙** | 住民から住民（またはグループ）への非同期メッセージ |
| **朝便** | 朝の定時配達。朝刊と手紙を郵便受けに届ける |
| **夕便** | 夕方の定時配達。夕刊と手紙を郵便受けに届ける |
| **朝刊** | 朝便で配達される新聞 |
| **夕刊** | 夕便で配達される新聞 |
| **夜間の組版** | 夜間に翌朝の朝刊コンテンツを自動生成するバッチ処理 |
| **新聞写真風の加工** | 投稿された画像をモノクロ・ハーフトーンなどで加工し、外見の情報を間引く処理 |
| **町内掲示板** | 街全体または地区向けの公開掲示板。住民が投稿・閲覧できる |
| **商店街** | 架空の街の商業地区。地域コミュニティの拠点 |
| **住所録** | 住民が手動で管理する連絡先リスト。フォロー概念の代わり |
| **知り合い** | 文脈で定義が分かれる（ADR-0051 の D2）。地図の知り合いの家の印（FR-114）では、自分の住所録に入れた住民（ADR-0084 の D1 (c)）。手紙を出せる知り合い（FR-121・FR-122）では、互いに住所録に入れた住民（ADR-0065 の D2）か、掲示板のオープンの掲載中の投稿から自分が住所録に足した、その投稿の投稿者（片向き。自分から相手へだけ出せ、その投稿がオープンの掲載中の間だけ、ADR-0065 の D7・D10）。新聞の知り合いの組（FR-108）と誕生日の欄（FR-127）では、互いに住所を入れて住所録に入れた住民（どちらもブロックしていない。掲示板の投稿と手紙から足したエントリの組は含めない。ADR-0074 の D2・ADR-0065 の D14） |
| **空き家** | 住民のいない住所。次の 3 つがある: 使われたことのない住所、アカウント削除ですぐになる `vacant_deleted`、引っ越しから 6 か月の転送期間が終わった旧住所の `vacant_forwarded`。ログインしないだけでは空き家にしない（休眠は入居。休眠を `vacant_expired` にするかは OQ-088）。MVP の候補は使われたことのない住所だけで、空き家を割り当て候補に戻すのは段階 3 から（ADR-0060 の D1〜D5、ADR-0062 の D1・D3・D4） |
| **引っ越し** | 住所（ユーザー ID）の変更 |
| **住所転送** | 旧住所に届いた手紙を新住所へ転送する設定 |
| **AI モデレーション** | LLM を使った非同期のコンテンツ審査 |
| **折込チラシ** | 将来の機能。企業や商店が新聞に同封する広告 |

| FR-115 | 街のすべての家について、空き家か人が住んでいるかを、住民の名前を載せない 2 値で示す。登録の前の人（登録の画面）にもログインした住民（地図の画面）にも、いつでも見せる（M1）。入居は `active`・`dormant`（休眠は空き家にしない）、空き家は使われたことのない住所と `vacant_deleted`・`vacant_expired`・`vacant_forwarded` とし、応答では状態の種類を分けない。示すのは要求を受けたときの状態。経路は認証なしの `GET /api/v1/addresses/occupancy` で、住所と `occupied` だけを番・号の順に返し、件数・名前・状態の値を返さない。表示は C1 が土台の上に重ねる入居の層で、白黒の 2 つの形で示し、土台の画像は変えない | [inferred]（マスターの答え OQ-054（2026-11-20）「また、空き家か人がいるかも表示する。ここにはユーザー名は載せず、boolean的に表示するものと考えている」と、OQ-079（2026-11-21）「1:これは全員にいつでも公開してOK。登録前、後いつでも確認が可能にする。」「2：休眠は空き家にしない。」より。ADR-0084 の D10・D13・D17。「街のすべての家」は問いの例からの読み方。経路と応答の形・要求のときの状態・2 つの形は [assumed]（ADR-0084 の D8・D14・D15）） |

### 3.2 郵便受けと手紙 (FR-011〜FR-020、FR-118、FR-121)

| ID | 要求 | 区分 |
|----|------|------|
| FR-011 | 各住民は郵便受けを持つ。郵便受けは定時配達で届いた手紙と新聞の一覧を表示する | [explicit]（構想 §2「ユーザーの中心的な体験は朝、自分の家のポストを開けること」） |
| FR-012 | 住民は他の住民宛に手紙を書ける。宛先は知り合いだけ（FR-121） | [explicit]（構想 §2-A「手紙による非同期コミュニケーション」）。知り合いだけは [inferred]（マスターの答え OQ-066（2026-11-20）「自由には手紙は出させない」より。ADR-0065 の D1） |
