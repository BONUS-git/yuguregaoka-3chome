# YGO-052 R-061 使用中のメールで登録したときの応答が未決
状態: open
M: M1

## 目的
`reviews/0003-phase-evaluation-2026-11-26.md` の R-061（区別: 中、評価の ID: E-015）を直す。
確認の済んだメールアドレスでもう一度登録したとき（`credentials.email_hmac` の UNIQUE に当たる場合）の応答と、そのとき押さえた住所の扱いが、`api.md` にも ADR にも書かれていない。暫定は `gaps.md` G-051 の行にしかない。
このチケットで、G-051 の暫定を新しい ADR と `api.md` §7 F-02 に書き、G-051 を閉じる。

## 範囲
- 新しい ADR（`.ai/adr/` の続き番号）: 使用中のメールアドレスで登録したときは、住所の割り当てを戻し（その要求で押さえた住所を残さない）、ふつうの登録と同じ 201 を返し、そのアドレスにだけ「登録の要求があった」知らせを送る。アカウントの有無を応答で明かさない（ADR-0080 の D4）。期限切れの確認が済まない登録は ADR-0087 の D5 で先に消すので当たらないことも書く。
- ADR-0080: 新しい ADR が ADR-0080 の決定を一部でも変えるなら、残る決定も新しい ADR に書いて丸ごと置き換え、ADR-0080 の状態を `置き換え（→ NNNN）` の 1 行にする。変えないなら ADR-0080 は触らず、新しい ADR から D4 を指すだけにする。
- `.ai/api.md` §7 F-02: `POST /api/v1/registrations` の行に、この場合の応答（201・住所を戻す・知らせ）と新しい ADR を書く。
- 知らせは YGO-051 で足したメールのジョブで送る。`async.md` のそのジョブに、この知らせの種類を足す。
- `.ai/diagrams/m1-registration-sequence.md`: 登録の分岐に、この場合の流れを足す（応答は同じ 201）。
- `.ai/gaps.md`: G-051 の行の理由と出どころの列（閉じたことと `YGO-052`）。
- `.ai/INDEX.md`: 新しい ADR を載せる。

## 依存
- YGO-051（`done`）のあとに行う。知らせを送るジョブが YGO-051 で決まるため。
