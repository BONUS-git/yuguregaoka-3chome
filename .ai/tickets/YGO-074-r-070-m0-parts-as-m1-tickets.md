## 範囲を広げた理由
- もとの範囲は 5 枚だった。M1 の登録とログインの TC（TC-018〜TC-020・TC-023・TC-001・TC-002）は、メールアドレスの暗号化と HMAC、トークンのハッシュ、セッションの署名に鍵を使い、鍵は `roadmap.md` §4 の M0 の行の「アダプタ（KeyProvider の偽の鍵…）」に入る。
- YGO-062 の「アダプタ」を切ったチケットの番号に分けると、KeyProvider だけ行き先がなくなり、R-070 と同じ「別のチケット」が残る。秘書の決まり（今の M の TC が依存する前の M の部品は、今の M のチケットとして切る）に合わせ、6 枚目の YGO-085 として切った `[assumed]`。
- 受け入れ確認 2 の 5 枚は、そのまま満たす。YGO-085 は受け入れ確認 7 で確かめる。

## 直さないところと理由
- 時計・キュー・環境変数の読み込み・アダプタ・worker のジョブの実行・KeyProvider の実装そのもの: 切ったチケットで 1 枚ずつ。
- M1 の TC が使わない M0 の残り（`scripts/dev-db.sh`・`APP_ENV` の起動の検査・web の起動 `src/server.ts`・C3 の空の形・ローカルの SMTP などほかのアダプタ・テストの準備で外への接続を失敗させること）: どの M1 の TC も確かめないため M1 のチケットにしない。`tests/test-plan.md` にこれらを確かめる TC がまだないので、M2 で TC（A-07 の (1)〜(4) とローカルの SMTP）とチケットを足す（`.ai/gaps.md` G-082）`[assumed]`。M2 にするのは、M1 の TC の動きを変えず、設定の読み込み（YGO-082）とメールのアダプタ（YGO-083）ができたあとの最初の M で、MVP の A-07 を確かめる前に済むため。
- `async.md` の時刻の条件（`now()`）: YGO-080 で、M1 の条件（J14 の確認が済まない登録・`auth_tokens`・`rate_limit_buckets` と J18 の手順 2）を時計の値 `$now` に書き直す。この変更では async.md を直さない（時計の実装と同じ変更でそろえるため）。
- 部品だけのテスト: 切ったチケットに入れない `[assumed]`。`tests/test-plan.md` の決まりでテストの名前には表の TC の番号が要り、名前に TC-NNN のないテストは `check.sh` が失敗にする。部品の動きは、それを使う TC のテスト（YGO-071 で切る FR のチケット）が確かめる。理由は各チケットの「直さないところと理由」に書いた。
- 使い捨ての PostgreSQL: YGO-076（YGO-073 で切ったチケット）で扱う。
- `.ai/status.md`: 秘書が書く。新しい OQ・要回答・ADR は 0 件（細部はどれも技術の `[assumed]`）。
