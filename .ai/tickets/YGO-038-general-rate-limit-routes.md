# YGO-038 R-018 G-066 一般の流量の制限の経路と値を §3.5 にそろえる
状態: done
M: M1

## 目的
条件 8 のために、レビューの指摘 R-018（中。`api.md` が指す「一般の流量の制限」が `security.md` §3.5 になく、通報・ブロック・プロフィール・住所録の検索・新聞の検索に制限がない）を片づける。

## 仕分け
- `triage.md` の最新の回（仕分け 4）に、R-018 を扱う K-NNN はない。R-018 を扱っているのは `gaps.md` の G-066（暫定・M1、「チケットで済みと確かめて閉じるだけ」）で、その指定に従い、題に G-066 を付けた。
- M の判定: `roadmap.md` の `- M1:` の行に FR-008（プロフィール）・FR-010・FR-092 があり、A-11・A-12 が流量の制限を確かめるので、M1 にかかわる。

## 確かめた済みの箇所
- `security.md` §3.5 の規則の表に、`POST /api/v1/reports`（住民、10 回／1 時間）・`POST /api/v1/blocks`（住民、20 回／1 時間）・`GET /api/v1/profiles/{address}`（住民、60 回／1 時間）・`GET /api/v1/address-book` の `?q=`（住民、60 回／1 時間）・表にない経路の既定（300 回／5 分）の行がある。表のあとの文に、段階 2 の過去の新聞の検索の 60 回／1 時間がある（YGO-027、ADR-0088 の D2）。
- `api.md` §5 の 429 `rate_limited`・§7 F-01（プロフィール）・F-08（通報・ブロック）・F-09（住所録の検索）・§9 の「一般的な流量の制限と CSRF 対策」は、すでに §3.5 の表と同じ。

## 範囲
- `.ai/api.md` §7 F-06 の過去の新聞の検索: 「ほかの住民の API と同じ」（既定の 300 回／5 分に読める）を、住民ごとに 1 時間 60 回・429 `rate_limited`・検索も照合もしないこと（security.md §3.5、ADR-0088 の D2）に書き直す。
- `.ai/gaps.md` の G-066: 残りがないことに書き直し、出どころを `R-018（YGO-027・YGO-038）` にする。
- `.ai/INDEX.md`: このチケットと、流量の制限の値の行に `api.md` §5 の 429・§7 F-06 を足す。

## 直さないところと理由
- ADR: ADR-0030・0059・0064・0084 の「数値は実装の段階で決める」は決めることを後に送っただけで、ADR-0088 がそこを埋めた（YGO-027 と同じ判断）。決定を変えないので ADR は足さず、状態の行も変えない。新しい要回答は 0 件。
- 手紙の 422 と `content_rejected` を合わせた制限の値: OQ-065（M4 の前、G-038）が扱う。
- `security.md`・`open-questions.md`・`triage.md`・`reviews/`・`mvp.md`・`roadmap.md`・`status.md`: 変えない。
- テスト: 文書だけの変更で足さない（くり返す確かめを `check.sh` に入れるのは G-061 の予定）。
