# YGO-038 R-018 G-066 一般の流量の制限の経路と値を §3.5 にそろえる
状態: done
M: M1

## 目的
条件 8 のために、レビューの指摘 R-018（中。`api.md` が指す「一般の流量の制限」が `security.md` §3.5 に定義されておらず、通報・ブロック・プロフィール・住所録の検索・新聞の検索に制限がない）を片づける。中心の点はあとの決定ですでに片づいている（値と対象の経路は ADR-0088、`security.md` §3.5 の規則の表）。残っている食い違いは、`api.md` §7 F-06 の過去の新聞の検索が「ほかの住民の API と同じ」と書き、§3.5 の既定（300 回／5 分）と読めることだけなので、そこを §3.5 の 60 回／1 時間にそろえる。

## 仕分け
- `triage.md` の最新の回（仕分け 4）に、R-018 を扱う K-NNN はない。R-018 を扱っているのは `gaps.md` の G-066（暫定・M1）で、題に G-066 を付けた。
- M の判定: `roadmap.md` の `- M1:` の行に FR-008（プロフィール）・FR-010・FR-092 があり、受け入れ条件の A-11・A-12 が流量の制限を確かめるので、M1 にかかわる。

## 確かめた済みの箇所
- `security.md` §3.5 の規則の表に、`POST /api/v1/reports`（住民・10 回／1 時間）・`POST /api/v1/blocks`（住民・20 回／1 時間）・`GET /api/v1/profiles/{address}`（住民・60 回／1 時間）・`GET /api/v1/address-book` の `?q=`（住民・60 回／1 時間）と、表にない経路の既定（300 回／5 分）の行がある。表のあとの文に、段階 2 の過去の新聞の検索に 60 回／1 時間を当てることがある。
- `api.md` §5（既定の制限で、どの経路も 429 `rate_limited` を返しうる）・§7 F-01（プロフィール）・F-08（通報・ブロック）・F-09（住所録の検索）・§9（値と対象の経路は決定）は、この表と同じ。

## 範囲
- `.ai/api.md` §7 F-06 の過去の新聞の検索: 流量の制限の文を、住民ごとに 1 時間 60 回（住所録の検索と同じ）、超えると 429 `rate_limited` で検索も照合もしない、に書き直す（security.md §3.5、ADR-0088 の D2）。
- `.ai/gaps.md` の G-066: 残りがないことに書き直し、出どころを `R-018（YGO-027・YGO-038）` にする。
- `.ai/INDEX.md`: 「流量の制限の値」の行に `api.md` §5 の 429・§7 F-06 を足し、このチケットを足す。

## 直さないところと理由
- `security.md` §3.5 の規則の表と値: レビューの直し方の案（住民ごとの既定の制限と経路ごとの値を足す）は ADR-0088 で済んでいるので変えない。
- ADR: 決定を変えないので足さず、状態も変えない。新しい要回答は 0 件（手紙の 422 を合わせた値は OQ-065 で持ち越し、G-038）。
- `open-questions.md`・`triage.md`・`reviews/`・`mvp.md`・`roadmap.md`・`status.md`: 変えない。
- テスト: 文書だけの変更で足さない。

- `.ai/api.md` §7 F-06 の「過去の新聞の検索」の項に、流量の制限は住民ごとに 1 時間 60 回（住所録の検索と同じ）で、超えると 429（`rate_limited`）で検索も照合もしないこと（security.md §3.5、ADR-0088 の D2）が書かれ、「ほかの住民の API と同じ」の文がない。
- `.ai/security.md` §3.5 の規則の表に、`POST /reports`・`POST /blocks`・`GET /profiles/{address}`・`GET /address-book?q=` の行と既定の 300 回／5 分の行があり、表のあとに過去の新聞の検索の 60 回／1 時間がある。§3.5 に差分がない。
- `.ai/api.md` §9 の「一般的な流量の制限と CSRF 対策」に、値と対象の経路は決定（ADR-0088、security.md §3.5 の表）と書かれている。
