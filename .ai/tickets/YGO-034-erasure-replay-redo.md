# YGO-034 K-008 R-014 消去の再生は控えから J7 をやり直す
状態: done
M: M1

## 目的
`triage.md` 仕分け 3（最新の回）の「今決める」K-008（出どころ R-014）を決める。
`erasure_log` に記録が残らない処理（本文を消す UPDATE・差出人などを NULL にする UPDATE・J14 の削除）があり、バックアップから戻すと消したはずの本文・却下した手紙・興味が戻る。
もう 1 つ、`erasure_log` は復元する DB と同じ DB にあるので、戻した時点より後の消去の記録も一緒に巻き戻り、再生に使う記録がなくなる。
R-014 のマスターの判断は「不要」で、すべて `[assumed]` で決める。新しい要回答は 0 件。

決めたこと（ADR-0096）:
- D1: `erasure.replay` は記録を順に当てず、住民ごとに J7 をやり直し、J14 を 1 回動かす。記録する表は ADR-0091 のまま（`sessions`・`auth_tokens`・`credentials`・`residents`）で足り、R-014 の案（すべて行ごとに記録する）は採らない。再生が積む J14 が、ADR-0091 の D6 の「次の J14」になる。
- D2: `erasure_log` に `table_name` の CHECK と `UNIQUE(table_name, record_id)`。記録は `ON CONFLICT DO NOTHING`。
- D3: J7 が手順 0 の前に、オブジェクトストレージの `erasure/<resident_id>.json` に住民の ID と受付の時刻だけを置く。DB を戻しても巻き戻らない。受付から J7 が控えを置くまでの数秒の穴は受け入れる。
- D4: `erasure.replay` は web を止めたまま、控えから J7 を積み直す → `erasure_log` の 3 つの表の残りの行を消す → J14 を 1 回積む → 積んだジョブがすべて終わってから web を戻す。
- D5: 控えは 60 日（`erasure_log` と同じ）で J14 が消す。
- D6: 戻した時点より後の住民やモデレーターの操作は戻らない。`gaps.md` G-055（M6）。

ADR-0096 は再生の仕組み（`erasure.replay` の手順・消去の控え・`erasure_log` の制約）だけを決め、ADR-0091 の決定（何を消すか・何を記録するか・保持期間・D6 の「次の J14 がまた消す」）はどれも変えない。そのため ADR-0091 は置き換えず、状態は `採用` のまま。
見直しの 1 回目（R1-F1）で、ADR-0096 が D6 を変えている（「次の毎日の J14 を待つ」を採らない）と読める書き方を指摘された。置き換えの案（ADR-0091 の D1〜D14 を新しい ADR に移し、ほかの文書の ADR-0091 への約 150 の参照を移し替える）ではなく、ADR-0096 を再生の手順に絞り、再生が積む J14 を D6 の「次の J14」として書く形にした。D6 は「戻した行は次の J14 が消す」で、その J14 をいつ動かすかを決めていないので、再生が web を戻す前に動かすことは D6 と食い違わない。
