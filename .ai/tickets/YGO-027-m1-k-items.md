## 決める順と理由

1. マスターの指示と、秘書の評価から足した決まりが、仕分けの順に従うことを求めている。
2. K-015 は FR の行に決定の ADR の番号を書く。先に ADR-0087〜0090 を作っておけば、FR の行を 1 回で書き終えられる。

## 決めたこと
- **K-004**（OQ-046 → 決定、ADR-0087）: メールの確認が済まない登録が住所を押さえるのは `credentials.created_at` から 24 時間 `[assumed]`。確認のリンクも同じ時刻に切れ、送り直しても延びない。期限を過ぎた登録は J14 が `auth_tokens` → `resident_interests` → `tenancies` → `addresses` → `credentials` → `residents` の順に行ごと消し（`erasure_log` に書かない）、登録の要求も同じ住所か同じメールアドレスの期限切れの登録を先に消す。住所は使われたことのない住所として候補に戻る（ADR-0062 の D3 と食い違わない）。J14 が消すまで、最長で登録から約 48 時間は入居と出る。
- **K-010**（ADR-0088、`security.md` §3.5 の規則の表が正本）: 窓は固定、超えたら 429 `rate_limited` で残り・時刻・`Retry-After` は返さない。登録は IP ごとに 3 回／1 時間・10 回／1 日、ログインはメールアドレスごとに 10 回／15 分と IP ごとに 50 回／15 分、ほかに再認証・確認・再設定・`PUT /me/email`・入居の一覧と候補・通報・ブロック・プロフィール・住所録の検索、表にない経路の既定は 300 回／5 分。再認証は住民ごとに 10 回／15 分。確かめる順番は 認証 → 流量の制限 → ロールと二要素認証 → 再認証 → 入力の検証（認証なしの経路は流量の制限が最初）。この 2 つは ADR-0081 の D5 を変えるので、ADR-0081 を丸ごと置き換える ADR-0090 に書いた（ADR-0081 の状態は `置き換え（→ 0090）`）。主体は `RATE_LIMIT_HMAC_KEY` の HMAC で持ち、成功も失敗も数え、数えは本来の処理より先に別のトランザクションで書く。422 の合計の値は OQ-065 のまま。
- **K-014**（ADR-0089、`db.md` §2）: `sessions`（`id`・`token_hash`（SHA-256）・`resident_id`・`created_at`・`last_seen_at`・`expires_at`・`reauthenticated_at`・`second_factor_at`・`invalidated_at`）、`staff_roles`（PK (`resident_id`, `role`)、`role` は `moderator` だけ、`granted_at`・`granted_by`）、`rate_limit_buckets`（PK (`key`, `window_start`)、J14 が 1 日で消す）。TOTP の秘密は `credentials` の 4 列（`totp_secret_encrypted`・`totp_key_version`・`totp_enabled_at`・`totp_last_step`）で、メールアドレスと同じ鍵輪で暗号化する。J7 の手順 5 で `staff_roles` を消す。確認と再設定のトークンと変更中の新しいメールアドレスは `auth_tokens`（`token_hash` は `RESET_TOKEN_SIGNING_KEY` の HMAC・`purpose`・`new_email_encrypted`・`expires_at`・`used_at`、ADR-0089 の D6）に置く。ADR-0080 の D2 が「トークンの保存先の表の定義は R-025 で決める」と R-025 に送っていたので、R-025 の K-014 で一緒に決めた。
- **K-015**（`requirements.md`）: FR-010（24 時間を足した）・FR-092・FR-098・FR-100・NFR-013 を、決めた中身と ADR の番号（0080・0090・0020・0087・0088・0089）で書き直した。区分は秘書の判断なので `[assumed]`（FR-010 はマスターの答えの部分が `[inferred]` のまま）。

## 置き換えの ADR
- **ADR-0081 → ADR-0090（置き換える）**: ADR-0081 の D5 は、確かめる順番を「認証 → ロールと二要素認証 → 再認証 → 入力の検証」とし、再認証に「ログインと同じ流量の制限」を掛けると決めていた。K-010 で、順番に流量の制限を入れ（認証のすぐあと）、再認証を住民ごとの 10 回／15 分にした（ログインはメールアドレスごとと IP ごと）ので、D5 の中身が変わる。生きている D1〜D7 と新しい D5 を、同じ番号のまま ADR-0090 にまとめ、ADR-0081 の状態を `置き換え（→ 0090）` にした。生きている文書（`api.md`・`security.md`・`db.md`・`architecture.md`・`features.md`・`requirements.md`・`roadmap.md`・`open-questions.md`・`gaps.md`・図・`INDEX.md`・`adr/README.md`・ADR-0087〜0089）の参照は ADR-0090 にそろえた。`mvp.md` の 52 行目は YGO-028 の範囲なので G-050 に書いた。古い ADR（ADR-0080 など）の本文は変えない。
- **ADR-0085 → ADR-0091（置き換える）**: J7 と J14 が消すものに、`auth_tokens`（J7 の手順 0、J14 の期限切れ）・`staff_roles`（J7 の手順 5）・`rate_limit_buckets`（J14、1 日）・確認が済まない登録（J14、24 時間）が増えた。ADR-0085 の退去の表と保持期間の表は J7・J14 の正本（`security.md` §2.4・`async.md` J7・J14）なので、生きている D1〜D12 を同じ番号のまま ADR-0091 に移し、4 つの行と D13・D14 を足した。ADR-0085 の状態は `置き換え（→ 0091）`。生きている文書（`api.md`・`async.md`・`db.md`・`environment.md`・`gaps.md`・`open-questions.md`・`requirements.md`・`roadmap.md`・`security.md`・ADR-0087・0089・0090）の参照は ADR-0091 にそろえた。`mvp.md` の参照は YGO-028 の範囲（G-050）。
