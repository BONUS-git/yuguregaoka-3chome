# YGO-007 セキュリティ設計（.ai/security.md）
状態: open

## 目的
Goal の条件 8 を満たすため、`.ai/security.md` にセキュリティ設計を書く。セキュリティの判断を LLM の裁量にしないことを方針として明記する。

## 範囲
- 個人情報: どのデータが個人情報にあたるか、保存時の扱い（ADR-0006 の手紙の暗号化を参照）、退去時の削除と保持期間（ADR-0013 を参照）、ログに残さないもの
- 認証: 方式の方針（内部 ID と住所を分ける ADR-0001 を前提にする）、セッションの扱い
- 権限: 誰が何を読めて書けるか（郵便受け・掲示板・住所録・朝刊と夕刊）。判定はコードの固定の規則で行い、LLM に委ねない
- モデレーション: ADR-0005 を参照し、自動判定を使う場合も最終判断を LLM の裁量にしない仕組み
- 脅威と対策の一覧（なりすまし・情報漏えい・濫用・大量送信など）
- 新しい重要な判断があれば `.ai/adr/` に ADR として書く（背景・決定・理由・代わりの案）。決めきれないことは `.ai/open-questions.md` に送る
- 構想 `.ai/brief.md` は書き換えない。公開レポジトリのため、個人情報・認証情報・実在の人や団体を書かない。実装はしない

## 受け入れ確認
- `.ai/security.md` があり、個人情報・認証・権限・モデレーションの節がある
- 「セキュリティの判断を LLM の裁量にしない」ことが方針として書かれ、各節でどう守るかが書かれている
- 既存の ADR・`.ai/db.md`・`.ai/api.md`・`.ai/async.md` と矛盾しない
- 実装を終えたら、同じ変更でこのチケットの状態を `done` にする
