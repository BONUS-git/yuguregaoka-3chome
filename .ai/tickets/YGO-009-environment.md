# YGO-009 開発・検証環境の構築計画（.ai/environment.md）
状態: done

## 目的
Goal の受け入れ条件 10（`.ai/environment.md` に開発・検証環境の構築計画（スタックの計画と IaC の設計まで。適用・クラウドの契約はしない）がある）を満たします。

## 範囲
- `.ai/environment.md` を新規作成します。
- ローカル開発環境: ADR-0009・ADR-0010 に合わせ、TypeScript・Fastify・React・PostgreSQL を使います。ADR-0008 の 2 プロセス（web と worker）を動かす構成にします。
- 検証環境: テスト用 DB、メールのモックまたはローカル SMTP（ADR-0033）、LLM のモックの扱い（ADR-0031）を書きます。
- CI の計画: `scripts/check.sh` との関係を書きます。
- 想定する本番構成と IaC の設計: ツールの選定、モジュールの分け方、秘密情報の扱い（`.ai/security.md`・ADR-0021 に合わせる）を書きます。
- 費用の見積もりの考え方: ADR-0012 の規模を前提にします。
- デプロイ・IaC の適用・クラウドの契約はしないことを明記します。
- 重要な選定（IaC ツールなど）は、`.ai/adr/` に新しい ADR として記録します。
- architecture.md・roadmap.md・security.md・async.md と食い違う点があれば、同じ変更で直します。
- 決めきれない点は `.ai/open-questions.md` に追加します。
- 実装はしません。`.ai/brief.md` は書き換えません。公開レポジトリのため、個人情報・認証情報・実在の人や団体・アカウントの ID を書きません。

## 受け入れ確認
- `.ai/environment.md` があり、範囲に挙げた各項目（ローカル開発環境・検証環境・CI の計画・本番構成と IaC の設計・費用の見積もりの考え方）を扱っている。
- 適用・契約をしないことが明記されている。
- 選定の理由が ADR として記録されている。
- 既存の文書・ADR と食い違いがない。
- `sh scripts/check.sh` が通る。
- 実装を終えたら、同じ変更でこのチケットの状態を `done` にする。
