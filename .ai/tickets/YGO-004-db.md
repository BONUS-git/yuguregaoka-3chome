# YGO-004 DB 設計方針（.ai/db.md）
状態: done

## 目的
目標の受け入れ条件 5「`.ai/db.md` に DB 設計方針（データのライフサイクル: 作る・保つ・消す）がある」を満たす。

## 範囲
- `.ai/db.md` を新規作成する（実装・マイグレーション・SQL ファイルは作らない）。
- 前提として既存の `.ai/requirements.md`・`.ai/features.md`・`.ai/open-questions.md`・`.ai/architecture.md` と ADR（特に 0001 内部 ID と住所の分離、0002 空き家化の明示削除、0003 転居時に住所録を自動更新しない、0004 配達の定時と上限、0006 手紙の保存時暗号化、0010 PostgreSQL を DB とジョブキューに使う、0012 想定規模）を読み、矛盾しないようにする。
- 主なデータ（住人・住所・手紙・郵便受け・配達・朝刊と夕刊・町内掲示板・住所録・モデレーション・ジョブ）ごとに、作る・保つ・消すの方針（保持期間、削除と匿名化、退去や転居のときの扱い、バックアップからの消去）を書く。
- 要求番号（FR・NFR）と ADR への参照を付ける。未確定のものは `.ai/open-questions.md` の OQ 番号を参照し、ここで決めない。新しく重要な判断をするなら ADR を 1 つ追加してよい。
- 個人情報・認証情報・実在の人や団体は書かない。

## 受け入れ確認
- `.ai/db.md` があり、主なデータそれぞれについて作る・保つ・消すが書かれている。
- 既存の ADR・architecture.md と矛盾がない。
- 実装したら同じ変更でこのチケットの状態を `done` にする。
