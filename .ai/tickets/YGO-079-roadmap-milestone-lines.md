# YGO-079 roadmap.md にすべてのマイルストーンの行を書く
状態: done
M: M1

## 目的
秘書の決まった変更（DLG-21）。秘書はロードマップの `- M<n>: …` の行からマイルストーンを読み、M ごとのタスクで進捗を出す。`.ai/roadmap.md` §4「今の M の範囲」に、M0〜M6 の行を `- M<n>: <名前>。FR-…` の形で M の順に書く。FR は今の表から写し、新しく決めない。

## 範囲
- `.ai/roadmap.md` §4「今の M の範囲」: M0〜M6 の 7 行と、その書き方の説明。名前は §4 の表のマイルストーンの列（括弧の F を除く）。FR は M1 が前の行のまま、M2〜M6 が `mvp.md` (b)「MVP の M2〜M6」の表の FR 列（M ごとに合わせ、番号の順に重複なく、範囲は 1 つずつ）`[assumed]`。
- `scripts/check.sh` の 2 か所の読み取り（今の M の FR の段と、M1 の図の FR の段）: `- M1: ` の行から `FR-NNN` を取り出す形にする。

## 範囲を広げた理由
指示は「変えるのは `.ai/roadmap.md` だけ」。しかし `scripts/check.sh` は roadmap.md を `^- M[0-9]+: FR-` と `^- M1: FR-` で読んでおり、行の形を `- M1: 住所・アカウント。FR-…` に変えるとどちらにも当たらず、`check.sh` が「roadmap.md に今の M の範囲の行がない」で止まる（検証の `sh scripts/check.sh` が通らない）。`- M[0-9]+: ` に広げるだけでは、M5・M6 の FR（FR-036・FR-097 など未決の書き方が残るもの）まで今の M として調べて失敗する。そのため、今の M（M1）の行だけを読み、名前の部分を飛ばして `FR-NNN` を取り出す形に、読み取りの 2 か所だけを合わせた。確かめる中身（未決の書き方・図の FR が M1 の行にあること）は変えていない。`check.sh` は変更禁止のファイルではない。この範囲の広がりは、秘書の見直し（R1-F1）が認めたうえでマージする。

## 直さないところ
- `mvp.md`: (b) の「FR の一覧は roadmap.md §4 の `- M1:` の行と同じ」は今も正しい。
- `triage.md`・`retros.md` の `- M1: FR-…` の記述: そのときの記録なので変えない。
- `requirements.md` の FR-126 と FR-120 の行が `||` で 1 行につながっている件: M4 が今の M になる前に直す（秘書の仕分けで M4 に向ける）。

## 受け入れ確認
1. `grep -nE '^- M[0-9]+: ' .ai/roadmap.md` が M0〜M6 の 7 行を M の順に出す。
2. M1 の行の FR が前の行と同じで、M2〜M6 の FR が `mvp.md` (b) の表の FR 列と同じ。
3. `sh scripts/check.sh` が通る。
