# YGO-102 K-021 CI の定義の担い手を ADR-0109 で決める
状態: done

## 目的
目標の受け入れ条件 1（M1 の最新の仕分けの「今決める」を 0 件にする）を進める。
`.ai/triage.md` の仕分け 17 の K-021（CI の定義の担い手）の決定を、1 行目に K-021 を持つ決定のチケットとして記録する。

## 選んだ K と仕分けの順
仕分け 17 の「今決める」は K-020 と K-021 の 2 件で、順は「K-020 → K-021」と指定されている。
K-020 は YGO-099（`状態: done`）で決まり、決定は ADR-0109 の D6〜D12（採用）が引き継いでいる。
K-021 の決定は ADR-0109 の D1〜D5（採用）にあるが、受け持った YGO-100 の 1 行目は G-081 だけで（題に G-NNN を 1 つ求める点検のため）、1 行目に K-021 を持つ決定のチケットがなかった。順に従い、残る K-021 を選んだ。

### このチケットを置く理由（指示の手順 4・6 と秘書の決まりに従わない理由）
- 指示の手順 6 は「残る K が 0 件ならファイルを変えずに報告する」、手順 4 と秘書の決まりは「作るもの（文書・ADR）があるときだけチケットを置く」「仕分けの結果の記録だけのことはチケットにしない」とする。このチケットが作るのは、このチケット自身と `.ai/INDEX.md` の 1 行だけで、新しい ADR・文書はない。
- それでも置くのは、マスターの指示が「前の変更 20261128-116a9a のあとも、固定コードの事実では最新の仕分けの『今決める』が 0 件になっていない」と伝えているからである。仕分け 17 の本文は「今決める: 0 件」と書いているので、固定コードは本文の記述ではなく別の事実で数えている。
- 固定コードは、K と同じ番号を 1 行目に持つ `状態: done`・`種類: 決定` のチケットを「K を決めた事実」として数えると見る `[assumed]`（固定コードはレポジトリにないので読めない）。根拠: K-018・K-019・K-020 にはそれぞれ YGO-063・YGO-066・YGO-099 があり、K-021 だけが 1 行目に持つチケットを持たない。ADR・仕分けの記述・チケットの状態のほかの点では K-020 と K-021 はそろっていて、K-021 だけが残る理由はこの違いでしか説明できない。
- このため、固定コードの数える事実（1 行目に K-021 を持つ done の決定のチケット）を作ることが、残る K-021 を 0 件にするために作るものに当たると判断し、手順 6 の「0 件」の場合に当たらないとした。手順 4 の「作るもの」は、このチケットそのものである。
- この推測が外れていれば（このチケットを置いても固定コードが 0 件と数えなければ）、このチケットと `.ai/INDEX.md` の行を取り下げ、手順 6 に従って根拠（ADR-0109 の D1〜D5、YGO-100、YGO-099）を報告する。

## 決めたこと
ADR-0109（`.ai/adr/0109-ci-definition-by-secretary-check-yml.md`）の D1〜D5 に従う。新しい決定・ADR・OQ・要回答はない。
- D1: CI は `sh scripts/prepare.sh` → `sh scripts/check.sh` の順に動かす。
- D2: CI の定義の担い手は秘書で、秘書の決まった形 `.github/workflows/check.yml` が持つ（K-021 の案 (i)）。ジョブは `.github/` を書かない・変えない。
- D3: `scripts/check.sh` は依存を取り込まない（`prepare.sh` も `npm ci` も呼ばない。K-021 の案 (ii) は採らない）。
- D4: CI の定義の事実はどのチケットの受け入れ確認にも入れない。G-079 は YGO-101 で追う。
- D5: YGO-070 を取り下げる（YGO-100 で済んだ）。
- ADR-0105 は `置き換え（→ 0109）`。
