# YGO-037 R-017 G-002 プロフィールの住所の探りを T-05 と §3.5 にそろえる
状態: done
M: M1

## 目的
条件 8 のために、レビューの指摘 R-017（中。`GET /profiles/{address}` で住所に人が住んでいるかが分かり、流量の制限もない）を片づける。中心の点はあとの決定ですでに片づいている（入居は OQ-079 → 決定で誰にでも見え、プロフィールの 404 はそのまま残す: ADR-0084 の D16。`GET /api/v1/profiles/{address}` に住民ごとの制限: ADR-0088、`security.md` §3.5 の規則の表）。残っている食い違いは、`security.md` §7 の T-05 と `roadmap.md` の A-12 がこの 2 つに触れていないことだけなので、そこをそろえる。

## 仕分け
- `triage.md` の最新の回（仕分け 4）に、R-017 を扱う K-NNN はない。R-017 を扱っているのは `gaps.md` の G-002（暫定・M1）で、題に G-002 を付けた。
- M の判定: `roadmap.md` の `- M1:` の行に FR-008（プロフィール）と FR-115（入居）があるので、M1 にかかわる（指示の (a)）。

## 範囲
- `.ai/security.md` §7 の T-05: プロフィールの 200 と、空き家と存在しない住所の同じ 404（ADR-0084 の D16）、プロフィール・ブロック・住所録の検索の住民ごとの流量の制限と 429 `rate_limited`（ADR-0088）を足す。値は §3.5 の規則の表を正本にし、T-05 に書き写さない `[assumed]`。
- `.ai/roadmap.md` の A-12: プロフィールの 61 回目の 429 と、404 が同じ本文であることの確かめを足し、確かめ方の列の根拠に ADR-0084 の D16 を足す。
- `.ai/gaps.md` の G-002: 残りがないことに書き直し、出どころを `R-017（YGO-037）` にする。
- `.ai/INDEX.md`: 「住所の列挙と探り」の行と、このチケットを足す。

## 直さないところと理由
- レビューの直し方の案「住所録か手紙のやり取りにある住所のときだけプロフィールを返し、ほかは住んでいても 404 にする」は採らない。ADR-0084 の D16 で 404 は変えないと決まっており、入居の一覧（`GET /addresses/occupancy`）が誰にでも入居を見せる今は、絞っても隠せるものがないため。
- ADR: 決定を変えないので足さず、状態も変えない。新しい要回答は 0 件。
- `security.md` §3.5 の規則の表の値・`api.md` §7 F-01（すでに 404 と 429 を書いている）・`mvp.md`・`status.md`・`triage.md`・`reviews/`: 変えない。
- テスト: 文書だけの変更で足さない（くり返す確かめを `check.sh` に入れるのは G-061 の予定）。
