# YGO-005 API 設計方針（.ai/api.md）
状態: open

## 目的
目標の条件 6「`.ai/api.md` に API 設計方針（API・DB・バッチの責務の分け方）がある」を満たす。

## 範囲
- `.ai/api.md` を新規作成する（このチケットの実装時。チケット作成の変更では作らない）
- 前提として `.ai/brief.md`・`.ai/requirements.md`・`.ai/features.md`・`.ai/architecture.md`・`.ai/db.md`・`.ai/open-questions.md`・既存の ADR を読み、それらと矛盾させない
- API・DB・バッチ（定時配達・夜間の組版など）の責務の分け方。どの処理をどこで行い、どこで行わないか
- API の方針: リソースの区切り、認証と権限の確認の位置、エラーの形、ページングなど。即時性と数値の評価を持ち込まない構想に合わせる（例: 既読・件数・リアルタイム通知を出さない）
- 主な機能（MVP の F-01〜F-09）ごとのエンドポイントの概略
- 重要な判断は `.ai/adr/` に ADR（背景・決定・理由・代わりの案）を追加してよい。決めきれないことは `.ai/open-questions.md` への追記ではなく、`.ai/api.md` の中に未確定事項として書く
- 実装（コード）はしない。`.ai/brief.md` は書き換えない

## 受け入れ確認
- `.ai/api.md` があり、API・DB・バッチの責務の分け方が節として書かれている
- MVP の機能に対応する API の概略がある
- 既存の文書・ADR と矛盾がない
- 個人情報・認証情報・実在の人や団体を書いていない
- 実装を終えたら、このチケットの 2 行目を `状態: done` にする
