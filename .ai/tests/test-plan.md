# テスト項目書（M1）

- 対象: `.ai/roadmap.md` §4 の `- M1:` の行の FR 18 件（FR-001, FR-002, FR-003, FR-007, FR-008, FR-009, FR-010, FR-091, FR-092, FR-094, FR-098, FR-100, FR-103, FR-113, FR-114, FR-115, FR-124, FR-127）。
- 根拠: `.ai/requirements.md`、`.ai/api.md` §5・§7 の F-01・F-02・F-19、`.ai/db.md` §2、`.ai/async.md` の J14・J18・§7、`.ai/security.md` §3・§4.2、各 ADR、M1 の図（`.ai/diagrams/m1-*.md`）。
- roadmap §4 の受け入れ条件 A-xx にかかわる TC は、確かめることの末尾に括弧で番号を書く。

## 決まり

- テストの名前に TC-NNN を入れる。Vitest の `test` / `it` の名前の頭に `TC-001 …` と書く。関数やファイルの名前にするときは `test_TC_001_…` の形にする `[assumed]`。
- `skip`・`todo` のテストは通っていないと数える。`check.sh` は JUnit XML に `skipped` があると失敗し、名前に TC-NNN のないテストも失敗にする（YGO-062）。
- テストの結果は JUnit XML で `test-results/junit.xml` に書く（`vitest.config.ts`。`test-results/` はコミットしない）。
- M1 の FR を確かめるテストは、どれもこの表の TC を持つ。1 つの TC を複数のテストに分けるときは、どのテストにも同じ ID を入れる。
- ID は `TC-` と 3 桁で、使い回さない。FR を足したら表の末尾に続きの番号で足す。
- どのテストも `sh scripts/check.sh` から、ネットワークなしで動かす（`.ai/environment.md` §4.1）。使うのは使い捨ての PostgreSQL（Unix ソケットだけ）・Fastify の `inject`・差し替えた時計。テストの準備で、外への接続を失敗させる。
- メールは ADR-0033 のモックのアダプタで確かめる（外の SMTP には送らない）。
- 偽の値は `.ai/environment.md` §4.2 のとおり: メールは `test@example.invalid`、住所は `夕暮ヶ丘三丁目 2-5`、存在しない住所は `夕暮ヶ丘三丁目 99-1`、鍵は `EXAMPLE_KEY_DO_NOT_USE`、漏れを探す目印の文字列は `EXAMPLE_MARKER_DO_NOT_USE` `[assumed]`。
- テストのコードは別のチケットで書く。実装済みかどうかは `.ai/status.md` が示す。

## 種類

| 種類 | 中身 |
|---|---|
| 単体 | DB なし。関数と定義だけを確かめる |
| 結合 | 使い捨ての PostgreSQL を使い、DB の行を直接読む |
| API | Fastify の `inject` で経路を呼ぶ（DB あり） |
| ジョブ | worker のジョブ J14・J18 を、差し替えた時計で動かす |
| 部品 | C1 の画面の部品。Vitest と Testing Library で、`fetch` は差し替える |
